二、@abstractmethod 跟 public 有關係嗎

沒有關係，它們解決的是完全不同的問題。

特性@abstractmethodpublic／protected／private
核心目的規範繼承架構規範資料封裝與權限
在回答什麼問題「子類別有沒有把這個方法寫出來？」「誰可以呼叫這個方法？」
運作機制強制子類別覆寫，沒寫就不能建立實例限制外部／子類別／內部的存取範圍

d @abstractmethod 管繼承規格。
e 存取修飾子管封裝。
f 兩者可以組合：抽象方法通常是 public，但也可以是 protected。

Python 沒有存取關鍵字，只有命名慣例

想表達Python 寫法實際效果
publicdef attack(self):大家都能呼叫
protecteddef _calc(self):只是提示，語言不會擋
privatedef __calc(self):觸發 name mangling，改名成 _ClassName__calc

g Python 的封裝是君子協定，雙底線也只是改名不是真的鎖住。
h TypeScript 的 private 是編譯期檢查，transpile 成 JS 後就沒了，要執行期私有請用 #field。

三、兩個常見的初學錯誤

NameError: name 'Warrior' is not defined
i Python 由上往下執行，只貼測試區塊而沒把 class Hero／class Warrior 放在前面，跑到 Warrior(...) 就找不到名稱。解法：把類別定義放在檔案上半部。
SyntaxError：def__init__ 少一個空格
j def 與 __init__ 之間必須有空格。

k def attack(self, target: 'Hero') -> None: 的型別提示對執行結果完全沒有影響，只是給編輯器補全用；寫成字串 'Hero' 是因為類別當下還沒定義完（forward reference）。

npm create vite@latest my-ts-app -- --template vanilla-ts
cd my-ts-app && npm install
npm i dayjs axios
npm run dev

m 開發期：dev server 把 .ts 即時 transpile 成 JS，並把裸模組名 'dayjs' resolve 成 node_modules 的實際路徑。
n npm run build：把你的 TS 與相依一起打包成標準 JS 與 HTML。
o vanilla-ts ＝「原生 JS ＋ TypeScript，不含任何框架」。
p 不能只用 tsc 配 <script>，因為 tsc 只 transpile，不把 node_modules 的相依打包進來。

發生在迴圈裡的 hero.attack(boss) 這一行。party 的靜態型別是 Hero[]，所以編譯期只知道「這東西一定有 attack 方法」；真正要跑 Warrior.attack 還是 Mage.attack，是執行期由該位置實際放的實例決定的（動態分派）。這就是為什麼同一行程式碼可以印出兩種完全不同的戰鬥訊息，而呼叫端完全不需要寫任何 if isinstance(...) 的判斷。

Q2：Warrior 覆寫 take_damage() 之後，還呼叫 super().take_damage()，這樣做的好處是什麼？


職責切乾淨：子類別只負責「這個職業特有的減傷規則」（護甲抵扣），至於「HP 不得低於 0、要印出剩餘血量」這種所有英雄共通的邏輯仍然只寫在父類別一份。日後要改共通邏輯（例如加上「受傷時觸發被動」），只要改 Hero.take_damage() 一個地方，所有子類別自動跟著變，不會出現複製貼上的漂移。
