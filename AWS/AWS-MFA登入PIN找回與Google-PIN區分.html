AWS 登入要求 MFA PIN 但找不到設定 — 排查與 Google PIN／備用碼區分

本篇重點 a–j，共 10 個

重點整理

a. MFA(Multi-Factor Authentication，多因子驗證) 是在密碼之外要求第二種驗證因素的安全機制；即使自己不記得主動設定過，也可能是當初建立帳號(尤其是 Root 帳號)時順手開啟建議設定，或是公司 IAM 政策強制要求。

b. 找回 AWS 6 位數 MFA PIN 的排查順序：①先檢查手機上的驗證 App(Google Authenticator、Microsoft Authenticator、Authy、Duo Mobile)，搜尋是否有 "AWS" 或 "Amazon Web Services" 項目；②檢查是否有實體金鑰(如 YubiKey)或密碼管理員(1Password、Bitwarden、iCloud 密碼)是否內建自動產生 TOTP 動態碼；③若都找不到且無法登入，在輸入 MFA 頁面找 "Troubleshoot MFA" 連結，Root 使用者可透過驗證電子郵件＋註冊電話暫時跳過 MFA；IAM 使用者則需聯繫帳號管理員從後台重設。

c. 容易搞混的三種「代碼」，位數與用途都不同，找 PIN 時務必分清楚:

代碼類型 位數 用途
Google 備用驗證碼 8 位(固定) 無法收簡訊或沒有驗證 App 時，登入 Google 帳號的最後手段
Google 密碼管理工具 PIN 自訂(4–6 位) 解鎖儲存在 Google 的密碼或 Passkey
AWS MFA PIN 6 位(每 30 秒動態變動) AWS 登入驗證，非固定值

⚠️ 若在 Chrome 密碼管理工具看到「輸入 PIN 解鎖」畫面，代表 AWS 的 MFA 金鑰(Passkey)很可能被存進了 Google 帳戶，此時應輸入平常用於 Windows／Android／Chrome 的自訂 PIN 來解鎖，而不是去找一組「6 位數固定密碼」。

追加 2026-08-27 — Passkey 與 TOTP 認錯的完整解法

d. TOTP（Time-based One-Time Password，時間型一次性密碼）就是手機驗證碼 App（Google Authenticator、Microsoft Authenticator、1Password）產生的那組 6 位數動態碼。AWS 文件若提到 TOTP token 不同步，代表系統認為這個帳號綁定的是「驗證器 App」這種 MFA。

e. AWS 預設不會自動開啟 MFA，不論 Root 帳號還是 IAM 使用者，剛建立時都是關閉的，一定是有人手動綁定過（自己、或當初建立 IAM 帳號的公司管理員）。沒有印象的三個常見原因：公司管理員用自己的裝置綁定、當初用的其實是瀏覽器內建 Passkey 而非獨立 App、換過手機而 Authenticator 資料沒備份移轉。

f. Passkey / FIDO2（通行密鑰）與 TOTP 是兩種不同的 MFA。最關鍵的辨識徵兆：掃 QR Code 之後手機只跳出「Google 密碼管理工具」而不給你選 Google Authenticator，就代表當初設定的是 Passkey 而不是 TOTP——瀏覽器遇到 Passkey 驗證會直接呼叫系統內建的密碼管理工具去找憑證，根本不會列出驗證碼 App。

g. 「顯示找不到密碼」代表雲端根本沒有那把憑證。Passkey 是加密金鑰對，建立時會同步到 Google 密碼管理工具或 iCloud 鑰匙圈；既然雲端查無資料，換到舊手機登入同一個 Google 帳號結果也一樣。而且 Passkey 絕不會以一般檔案形式存在手機儲存空間或資料夾中，無法單獨複製或搬移，所以「翻舊手機找檔案」這條路不通。

h. IAM 使用者被刪除時金鑰會怎樣：管理員若執行 Delete User，AWS 會自動註銷該帳號綁定的所有 MFA 裝置，手機 App 或硬體金鑰裡的資料就失效；若管理員只是拿掉登入權限而沒有點 Deactivate MFA，該金鑰在後台仍顯示「綁定」狀態，但因權限已廢除也無法用來登入。

i. Passkey 與 SMS 都不通時的正解：不要再反覆嘗試登入，直接走 AWS 的免登入 MFA 支援表單申請人工重置。填 Root 帳號 Email，Inquiry type 選 MFA - Multi-Factor Authentication，Problem Type 選 Root account MFA reset，說明欄貼上英文陳述（憑證正確但無法完成 MFA、被要求 Passkey 但密碼管理工具無憑證、收不到 SMS、請求停用 MFA 以便驗證身分後重新取得存取權）。送出後 AWS 客服會以 Email 或電話聯繫驗證身分。

j. 想改用 TOTP 必須先能登入，順序是「先請客服重置現有 MFA → 只用 Email＋密碼登入 → 進 IAM 主控台的安全性憑證頁面 → 多因素驗證區塊點『指派 MFA 裝置』→ 選 Authenticator app → 用 Google Authenticator 掃 QR Code」。卡在登入畫面時是無法直接切換驗證方式的。

k. 另一個容易誤判的點：登入頁看到的 "If your virtual MFA device or hardware TOTP token appears to be functioning properly..." 那段，是 AWS 官方說明文件的通用段落，不是針對你個人帳號狀態的警示，可以直接忽略、繼續走客服表單流程。
