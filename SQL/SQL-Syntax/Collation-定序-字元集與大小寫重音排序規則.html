Collation（定序）——資料庫比較與排序字串的規則，與字元集的差別

本篇重點 a–g，共 7 個。

重點整理

(a) Collation（定序／排序規則）是資料庫用來「比較與排序字串」的一套規則。字串存進資料庫的只是字元，但「'A' 和 'a' 算不算相等」「'é' 排在 'e' 前後」「中文按注音還是筆劃排」都要靠 Collation 決定。

(b) Collation 主要控制三件事：

  • 大小寫敏感度：CI（Case-Insensitive）下 WHERE name = 'alex' 找得到 'Alex'，CS（Case-Sensitive）下找不到。
  • 重音敏感度：AI（Accent-Insensitive）把 'é' 視為 'e'，AS（Accent-Sensitive）視為不同。
  • 排序順序：ORDER BY 時文字怎麼排。德語 ä 可能排在 a 後或等同 ae，中文有注音、筆劃、拼音三種需求。

(c) 命名範例 utf8mb4_unicode_ci 拆開讀：utf8mb4 是字元集（完整 Unicode，含 Emoji）、unicode 是比對演算法、ci 是大小寫不敏感。utf8mb4_bin 的 bin 表示直接比對二進位位元組，區分大小寫且最快。

(d) Character Set（字元集）決定資料庫能「儲存」哪些字，負責把字元轉成二進位碼（UTF-8、Big5）。Collation決定儲存後怎麼「比較與排序」。一個字元集可搭配多個 Collation。

(e) 實務影響：UNIQUE 約束、WHERE =、LIKE、ORDER BY、GROUP BY 都吃 Collation。例如在 CI 的欄位上 'Alex' 與 'alex' 會撞 UNIQUE，這是新手常見的「為什麼明明大小寫不同卻重複」。

(f) ⚠️ 存疑／補充：對話的命名範例（_ci、_bin、CI/CS/AI/AS 後綴）主要是 MySQL／SQL Server 的慣例。PostgreSQL 不用這種後綴，它的 Collation 來自作業系統 libc 或 ICU 的 locale 名稱（例如 en_US.utf8、zh-TW-x-icu），要做大小寫不敏感比較通常改用 citext 擴充、lower() 索引，或 ICU 的 nondeterministic collation。另外 MySQL 8.0 的預設已是 utf8mb4_0900_ai_ci，不是 utf8mb4_unicode_ci。

(g) 查法：MySQL 用 SHOW COLLATION LIKE 'utf8mb4%';，PostgreSQL 用 SELECT collname FROM pg_collation;。

使用者：Collation到底是什麼

Gemini：簡單來說，Collation（定序／排序規則）就是資料庫用來「比較與排序文字（字串）」的一套規則。不同語言、地區或業務需求對「文字如何比較大小」與「是否相等」的認定並不一樣。

  1. 主要控制三件事：大小寫敏感度（CI／CS）、重音／聲調敏感度（AI／AS）、排序順序（德語 ä、中文注音筆劃拼音）。
  2. 命名範例：utf8mb4_unicode_ci 為 字元集 utf8mb4（支援完整 Unicode／Emoji）＋ 比對演算法 unicode ＋ ci 大小寫不敏感。utf8mb4_bin 為直接比較二進位位元組，區分大小寫且比對速度最快。
  3. Character Set 決定能「儲存」哪些字，Collation 決定如何「比較與排序」這些字。
