SQL Join 全解—Inner／Left／Right 的主表判定與資料保留規則

🔖 本篇重點索引：a–n，共 14 個。

重點整理

(a) Join 的本質：把兩張（或以上）資料表，依照某個共通欄位（Key，鍵）做橫向合併。想像拼圖——Join 就是找到拼塊邊緣並接合的過程。注意是「加寬欄位」而不是「加長列數」的合併，這點跟 UNION（縱向疊加）完全不同。

(b) Inner Join 與 Left Join 的唯一差別：對待「不匹配資料」的方式。

  • Inner Join（內聯結）＝交集：只保留兩張表都有出現的資料，A 表某列在 B 表找不到對應就整列消失。
  • Left Join（左外部聯結）＝以左表為主：保留左表全部資料，右表沒對應時，右表的欄位補 NULL。

(c) Inner Join 沒有「主表」的概念：因為結果是交集，把 Students 放左邊或把 Grades 放左邊，最終列數完全一樣，兩表地位對等。

(d) 語法位置上的稱呼（跟主從無關）：寫在 FROM 後面的叫左表（Left Table），寫在 JOIN 後面的叫右表（Right Table）。這只是「位置」的稱呼，只有在 Outer Join 才會升格成「主表」。

(e) 主表判定口訣（考自己用）：

Join 類型 誰是主表 主表的保證
INNER JOIN 沒有主表，兩表對等 只有交集才出現
LEFT JOIN FROM 後面那張（左表） 左表每一筆都保證出現
RIGHT JOIN JOIN 後面那張（右表） 右表每一筆都保證出現

(f) 實戰範例—學生與成績：

-- 只會列出「有成績」的學生，沒考試的人整列消失
SELECT * FROM Students
INNER JOIN Grades ON Students.id = Grades.student_id;

-- 會列出「所有」學生，沒成績的人 Grades 相關欄位是 NULL
SELECT * FROM Students
LEFT JOIN Grades ON Students.id = Grades.student_id;

(g) Inner Join 的顯示邏輯，就是一道過濾器：不管是「學生沒參加考試（Grades 表裡根本沒有那個 student_id）」還是「成績級距沒填」，只要 ON Students.id = Grades.student_id 這個條件不成立，該名學生就完全不會出現在結果中。

(h) Left Join 的顯示規則：學生有成績就正常顯示 A／B／C；學生沒成績時，主表（學生）依然出現在清單上，只有從表（成績）的欄位自動補 NULL。

(i) Left 與 Right 的關係—只是方向不同：邏輯完全一樣，差別只在「誰當主角」。用文氏圖（Venn Diagram）記——A LEFT JOIN B 是圓圈 A 完整、B 只取重疊；A RIGHT JOIN B 是圓圈 B 完整、A 只取重疊。

-- 情境 A：想列出「所有學生」，看他們參加什麼社團 → 學生是主角
SELECT Students.name, Clubs.club_name
FROM Students
LEFT JOIN Clubs ON Students.club_id = Clubs.id;

-- 情境 B：想列出「所有社團」，看裡面有哪些學生 → 社團是主角
SELECT Students.name, Clubs.club_name
FROM Students
RIGHT JOIN Clubs ON Students.club_id = Clubs.id;

(j) 為什麼工程師幾乎不用 Right Join：因為 A RIGHT JOIN B 的結果完全等於 B LEFT JOIN A，而人類閱讀習慣是從左到右。實務上會把「最重要的主表」寫在 FROM 後面，然後一路 LEFT JOIN 下去，程式碼比較好讀。

(k) 陷阱一—資料膨脹（Row Multiplication）：如果 Join 的 Key 不是唯一的（一對多），結果的列數會比原來的表更多。例如一個學生有五科成績，Join 之後這名學生就會出現五列。做 SUM／COUNT 前一定要先確認這件事，否則金額會莫名其妙被灌大。

(l) 陷阱二—WHERE 會把 Left Join 偷偷變成 Inner Join：在 Left Join 中，如果把「右表的過濾條件」放在 WHERE 而不是 ON，因為沒對應的列右表欄位是 NULL，而 NULL 會被 WHERE 過濾掉，結果就退化成 Inner Join。

-- ❌ 這其實變成 Inner Join：沒成績的學生被 WHERE 濾掉了
SELECT * FROM Students
LEFT JOIN Grades ON Students.id = Grades.student_id
WHERE Grades.score > 60;

-- ✅ 想保留所有學生，過濾條件要放進 ON
SELECT * FROM Students
LEFT JOIN Grades ON Students.id = Grades.student_id AND Grades.score > 60;

(m) 實務選擇建議：

  • 想算全班平均分數 → 用 INNER JOIN，因為沒考的人不該算進平均。
  • 想確認誰還沒交作業 → 用 LEFT JOIN，列出全班之後看誰的成績欄位是 NULL（可再加 WHERE Grades.student_id IS NULL 精準抓出來）。

(n) 誰放前面的效能考量：Inner Join 兩者對等時，傳統觀念會建議把「資料量較小的表」當驅動表（Driving Table，驅動資料表）以提升讀取效率。不過現代資料庫的查詢優化器（Query Optimizer）通常會自行重排執行計畫，實際效能還是要看 EXPLAIN 的執行計畫而不是寫法順序。
