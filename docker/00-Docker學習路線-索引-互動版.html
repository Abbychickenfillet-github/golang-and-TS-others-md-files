把 docker/ 資料夾裡散落的筆記照學習順序串起來 · 建立於 2026-10-14

1. 要學多深

目標定位：前端工程師、有全端基礎，能自己把後端開發環境跑起來、看得懂也改得動 compose 和 Dockerfile、出問題會自己查。不用學到 DevOps 的程度。

程度內容
必會image 和 container 的差別、常用指令（ps、logs、exec、up、down）、讀懂並修改 compose 和 Dockerfile、volume、service 名稱連線、env 變數、清理 vhdx
知道就好client 和 daemon 的架構、layer cache、multi-stage build、healthcheck、CI 裡 build 映像檔再推到 registry
先不用Kubernetes、Docker Swarm、自訂網路驅動、映像檔簽章、dockerd 的進階參數

面試時能講出「我用 compose 起 Go＋MySQL＋Redis 的開發環境，backend 用 service 名稱連 DB，env 在執行時注入，密碼不進 git」就很夠了。

2. 調整後的學習順序

1 架構→2 image 與 container→3 基本指令→4 Dockerfile→5 volume→6 網路與 port→7 compose 與 env→8 啟動與關閉→9 清理 vhdx→10 選修 CI/CD

修正一個觀念：容器沒關不會讓 vhdx 變大，只會吃 CPU 和記憶體。vhdx 變大是因為反覆 --build 留下的舊映像檔、build cache、volume 資料，而且 vhdx 只會長不會自己縮。所以第 8 站是「用完要 down」，第 9 站才是「定期 prune 再壓縮 vhdx」。

3. 各站內容與既有筆記

第 1 站：架構（client、daemon、Docker Desktop、WSL2）知道就好

docker CLI（client）把指令透過 socket 或 named pipe 傳給 dockerd（daemon），daemon 才真的去建映像檔和容器。Docker Desktop 是 GUI，加上一台跑在 WSL2 裡的 Linux VM，資料都存在那顆 vhdx 裡。

筆記：[[docker-引擎-context-image-container-觀念]]、[[Docker-Socket與Client-Daemon通訊-var-lib-docker路徑解剖]]、[[windows-用-linux-的方式]]、[[如何啟動docker-desktop與WSL]]、[[Docker-Desktop-卡在starting或distro-stopped-排查]]、[[比較Git bash 與Docker WSL bash]]

第 2 站：image 與 container、映像檔注意事項 必會

image 是唯讀的模板（由很多層 layer 疊成），container 是用 image 跑起來的執行個體。注意事項：

　a. 不要用 latest 當正式版本的 tag，會不知道實際跑的是哪一版。

　b. alpine 映像檔小，但用的是 musl 而不是 glibc，偶爾會有相容問題。

　c. 密碼、金鑰不要寫進映像檔，拿到映像檔的人都看得到。

筆記：[[docker-引擎-context-image-container-觀念]]、[[建立IMAGE指令]]、[[docker-scout常用指令與介紹]]

第 3 站：docker 基本指令 必會

先熟這 8 個：ps、images、logs、exec、run、stop、rm、pull。

筆記：[[docker-本次指令清單-中英對照]]、[[docker-notes]]、[[CONTAINER_PATH_AND_SHELL_EXPLANATION]]、[[mysql-docker-cli]]

第 4 站：Dockerfile 必會

看懂 FROM、WORKDIR、COPY、RUN、EXPOSE、CMD。重點是 layer cache：先 COPY go.mod 再 go mod download，最後才 COPY 全部原始碼，這樣改程式碼時不用重抓套件。Go 正式版常用 multi-stage build（知道就好）。

筆記：[[建置失敗排查-Module-not-found與ESLint在哪一階段-npm-ci與Dockerfile-WORKDIR]]、[[建立IMAGE指令]]

第 5 站：volume 必會

named volume（例如 mysql-data）讓資料庫資料在容器刪掉後還在。bind mount（例如 .:/app）把你的原始碼掛進容器，熱重載靠它。down -v 會連 named volume 一起刪掉，資料庫資料就沒了。

筆記：[[2025-12-01_volume_在docker-compose.yml是什麼意思跟用途_696a2788]]、[[MySQL資料庫備份指南]]、[[PostgreSQL-Checkpoint與SIGTERM-Docker停止機制]]

第 6 站：網路與 port 必會

compose 裡的 service 名稱就是內部網路的主機名稱。ports: 是開給主機用的，容器互連不需要它。

筆記：[[Docker-Compose連資料庫-env變數與DSN]]（第 4 節）、[[DOCKER_PORT_CONFLICT_SOLUTION]]、[[PORT_CONFLICT_TROUBLESHOOTING]]、[[QUICK_FIX_5004_PORT]]、[[ROUTING_AND_DOCKER_EXPLANATION]]、[[Nginx-反向代理與動靜分離]]

第 7 站：docker compose 與 env 變數 必會

services、build、ports、volumes、depends_on、healthcheck、environment、env_file。env 在執行時注入，Vite 的 VITE_* 卻是 build 時寫死，這個對比要記住。

筆記：[[Docker-Compose連資料庫-env變數與DSN]]（今天新寫）、[[2025-11-25_docker-compose-guide]]、[[DOCKER_COMPOSE_COMMAND_EXPLANATION架構]]、[[compose-dev-references-dockerfile-dev-and-mysql-host-check]]、[[docker-compose-modes]]、[[docker-compose-develop-section]]、[[並行串行]]、[[docker-compose-ps-and-unix-ps]]

第 8 站：啟動、熱重載、關閉 必會

指令做什麼
docker compose -f 檔案 up --build重新 build 後啟動，log 印在前景
docker compose -f 檔案 up -d在背景啟動，env 有改會自動重建容器
docker compose -f 檔案 logs -f backend-go持續看某個 service 的 log
docker compose -f 檔案 down停止並刪除容器和網路，volume 保留
docker compose -f 檔案 down -v連 volume 一起刪，資料庫資料會消失

VS Code 裝 Docker 擴充套件後，對 compose 檔按右鍵選 Compose Up 和打指令效果一樣。

筆記：[[docker-compose-watch-vs-npm-dev]]、[[air-docker-compose]]、[[WATCH_AND_RELOAD_TROUBLESHOOTING]]、[[docker-compose-switch-mode]]、[[docker-compose-watch]]

第 9 站：清理與壓縮 vhdx 必會

先用 docker system df 看誰佔空間，再 prune build cache 和沒用的映像檔，最後用 diskpart compact 把 vhdx 縮回來。

筆記：[[Docker問題prune+壓縮vhdx(虛擬磁碟)解決硬碟爆掉]]、[[Docker磁碟清理與WinRE事件4502(互動測驗)]]、skill：docker-vhdx-cleanup
