🧠 自我測驗

是非題

  1. VS Code 是用 Electron 做的，Electron 內含 Chromium 與 Node.js。

    所以說它骨子裡是一個去掉網址列的 Chrome，並不誇張。

  2. 因為 VS Code 自帶 V8 引擎，所以你不用安裝 Node.js 也能在整合終端機打 node app.js。

    這是 Gemini 講得太滿的地方。VS Code 內建的 Node 是給它自己的擴充功能與 tsserver 用的，沒有對外開放。終端機的 node 走的是你系統 PATH 上的 Node.js。

  3. 要在 VS Code 寫 C#，只裝擴充功能不裝 .NET SDK 就能編譯執行。

    擴充功能只是操作面板，SDK 才是編譯器與執行環境本體。

  4. Dockerfile 裡 FROM golang:1.23-alpine 的 Image 已經預裝好 Go toolchain。

    這就是「本機沒裝 Go 也能跑 Go」的真正原因。

  5. golang 這個 Docker 官方 Image 是微軟維護的。

    是 Docker Official Images 專案維護的，跟微軟無關。Gemini 在這裡講錯了。

  6. 只用 docker build、不用 Dev Containers 的話，VS Code 的 Go 擴充功能會跳 Go command is not available。

    因為 VS Code 在 Windows 這一側找不到 toolchain，建不起語言服務，Go to Definition 也會失效。

  7. 瀏覽器絕對不可能執行 C#。

    透過 WebAssembly，Blazor WebAssembly 可以在瀏覽器裡跑 C#。不過你仍然得先有 .NET SDK 才編得出 Wasm。

填空題

  1. VS Code 所使用的桌面應用框架，把 Chromium 與 Node.js 打包在一起，叫做 。

    這也是 Slack、Discord 桌面版的基礎。

  2. SDK 的全名是 Software Development 。

    一整組工具：編譯器、連結器、標準函式庫、套件管理器。

  3. Java 的開發套件縮寫是 ，全名 Java Development Kit。

    只想執行不想開發的話是 JRE。

  4. 讓 VS Code 直接連進容器內部、讀取容器裡 toolchain 的擴充功能叫 Dev 。

    裝了它，Go to Definition 與智慧提示才會恢復。

  5. golang:1.23-alpine 裡的 alpine 指的是一個極小的 Linux 發行版 Alpine 。

    約 5 MB，常拿來當精簡基底映像。

申論題

  1. 請完整說明「編輯器」「執行環境（Runtime）」「工具鏈（Toolchain / SDK）」三者的分工，並用它解釋這兩個現象：(1) 為什麼在 VS Code 寫 C# 一定要另外裝 .NET SDK；(2) 為什麼有人本機完全沒裝 Go，Go 程式卻跑得起來。最後說明第二種情況會帶來什麼開發體驗上的副作用、以及怎麼解。

    參考方向：(1) 三者分工——編輯器負責打字、上色、補全，本身不執行程式；Runtime 是真正跑起來的引擎（Node.js、JVM、CPython）；Toolchain/SDK 是編譯器加標準函式庫加套件管理器的整組工具。VS Code 是 Electron 做的編輯器，它內建的 Node 只服務自己的擴充功能與語言服務（tsserver），不對外開放。(2) C# 的情況——VS Code 對 C# 只是高級打字機，按下執行時它把原始碼交給後台的 .NET SDK 編譯執行，再把結果接回終端機顯示。沒有 SDK，程式碼就只是純文字。(3) Go 的情況——Dockerfile 的 FROM golang:1.23-alpine 拉的 Image 裡已經預裝完整 Go toolchain，編譯發生在容器內的 Linux，本機 Windows 完全不需要有 Go。好處是不污染本機環境、沒有版本衝突，刪掉容器就乾淨。(4) 副作用——VS Code 在 Windows 這側找不到 toolchain，Go 擴充功能會一直跳 Go command is not available，語言服務起不來，Go to Definition 跳轉失效，型別提示全無。(5) 解法——裝 Dev Containers 擴充功能，讓 VS Code 直接連進容器內執行語言服務，就讀得到容器裡的 toolchain。

重點整理

一、名詞先講清楚（f–h）

先把三個常被混用的字釘死，後面才不會亂：

名詞 全名 白話
Editor / IDE Integrated Development Environment（整合開發環境） 你打字的地方。負責上色、自動補全、跳轉定義
Runtime Runtime Environment（執行環境） 真正把你的程式跑起來的引擎。例如 Node.js、JVM、CPython
Toolchain / SDK Software Development Kit（軟體開發套件） 一整組工具：編譯器、連結器、標準函式庫、套件管理器。例如 Go toolchain、.NET SDK、JDK

f. VS Code 是用 Electron 做的。Electron 是把 Chromium（瀏覽器核心）加上 Node.js 打包成桌面 App 的框架。所以 VS Code 骨子裡確實是「一個去掉網址列、專門用來改程式碼的 Chrome」。

g. 因為 Electron 內含 Node.js，VS Code 自帶了一份 Node 與 V8 引擎，用來跑它自己的擴充功能與語言服務（Language Server）。TypeScript 的型別檢查、JS 的 IntelliSense，就是靠這份內建的 Node 在背後跑 tsserver。

h. 但 「VS Code 自帶 V8」不等於「你可以不裝 Node.js 就跑 JS」——這是 Gemini 在對話裡講得不夠精確的地方，見下方「⚠️ 存疑／更正」。

二、為什麼寫 C# 要下載 .NET SDK（i–j）

i. VS Code 對 C#、Java、Go、Python 這些語言而言，只是一台高級打字機。它沒有能力執行這些語言，它做的事是：把你的原始碼丟給後台真正的 SDK，SDK 編譯並執行完，再把結果接回來顯示在整合終端機裡。

[ 你在 VS Code 寫 C# ] ──(把程式碼丟過去)──> [ 後台的 .NET SDK ]
                                                     │ (編譯並執行)
[   看到輸出結果      ] <──(把結果傳回來)──────── [ 電腦 CPU (x64) ]

j. 跨語言對照表：

你想寫的語言 VS Code 本身能做什麼 你必須另外下載的「發動機」
JavaScript / TypeScript 語法上色、IntelliSense、型別檢查（靠內建 Node 跑 tsserver） 要在終端機 node app.js 執行，仍需自行安裝 Node.js
C# 只提供文字打字與擴充功能 .NET SDK
Python 只提供文字打字與擴充功能 CPython Interpreter
Java 只提供文字打字與擴充功能 JDK（Java Development Kit）
Go 只提供文字打字與擴充功能 Go toolchain

補充：所有語言都還需要對應的 VS Code Extension（C# Dev Kit、Python、Go、Extension Pack for Java）才會有智慧提示。Extension 只是「翻譯機的操作面板」，SDK 才是翻譯機本體。

三、那我寫 Go 沒裝 toolchain 也能跑，是怎麼回事（k–m）

這是這場對話裡最好的一次質疑。答案是：Docker 把 Go toolchain 藏在容器裡幫你裝好了。

k. Dockerfile 的第一行就洩漏了答案：

FROM golang:1.23-alpine
片段 意思
FROM Dockerfile 指令，宣告「這個 Image 要以哪個既有 Image 為基底」
golang Docker Hub 上的官方 Image 名稱。由 Docker Official Images 團隊維護
1.23 Go 的版本 tag
alpine 基底作業系統是 Alpine Linux（極小、約 5 MB 的 Linux 發行版）

這個 Image 裡面已經預先裝好完整的 Go toolchain（go build、go run、gofmt、標準函式庫），所以容器裡打 go build 當然跑得動。

l. 兩種模式的路徑對照：

傳統本機開發 Docker 容器開發
toolchain 在哪 裝在你的 Windows 上 裝在 Image 裡的 Linux 環境
編譯發生在哪 Windows 本機 容器內部的 Linux
沒裝會怎樣 go: command not found，完全動不了 不影響，因為根本不需要本機有
對本機環境的污染 有：PATH、GOPATH、版本衝突 幾乎沒有，刪掉容器就乾淨了 
[ 你的 Windows 本機 ] ── (完全沒裝 Go)
          │
          ▼ (啟動容器)
[ Docker 容器 (Linux) ] ── (內部預裝 Go toolchain，在這裡完成編譯)
          │
          ▼ (執行)
[   你的 x64 CPU     ]

m. 後遺症：如果你完全不用 Dev Containers、只是 docker build 而已，VS Code 的 Go 擴充功能會一直跳 "Go command is not available"，而且沒辦法「Go to Definition」跳轉函式定義——因為 VS Code 在 Windows 這一側找不到 toolchain，無法建立語言服務。

解法是用 Dev Containers 擴充功能，讓 VS Code 直接「連進容器裡面」執行語言服務，這樣它就讀得到容器內的 Go toolchain，提示與跳轉就會恢復正常。

⚠️ 存疑／更正

Gemini 說法 查證後 說明
「VS Code 自帶 V8 引擎，所以寫 JS 不需要另外下載」 ⚠️ 講得太滿 正確的是：VS Code 內建的 Node 是給它自己（擴充功能、tsserver、Language Server）用的，並沒有對外開放給你的專案。你在整合終端機打 node app.js，用的是你自己安裝在系統 PATH 上的 Node.js。沒裝 Node 的機器打 node 一樣會 command not found。所以「JS 完全不用裝發動機」是錯的，只是「型別檢查與語法提示不用裝」而已
「微軟或 Go 官方已經把 Go Toolchain 安裝在這個毛胚屋裡面」 ⚠️ 主體弄錯 golang 這個 Image 是 Docker Official Images 專案維護的，跟微軟無關
「瀏覽器天生看不懂 C# / Java」 基本正確但有例外 透過 WebAssembly（Wasm），Blazor WebAssembly 確實可以在瀏覽器裡跑 C#。這不影響本篇結論（你還是得先有 .NET SDK 才編得出 Wasm），但講「絕對看不懂」不夠精確
