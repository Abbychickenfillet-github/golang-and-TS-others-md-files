2. 啟動對照判讀

能開的模式病灶修法
normal殘留行程Stop-Process -Name Cursor -Force
--disable-gpu顯示卡驅動或 GPUCache更新驅動，或刪 %APPDATA%\Cursor\GPUCache
--disable-extensions某個擴充功能卡住逐一移走 %USERPROFILE%\.cursor\extensions 裡的擴充
全新 --user-data-dir設定或 state.vscdb 損毀先備份整個 %APPDATA%\Cursor，再改名重建
全部都不行程式本體／系統層重新安裝

3. 自我測驗

填空 a：讓 Electron 執行檔變成純 Node.js 行程的環境變數是 ?。
填空 b：判斷行程有沒有視窗，看的是行程物件的 ? 屬性（0 代表沒有）。
填空 c：Cursor 存全域狀態與對話紀錄的 SQLite 檔名是 ?。
是非 1：Cursor 行程在背景跑但沒視窗時，再點捷徑通常會開出新視窗。
非。新的啟動請求會交給卡住的舊實例處理，所以看起來完全沒反應。
是非 2：-ExecutionPolicy Bypass 只對這一次執行生效，不會永久改系統設定。
是。它是 powershell.exe 的啟動參數，只影響這個行程。
是非 3：只要 C 槽還有 1 GB，Cursor 一定能正常啟動。
非。state.vscdb 與 -wal 檔寫入、更新暫存都要空間，1 GB 很容易不夠。
申論：只有 --user-data-dir 指到全新資料夾時 Cursor 能開，請說明病灶在哪、修之前要先做什麼、為什麼。
病灶在 %APPDATA%\Cursor（設定、快取或 state.vscdb 損毀），因為換掉這個資料夾就能開，代表程式本體沒問題。
修之前要先備份整個資料夾，因為 state.vscdb 裡有 Cursor 對話紀錄與全域設定，直接刪掉就救不回來。
備份後把資料夾改名（不是刪除），讓 Cursor 重建一份乾淨的，確認能開後再把需要的設定逐步搬回去。
