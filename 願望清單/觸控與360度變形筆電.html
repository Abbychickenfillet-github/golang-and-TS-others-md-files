1. 把口語需求翻成買得到東西的規格名詞

你原本的說法是「可以觸控」跟「有 yoga 功能、轉軸角度很多」。這兩句話拿到購物網站搜尋是搜不到東西的，因為前者太寬、後者是品牌名。下面這張表把它們翻成規格欄位上真正會出現的字。

你的口語正式規格名詞要往下追問的那一層
可以觸控，不想一直滑 touchpad Touchscreen（觸控螢幕）
Multi-touch 十點觸控		 手指點，還是筆也要能寫。只要手指點，規格寫 Multi-touch 就夠；要寫字畫畫，就得往下看第 3 節的觸控筆協定
yoga 功能，轉軸角度很多 Convertible（變形筆電），也叫 2-in-1
關鍵字是 360-degree hinge		 Yoga 是 Lenovo 的產品線名稱，不是技術名稱。用 360-degree hinge 去搜，才會同時搜到別家對手
（容易買錯的鄰居） Detachable（可拆鍵盤） 螢幕整片拔下來的機構，例如 Surface Pro。它不是轉軸式，鍵盤拔掉就沒有鍵盤了。你要的是鍵盤永遠黏著、只是會翻的那種
同類產品線怎麼找 Lenovo 叫 Yoga，HP 叫 OmniBook X Flip（更早叫 Spectre x360），ASUS 叫 Zenbook Flip，Acer 叫 Spin，Dell 走 2-in-1 命名。 看到名字裡有 Flip、Spin、x360、Yoga 這四個字，大致就是 360 度轉軸這一類。

2. 主軸圖：360 度轉軸的四種模式

這張是本篇的主軸圖。你真正花錢買的不是「觸控」這件事，而是下面這四種姿勢，因為觸控螢幕本身在一般筆電上也買得到，轉軸才是變形筆電的本體。

模式轉軸角度你實際會在什麼時候用它
Laptop 一般模式約 110 度寫程式、打字。這個模式下觸控只是多一條輸入路，不是主力
Tent 帳篷模式約 300 度倒 V 字站在桌上，佔的桌面面積最小。追劇、視訊、在廚房看食譜
Stand 站立模式約 270 度鍵盤朝下當底座，螢幕推到最靠近你。這是四種模式裡觸控點擊最穩的一種，因為戳螢幕時機器不會往後倒
Tablet 平板模式360 度翻到底手拿著看 PDF、手寫筆記、畫圖。重量與螢幕反光這兩個缺點，全部在這個模式才會真正被你感覺到

3. 觸控筆協定：買錯筆就寫不了字

這一節是最容易踩雷的地方。觸控螢幕能不能用筆寫字，取決於螢幕裡的數位板（digitizer）支援哪一種協定，而不是取決於你買了多貴的筆。協定對不上，筆在螢幕上就只是一根塑膠棒。

協定筆要不要電池誰在用要注意什麼
MPP
Microsoft Pen Protocol		 要 Microsoft Surface、HP、部分 Dell（Inspiron 與 Latitude 的一部分） 版本從 1.2 一路到 2.6。最新的 2.6 是 Surface Slim Pen 2，多了 Zero-Force Inking 與觸覺回饋。高版本的筆接到低版本的螢幕會自動降級，功能縮水但還能用
Wacom AES
Active ElectroStatic		 要 多家 Windows 筆電採用 原理跟 MPP 最接近，都是筆自己供電、把訊號電容耦合進觸控螢幕，所以螢幕可以是一整片平貼玻璃，不用多一層感應層
Wacom EMR
電磁共振		 不要 Samsung Galaxy Book 系列 筆不用充電不用換電池，但螢幕背後要多一層感應層，所以機身會稍厚。這是另一套東西，不要跟 AES 搞混
USI 要 Chromebook Windows 筆電基本上不會遇到
下單前一定要單獨確認的一行字 規格表寫「支援觸控筆」不等於「附觸控筆」。很多機型的筆是另外加購，一支筆台幣兩三千起跳。 正確的問法是：這台用哪一個協定，筆有沒有附在盒子裡，如果要另外買的話型號是哪一支。

5. 選購檢核八問 a–h

這八點沒有先後順序，所以用字母編號。到店裡或下單前逐條問一次。

要確認的項目為什麼它會影響你
a重量與螢幕尺寸14 吋翻成平板單手拿久會痠。想常用平板模式，建議壓在 1.3 kg 以下
b面板是亮面還是霧面觸控螢幕幾乎都是亮面（glossy），在窗邊會照到自己的臉。這是觸控機的固定代價，有沒有霧面選項要問清楚
c翻過 190 度鍵盤會不會自動上鎖會上鎖，所以手掌壓到按鍵不會打出字。但手指還是摸得到凸起的按鍵，這個觸感有些人受不了，要實機摸過
d觸控筆協定與筆是否附贈見第 3 節。這一條最常被規格表的「支援觸控筆」五個字騙過去
e鉸鍊的保固條款轉軸是機械件，是這類機型最常見的維修點。保固有沒有涵蓋鉸鍊，要翻條款不要聽櫃台說
fOLED 還是 IPSOLED 顏色漂亮但有烙印（burn-in）風險，而你寫程式會整天開著同一個 IDE 版面，是烙印的高風險用法
g連接埠的位置翻成 Tent 或 Stand 的時候，原本在側面的埠會跑到奇怪的方向，插著電源線可能會卡住
h記憶體是否焊死現在的輕薄變形機幾乎都是 LPDDR5X 直接焊在主機板上，買下去就不能加。要一次買到夠用的容量

6. 對前端工程師的額外意義：PointerEvent

買觸控機對你還有一個職業上的好處：你終於能在自己的機器上測觸控行為，不用再靠 Chrome DevTools 模擬。這裡補一段跟它直接相關的前端知識。

瀏覽器處理輸入裝置的歷史走過三代。滑鼠事件 MouseEvent 只認滑鼠；後來為了手機加了 TouchEvent，結果同一段互動要寫兩套；PointerEvent 把三種輸入裝置統一成同一組事件，用 pointerType 這個屬性去分辨來源。

element.addEventListener('pointerdown', (e) => {
  if (e.pointerType === 'pen') {
    draw(e.clientX, e.clientY, e.pressure);
  }
});

這段在做的事是：我在元素上掛一個 pointerdown 監聽器，不管使用者是用滑鼠、手指還是觸控筆按下去，都會進到同一個 callback。
進來以後我用 e.pointerType 判斷來源，它的值只會是 'mouse'、'touch'、'pen' 三者之一。
確認是筆的時候，我才去讀 e.pressure——這是 0 到 1 的壓力值，滑鼠永遠回傳 0 或 0.5，只有支援壓感的筆才有真實數值。

另外一個跟觸控機直接相關的坑是 CSS 的互動媒體查詢。你的新機器同時有 touchpad 跟觸控螢幕，所以它會同時符合精準指標與粗略指標兩種條件：

@media (hover: hover) and (pointer: fine) {
  .btn:hover { background: #e7f0fb; }
}

這段在做的事是：只有當裝置「能夠 hover」而且「指標是精準的」時候，才套用 hover 樣式。
純觸控裝置的 hover 會是 none、pointer 會是 coarse，所以不會套到，避免手指點完以後 hover 樣式黏在上面不消失。
變形筆電比較麻煩的地方在於它兩種都符合，所以用這組查詢做 feature detection 在變形機上會失準，真的要區分就得改用 pointerType 在 JavaScript 裡判斷。

可以直接跑的示範檔放在同一個資料夾：pointer-events-demo.html（配合 pointer-events-demo.js）。用滑鼠、手指、觸控筆分別點它，畫面會即時印出 pointerType 與 pressure。

關於 LeetCode／NeetCode 對應題目 這一節是瀏覽器事件模型與硬體規格，不屬於演算法題範疇，LeetCode 與 NeetCode 都沒有對應題目，所以這裡不硬塞連結。要練相關的東西，方向是 MDN 的 Pointer events 文件與實作練習，不是刷題。

7. 自我測驗

7-1　點擊填空（點一下空格看答案）

a.　Yoga 是 Lenovo 的產品線名稱，真正該拿去搜尋的技術關鍵字是 360-degree hinge。

b.　螢幕整片拔得下來的機構叫 Detachable，代表機種是 Surface Pro，它跟轉軸式是兩種不同的東西。

c.　轉軸翻過 190 度 以後，韌體會自動停用鍵盤與 touchpad 的輸入。

d.　筆不需要電池、靠電磁共振運作的協定叫 Wacom EMR，代表廠商是 Samsung。

e.　PointerEvent 用來分辨輸入來源的屬性是 pointerType，它的三個可能值是 mouse / touch / pen。

f.　MPP 目前最新的版本是 2.6，它多出來的兩個功能是 Zero-Force Inking 與觸覺回饋。

7-2　是非題

a.　規格表上寫「支援觸控筆」，就代表盒子裡會附一支觸控筆。
錯。支援與附贈是兩件事。很多機型的筆要另外加購，所以下單前要單獨問「筆有沒有在盒子裡」。
b.　觸控螢幕的機型幾乎都是亮面面板，在窗邊會反光照到自己。
對。這是觸控機的固定代價，不是某一家廠商偷工。想要霧面就要特別找，而且選擇很少。
c.　高版本的 MPP 觸控筆接到低版本的數位板，會完全不能用。
錯。會自動降級到舊的功能集，還是能寫，只是壓力階數、傾斜偵測這些功能會縮水。
d.　在變形筆電上，用 CSS 的 (hover: hover) and (pointer: fine) 來判斷「使用者是不是在用觸控」會失準。
對。變形筆電同時有 touchpad 與觸控螢幕，兩種條件都符合，所以這組查詢分不出當下是哪一種。要準確判斷必須在 JavaScript 裡讀 e.pointerType。

7-3　申論題

a.　為什麼「願望清單」不應該整張寫進 Google Calendar？請從工具的第一欄位說明。
Google Calendar 的資料模型以時間為主鍵，每一筆記錄都必須先回答「什麼時候」。願望本身沒有日期，為了塞進日曆而硬編一個假日期，會造成兩個後果。

第一，日曆上出現大量不需要你當天行動的項目，訊號雜訊比下降，你會開始習慣性忽略通知，連真正有時間性的事也一起被忽略。
第二，願望的核心資訊是比較與理由，而日曆的事件欄位沒有表格也沒有結構，寫進去就是一團純文字。

正確做法是把有日期的那一小部分（買點，例如雙 11）切出來放日曆，其餘留在 Obsidian 與 Google Tasks。
b.　同樣是「可以用筆寫字的螢幕」，MPP、Wacom AES、Wacom EMR 三者的取捨差在哪裡？
MPP 與 Wacom AES 的運作原理相近，都是筆自己帶電源、把訊號以電容方式耦合進觸控顯示面板，因此螢幕可以做成一整片平貼玻璃，不需要額外的感應層，機身可以更薄，代價是筆要充電或換電池。

Wacom EMR 走的是電磁共振，感應層在面板背後主動供能給筆，所以筆完全不用電池、重量輕、也不會沒電，代價是機身必須多容納一層感應結構。

對你的使用情境來說：如果筆只是偶爾點一點，MPP 或 AES 的機型就夠，而且機身更薄更輕；如果會長時間畫圖、很在意筆沒電，EMR 比較省心，但選擇被限縮到 Samsung Galaxy Book 這一條線上。
c.　你的原始需求是「不想一直用 touchpad 慢慢滑」。觸控螢幕真的解決了這個問題嗎？請誠實評估。
部分解決，而且有條件。

觸控確實消除了「滑很遠」這個動作，手指直接落在目標上，對點按鈕、捲長頁面、切分頁這類大目標操作是真的快。
但是在 Laptop 模式下，螢幕是立著的，手要離開鍵盤抬到半空中去戳，長時間會造成俗稱 gorilla arm 的手臂疲勞，所以寫程式時你多半還是會退回 touchpad。
另外觸控的精準度對小目標不利，例如 IDE 裡的行號、游標定位、拖曳分隔線，這些用手指反而比 touchpad 慢。

真正會讓你覺得划算的是 Stand 與 Tablet 這兩個模式：螢幕被推到離手很近、或者直接拿在手上，這時候觸控才是主力輸入而不是輔助。

所以結論是：如果你買它只為了取代 touchpad，期待值要放低；如果你同時會用到看文件、手寫筆記、追劇這幾種情境，它就值得。
