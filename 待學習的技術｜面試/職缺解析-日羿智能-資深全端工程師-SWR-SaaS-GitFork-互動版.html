c. SWR（stale-while-revalidate）

SWR 的意思是：先回傳舊的（stale）快取資料，同時在背景重新驗證（revalidate）並抓新資料。

它有兩層意思：

1. RFC 5861（2010-05）定義的 HTTP 快取指令 Cache-Control: max-age=600, stale-while-revalidate=30

2. Vercel 開發的 React 資料抓取套件 SWR，Hook 名稱是 useSWR

① 元件呼叫 useSWR(key)，SWR 先去快取找這個 key
② 快取有舊資料，立刻回傳給畫面（stale）
③ 同時在背景呼叫 fetcher 重新抓資料（revalidate）
④ 新資料回來後更新快取，元件重新渲染成最新畫面
const { data, error, isLoading } = useSWR(`/api/user/${userId}`, fetcher)

白話：用網址字串當快取的 key，用 fetcher 抓資料，拿回資料、錯誤、是否載入中三個值。

d. SaaS（Software as a Service，軟體即服務）

廠商把軟體架在自己的雲端上，客戶用瀏覽器連線使用，不必自己安裝和維護伺服器。

模型全名廠商提供什麼例子
IaaSInfrastructure as a Service虛擬機器、網路、儲存空間AWS EC2
PaaSPlatform as a Service可以直接部署程式的平台Zeabur、Vercel
SaaSSoftware as a Service完整可用的軟體Gmail、Notion

出處：NIST SP 800-145（2011-09）

在這個職缺裡，主系統是 SaaS，本地端版本（on-premise）則是 fork 出來、裝在醫療院所現場機器上的那一份。

e. Git Fork 包含哪些

Fork 不是 Git 指令，而是 GitHub 等平台的功能：在伺服器端把整個 repo 複製成你名下一個獨立的新 repo。

項目會不會被複製
程式碼與完整 commit 歷史會
分支預設只複製 main，取消勾選「Copy the DEFAULT branch only」才會複製全部
tags會
issues、pull requests不會，fork 有自己一套全新的
repo 設定、協作者、Actions secrets不會
Actions workflow 檔案檔案會複製，但 fork 上預設不會自動執行

h. 申論題（先自己想，再按顯示）

1. 本地端分叉要和 SaaS 主系統長期並行，你會怎麼降低每次同步的衝突？

先把本地端客製集中在設定檔、環境變數和擴充點，不去改主系統的核心程式碼。
再固定節奏 fetch upstream 並合併，不要累積太多版本才一次合。
行為差異用 feature flag 控制，合併時就只需要處理少量衝突。

2. 為什麼到醫療院所現場裝機適合用 Docker？

Docker 映像檔把程式和執行環境一起打包，現場機器只要裝好 Docker 就能跑出和開發時一樣的環境。
版本升級時只要換映像檔，出問題也能快速退回上一版。
醫療資料不能離開院內，本地端部署加上容器化，可以同時滿足資料留在院內和安裝可重現。

3. 你用過 TanStack Query，要怎麼說明自己能馬上上手 SWR？

兩者都實作 stale-while-revalidate 策略，都用 key 管理快取、都會在背景重新驗證並去除重複請求。
差別在 API 名稱，例如 TanStack Query 用 queryKey 和 useMutation，SWR 用字串 key 和 mutate。
我已經理解伺服器狀態和 UI 狀態要分開管理，換套件只是換 API。
