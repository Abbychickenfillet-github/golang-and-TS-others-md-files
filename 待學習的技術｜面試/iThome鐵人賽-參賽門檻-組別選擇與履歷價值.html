重點整理

一、開賽前的兩道關卡

c. 帳號授權：iT 邦幫忙用第三方登入（例如 Facebook），要先完成帳號綁定授權才能操作。

d. 新手任務未完成就無法報名。新帳號要先解完三項才會解鎖完整的發文與報名功能：

  • 完成「個人背景」
  • Like 三篇「好問題／文章」
  • 通過「iT 邦幫忙版規的 Q&A」

e. 三項解完之後，才前往當屆鐵人賽頁面報名。

二、獎項機制：完賽獎與評審獎是兩回事

f. 完賽獎——只要完賽，人人有獎，不需要票選。在 30 天內每天發表 1 篇符合規範的文章、中間不能斷，就能拿到鐵人賽完賽證書。很多人放在履歷或 LinkedIn 上的就是這張。

g. 評審獎——要拿名次與獎金才需要評選，而且是專業評審評分，不是網友票選。各組別選出冠亞季軍與數名優選。評分標準通常包含：內容技術深度與正確性、文章架構與流暢度、實用性與原創性。

h. 策略上的意義：完賽獎是可以靠自律 100% 拿到的確定性報酬，評審獎是機率。先以完賽為唯一目標，名次當作意外之喜。

三、Modern Web 還是 JavaScript 組？

i. 兩組的分界是「寫生態系」還是「寫語言機制」：

情境 建議組別
內容偏實戰與 Web 開發生態（React、Next.js 專案實作、部署、工具鏈） Modern Web（多數寫 React／Next.js 的參賽者選這組）
內容偏語言核心機制與底層原理（Closure 在 Hooks 裡的運作、Virtual DOM 演算法、Promise／async、Vanilla JS 重構到 React） JavaScript

j. 寫 React 主題報名 JavaScript 組完全算數，不會被判違規。理由是 React 本身就是 JS 函式庫——JSX 只是語法糖、Hooks 依賴閉包、組件化依賴 ES6 模組化。鐵人賽的 JavaScript 組涵蓋純 JS、TypeScript、前端框架（React／Vue／Angular）與 Node.js。

k. 選 JavaScript 組的下標建議：在標題就把「框架現象」扣回「語言機制」，例如——

  • 從 Closure（閉包）看 React useEffect 的陷阱
  • 從 Array.map / filter 聊到 React List Rendering
  • 從 Event Loop 理解 React 的批次更新（Batching）

l. 對求職的實際價值：完賽證明的不只是技術能力，更是自律性、持續學習態度、文字表達能力三件事——而後兩項正好是履歷上最難自我宣稱、最需要第三方背書的部分。
