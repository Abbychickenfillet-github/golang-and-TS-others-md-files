SemVer 語意化版本｜版本號的 ^ 與 ~ 怎麼看

npmpackage.jsonsemverpackage-lock.jsoniron-session
系列：編譯與打包學習路徑 第 13 篇｜承接 07（npm 鎖版本）｜建立於 2026-11-14

1. 三段數字各代表什麼

SemVer（Semantic Versioning，語意化版本）規定版本號寫成 MAJOR.MINOR.PATCH：兩個英文句點把三個非負整數連在一起。

以 TimeLog 專案的 "iron-session": "^8.0.4" 為例

「向下相容」的例子

向下相容（backward compatible）是指新版本發布後，照舊版寫法寫的程式碼不用改，也能繼續正常運作。

升級發生什麼事妳的程式碼
8.0.4 → 8.0.5
PATCH		作者修好一個 bug，例如 cookie 過期時間算錯幾秒不用改
8.0.4 → 8.1.0
MINOR		假設作者替 sessionOptions 多加一個選填欄位不用改，舊的 getIronSession(cookies(), sessionOptions) 照樣能用
想用新功能時再自己加上去
7.x → 8.0.0
MAJOR		真實案例：v8 移除了 withIronSessionApiRoute、withIronSessionSsr，統一改用 getIronSession()要改，照 v7 寫法的程式碼會直接報錯

MAJOR 變更的判斷依據是舊程式碼會不會壞，跟改動規模大小無關。
拿掉一個函式只是一行改動，但舊程式碼會壞，所以算 MAJOR。

2. 發新版時怎麼決定加哪一段

套件作者發新版時，照下面的流程決定要加哪一段。進位時，右邊的數字全部歸零。

ISO 5807 符號：橢圓＝起止，菱形＝判斷，直角矩形＝處理

3. 主軸圖：^ 與 ~ 的範圍

package.json 裡的符號規定「npm 可以自動接受哪些新版本」。點圖上的版本號可以看說明。

點數線上的版本號。
{
  "dependencies": {
    "iron-session": "^8.0.4",  // ^：鎖住最左邊非 0 的那一段，這裡鎖 MAJOR 8
    "axios": "~1.7.2",         // ~：鎖住 MAJOR 和 MINOR，只放行 PATCH
    "lodash": "4.17.21"        // 沒符號：固定這一版
  }
}

第一行白話：TimeLog 接受 iron-session 從 8.0.4 開始、9.0.0 之前的任何版本。
第二行白話：axios 只接受 1.7.2 到 1.7.x 的修補版。
第三行白話：lodash 只裝 4.17.21。

4. 讀版本號的三個提醒

  1. 每一段是一個整數，可以超過 9。
    8.12.30 讀作「主版本 8、次版本 12、修補 30」。
    ^8.0.4 的上限是 <9.0.0，不是 8.9.9，所以 8.12.30 也在範圍內。
    寫筆記時用「段」或「欄位」稱呼，不用 digit（個位數字）。
  2. PATCH ＝ 向下相容的 bug 修正。
    SemVer 看的是公開 API（別人呼叫妳套件的方式）有沒有變，與改動是不是 UI 無關。
    以 UI 元件庫為例：按鈕顏色修正可能是 PATCH，新增一個 size prop 是 MINOR，把 variant prop 改名是 MAJOR。
  3. MINOR 歸零規則。
    MINOR 進位時 PATCH 歸零：8.0.4 → 8.1.0。
    MAJOR 進位時後兩段都歸零：8.3.2 → 9.0.0。

5. 0.x 版本的例外

MAJOR 是 0 代表套件還在初期開發，隨時可能有破壞性變更。所以 ^ 會改成鎖住最左邊第一個非 0 的段：

寫法實際範圍
^8.0.4>=8.0.4 <9.0.0（鎖 8）
^0.2.3>=0.2.3 <0.3.0（鎖 0.2，效果跟 ~ 一樣）
^0.0.3>=0.0.3 <0.0.4（只能是 0.0.3）

6. 實際裝的是哪一版

package.json 寫的是可接受的範圍，package-lock.json 記錄的是實際安裝的版本（詳見 07 的 k 節）。

npm ls iron-session

在專案根目錄的 terminal 執行：npm 讀取 node_modules，列出 iron-session 實際安裝的版本，以及是哪個套件依賴它。

  1. npm install：照 lock 檔安裝，每台電腦和 Vercel 都會裝到同一版。
  2. npm update iron-session：在 ^ 範圍內升到最新版，並且改寫 lock 檔。
  3. npm outdated：列出每個套件的 Current（目前）、Wanted（範圍內最新）、Latest（npm 上最新）三欄。
LeetCode 練習165. Compare Version Numbers：用 . 切開版本號，逐段比大小。這題剛好練到「每一段是整數，不是個位數」這個觀念。

7. 自我測驗

填空題

  1. MAJOR.MINOR.PATCH 中，新增功能而且向下相容時要加 。
    MINOR（見第 1 節）
  2. ^8.0.4 的範圍是 >=8.0.4 < 。
    9.0.0（見第 3 節主軸圖）
  3. 查專案實際安裝的 iron-session 版本，要執行 npm iron-session。
    ls（見第 6 節）

是非題

  1. ^8.0.4 不會自動裝到 8.12.30。
    非。每一段是整數，8.12.30 小於 9.0.0，在範圍內。
  2. ~1.7.2 可以裝到 1.7.9，但不能裝到 1.8.0。
    是。~ 鎖住 MAJOR 和 MINOR，只放行 PATCH。
  3. ^0.2.3 可以裝到 0.3.0。
    非。0.x 時 ^ 鎖最左邊非 0 的段，範圍是 <0.3.0。

申論題

  1. iron-session 從 v7 升到 v8 為什麼是 MAJOR？用「向下相容」解釋。
    v8 移除了 withIronSessionApiRoute 與 withIronSessionSsr，改用單一的 getIronSession()。照 v7 寫法的程式碼呼叫不存在的函式，升級後會直接壞掉，代表沒有向下相容，所以 MAJOR 要加 1。^7.x 也因此不會自動升到 v8。
  2. 既然 package.json 寫 ^8.0.4，為什麼同事和 Vercel 還是會裝到同一版？
    npm install 優先照 package-lock.json 記錄的確切版本安裝。^ 只在 lock 檔沒有記錄，或執行 npm update 時才發揮作用。所以 lock 檔要 commit 進 git。
