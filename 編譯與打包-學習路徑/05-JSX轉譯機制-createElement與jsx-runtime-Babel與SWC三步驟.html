申論題

  1. 有人說「ECMA 又沒有定義 JSX，那 React 怎麼跑得起來」，請完整回答他。

    參考方向：兩件事發生在不同層。轉譯器層（Babel／SWC／esbuild）在建置階段把程式碼當成文字讀進來，剖析成 AST，把 JSXElement 節點改寫成 CallExpression，再重新生成標準 .js 輸出——這一層不執行程式碼，也不受 ECMA 規範限制，因為它只是文字工具。執行階段層（V8 等引擎）看到的已經是 React.createElement('button', {...}, ...) 或 _jsx(...)，那是 100% 合乎 ECMA 的物件屬性存取與函式呼叫。所以「ECMA 沒定義 JSX」跟「JSX 最後變成合法 JS」完全不衝突。想親眼驗證可以開 Babel REPL 勾選 react preset。

  2. 為什麼 React Element 要用 Symbol 當 $$typeof，而不是用一個普通字串？

    參考方向：安全性。React 渲染時會檢查物件的 $$typeof 是不是它認得的 Symbol，才把它當成合法 Element。Symbol 是唯一且無法被序列化的原始型別，JSON.parse 不可能產出一個 Symbol。假設後端 API 回傳的 JSON 被直接塞進 JSX 渲染，攻擊者最多只能偽造 { type: 'div', props: {...}, $$typeof: 'react.element' } 這種字串版本，過不了檢查，因此無法透過 dangerouslySetInnerHTML 之外的路徑注入任意元素。這是 React 對 XSS 的一道縱深防禦。

JSX 轉譯機制 — createElement、jsx-runtime 與 Babel／SWC 的三個步驟

本篇重點 a–n，共 14 個。

重點整理

一、JSX 不是 JavaScript

(a) Transpile（轉譯）是「同一個抽象層級的語言之間互轉」，跟 Compile（編譯成低階碼）不同。JSX 是非標準的語法擴充，ECMAScript 規範裡完全沒有它，JavaScript 引擎（例如 Chrome 的 V8）直接看到 <MyComponent/> 只會丟 SyntaxError。

(b) 轉譯不是引擎做的，是打包建置工具在你的程式碼送進瀏覽器之前做的。Babel、SWC、esbuild、Vite 這些工具不執行你的程式碼，它們把程式碼當成「文字」來剖析與重組。

(c) 轉譯完之後，引擎看到的只是一段 100% 合乎 ECMAScript 規範的普通程式碼：React 是一個匯入的物件，.createElement 是它的一個方法，回傳值是一個普通物件。所以「ECMA 沒有定義 JSX」跟「JSX 最終變成合法 JS」這兩件事完全不衝突。

二、兩套轉譯機制：Classic vs Automatic

(d) Classic Runtime（舊版轉譯，React 16 及以前）：

// 輸入
<MyComponent color="blue">Hello</MyComponent>

// 輸出
React.createElement(MyComponent, { color: 'blue' }, 'Hello');

因為輸出直接用到 React 這個識別碼，所以檔案頂部必須手動 import React from 'react'，否則會 ReferenceError。

(e) Automatic Runtime（新版轉譯，React 17 起預設）：

// 輸入
<MyComponent color="blue">Hello</MyComponent>

// 輸出（引入檔由建置工具自動注入）
import { jsx as _jsx } from 'react/jsx-runtime';
_jsx(MyComponent, { color: 'blue', children: 'Hello' });

單一子節點用 jsx()，多個子節點用 jsxs()（s 是 static children 的意思，事先知道 children 是陣列可省掉執行期判斷）。好處是不用再手動 import React，打包體積與效能也略有優化。

(f) 但注意：不用 import React ≠ 不用 import Hook。useState、useEffect 這些具名匯出仍然必須自己寫 import { useState } from 'react'，因為它們是你程式碼裡真的用到的識別碼，轉譯器不會幫你補。

三、createElement 到底做了什麼

(g) React.createElement 就是 React 團隊用標準 JavaScript 寫的一個普通函式，躺在 node_modules/react 裡（原始碼位置 packages/react/src/ReactElement.js）。它的工作只有三件事：整理 props、整理 children、回傳一個普通物件。

// 簡化示意（非可執行的官方碼）
function createElement(type, config, children) {
  const props = {};
  for (const propName in config) {
    if (hasOwnProperty.call(config, propName)) props[propName] = config[propName];
  }
  const childrenLength = arguments.length - 2;
  if (childrenLength === 1) props.children = children;
  else if (childrenLength > 1) props.children = Array.prototype.slice.call(arguments, 2);

  return {
    $$typeof: REACT_ELEMENT_TYPE,   // 一個 Symbol，用來標示這是真的 React Element
    type: type,
    props: props,
  };
}

(h) 最終產物長這樣，所謂 React Element 就是一個普通的 JavaScript 物件，不是 DOM 節點：

{
  $$typeof: Symbol(react.element),
  type: 'button',
  props: { color: 'red', children: 'Click me' }
}

(i) $$typeof 為什麼要用 Symbol？因為 Symbol 沒辦法被 JSON.parse 產生出來。如果伺服器回傳的 JSON 被直接塞進 JSX 渲染，攻擊者無法偽造一個帶有正確 $$typeof 的假 Element，這是 React 防 XSS 的一道防線。這也是 (g) 那段簡化碼不能直接貼進專案當成 React 用的原因之一——它省略了 key、ref、__self、__source 的處理與開發環境警告。

(j) 如果只是想自己實驗一個微型 Virtual DOM，這段是可獨立執行的：

function myCreateElement(type, props, ...children) {
  return {
    $$typeof: Symbol.for('react.element'),
    type,
    props: { ...props, children: children.length === 1 ? children[0] : children },
  };
}
console.log(myCreateElement('h1', { id: 'title' }, 'Hello World'));

四、Transpilation 的三個步驟

(k) 第一步 Parsing（語法剖析）：讀進 .jsx 文字，拆成 AST（Abstract Syntax Tree，抽象語法樹）。<button color="red">Click</button> 會變成一個 JSXElement 節點，底下掛著 OpeningElement button、Attributes color="red"、Children "Click"。

(l) 第二步 Transformation（語法樹轉換）：外掛（例如 @babel/plugin-transform-react-jsx）掃描 AST，遇到 JSXElement 就把它改寫成 CallExpression（函數呼叫節點）——函式名 React.createElement，第一參數標籤名字串，第二參數把 Attributes 組成物件，第三參數之後放 children。

(m) 第三步 Code Generation（程式碼生成）：把改寫後的 AST 重新組裝成標準 .js 文字輸出。

// 輸入
const button = <button color="red">Click</button>;
// 輸出
const button = React.createElement("button", { color: "red" }, "Click");

(n) 動手驗證的最快方式：打開 Babel 官方線上工具 REPL（https://babeljs.io/repl），左側 Presets 勾選 react，貼上 JSX，右邊即時看到轉譯結果。想看新版轉譯就把 Runtime 設為 automatic。

五、名詞補全

  • SWC = Speedy Web Compiler，用 Rust 寫的高效能 JavaScript／TypeScript 轉譯器與打包工具。
  • AST = Abstract Syntax Tree，抽象語法樹。
  • REPL = Read–Eval–Print Loop，讀取－求值－印出的互動式環境。
  • JSX 官方全稱沒有正式展開，一般理解為 JavaScript XML（XML-like syntax extension to JavaScript）。

⚠️ 存疑／更正

  • Gemini 說「SWC 目前廣泛應用於 Next.js、Vite 等現代前端工具鏈中」：Vite 這一半不精確。Next.js 從 12 起確實預設用 SWC 取代 Babel；但 Vite 預設的 JSX／TS 轉換器是 esbuild（Go 寫的），SWC 在 Vite 是可選方案，要自己裝 @vitejs/plugin-react-swc 才會用到。預設的 @vitejs/plugin-react 走的是 Babel。
  • 另一段語音對話中 Gemini 說「React 18 之後不用 import React」：版本講錯。新版 JSX Transform 是 React 17（2020 年 10 月）引進的，並且官方有回移（backport）到 16.14、15.7、0.14.10。React 18 沒有再改這件事。
