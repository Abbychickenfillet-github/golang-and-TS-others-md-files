是非題

  1. UIKit 跟 React 的寫法很接近，都是宣告式的。

    錯。UIKit 是指令式（Imperative），要手動 addSubview、layoutSubviews，比較像傳統 DOM 操作。接近 React 的是 SwiftUI。

  2. SwiftUI 的佈局可以直接把 Flexbox 的觀念套過去。

    錯。SwiftUI 用 VStack／HStack／ZStack 的堆疊模型，是另一套思路。

  3. @State 對應的是 React 的 useState。

    對。兩者都是元件內部狀態，改變時框架自動重繪對應 UI。

重點整理

一、核心概念一一對照（a–c）

(a) SwiftUI 與 React 在設計哲學上非常接近，核心公式是同一句：UI = f(State)。有 React 經驗轉 SwiftUI 會相當快。

概念 React (Web) SwiftUI (iOS) 共同點
宣告式 UI JSX View Builder 描述 UI 該長什麼樣，而不是一步步操作 DOM／View
組件化 Component View 切成可重用的獨立模組
單向資料流 State Driven UI State Driven UI UI 是狀態的映射
元件內部狀態 useState() @State 狀態改變框架自動重繪對應 UI
跨層級共享狀態 useContext() @Environment 不用層層 props 傳遞
副作用 useEffect() .task / .onChange 初始化請求或監聽特定狀態

(b) 同一個計數器，兩邊寫起來的節奏幾乎一樣：

// React
function Counter() {
  const [count, setCount] = useState(0);
  return (
    <div style={{ padding: 20 }}>
      <p>Count: {count}</p>
      <button onClick={() => setCount(count + 1)}>Increment</button>
    </div>
  );
}

// SwiftUI
struct CounterView: View {
    @State private var count = 0

    var body: some View {
        VStack {
            Text("Count: \(count)")
            Button("Increment") {
                count += 1
            }
        }
        .padding(20)
    }
}

(c) @State 前面那個 @ 是 Swift 的 property wrapper（屬性包裝器），作用是讓一個普通變數在被讀寫時多做一層事情——這裡是「通知框架重繪」。概念上跟 Vue 用 getter／setter 攔截、React 用 Hook 排程更新，是同一類「在賦值這件事上動手腳」的設計。

二、三個要注意的差異（d–g）

(d) UIKit 才是跟 React 差很多的那個。UIKit 是 iOS 的舊架構、屬於指令式（Imperative）寫法，要手動 addSubview()、layoutSubviews()、手動改文字，比較像傳統的 DOM 操作。看教學文章時要先確認講的是 SwiftUI 還是 UIKit。

(e) 佈局系統完全不同：React 主要靠 Flexbox；SwiftUI 用 VStack（垂直堆疊）、HStack（水平堆疊）、ZStack（層疊）。不要想把 Flexbox 的 justify-content / align-items 直接翻譯過去，堆疊模型是另一套思路。

(f) Swift 的型別系統比 JavaScript／TypeScript 嚴格得多，而且是編譯期強制檢查。TypeScript 的型別可以被 any 繞過，Swift 不行。

(g) 面試可用的一句話：「SwiftUI 與 React 的相似不是巧合——兩者都是宣告式 UI 這一波典範轉移的產物，差別在宿主語言的型別強度與佈局原語不同。」
