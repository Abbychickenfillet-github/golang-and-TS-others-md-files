🧠 自我測驗

是非題

  1. 把變數標成 any 之後，TypeScript 仍然會檢查你有沒有呼叫不存在的方法。

    完全不會。any 就是「請關掉這個變數的型別檢查」，someValue.abc.def() 也照樣編譯通過。

  2. unknown 跟 any 一樣，什麼值都可以塞進去。

    賦值這一端兩者相同。差別在「取出來用」那一端——unknown 必須先收窄才能動。

  3. unknown 型別的變數可以直接賦值給 string 型別的變數。

    不行。unknown 只能賦值給 unknown 與 any，其他都要先斷言或收窄。

  4. JSON.parse 的回傳型別在 TypeScript 內建定義裡就是 any。

    因為一段 JSON 解出來可能是物件、陣列、數字、布林、null 或字串，編譯期不可能預知。

  5. 只要專案有裝 TypeScript，就算全部標 any 也還是享有重構安全性。

    正好相反。改了欄位名稱，any 標註的地方不會報錯，錯誤會延到執行期才炸。

  6. typeof u === 'string' 這種判斷可以讓 TypeScript 自動把 unknown 收窄成 string。

    這叫型別守衛（Type Guard），編譯器的控制流分析看得懂。

  7. 官方 Handbook 建議：不知道型別時優先用 any。

    官方推薦 unknown。Handbook 明說 unknown 是 any 的 type-safe counterpart。

填空題

  1. any 在 TypeScript 裡被稱為型別系統的「逃生艙口」，英文是 Escape 。

    Handbook 也用 escape clause 這個說法。

  2. 比 any 安全、什麼都能塞但什麼都不能直接做的型別，叫做 。

    TypeScript 3.0 引入。

  3. `const name = data as string` 這種寫法叫型別 （assertion）。

    等於簽切結書：我負責，這傢伙就是字串。

  4. 函式回傳型別寫成 `v is { name: string }`，這種語法叫型別 （Type Predicate）。

    用來自訂型別守衛。

  5. TypeScript 能在 if 區塊裡自動把型別變窄，這個機制叫控制流 （Control Flow Analysis）。

    型別守衛之所以有效就是靠它。

申論題

  1. 你的同事說「反正 TypeScript 編譯完也是 JavaScript，型別標 any 比較快，之後有空再補」。請完整說明你會怎麼回應：any 具體讓你失去什麼、什麼情況下用 any 是合理的、以及 unknown 為什麼是更好的預設選擇（請一併說明它安全在哪、要怎麼把它變得可用）。

    參考方向：(1) 失去什麼——IntelliSense 自動完成、重構安全性（改欄位名不報錯，錯誤延到執行期）、程式碼即文件三者一次消失，專案退化成「換副檔名的 JavaScript」。(2) 合理場景——JS 專案遷移過渡期、第三方套件沒提供型別定義、JSON.parse 這種編譯期不可能預知的外部資料。關鍵字是「你控制不了的資料」，不是「我懶得寫 interface」。(3) unknown 為何更好——賦值端跟 any 一樣寬鬆（什麼都能塞），但取用端被鎖死：不能存取屬性、不能賦值給其他型別。這強迫你在使用前先驗證。(4) 怎麼變得可用——用 typeof / instanceof / in 做型別守衛，或寫回傳 `v is T` 型別謂詞的自訂守衛函式，讓控制流分析在 if 區塊內自動收窄。(5) 加分：提 tsconfig 的 noImplicitAny，把「沒標型別就變隱含 any」這條後門也堵起來。

重點整理

一、any 到底是什麼（e–g）

e. any 是 TypeScript 的「逃生艙口（Escape Hatch）」。當你把一個變數標註成 any，你等於在跟編譯器說：「這個變數以後別檢查了，我要像寫純 JavaScript 一樣自由。」

一行一行拆解這句經典範例：

let someValue: any = "this is a string";
片段 意思
let 宣告一個「可重新賦值」的變數（block scope，跟 var 的 function scope 不同）
someValue 變數名稱，你自己取的
: any 型別註解（Type Annotation）。冒號後面那個字就是「這個變數被允許裝什麼」。寫 any 代表「什麼都行，而且不要檢查」
= "this is a string" 初始值。此刻它「執行期的真實型別」是 string，但「編譯期的靜態型別」被你釘死成 any

f. 這代表下面這些明顯會爆炸的寫法，TypeScript 一句話都不會唸你：

let someValue: any = "this is a string";

someValue.toFixed();  // 執行時 TypeError（字串沒有 toFixed），但編譯時 TS 覺得 OK
someValue = 123;      // 型別隨意漂移也 OK
someValue.abc.def();  // 存取不存在的巢狀屬性也 OK

toFixed 是 Number.prototype 上的方法（把數字轉成固定小數位的字串），字串身上沒有這個方法，所以執行期一定丟 TypeError。但因為靜態型別是 any，型別檢查器整個放行。

g. 滿滿 any 的專案，本質上就是「只是換了副檔名的 JavaScript」。你會一次失去三樣東西：

失去的東西 為什麼會失去
自動完成（IntelliSense） 編輯器不知道這變數是什麼，當然沒東西可提示
重構安全性 改了欄位名稱，被標成 any 的地方不會報錯，錯誤延到執行期才炸
程式碼即文件 三個月後的你看不出這變數該裝什麼

二、那為什麼不直接把 any 換成 string 就好（h–j）

這是這場對話裡最好的一個追問。答案是：能直接寫 string 就一定要直接寫 string。會出現「先 any 再斷言」，是因為遇到了「你控制不了的資料」。

h. 資料來自外部世界（API 或 JSON）。

const data: any = JSON.parse(userInput);
const name = data as string;

JSON.parse 在 TypeScript 內建型別定義裡的回傳型別就是 any，因為一段 JSON 字串解出來可能是物件、陣列、數字、布林、null 或字串——編譯期根本不可能知道。所以你不能在宣告的當下就寫 const data: string，只能在「你自己確認過」之後用斷言告訴編譯器。

i. 第三方套件的限制。老舊或寫得不嚴謹的 JavaScript 套件，回傳值本身就標 any。你改不動別人的原始碼，只能在接到結果後自己斷言回你要的型別。

j. 型別收窄（Narrowing）的中繼站。一個變數可能是 string 也可能是 null，你得先經過判斷才能收窄。

決策速查：

情境 該怎麼寫 理由
變數是你自己定義、自己賦值 let name: string = "Tom" 從一開始就上鎖，裝錯編譯器立刻罵人
變數來自 API、檔案、資料庫、無型別的舊 JS 先 any 或 unknown，再斷言或收窄 編譯期不可能預知，只能事後補償
只是懶得寫 interface 不要用 any 這是藉口，不是理由

[!tip] 兩者的心智模型
直接寫 string ＝ 打預防針。一開始就規定只能裝字串。
用 as string ＝ 簽切結書。資料已經進來了，你簽字保證「我負責，這傢伙就是字串」。

三、unknown：更安全的那個選擇（k–n）

k. 現代 TypeScript 遇到「真的不知道型別」時，官方推薦 unknown 而不是 any。官方 Handbook 的說法是：unknown 是 any 的「type-safe counterpart（型別安全的對應物）」。

l. 兩者的差別只有一句話：什麼都能塞進去這點兩者相同，但 unknown 不能被拿去做任何事，any 可以。

特性 any（危險） unknown（安全）
允許被賦予任何值 ✅ ✅
允許直接存取屬性或方法 ✅ 完全不檢查 ❌ 必須先收窄型別
可以被賦值給其他型別 ✅ 全部都行 ❌ 只能給 unknown 與 any
心智定位 放棄型別檢查 「我還不知道是什麼，等我檢查完再說」

m. 實際差別長這樣：

let a: any = getSomething();
a.toUpperCase();          // 編譯過，執行期可能爆

let u: unknown = getSomething();
u.toUpperCase();          // ❌ 編譯就擋下來：Object is of type 'unknown'

if (typeof u === "string") {
  u.toUpperCase();        // ✅ 收窄成 string 之後才准用
}

typeof u === "string" 這行叫 型別守衛（Type Guard）。TypeScript 看得懂 typeof 的比較結果，會在 if 區塊裡把 u 的型別從 unknown 自動收窄成 string，這叫「控制流分析（Control Flow Analysis）」。

n. 所以 JSON.parse 的回傳你可以自己收成 unknown，強迫自己在用之前先驗證：

const data: unknown = JSON.parse(userInput);

function isUser(v: unknown): v is { name: string } {
  return typeof v === "object" && v !== null && typeof (v as any).name === "string";
}

if (isUser(data)) {
  console.log(data.name);   // ✅ 這裡 data 已經是 { name: string }
}

v is { name: string } 是 型別謂詞（Type Predicate）——回傳 true 的時候，請把參數 v 當成那個型別。這是自訂型別守衛的寫法。
