一、錯誤現場

ERR error="Unable to reach the origin service...
dial tcp [::1]:3001: connectex: No connection could be made
because the target machine actively refused it."
originService=http://localhost:3001

核心原因：Tunnel 連得上 Cloudflare，只是連不到你本機的服務。

  1. a::1 是 IPv6 的 loopback 位址，等同 IPv4 的 127.0.0.1。cloudflared 把 localhost 解析成 IPv6 了。
  2. bactively refused 不是被防火牆擋（那會 timeout），而是 那個 port 上根本沒有程式在監聽，作業系統直接回 TCP RST。
  3. c兩個可能：服務沒啟動，或服務只綁 IPv4 而沒監聽 ::1。

二、為什麼 localhost 有時 IPv4、有時 IPv6

  1. dlocalhost 只是一個名字，Windows 的 hosts 檔裡同時對應 127.0.0.1 與 ::1。
  2. e走哪一個由 client 的解析順序決定；Windows 與新版 Node 都偏好 IPv6 優先。
  3. f很多 Node／Next.js dev server 預設只 bind 在 127.0.0.1，才會出現「瀏覽器打得開、cloudflared 打不到」的錯覺（瀏覽器會自己 fallback 到 IPv4）。

三、解法

解法一（最快）
cloudflared tunnel --url http://127.0.0.1:3001

g 把 localhost 換成 127.0.0.1，跳過名稱解析直接走 IPv4。
h 先在瀏覽器開 http://127.0.0.1:3001 確認服務真的活著，再開 tunnel。
i 或讓服務同時監聽兩個 stack，例如 next dev -H 0.0.0.0（0.0.0.0 ＝所有 IPv4 介面；要吃 IPv6 用 ::）。

k 用完立刻 Ctrl+C 關掉；需要長期分享請改 named tunnel 並掛 Cloudflare Access。

五、自己考自己

1. connectex: actively refused 代表被防火牆擋掉了。
2. ::1 與 127.0.0.1 都是 loopback，只是分屬 IPv6 與 IPv4。

申論：為什麼「瀏覽器開 http://localhost:3001 正常，但 cloudflared 說連不到」？


因為兩個 client 對同一個名字 localhost 的處理方式不同。瀏覽器拿到 localhost 會依 Happy Eyeballs 之類的策略同時／依序嘗試 ::1 與 127.0.0.1，IPv6 失敗就自動 fallback 到 IPv4，所以你看得到頁面。cloudflared 只挑了偏好的 ::1 去 dial，而你的 dev server 只 bind 在 127.0.0.1，作業系統在 ::1:3001 上找不到監聽者就回 TCP RST，於是 cloudflared 直接判定 origin 不可達，不會再試 IPv4。
