Jekyll 與 GitHub Pages：把 Markdown 筆記變成免費網站

本篇重點 a–m，共 13 個。
起因：Abby 想把 golang-and-TS-others-md-files 這個滿是 .md 筆記的儲存庫變成公開網站，在 GitHub Pages 設定頁看到「Jekyll site」不知道是什麼。

Jekyll 是什麼

(a) Jekyll 是一個用 Ruby 寫的靜態網站產生器（Static Site Generator，SSG）。你寫 Markdown，它幫你編譯成 HTML 靜態網頁。

(b) 它是 GitHub Pages 的內建預設引擎——這就是為什麼 GitHub 的設定頁面會直接跟你提 Jekyll，而不是 Hugo 或 Astro。你不用自己安裝 Ruby，GitHub 在背景幫你跑。

(c) 適合的場景：技術部落格、專案文件、履歷頁、筆記站。不適合的場景：需要登入、需要即時資料的應用（那要的是後端，不是 SSG）。

要錢嗎

(d) 公開儲存庫（Public Repository）完全免費。

項目 費用
網址 https://<帳號>.github.io/<專案名> 免費
託管 免費
GitHub Actions 建置時間（公開專案） 免費
自訂網域（例如 www.yourname.com） 要錢，但錢是付給網域註冊商，不是付給 GitHub

(e) ⚠️ 存疑／更正：原對話說「GitHub Actions 對公開專案提供無限量的免費執行時間」。正確說法是：使用 GitHub 託管執行器（GitHub-hosted runners）的公開儲存庫不計費，但仍受並行數與單次工作流程時間上限等使用限制，而且私有儲存庫是有免費額度上限的（超過要付費）。「不計費」和「無限量」不是同一件事，請以下方官方文件為準。

兩種部署來源（Source）二選一

(f) GitHub Pages 的 Settings → Pages → Build and deployment → Source 有兩個選項：

選項 意思 適合誰
Deploy from a branch 指定某個分支＋資料夾，GitHub 自動用內建 Jekyll 建置 純 Markdown 筆記站，最省事
GitHub Actions 自己寫 workflow，想用什麼工具都行 要用 Hugo / Astro / Next.js，或需要自訂建置步驟

(g) 切回分支模式的實際步驟：

  1. 進 Settings → 左側選 Pages
  2. Build and deployment 區塊，Source 下拉選單改成 Deploy from a branch
  3. 下方出現 Branch 設定，選 main
  4. 資料夾選 / (root)（或把網頁內容集中在 /docs 就選 /docs）
  5. 按 Save

(h) 同一頁往下還有兩個東西值得留意：Custom domain（自訂網域，留空就用預設的 <帳號>.github.io）與 Enforce HTTPS（用預設網域時會強制勾選且不能取消，這是好事）。

兩個一定會踩到的檔案

(i) .nojekyll：在儲存庫根目錄放一個空的 .nojekyll 檔，代表「完全跳過 Jekyll，把檔案原封不動當靜態檔送出」。什麼時候需要：你的資料夾或檔名以底線 _ 開頭時（Jekyll 預設會忽略底線開頭的目錄），或你根本不想要 Jekyll 處理任何東西。

(j) _config.yml：Jekyll 的設定檔。Abby 的設定是：

defaults:
  - scope:
      path: ""
    values:
      render_with_liquid: false

{% raw %}(k) 這段設定在解決一個很煩的問題：Jekyll 預設會用 Liquid 樣板引擎處理所有檔案，而 Liquid 把 {{ }} 和 {% %} 當成語法。如果筆記裡有 Vue、Handlebars、Jinja 的雙大括號範例，或者 Obsidian 的 {{date}} 樣板，建置就會直接失敗或內容被吃掉。render_with_liquid: false 對所有路徑（path: "" 代表全站）關掉 Liquid 處理，Markdown 照樣會被轉成 HTML，但大括號會原樣保留。{% endraw %}

(l) .nojekyll 與 render_with_liquid: false 的差別：前者是「連 Markdown 都不轉了，全部當原始檔」；後者是「還是要 Jekyll 幫我轉 Markdown，只是不要碰我的大括號」。兩個同時放會互相矛盾——.nojekyll 一旦生效，_config.yml 就完全不會被讀。

(m) 給 Abby 的實務建議：既然目標是「把 .md 筆記變成可閱讀的網頁」，應該要留著 Jekyll（不要 .nojekyll），只用 render_with_liquid: false 避開大括號問題。如果放了 .nojekyll，網站上點開會是一堆 Markdown 原始碼而不是排版好的網頁。

關聯筆記與關聯原因

  • 學習順序與免費部署作品集策略：同一個目標的兩塊拼圖——那篇談「要放什麼上去給面試官看」，這篇談「怎麼零成本放上去」。
  • GitHub-Actions-CICD-ghcr與Docker映像檔：本篇 (f) 的另一個選項就是它。Deploy from a branch 是 GitHub 幫你跑好的黑盒子，GitHub Actions 是自己掌控整條建置流水線，那篇是後者的完整版。
  • Zeabur-主機遷移-DeepSeek-API與費用比較：同屬「部署與費用」主題。差別在於靜態站可以完全免費，有後端就得付主機錢，選型時先問「這個東西需不需要伺服器」。

順帶檢查兩個設定

a. ⚠️ 存疑／更正（2026-08-27 實測）：render_with_liquid: false 沒有真的擋掉 Liquid

原本以為 _config.yml 設了這個，Jekyll 就不會用 Liquid 處理筆記——但 2026-08-27 那次建置失敗直接打臉：這篇筆記自己這一段（原本寫著範例用的裸 {% raw %}{{ }}{% endraw %} / {% raw %}{% %}{% endraw %}）沒包 {% raw %}，即使有 render_with_liquid: false，Jekyll 還是照樣把它當 Liquid 語法解析，直接炸掉整站建置。
結論：這個設定不可靠，真正有效的防線是：① exclude: 整個資料夾排除、② 逐檔把裸的 {% raw %}{{ }}{% endraw %} / {% raw %}{% %}{% endraw %} 包上 {% raw %}...{% endraw %}（或改用 HTML 實體 &#123;&#123;）。這行設定可以留著當保險，但不能只靠它。
