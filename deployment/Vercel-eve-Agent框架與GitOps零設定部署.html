重點整理

一、名詞各自是什麼角色（最容易混在一起的三個）

a. eve：Vercel 推出的 AI Agent 開發框架與 CLI 工具，不是某個特定 Agent 的名字。可以用 npx eve@latest init my-agent 建立自己的 Agent 專案，用 eve set --model zai/glm-5.2 之類的指令設定模型。指令裡的 my-agent 才是你自己 Agent 的名字。

b. Vercel AI Gateway：模型呼叫的統一入口（Gateway），把多家模型供應商串在同一個 API 後面，讓你在專案裡換模型只要改設定字串。

c. Blackbox AI：在這件事裡扮演的是模型託管與提供商（Provider）的角色。Vercel 的 AI Gateway 整合了它的服務，把 GLM 5.2 等開放模型串進平台供開發者呼叫。

d. Claude 與 eve 的關係：兩者性質不同，不用二選一。Claude 是模型（Brain），eve 是 Agent 的開發框架與軟體架構（Skeleton／Environment）。在 agent/agent.ts 裡可以先把模型設成 GLM 5.2 享優惠，之後隨時切回 Claude 或其他 AI Gateway 支援的模型。

e. 只要在既有專案中引入 eve 套件並建立 agent/agent.ts 寫入設定，該專案就具備 eve Agent 的基礎架構——這個設定檔就是讓應用程式變成 Agent 的關鍵核心。

二、「Clone 模板到 GitHub 就能部署」背後的理念

f. 這套流程背後是 IaC（Infrastructure as Code，基礎設施即程式碼）與 GitOps 的整合，加上 Vercel 主打的 Zero-Configuration（零設定）開發體驗。

g. 版本控制即單一事實來源（Single Source of Truth）：專案原始碼與設定檔集中放在 GitHub，每次變更與部署狀態都有歷史紀錄可循，要回滾就是回到某個 commit。

h. 自動化 CI/CD 流水線：GitHub 帳號連結 Vercel 之後，只要 Fork／Clone 該模板並推送到 GitHub，Vercel 就自動觸發 Build（打包）與 Deploy（部署），不必自己設定伺服器或寫部署腳本。

i. 快速驗證 MVP：讓開發者能在幾分鐘內，從一個想法變成線上有網址、具備串流（Streaming）與 AI 介面的完整應用。

三、實際操作步驟

j. 官方模板路徑：點畫面上的 Clone Template 按鈕 →「Create Git Repository」步驟中選擇你自己的 GitHub 帳號並填一個新的 repo 名稱（Vercel 會自動幫你在該帳號底下建立 repo 並推入模板程式碼，不需要你手動貼到 GitHub 任何地方）→ 填入所需環境變數（該模板要求 EVE_CHAT_PASSWORD）→ Deploy。部署完成後在 Vercel AI Gateway 把模型切換／設定為 GLM 5.2 即可。
