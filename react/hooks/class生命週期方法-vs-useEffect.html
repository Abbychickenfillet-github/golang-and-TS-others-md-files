class 生命週期方法 vs function component（useEffect）

1. 核心觀念：三個生命週期方法 → 一個 useEffect

生命週期方法（lifecycle methods）是 class component 專屬的機制：你在 class 裡定義特定名字的方法，React 會在元件的不同階段（掛載、更新、卸載）自動幫你呼叫它們。

function component 沒有這些方法，改用一個 useEffect Hook 把三件事統一起來。

一句話記住：三個生命週期方法，被一個 useEffect 取代，靠「依賴陣列」決定什麼時候跑。

先認識三個名詞的中英全名，後面都會用到：

  • mount（掛載）：元件第一次被放到畫面上
  • update（更新）：元件因為 props 或 state 改變而重新 render
  • unmount（卸載）：元件從畫面上被移除

1-1. 真正的關係：不是「三合一」，而是「換一個思考框架」

最容易誤會的地方：useEffect 不是把 componentDidMount ＋ DidUpdate ＋ WillUnmount 三個方法黏在一起。它是把同一件事換一個角度描述。

生命週期方法（class）useEffect（function）
思考單位元件的「時間點」跟某些值的「同步（synchronization）」
你對 React 說「mount 時做 A、update 時做 B、unmount 時做 C」「這個 effect 要跟 [deps] 保持同步，這是 setup、這是 cleanup」
誰決定何時跑你，綁死在三個時刻React，依 deps 自己推算何時 setup／cleanup
可以跑幾次各時刻各一次一段 effect 可反覆 setup→cleanup→setup…很多次

白話：生命週期是你盯著「元件走到哪個階段」，在那個階段插程式碼；useEffect 是你盯著「某個值」，宣告「只要這個值在，這個 effect 就同步存在；值變了或元件沒了就清掉」。剩下「什麼時候像 mount、什麼時候像 unmount」交給 React 算。

所以兩者可以互相「對照」（下面第 4 章），是因為 useEffect 的行為涵蓋了那三個時刻；但 React 官方建議：寫 useEffect 時不要再用 mount／update／unmount 的腦袋想，改用「我的 effect 跟哪些值同步」來想，才不會漏寫依賴、寫出 bug。生命週期對照只是幫你從舊觀念接過來的橋。

2. 三個生命週期方法各自是什麼

2-1. componentDidMount()：掛載後跑一次

時機：元件第一次 render 到畫面上之後，跑一次。

用途：抓後端資料、設定訂閱、啟動計時器、操作剛生成的 DOM。

componentDidMount() {
  this.timerID = setInterval(() => this.tick(), 1000);
}

白話：元件一出現在畫面上，就開一個每 1000 毫秒跳一次的計時器，並把它的編號存到 this.timerID，之後要關掉它時才找得到。

2-2. componentDidUpdate(prevProps, prevState)：每次更新後跑

時機：每次重新 render 之後跑；第一次 mount 不會跑。

它會收到兩個參數 prevProps、prevState（前一次的 props 與 state），讓你比對「到底哪個值變了」再決定要不要做事。

componentDidUpdate(prevProps) {
  // 先比對：只有 userId 真的變了才重抓，否則會無限迴圈
  if (prevProps.userId !== this.props.userId) {
    this.fetchData(this.props.userId);
  }
}

白話：拿「上一次的 userId」跟「這一次的 userId」比，只有真的不一樣才去重新抓資料。少了這個 if，每次 render 都 setState、又觸發 render，會變成無窮迴圈。

2-3. componentWillUnmount()：卸載前跑，負責清理

時機：元件要從畫面上移除之前跑。

用途：清理（cleanup）——清掉計時器、取消訂閱、移除事件監聽，避免元件消失後資源還在背景跑造成記憶體洩漏（memory leak）。

componentWillUnmount() {
  clearInterval(this.timerID);
}

白話：元件要消失了，把 2-1 開的那個計時器用它的編號關掉，不然元件不見了、計時器還每秒跑，記憶體就被白白佔著。

3. useEffect 如何用「依賴陣列」一次取代三者

function component 把上面三件事濃縮成一個 useEffect：

useEffect(() => {
  // A：effect 本體 —— 每次 render 之後執行
  return () => {
    // B：cleanup 清理函式 —— 下次 effect 重跑前、或 unmount 時執行
  };
}, [deps]); // C：依賴陣列 —— 決定 effect 什麼時候重跑

白話：傳給 useEffect 的第一個參數是一個函式（effect 本體）；這個函式可以 return 另一個函式，那個被 return 的函式就是清理函式；第二個參數 [deps] 這個陣列，控制整個 effect 多久重跑一次。

3-1. 依賴陣列的三種寫法（這是全部的關鍵）

寫法什麼時候跑 effect對應 class
useEffect(fn)　不給陣列每次 render 後都跑componentDidMount ＋ 每次 componentDidUpdate
useEffect(fn, [])　空陣列只在 mount 後跑一次；cleanup 在 unmount 跑componentDidMount ＋ componentWillUnmount
useEffect(fn, [a,b])　有依賴mount 後跑一次，之後只要 a 或 b 變就再跑≈ componentDidUpdate（但 mount 時也會跑）

白話：陣列是空的 []，代表「我沒有任何會變的依賴」，所以 React 只在第一次跑一次就不再跑；陣列裡放 [a,b]，代表「a 或 b 變了我就要重跑」。

4. class vs function 對照表

class 生命週期function（useEffect）寫法重點
componentDidMountuseEffect(() => {...}, [])空陣列 ＝ 只 mount 跑一次
componentDidUpdateuseEffect(() => {...}, [dep])dep 變才跑（但 mount 時也會跑一次）
componentWillUnmountuseEffect(() => { return () => {...} }, [])return 的清理函式在 unmount 跑
三者合一useEffect(() => {...; return () => {...}}, [dep])一個 effect 同時管 setup ＋ teardown

5. 完整範例：Clock 計時器（class vs function 並排）

這是最經典的對照，一眼看出差別：

❌ class 寫法（setup 與 teardown 分兩處）

class Clock extends React.Component {
  state = { date: new Date() };

  componentDidMount() {          // 掛載後
    this.timerID = setInterval(
      () => this.tick(), 1000
    );
  }
  componentWillUnmount() {       // 卸載前
    clearInterval(this.timerID);
  }
  tick() {
    this.setState({ date: new Date() });
  }
  render() {
    return <h1>{this.state.date
      .toLocaleTimeString()}</h1>;
  }
}

✅ function 寫法（setup 與 teardown 同一處）

function Clock() {
  const [date, setDate] = useState(new Date());

  useEffect(() => {
    const timerID = setInterval(      // = didMount
      () => setDate(new Date()), 1000
    );
    return () => clearInterval(timerID); // = willUnmount
  }, []); // 空陣列：只在 mount 設定一次

  return <h1>{date.toLocaleTimeString()}</h1>;
}

白話：兩邊做的事一樣——掛載時開每秒跳的計時器、卸載時關掉它。差別在 class 把「開」寫在 componentDidMount、「關」寫在 componentWillUnmount，兩個方法離得很遠；function 把「開」跟「關」寫在同一個 useEffect 裡（開在本體、關在 return 的函式），一組邏輯放在一起，比較不會忘記清理。

這就是 Hooks 設計的核心動機：把「同一個功能的 setup 與 teardown」放在一起，而不是依「生命週期時機」拆散到不同方法。

6. cleanup 清理函式的時序（最多人搞混）

cleanup 不是只有 unmount 才跑。當依賴陣列裡有值時，每次 effect 要重跑之前，React 會先跑上一次的 cleanup，再跑這次的 effect。

① Mount 掛載
effect 本體跑（訂閱 A）
→
② Update 依賴變
先跑上次 cleanup（退訂 A） 再跑新 effect（訂閱 B）
→
③ Unmount 卸載
最後跑 cleanup（退訂 B）
useEffect(() => {
  const sub = api.subscribe(userId);   // 訂閱這個 userId
  return () => sub.unsubscribe();       // 換 userId 或卸載前，先退訂舊的
}, [userId]);

白話：userId 從 A 換成 B 時，React 會先退訂 A（跑 cleanup），再訂閱 B（跑新的 effect），所以不會兩個訂閱疊在一起。cleanup 的任務就是「把上一次 effect 留下的東西收乾淨」，因此它在「下次 effect 開始前」和「元件消失時」都會跑。

7. 容易踩的雷

7-1. 有依賴的 useEffect，mount 時也會跑

componentDidUpdate 第一次 mount 不跑，但 useEffect(fn, [dep]) 在 mount 時也會跑一次。要完全模擬「只有 update 才跑、mount 不跑」，得自己用 useRef 擋掉第一次：

const first = useRef(true);
useEffect(() => {
  if (first.current) { first.current = false; return; } // 第一次略過
  doSomethingOnUpdate();
}, [dep]);

白話：用一個 useRef 記「是不是第一次」，第一次就直接 return 不做事、把旗標關掉；之後才真的執行。這樣才等於「只在 update 跑」。

7-2. 執行時機：useEffect 在 paint 之後（非同步）

這是跟 class 一個真實但細微的差別：

  • componentDidMount / componentDidUpdate：在 DOM 更新後、瀏覽器繪製（paint）前「同步」跑
  • useEffect：在 paint 「之後」才跑（非同步），所以如果你在 effect 裡改版面，使用者可能會看到閃一下

要在 paint 前同步做（量 DOM 尺寸、避免閃爍），用 useLayoutEffect，它才對應 class 的同步時機。

白話：大部分情況用 useEffect 就好；只有「必須在使用者看到畫面之前就把 DOM 量好或改好」的少數狀況，才換成 useLayoutEffect。

7-3. 開發環境下 effect 會跑兩次（React 18 StrictMode）

React 18 的 <StrictMode> 在開發環境（production 不會）會故意掛載 → 卸載 → 再掛載一次，讓 effect 跑兩次（setup → cleanup → setup）。這是刻意的，用來幫你抓出「沒寫 cleanup」的 bug——如果你的 effect 有正確清理，跑兩次也不會出問題。

8. 自我測驗

  1. (填空) function component 裡，componentDidMount 對應的寫法是 useEffect(fn, ​)（填依賴陣列）。

    空陣列 [] 代表沒有會變的依賴，所以 effect 只在 mount 後跑一次，等同 componentDidMount。

  2. (是非) cleanup 清理函式只有在元件 unmount 時才會執行。

    當依賴陣列有值時，每次 effect 重跑之前也會先跑上一次的 cleanup，不是只有 unmount 才跑。

  3. (填空) 要清掉 setInterval 開的計時器，cleanup 裡要呼叫 ​(timerID)。

    用 clearInterval(timerID)，timerID 是當初 setInterval 回傳的編號。

  4. (是非) useEffect(fn, [userId]) 在元件第一次 mount 時不會執行，只有 userId 變了才執行。

    有依賴的 useEffect 在 mount 時也會跑一次，之後才在 userId 改變時重跑。這正是它跟 componentDidUpdate 的差別。

  5. (申論) 用 Clock 計時器的例子，說明為什麼「把 setup 和 teardown 寫在同一個 useEffect」比 class 拆成兩個方法好。

    class 把「開計時器」放 componentDidMount、「關計時器」放 componentWillUnmount，兩段相關邏輯分散在相隔很遠的方法裡，容易改了一邊忘了另一邊、漏掉清理造成 memory leak。useEffect 把開（本體）跟關（return 的 cleanup）寫在一起，一組功能一個 effect，新增或刪除功能時 setup 與 teardown 一起動，較不易出錯。

  6. (申論) useEffect 與 useLayoutEffect 的執行時機差在哪？什麼時候該用後者？

    useEffect 在瀏覽器 paint 之後才非同步執行；useLayoutEffect 在 DOM 更新後、paint 之前同步執行（對應 class 的 componentDidMount/Update 時機）。當你必須在使用者看到畫面之前先量好或改好 DOM（避免畫面閃動）時，才用 useLayoutEffect，其餘情況用 useEffect。
