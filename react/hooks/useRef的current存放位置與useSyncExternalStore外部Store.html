重點整理

  • (a) useRef 的 current 在 React 原始碼 ReactFiberHooks.js 的 mountRef 函式中建立：元件首次 render 時，React 建立一個 Hook 物件，並把 { current: initialValue } 存進 hook.memoizedState。
  • (b) 之後 re-render 走 updateRef，直接回傳 hook.memoizedState 裡同一個物件，所以 current 能跨 render 保留，且修改它不會觸發重新 render。
  • (c) external store（外部 store）指不在 useState / useReducer 管理的 React state tree 內的資料來源，例如 Redux、Zustand、MobX、Jotai，或瀏覽器 API。
  • (d) 要搭配 useSyncExternalStore 使用，external store 必須提供 subscribe(callback)：資料變動時呼叫 callback 通知 React，並回傳 unsubscribe 函式供元件卸載時清理。
  • (e) 還必須提供 getSnapshot()：回傳目前資料快照。資料沒變時，重複呼叫必須回傳同一個值或同一個 reference，否則每次回傳新物件會造成無限重新 render。
  • (f) 瀏覽器內建的 external store 例子：navigator.onLine（聽 online / offline 事件）、window.innerWidth / matchMedia（聽 resize 或 media query change）、location.pathname（聽 popstate）。
  • (g) 純 JS 的 module 層級 pub/sub 物件或自訂 event emitter 也算 external store。
  • (h) 兩者關聯：useRef 的 {current} 本身就是「存在 Fiber 上、不參與 render 通知」的可變容器；external store 則是「存在 React 外、需要主動 subscribe 才能通知 React」的可變容器。
// 最小可用 external store
let state = 0;
const listeners = new Set();
const store = {
  subscribe(cb) { listeners.add(cb); return () => listeners.delete(cb); },
  getSnapshot() { return state; },          // 沒變就回傳同一個值
  inc() { state++; listeners.forEach(l => l()); },
};
// 元件內：const v = useSyncExternalStore(store.subscribe, store.getSnapshot);
