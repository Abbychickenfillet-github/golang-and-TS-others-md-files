申論題

  1. 請用 React 的心智模型完整解釋 Claude Desktop 與 Claude Code 在對話狀態上的差異，並說明各自的復原機制。

    Claude Desktop 像是一個接了後端 API 的 React App：Mount 時透過 useEffect 呼叫雲端 API 把帳號的歷史對話載入 state；對話中每次送訊息就用 [...messages, newMessage] 產生新陣列並打包整個 Context Window 送給模型；同時後端會把新訊息 persist 進雲端資料庫。所以視窗關掉等於 Unmount，但資料在 Server，下次啟動重新 Fetch 就完整復原，甚至換一台電腦也還在。Claude Code 像是一個沒有後端、只有 LocalStorage 的 React App：執行 claude 啟動一個 Node.js 行程，相當於初始化空白的 useState([])；state 只活在該行程的 RAM 裡；關閉 Shell 時作業系統送出 SIGINT 或 SIGHUP，行程終止、記憶體釋放，等同直接按 F5。它的復原靠 Rehydration：claude -c 或 claude -r 在啟動時從磁碟讀取 ~/.claude/projects/<專案路徑編碼>/<uuid>.jsonl，把 JSON Lines 逐行 parse 回記憶體。關鍵差異是儲存位置與作用範圍——雲端 vs 本機硬碟，帳號綁定 vs 專案路徑綁定，所以換個資料夾執行 claude 就找不到原本的對話。

  2. 你想把每天用 Claude Code 的提問整理成工作日誌。請說明資料在哪、格式是什麼、要先做什麼設定、以及你會怎麼實作。

    資料在 ~/.claude/projects/<專案路徑編碼>/<uuid>.jsonl，Windows 上例如 C:\Users\User\.claude\projects\C--coding-futuresign\<uuid>.jsonl。資料夾名是把專案絕對路徑的分隔符換成連字號編碼而成，所以同一台機器上不同專案分開存；檔名 UUID 就是 session ID；格式是 JSON Lines，一行一筆完整的 JSON 訊息物件。第一件事是先在 ~/.claude/settings.json 設 cleanupPeriodDays 為一個極大值（例如 999999），否則舊 log 會被定期清掉，日誌就斷了——同時要注意這會讓 log 一直長，得留意磁碟空間。實作上因為是 JSON Lines，可以逐行 parse 而不必把整份讀進記憶體：開檔後對每一行 json.loads，篩出 role 為 user 的訊息，取出 timestamp 與內容，按日期分組輸出成 Markdown。這正是 show-my-prompts.py 的做法，支援 <session-id-prefix> 抽單一 session 與 --date today|yesterday|YYYY-MM-DD 抽某一天所有 session。要自動化就再掛 Windows Task Scheduler 每天定時跑一次。若想要現成工具，claude-log-cli 也能瀏覽本機 session log，但它是 C# 寫的且沒有 Windows binary，要自己用 .NET SDK 編譯。

Claude Desktop 與 Claude Code 的狀態持久化差異：用 React 心智模型理解 Session 與 jsonl

本篇重點 a–r，共 18 個。兩段 Gemini 對話合併：為什麼關掉 Terminal 對話就不見、claude -c 與 claude -r 到底在做什麼、對話記錄實際存在哪個檔案、以及怎麼把自己的提問撈出來做成日誌。

重點整理

先把縮寫講清楚

  • CLI ＝ Command Line Interface，命令列介面，也就是在終端機打指令操作的程式。
  • RAM ＝ Random Access Memory，隨機存取記憶體，斷電或行程結束就清空的揮發性記憶體。
  • Process ＝ 行程，作業系統執行中的一個程式實例。
  • SIGINT ＝ Signal Interrupt，中斷訊號（按 Ctrl+C 送出）；SIGHUP ＝ Signal Hang Up，掛斷訊號（終端機關閉時送出）。
  • Hydration ＝ 水合／注水，前端術語，指把伺服器或磁碟上的資料灌回前端的記憶體狀態；Rehydration ＝ 再水合，重新灌回。
  • JSONL ＝ JSON Lines，一行一筆完整 JSON 物件的純文字格式，適合逐行追加（append）而不必重寫整份檔案。
  • UUID ＝ Universally Unique Identifier，通用唯一識別碼。

一、Claude Desktop：像是對接遠端資料庫的 React 全域狀態

(a) Mount（啟動）：打開 Desktop App 相當於 React Component 掛載，透過類似 useEffect 的初始化流程呼叫 Anthropic 雲端 API，把該帳號的歷史對話載入到 UI 狀態（React State 或 Redux）。

(b) Update（對話中）：每次送出訊息就更新狀態。

// 類似 React 內部維護的狀態變數
const [messages, setMessages] = useState<Message[]>([]);

// 每次發新訊息時打包完整的 Context Window 傳給 LLM
const payload = [...messages, newMessage];

一行一行的意思：useState<Message[]>([]) 開一個訊息陣列的狀態容器，初始是空陣列；[...messages, newMessage] 用展開運算子（spread）做出「舊訊息＋新訊息」的新陣列——注意這裡是產生新陣列而不是 messages.push()，因為 React 靠參照是否改變來判斷要不要重繪，直接 push 會改到原陣列、參照沒變、畫面不更新。而Context Window（上下文視窗）就是每次都要整包送給模型的對話歷史，這也是為什麼對話越長越花 token。

(c) Persist（持久化）：後端 API 自動把 newMessage 寫進雲端資料庫。所以即使 Electron 視窗關掉（Unmount），下次啟動重新 Fetch，狀態完美復原。

二、Claude Code（CLI）：像是沒有 Backend、只靠 LocalStorage 的 React App

(d) Init（啟動）：執行 claude，Node.js 行程啟動，相當於 React 初始化了一個空白的 const [messages, setMessages] = useState([])。

(e) Unmount（關閉 Shell）：關閉 Terminal 相當於直接按 F5 重新整理網頁。因為 state 只存在 RAM 裡、沒有自動寫入全域 Server，記憶體內的 state 瞬間清空。

(f) Rehydrate（claude -c 或 claude -r）：等同在 useEffect 裡讀取本地檔案再把狀態灌回去。Gemini 給的示意碼是：

// 類似於 persisted State 的復原過程
const savedContext = fs.readFileSync('~/.claude/session.json');
setMessages(JSON.parse(savedContext));

這段是「示意碼」不是真實路徑，實際檔案位置見下方第四節與「存疑／更正」。

三、CLI 為什麼是靠 Node.js 行程存活

(g) 在 Terminal 輸入 claude 時，作業系統背後觸發的是一個 Node.js 行程（Process）。

(h) 執行時：Node.js 行程啟動，把程式碼與當前對話的 Context 載入到系統記憶體（RAM）中。

(i) 關閉 Terminal 或關閉 Shell 時：作業系統向該行程發送 SIGINT 或 SIGHUP 訊號，Node.js 行程隨即終止（相當於 process.exit()）。

(j) 記憶體釋放：行程結束後，記憶體中的 Context State 隨之消失。這就是為什麼每次重新開機或關閉 Shell 後記憶體狀態就歸零，而 claude -c 的原理就是啟動時執行一段 Rehydration 邏輯，從磁碟（~/.claude/ 底下）讀取 JSON、重新寫入 Node.js 的記憶體變數中。

(k) 補充：Electron 的底子的確可以說是 JavaScript。拆解來看——程式語言視角：撰寫 Electron 應用時 100% 使用 JavaScript／TypeScript；執行環境視角：內建 Chromium 渲染引擎（負責畫頁面）與 Node.js 執行環境（負責讀寫本地檔案與系統 API）；底層實作視角：Chromium 與 Node.js 本身是 C/C++ 寫的，但都掛載了 Google 的 V8 引擎，最終對外暴露的全部都是 JavaScript Runtime。

(l) 三者的概念對照表：

React 概念 Claude Desktop 的對應實作 Claude Code（CLI）的對照實作
Component useState RAM 中的 Session State：當前開啟視窗記憶體裡的對話陣列 Node.js 行程記憶體 State：當前 Shell 執行時存在 RAM 裡的上下文

四、對話記錄實際存在哪裡：~/.claude/projects/ 的 jsonl

(m) 真實路徑是 ~/.claude/projects/<專案路徑編碼>/<uuid>.jsonl。Windows 上以 Abby 的專案為例是：

C:\Users\User\.claude\projects\C--coding-futuresign\<uuid>.jsonl

專案資料夾名稱是把絕對路徑的分隔符換成連字號後編碼而成（C:\coding\futuresign → C--coding-futuresign），所以同一台機器上不同專案的記錄是分開存的。

(n) 檔名的 UUID 就是 session ID，檔案內容是 JSON Lines：一行一筆訊息物件。因為是逐行追加，所以可以用 tail -f 即時跟看，也可以用任何語言逐行 parse 而不必把整份讀進記憶體。

(o) 避免記錄被自動清掉：在 ~/.claude/settings.json 加入 "cleanupPeriodDays": 999999，jsonl 就不會被定期清除。

{
  "cleanupPeriodDays": 999999
}

注意這是把清理週期設成一個極大值，不是官方定義的「永不刪除」開關；改設定前建議先確認自己的磁碟空間，log 會一直長。

(p) 實用工具：C:\coding\futuresign\claude-log-cli\show-my-prompts.py（Abby 自己寫的），用途是把自己的提問撈出來：

# 抽單一 session 的 user 訊息（給 session id 前綴即可）
python show-my-prompts.py e34a8787

# 抽某一天所有 session 的 user 訊息
python show-my-prompts.py --date today
python show-my-prompts.py --date yesterday
python show-my-prompts.py --date 2026-05-19

(q) 相關工具備忘：claude-log-cli 是 C# 寫的 CLI，用來瀏覽本機 Claude Code session log，沒有提供 Windows binary，要自己編譯（需要 .NET SDK）；Symbiont 是 Python daemon，讓 Claude 持續學習使用者偏好。

(r) 另一則對話的除錯情境：在 Antigravity 編輯器裡對話標題被設成 futuresign / Locating Text Editor、AI 回「雖然這裡沒有編輯器」，代表它把該對話當成純文字 Chat 視窗，底層的檔案系統連結（Language Server／Workspace）在建立對話時斷開了。修復步驟是回到正確的 Workspace（主選單 → Open Folder 選 C:\coding\futuresign），再點 New Conversation 重開一個對話，並確認底下的模型與 Agent 設定正確。

一句話總結

Claude Desktop 的記憶在雲端資料庫，Claude Code 的記憶在你自己的硬碟。前者換一台電腦也還在，後者換一個資料夾就找不到——因為 jsonl 是按專案路徑分開存的。

⚠️ 存疑／更正

  • Gemini 的示意碼寫 fs.readFileSync('~/.claude/session.json')，這個路徑不存在。真實的對話記錄是 ~/.claude/projects/<專案路徑編碼>/<uuid>.jsonl，格式是 JSON Lines 不是單一 JSON 物件，而且是「一個專案一個資料夾、一個 session 一個檔」。另外 Node.js 的 fs 不會自動展開 ~，要用 os.homedir() 組路徑，直接傳 ~/... 會找不到檔案。這點在同一批的另一則對話（app/10f9c54f35984248）裡 Abby 自己已經驗證過正確結構。
  • claude -c 與 claude -r 不是同一件事：-c／--continue 是接續「當前目錄最近一次」的對話，-r／--resume 是列出 session 讓你挑一個。Gemini 在同一段裡混用了兩者，實際行為請以 claude --help 為準。
  • 「cleanupPeriodDays: 999999 ＝ 永不刪除」是把數字設得夠大的權宜寫法，並非官方的永久保留開關，語意上要區分清楚。
