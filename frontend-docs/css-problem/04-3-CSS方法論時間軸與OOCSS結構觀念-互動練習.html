一‧四大方法論時間軸

2009年
OOCSS —— Nicole Sullivan
提出結構與外觀分離、容器與內容分離兩大原則，四者中最早出現。
來源：Ben Nadel（2009-07-08）‧OOCSS - Wikipedia
2005起步‧2009正式成形
BEM —— Yandex團隊
2005年萌芽、2007年提出Independent Block、2009年3月Lego 2.0發布正式定型為BEM、2010年開源。
來源：History / Methodology / BEM‧BEM - Web Design Museum
2011年
SMACSS —— Jonathan Snook
取材自Yahoo! Mail改版經驗，把CSS規則分五類管理的架構思維。
來源：SMACSS - About
2014年11月
ITCSS —— Harry Roberts
在dafed研討會首次公開發表《Managing CSS Projects with ITCSS》，四者中最晚出現、唯一管檔案分層與載入順序。
來源：Csswizardry - ITCSS投影片（2014-11）
時間順序大致對應「解決問題的抽象層級」：先解決單一元件內部怎麼拆與命名（OOCSS、BEM，2009年），再解決整個專案怎麼分類（SMACSS，2011年），最後解決檔案怎麼排序載入（ITCSS，2014年）。

三‧是非題（點按鈕作答）

1. OOCSS只是一種class命名規範，跟CSS規則內部要怎麼寫沒有關係。
是
非
答案：非。OOCSS的本質是「拆職責」的架構思維——結構與外觀分離、容器與內容分離，這兩條原則要求的是CSS規則本身要被拆成獨立區塊，命名只是這個思維的外顯結果。BEM才是單純的命名規範，套用在完全沒拆結構的CSS上也成立；OOCSS若沒把規則拆開，就不算真正實踐。
2. <button class="btn btn--primary"> 是標準的BEM Modifier寫法。
是
非
答案：是。.btn是Block，--primary是Modifier，語意是「btn這個Block底下的primary變體」。雙連字號--是BEM獨有的命名規範。
3. 純OOCSS的skin類別通常會加上元件前綴，例如寫成.btn-color而不是.primary-skin。
是
非
答案：非。OOCSS的skin類刻意設計成「跟元件無關、可被btn、card、alert等任何元件共用」，命名上通常不加元件前綴（例如.primary-skin），這樣才能達到跨元件重複利用的目的；加了btn-前綴反而比較接近BEM「綁定在特定Block底下」的精神。

四‧申論題（點連結展開參考答案）

Q：.btn-skeleton { width: 2rem; height: 1rem; } 這樣寫算不算把「骨架」與「顏色」分離了？请说明理由，並補上你認為缺少的另一半class。
👉 展開參考答案
方向正確。.btn-skeleton只處理width/height這類尺寸大小（結構性質），完全沒有碰顏色、背景，符合OOCSS「結構與外觀分離」的第一原則。但要注意，OOCSS所謂的structure通常也包含padding、border-radius、display、cursor這類跟顏色無關的通用規則，不只是width/height。缺少的另一半，是一個專門處理background-color/color的skin類，例如.primary-skin { background-color: blue; color: white; }，兩個class一起套用在同一元素上，才是完整的OOCSS結構/外觀分離範例。
Q：如果要把<button class="btn btn--primary">這個BEM寫法「翻譯」成純OOCSS風格，會是.btn-skeleton + .btn-color嗎？兩者在設計理念上差在哪裡？
👉 展開參考答案
拆分骨架與外觀的方向完全正確，但.btn-color這個命名還綁著btn-前綴，比較接近BEM思路。真正的OOCSS寫法通常是兩個完全獨立、彼此沒有派生關係的class，例如.btn-skeleton + .primary-skin（拿掉元件前綴）。關鍵差異：BEM的Modifier綁定在特定Block底下，.card要同樣的紅色必須另外寫一次.card--primary；OOCSS的skin類則刻意設計成與元件無關、可被btn、card、alert等任何元件共用，才能真正達到重複利用的目的。
