# 01-1‧選擇器（Simple／Compound／Complex／Selector List／Relative Selector）

> 複習順序上的位置：這是[[00-CSS觀念複習地圖與資料夾索引]]裡的第a項（檔名01-1），整個CSS最底層的基礎，沒有前備知識。後面的[[02-1-盒模型-BoxModel與border-box]]、specificity權重計算（見[[04-1-CSS方法論與權重-OOCSS-BEM-SMACSS-ITCSS]]的權重速查段落）都要先搞懂「選擇器選到的到底是誰」才看得懂。

> [!info] 這篇改版說明
> 這篇原本是照我自己的分類方式寫的（先分「基本選擇器」跟「組合選擇器」兩類），後來確認過MDN官方文件的分類法完全不同，官方是照結構複雜度分五種：simple、compound、complex、selector list、relative selector。這一版改成完全照官方架構重寫，來源：[CSS selector structure - MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Selectors/Selector_structure)（最後更新於2025-12-16）。

## 一‧Simple selector（簡單選擇器）

官方定義：只有**單一個組成成分**的選擇器，例如單一個type selector、attribute selector或pseudo-class，沒有跟其他任何選擇器成分或組合器（combinator）搭配使用。只要一個選擇器裡只含一個基本選擇器（basic selector）、屬性選擇器、偽類或偽元素選擇器，就算是simple selector。

```css
#myId {
}

[pattern*="\d"] {
}
```

### 官方原文提到的四種simple selector成員，各舉一個例子

a. **Basic selector（基本選擇器）**：包含type、class、id、universal選擇器，來源：[Selectors and combinators - MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_selectors/Selectors_and_combinators#basic_selectors)（最後更新於2025-11-07）。例如type選擇器：

```css
div { color: black; }
```

b. **Attribute selector（屬性選擇器）**：例如`[type="text"]`，選中所有`type`屬性值剛好等於`text`的元素。

```css
[type="text"] { border: 1px solid #ccc; }
```

c. **Pseudo-class（偽類）**：例如`:hover`，選中滑鼠移入的既有元素。

```css
a:hover { color: red; }
```

d. **Pseudo-element（偽元素）**：例如`::before`，在元素前面生出一個CSS虛擬節點（要搭配`content`屬性才會顯示）。

```css
li::before { content: "▸ "; }
```

### 補充：`[pattern*="\d"]`到底在選什麼（MDN原文範例，容易看錯，特別拆一次）

這是**CSS屬性選擇器（Attribute Selector）**的寫法，不是萬用字元（glob）。拆解如下：

a. `[...]`：屬性選擇器語法，代表「找擁有某個屬性的HTML標籤」。
b. `pattern`：屬性名稱，最常見於`<input>`標籤，是HTML5原生的表單驗證屬性。
c. `*=`：屬性選擇器的**子字串比對（contains）**運算子，只要屬性值裡面「包含」後面的字串就算命中，來源：[Attribute selectors - MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/Selectors/Attribute_selectors)（最後更新於2025-11-27）。CSS屬性選擇器總共有七種比對方式：`[attr]`（有此屬性就算）、`[attr=value]`（完全相等）、`[attr~=value]`（空白分隔詞組裡有這個詞）、`[attr|=value]`（完全相等或以`value-`開頭）、`[attr^=value]`（開頭比對）、`[attr$=value]`（結尾比對）、`[attr*=value]`（子字串比對）。
d. `"\d"`：這裡要特別澄清一個容易誤會的地方——**CSS的`*=`只做逐字元的字串比對，完全不會解析正則表達式**，`\d`在CSS這邊就是兩個普通字元（反斜線跟d）組成的字串，CSS不會把它當成「任何數字」的正則語法來解讀。`\d`之所以會出現在這裡，是因為`pattern`這個HTML屬性本身另有一個獨立機制：瀏覽器會把`pattern`屬性的值當成**JavaScript正則表達式**拿去做表單驗證（例如`pattern="\d{4}"`要求輸入4位數字），來源：[pattern attribute - MDN](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Attributes/pattern)（最後更新於2026-04-20）。這是HTML5表單驗證的功能，跟CSS選到這個元素完全是兩件事——CSS只是「剛好」用子字串比對，抓到了「pattern屬性值裡面含有`\d`這幾個字元」的`<input>`而已。

整句`[pattern*="\d"] { }`白話翻譯：選出畫面上所有標籤中，`pattern`屬性值裡面含有`\d`這個子字串的元素，例如`<input pattern="\d+">`。

- 屬於simple selector的成員：元素選擇器（`div`）、class選擇器（`.btn`）、id選擇器（`#header`）、屬性選擇器（`[type="text"]`）、萬用選擇器（`*`）、單獨一個偽類（`:hover`）、單獨一個偽元素（`::before`）。

## 二‧Compound selector（複合選擇器）

官方定義：一串**沒有被combinator分隔**的simple selector組合。代表的是「同時作用在同一個元素上的一組條件」，一個元素只有在**同時符合這串裡所有的simple selector**時，才算符合這個compound selector。

```css
a#selected {
}

[type="checkbox"]:checked:focus {
}
```

- 規則：compound selector裡如果有type selector或萬用選擇器，一定要放在**最前面**，而且最多只能有一個。因為空白代表的是後代組合器，所以compound selector裡面的simple selector之間**不能有任何空白**。
- 這一段直接回答我自己之前的疑問：Emmet打`.image.active`兩個class連在一起、中間沒有空白，出來的`<div class="image active">`身上那個`.image.active`選擇器，就是**compound selector**（兩個class simple selector黏在一起，同時作用在同一個元素身上），**不是combinator**。combinator一定是用來連接**兩個不同元素之間關係**的符號（空白、`>`、`+`、`~`），而compound selector中間完全沒有分隔符號，兩者是不同層次的概念，不要搞混。

## 三‧Complex selector（複雜選擇器）——四種組合器（combinator）在這裡出場

官方定義：一串simple／compound selector，中間用**combinator**分隔（包含代表後代組合器的空白）。代表的是「一組元素之間的關係」，而不是只針對單一元素的條件。

```css
a#selected > .icon {
}

.box h2 + p {
}
```

- 官方特別提到選擇器可以**由右往左讀**：例如`a#selected > .icon`，意思是「所有class為`icon`、而且是id為`selected`的`<a>`元素的直接子層」的元素；`.box h2 + p`，意思是「所有`class="box"`元素底下的`<h2>`後代元素，緊接在它後面的第一個`<p>`」。

### 四種combinator（依「關係越來越窄」排列，官方另有專篇說明：[Selectors and combinators - MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/CSS_selectors/Selectors_and_combinators)，最後更新於2025-11-07）

a. **後代組合器（Descendant Combinator）**：語法是一個空白，例如`div span`。意思是「選出所有在`div`裡面的`span`」，不管中間隔了幾層都算，是四種裡範圍最廣的。

```css
div span { color: red; }
```
```html
<div>
  <span>會變紅（直接子層）</span>
  <p><span>也會變紅（隔了一層p）</span></p>
</div>
```

b. **子組合器（Child Combinator）**：語法是`>`，例如`div > span`。意思是「只選`div`的直接子層`span`」，中間隔了一層就不算。

```css
div > span { color: blue; }
```
```html
<div>
  <span>會變藍（直接子層）</span>
  <p><span>不會變藍（隔了一層p，只對後代組合器有效）</span></p>
</div>
```

c. **相鄰兄弟組合器（Adjacent Sibling Combinator）**：語法是`+`，例如`h2 + p`。意思是「選出緊接在`h2`後面的那一個`p`」，兩者要同一個父層、而且中間不能隔其他元素，只選一個。

```css
h2 + p { font-weight: bold; }
```
```html
<h2>標題</h2>
<p>會變粗體（緊接在h2後面）</p>
<p>不會變粗體（隔了一個p）</p>
```

d. **一般兄弟組合器（General Sibling Combinator）**：語法是`~`，例如`h2 ~ p`。意思是「選出`h2`後面所有同層的`p`」，不用緊接，中間可以隔別的元素，但一樣要同一個父層。

```css
h2 ~ p { color: green; }
```
```html
<h2>標題</h2>
<p>會變綠（同層、在h2後面）</p>
<div>分隔用</div>
<p>也會變綠（雖然隔了一個div，但~不要求緊鄰）</p>
```

- 四者的範圍關係：後代（最廣，任意深度）＞子組合器（只看一層）；一般兄弟`~`（同層、任意距離）＞相鄰兄弟`+`（同層、只看緊接的下一個）。
- 常見誤區：`+`跟`~`都只能選「後面」的兄弟，不能選「前面」的兄弟，CSS沒有「選前一個兄弟」的組合器（這是純CSS的限制，要選前一個兄弟只能靠JS或重新設計HTML結構）。

## 四‧Selector list（選擇器清單）

官方定義：用逗號分隔的一串simple、compound、complex selector。只要元素符合清單裡**任何一個**選擇器，就算符合這個selector list。

```css
#main,
article.heading {
}
```

- 官方特別提醒：這是**non-forgiving（不寬容）**的清單，如果清單裡有任何一個選擇器是無效的，**整個規則區塊都會失效**：

```css
#main,
:bad-pseudoclass,
.validClass {
  /* :bad-pseudoclass 是無效的，導致整個樣式區塊失效 */
}
```

- 如果想要「就算某個選擇器寫錯也不要整包失效」，可以用`:is()`或`:where()`包起來，組成**forgiving selector list（寬容選擇器清單）**。

## 五‧Relative selector（相對選擇器）

官方定義：代表「相對於一個或多個錨點元素（anchor element）」的選擇器，前面會接一個combinator；如果沒有明確寫出combinator，會**隱含一個後代組合器**。Relative selector不能直接用在一般的selector list裡，只能用在特定情境下，例如`:has()`偽類裡面。

```css
:has(+ div#topic > #reference) {
}

:has(> .icon) {
}

dt:has(+ img) ~ dd {
}
```

## 六‧偽類與偽元素：兩者都是simple selector的成員，但意義不同

- **偽類（Pseudo-class）**：單冒號`:`，選的是「符合某種狀態或位置的既有元素」，元素本身是真實存在於HTML裡的。常見例子：`:hover`（滑鼠移入）、`:focus`（取得焦點）、`:first-child`（第一個子元素）、`:nth-child(2)`（第二個子元素）、`:not(.active)`（排除掉某個class）。
- **偽元素（Pseudo-element）**：雙冒號`::`（CSS3標準寫法，舊版瀏覽器相容也接受單冒號），選的是「元素身上並不真實存在、但CSS幫你生出來的一小塊」。常見例子：`::before`、`::after`（配合`content`屬性插入文字或圖示）、`::first-line`（第一行文字）、`::first-letter`（第一個字）。
- 分辨方法：偽類選的東西「本來就在DOM樹裡」，偽元素選的東西「DOM樹裡本來沒有、是CSS生出來的虛擬節點」。

```css
li:hover { background: #eee; }         /* 偽類：滑鼠移到既有的li上 */
li::before { content: "▸ "; }          /* 偽元素：li前面生出一個不存在於HTML的小圖示 */
```

## 七‧跟specificity的關聯（先點一下，深入版本在方法論筆記裡）

- 偽類（`:hover`、`:nth-child()`等）的權重算法**等同一個class**。
- 偽元素（`::before`、`::after`等）的權重算法**等同一個元素選擇器**。
- Combinator本身（空白、`>`、`+`、`~`）**不會額外加權重**，權重只看combinator兩邊各是什麼選擇器；但用了後代組合器，通常意味著complex selector變長，總權重容易疊高，這也是[[04-1-CSS方法論與權重-OOCSS-BEM-SMACSS-ITCSS]]裡OOCSS反對「位置依賴樣式」（例如`.sidebar h3`）的技術原因之一。

## 八‧常見誤區總整理

- 把**compound selector**（`.image.active`，無分隔符、同時作用在同一個元素）誤認為是某種combinator，其實combinator一定要有分隔符號、而且連接的是兩個不同元素之間的關係，跟compound selector是完全不同層次的概念。
- 把`>`（子組合器）跟空白（後代組合器）搞混，導致該選到的沒選到，或選過頭。
- 把`+`（只選一個、要緊接）跟`~`（選全部、不用緊接）搞混。
- 以為偽元素可以像偽類一樣選中「已存在的元素狀態」，其實偽元素是無中生有插入內容，且必須搭配`content`屬性才會真正顯示（`::before`、`::after`如果沒寫`content`，即使有其他樣式也不會渲染出來）。
- 以為selector list裡有一個選擇器寫錯，只有那一個選擇器會失效，其實non-forgiving的selector list是整包規則區塊一起失效，除非用`:is()`／`:where()`包成forgiving selector list。
- 把`[pattern*="\d"]`裡的`\d`誤認為CSS在做正則比對，其實CSS屬性選擇器的`*=`只做字面上的子字串比對，`\d`在CSS眼中就是兩個普通字元，正則的意義只存在於`pattern`這個HTML屬性另外被瀏覽器拿去做JS表單驗證的機制裡，兩者是不同層次的事。
