a. 先回答「為什麼無頭就是跟 SSG」

答案 不是「就是」。Headless 管的是內容放在哪裡、怎麼取得。SSG 管的是 HTML 什麼時候產生。兩者可以獨立選擇，只是常搭配，因為 headless 把內容變成 API，需要有東西把 API 內容變成頁面，而 SSG 在建置時做這件事最快、最便宜、可放 CDN。

b. 兩個概念各管什麼

項目Headless（Headless CMS）SSG
回答的問題內容存在哪裡，誰編輯，怎麼提供給前端HTML 在哪一刻、由誰產生
分離的是什麼內容後台與前端展示層分離，內容透過 API 提供建置期與請求期分離，頁面在建置期就先算好
前端可以怎麼做CSR、SSR、SSG 都可以內容可以來自檔案、資料庫、API 任何來源
換掉它會怎樣換前端框架不用搬內容改成 SSR 則每次請求重算

d. 為什麼常搭配

理由說明依據
需要有人把 API 內容變成頁面Headless 只給資料，前端要自己做成 HTML。建置時做完最簡單整理
結果是檔案預渲染的結果是 HTML 與 RSC Payload，可快取並從 CDN 送出Next.js 詞彙表，2026-10-01
可放在任何靜態主機Static export 產出 HTML、CSS、JS，任何能送靜態檔案的伺服器都能部署Next.js Static Exports，2026-08-09
便宜且快請求時不用再算頁面，伺服器負載小ISR 頁面說明「大部分請求送預渲染的靜態頁以減少伺服器負載」，2026-10-15
更安全常見說法是訪客只拿到靜態檔，不碰資料庫未查證

e. 代價與解法：內容更新怎麼辦

SSG 的頁面在建置時就定案，CMS 裡改了內容，網站不會自己變。常見解法在 Next.js 官方文件裡叫做 ISR。

做法怎麼運作程式碼
時間型重新驗證設定秒數，過期後下一個請求仍回舊頁，同時背景重新產生，成功後換掉快取。官方建議設高一點，例如一小時而不是一秒export const revalidate = 3600
按需重新驗證（整頁）內容一變就讓該路徑的快取失效，下一次請求才重新產生revalidatePath('/posts')
按需重新驗證（標籤）fetch 帶 tags，內容變更時讓該標籤的資料失效revalidateTag('posts', 'max')
怎麼觸發官方範例放在 Server Action，也可以放在 Route Handler。讓 CMS 在內容發佈時呼叫它，是常見接法CMS 接 webhook 的部分為整理，官方頁未寫 CMS
限制內容
Static export 不支援 ISR官方列為不支援功能，Static Exports 頁與 ISR 頁都有寫
多個實例時預設檔案系統快取是每個實例各一份，按需重新驗證只會讓收到呼叫的那個實例失效，要用共用的 cache handler
需要即時資料官方建議改成動態渲染

f. CSR、SSR、SSG、ISR 對照

方式HTML 何時產生誰產生資料新鮮度更新內容
CSR瀏覽器執行 JS 之後使用者的瀏覽器每次開頁最新，但要等 JS不需任何動作
SSR每個請求進來時伺服器每個請求都最新不需任何動作
SSG建置時建置機器建置當下的快照重新建置
ISR建置時先產一份，之後背景重新產生建置機器加伺服器可設定的過期時間，或內容變更時失效自動或按需

SSG 與 SSR 的分法來自你 vault 的 SSR 筆記。官方詞彙表則稱建置時或背景重新驗證的渲染為 Prerendering，請求時渲染為 Dynamic rendering，所以 SSR 在官方歸類是 Dynamic rendering。

項目內容狀態
影片引述「If you're going to go headless … your web experience are based on the JavaScript framework. And the problem is that JavaScript frameworks are evolving all the time」引自使用者，未對照影片
我的解釋Headless 讓內容與前端框架解耦。框架一直在變，內容留在 CMS，換前端不用搬內容。這是解釋，不是影片原意解釋
ISR 與按需重新驗證Next.js 官方版本歷程標示 Pages Router 的 ISR 在 v9.5.0 穩定，按需 ISR 在 v12.2.0 穩定。哪個版本落在 2021 年之前或之後，這裡沒有查日期版本號已查證，年份未查證
App Router 與 Server ComponentsApp Router 在 v13.0.0 引入，v13.4.0 起穩定並支援 Static Export 搭配 Server Components 與 Route Handlers。現在的建議是用 App Router 的做法已查證版本
Static export 的指令v14.0.0 起 next export 移除，改為設定 output: 'export'已查證
GatsbyNetlify 說明 Gatsby Cloud 將結束服務，每位客戶依合約有結束日，並表示不影響 Gatsby JS，Gatsby JS 會持續維護。GitHub 上最新發行為 5.16.1，頁面標「Latest」，發布日只顯示 10 Feb 沒有年份Netlify 文章頁面沒有發布日期。5.16.0 的說明提到 2026 年 1 月，所以 5.16.x 推定為 2026 年，屬推論
