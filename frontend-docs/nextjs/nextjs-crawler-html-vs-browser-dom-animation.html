a. 精確說法

原本的說法修正為什麼
爬蟲看的是 HTML 還沒有被 parse 過的狀態爬蟲拿到的是 HTML 文字，也就是 view-source 或 curl 看到的那份，還沒被瀏覽器端 JS 修改過爬蟲自己也會 parse 這串文字來抽出文字與連結，所以重點不在「沒 parse」，而在「沒有經過瀏覽器執行 JS 之後的 DOM」
爬蟲都這樣Googlebot 是例外，會排隊渲染Google 官方文件說 200 狀態的頁面都會送進渲染佇列，由無頭 Chromium 執行 JS，之後用渲染後的 HTML 索引

b. 動畫：同一份 HTML 文字，三方各自怎麼處理

頁面類型： 爬蟲類型：
範例而非實測輸出 動畫中的 HTML 是依你專案 app/intro/page.js 第 172 行的標題文字寫成的範例。localhost:3001 沒在執行，所以沒有 curl 到真正的回應，連結 /pricing 是示意。

c. 怎麼讀這張動畫

欄位代表什麼差別
左：伺服器回應的 HTML 文字curl 與 view-source 看到的內容，三方拿到的是同一份紅底的行是後來被 JS 加上的，不在這份文字裡
中：爬蟲自己 parse 文字，抽出文字與連結。Googlebot 還會等渲染不執行 JS 的爬蟲，索引內容永遠停在步驟 2
右：瀏覽器parse 成 DOM，再執行 JS 修改 DOM，最後畫出畫面使用者看到的是 DOM，不是 HTML 文字

d. 專案證據：--deck-h 為什麼在原始 HTML 出現 0 次

項目內容驗證方式
寫入位置hooks/use-slide-deck.js 第 43 行 deck.style.setProperty('--deck-h', ...)，包在 useEffect 內已打開檔案確認
為什麼原始 HTML 一定是 0 次useEffect 在伺服器渲染與預渲染時不會執行，而且它要讀 main.clientHeight，這個值只有瀏覽器排版後才有effect 不在伺服器執行：本 vault SSR 筆記 (e)。clientHeight 為推論
首頁標題文字是否在原始 HTML原始碼 app/intro/page.js 第 172 行 h1 是「智能時間管理 從免費開始」。是否出現在原始 HTML 取決於首頁有沒有被 Bailout未驗證。localhost:3001 沒在執行，也沒重跑 build
要自己驗證時先 curl -s http://localhost:3001/ | grep -c "智能時間管理"，再 curl -s http://localhost:3001/ | grep -c "deck-h"。第二個應為 0。接著在 Elements 面板找 --deck-h，應該看得到指令未執行

next dev 是按需渲染，dev 下 curl 到的內容不等於 production 預渲染的檔案，要比對請用 next build 後 next start。這點依據 Next.js useSearchParams 文件中 dev 與 production 行為不同的說明推廣，本次未另測。
