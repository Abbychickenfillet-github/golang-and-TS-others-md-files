Prerender 是什麼在 建置期（或重新驗證的背景中）先渲染，也就是執行元件函式並轉成文字，把結果存成 HTML 與 RSC Payload。請求進來才渲染的叫 動態渲染，官方詞彙表把兩者分開。b
預渲染出的 HTML 到 DOM 了嗎還沒。HTML 只是文字，瀏覽器解析之後才有 DOM，最後 Hydration 才接上事件。c

b. Prerender 的定義與功能

名稱什麼時候渲染在哪裡執行元件函式官方詞彙表怎麼歸類
Prerender 預渲染建置時，或重新驗證的背景中建置機器的 Node.js，不是瀏覽器Prerendering，也稱 Static rendering
SSG建置時建置機器等於預渲染的一種做法
SSR每個請求進來時伺服器的 Node.js，不是瀏覽器Dynamic rendering，不叫 Prerendering
CSR瀏覽器執行 JS 之後使用者的瀏覽器不在伺服器渲染
存疑與更正 本 vault 的舊筆記寫「廣義上 SSR 也算預渲染」，但 Next.js 詞彙表（頁面標示 2026-10-01）把 Prerendering 限定在建置時或重新驗證的背景，請求當下才渲染的叫 Dynamic rendering。本篇以官方詞彙表為準，舊筆記相關句已加上存疑標註。
預渲染的功能為什麼有用
結果是檔案可以放在 CDN，不必每次請求都重算
第一份 HTML 就有內容瀏覽器收到後立刻能畫，FCP 提早到 HTML 與 CSS 就緒時，不必等 JS 跑完
爬蟲讀得到內容空殼 HTML 只有 <div id="root">，預渲染的 HTML 有文字

d. CSR Bailout 算不算預渲染

情境建置期有預渲染嗎HTML 裡有什麼Hydration 時
Server Component有完整內容不需要，JS 不送到瀏覽器
Client Component（正常）有，官方說 Client Components 與 RSC Payload 用來預渲染 HTML完整內容認領既有 DOM 並掛事件
被 Bailout 的 Client 子樹沒有，這棵子樹被放棄最近 Suspense 的 fallback 或空殼React 在瀏覽器重試渲染，成功就取代 fallback
Suspense 以外的部分有，照常預渲染完整內容認領既有 DOM

結論：Bailout 是預渲染這個動作在某棵子樹上被放棄，所以「降級成使用者端渲染」本身不是預渲染。但同一頁的其他部分仍然是預渲染。'use client' 只宣告打包邊界，沒有說不要在伺服器渲染。

常見觸發原因

觸發點為什麼建置期做不到怎麼處理依據
useSearchParams() 外面沒有 Suspense查詢字串是請求時才有的資料用最小範圍的 Suspense 包住呼叫點，或改用 page 的 searchParams prop，或改用 usePathnameNext.js 錯誤頁與 useSearchParams 文件，已查證
next/dynamic 設 ssr: false明確要求跳過預渲染只用在真的需要瀏覽器 API 的元件，並給 loadingLazy Loading 文件，已查證。安裝的 next 15.5.28 原始碼中，dynamic-bailout-to-csr.js 處理這個選項
元件在伺服器渲染時丟錯，例如 typeof window === 'undefined' 就 throw錯誤被最近的 Suspense 接住，伺服器 HTML 放 fallback這是 React 提供的刻意做法，非刻意時要修掉React Suspense 文件，已查證
其他觸發原因未查證未查證不在本次查證範圍

f. 你在 npm run build 看到 prerender 錯誤，怎麼讀

Prerender 發生在 建置期，所以元件被拿到 Node.js 裡真的執行一遍。凡是在 Node.js 裡跑不過、或需要請求時資料的東西，都會在這時失敗。next dev 是按需渲染，官方明說 dev 裡 useSearchParams 不會 suspend，所以 dev 正常不代表 build 會過。

build 輸出可能的樣子意思先做什麼查證狀態
Missing Suspense boundary with useSearchParams靜態路由裡有 Client 元件呼叫 useSearchParams() 又沒有 Suspense找呼叫點，用最小範圍的 Suspense 包住。查不到位置就加 next build --debug-prerender錯誤頁與參數都已查證
window is not defined 或 document is not defined元件本體或模組頂層在 Node.js 預渲染時碰了瀏覽器 API移進 useEffect，或該元件改用 ssr: false原理已查證（Node 沒有 window 與 document）。訊息字樣未查證
Error occurred prerendering page "/xxx"某個路徑預渲染時丟出例外的總括訊息往上找第一個真正的 error，總括訊息本身不是原因字樣未查證
build 時抓資料失敗（例如後端 API 沒起來）Server Component 的 fetch 在建置期就被執行確認 build 環境連得到資料來源，或把該頁改成動態渲染推論，未查證
還缺你的實際訊息 我在你的終端機沒有看到 build 輸出，所以不能判定是上表哪一種。把 npm run build 輸出中第一個 error 那幾行貼過來，才能對到具體檔案。

h. 名詞 hover 規格

目前這頁的做法稱為「做法 A：HTML 加名詞表」。未來要變成 Next.js 的 React 元件稱為「做法 B：React 元件化 vault」。兩者共用同一份名詞表資料，之後可以搬。

做法 A 的運作方式

步驟內容
1 單一名詞表nextjs-terms.js 裡的 window.NOTE_TERMS，每個詞一筆：t 顯示名稱，d 一句定義，s 依據。改定義只改這一處
2 內文標記<span class="term" data-term="hydration">Hydration</span>
3 載入時填入載入器依 data-term 寫入 data-def 與 tabindex="0"。找不到 id 會標成紅底並在 console 警告，避免同詞不同說法或打錯字
4 顯示沿用 assets/notes.css 的 .term::after { content: attr(data-def) }，顯示與隱藏是純 CSS 的 :hover 與 :focus
5 窄螢幕寬度 900px 以下氣泡改成貼螢幕底部的固定面板，不會超出畫面。手機點一下元素即聚焦並顯示
6 靠邊對齊氣泡太靠左右邊界時，載入器只加上 data-align 屬性，位置由 CSS 決定
7 與現有點擊釘選相容assets/notes.js 已有點擊後釘成可拖曳說明卡，會讀同一個 data-def，不衝突

放進其他筆記

做法 B：React 元件化

把 NOTE_TERMS 原樣存成 terms.json，元件讀同一份資料。因為只用 CSS 的 hover，可以當 Server Component，不寫 'use client'，不增加瀏覽器端 JS。

// components/term.jsx
import terms from '@/data/terms.json'

export function Term({ id, children }) {
  const item = terms[id]
  if (!item) throw new Error(`terms.json 沒有 ${id}`)
  return (
    <span className="term" tabIndex={0} data-def={`${item.t}：${item.d}`}>
      {children ?? item.t}
    </span>
  )
}

// 用法
// <Term id="hydration" />

關聯筆記與關聯原因

筆記為什麼相關
usePathname 與 useSearchParams你引用的那句「Next.js 在建置期放棄把某棵元件樹預渲染成 HTML」就出自該篇的 f。本篇補上 Prerender 的定義與 HTML 到 DOM 的時間線

FCP 與 SEO 爬蟲解釋為什麼 HTML 沒內容會讓 FCP 與爬蟲一起受害
SSR、renderToString 與 Hydration時間線第 3 到 8 步的來源：伺服器沒有 DOM、瀏覽器解析後才有 DOM、Hydration 認領
編譯期與執行期三條分界線預渲染發生在建置期，這篇說明建置期能做什麼、不能做什麼，解釋為何查詢字串在建置期不可知
Critical Rendering Path時間線第 4 到 6 步 DOM、CSSOM、Layout、Paint 的細節
爬蟲看到的 HTML 與瀏覽器的 DOM接續本篇：預渲染的 HTML 文字就是爬蟲拿到的那份，該篇用三欄動畫說明爬蟲與瀏覽器的差別
SSG 與 Headless CMSSSG 是建置期預渲染，該篇說明為何常與 headless 搭配以及 ISR 怎麼更新內容
url.parse 與 URL.parsebuild 時出現的 Node 棄用警告，與建置期程式碼跑在 Node 裡是同一個原因
App Router 與 RSC、StreamingSuspense 邊界與 Server Component 的背景，說明 Suspense 為何決定靜態外殼的範圍
