🧠 自我測驗

是非題

  1. <style scoped> 編譯出來的結果本質上是 inline style。

    它是一般的 CSS 規則加上 [data-v-xxx] 屬性選擇器，會被抽成獨立 CSS 檔或注入 head。

  2. <style lang="scss"> 的 lang 是用來指定外部檔案路徑的。

    lang 指定預處理器；指定外部檔案路徑的是 src 屬性。

  3. Vue 3 可以用 JSX，但大部分 v- 指令（v-if、v-for）在 JSX 裡不能用。

    要改寫成原生 JS 的三元運算與 map。v-model 則有外掛支援。

  4. 元件專屬樣式的常見做法是把每個元件的 CSS 拆到 src/styles 資料夾。

    styles 資料夾放的是全域樣式與變數；元件樣式寫在 .vue 底部的 <style scoped>。

填空題

  1. scoped 編譯後會給標籤加上唯一的屬性，長得像 data-v-（一串雜湊）。

    hash 值每個元件不同，用來做屬性選擇器隔離。

  2. Sass 官方現在建議用 @ 取代舊的 @import 來引入變數與 mixin。

    @import 正在被淘汰，@use / @forward 是新的模組系統。

  3. 在 Vite 專案啟用 Vue JSX 要安裝的官方外掛是 @vitejs/plugin-vue-。

    再到 vite.config.js 的 plugins 加上 vueJsx()。

申論題

  1. 什麼情況你會在 Vue 專案裡改用 JSX 而不是 Template？請說明取捨。

    參考方向：(1) 適合 JSX 的情境：要寫高度動態的元件（Table 的欄位設定、Tree 的遞迴節點、Dialog 的多種內容型態），這些用 Template 的 v-if/v-for 會層層巢狀難以維護，用 JS 的函式與遞迴反而更直觀；元件庫作者也常選 JSX，因為要對外暴露 render props 這類 API。(2) TypeScript 的型別推導在 JSX 裡通常比 Template 更完整，尤其是 slot 與 props 的泛型。(3) 代價：失去 Vue Template 編譯器的靜態優化（靜態提升、Block Tree、PatchFlag），這些是 Vue 效能的重要來源；大部分 v- 指令不能用；團隊裡熟 Template 的人看 JSX 會卡。(4) 結論：一般業務頁面留在 Template，只有需要極高動態性的少數元件才局部改用 JSX，兩者可以在同一個專案共存。

重點整理

一、Vue 專案的 styles 資料夾放什麼（a–c）

(a) 會有 src/styles 或 src/assets/styles 資料夾，但它放的是「全域樣式」，不是每個元件的樣式。

(b) 典型內容：reset.css / normalize.css（清除瀏覽器預設）、variables.scss / theme.css（顏色、字體尺寸變數）、global.css（全域通用排版）。

(c) 全域檔在 main.js 一次性載入（例如 import './assets/styles/global.css'），整個專案生效，不必在每個 .vue 重複 import。元件要用共用變數時才在元件內 @use。

<style lang="scss" scoped>
@use '@/styles/variables.scss' as *;

.card {
  color: $primary-color;
}
</style>

二、<style scoped> 不是 inline style（d–h）

(d) <style scoped> 完全不是 inline style。它編譯出來的本質是傳統的 CSS 類別選擇器，只是 Vue 編譯器在背後自動加了防衝突的屬性選擇器。

(e) 編譯器做兩件事：

<!-- 你寫的 -->
<template><button class="btn">按鈕</button></template>
<style scoped>
.btn { color: red; }
</style>

<!-- 編譯後：標籤被加上唯一的 hash 屬性 -->
<button class="btn" data-v-7ba5bd90>按鈕</button>

<!-- CSS 被改寫成帶屬性的限定選擇器 -->
.btn[data-v-7ba5bd90] { color: red; }

(f) 這些 CSS 最後會被抽離成獨立的 .css 靜態檔，或注入到頁面的 <head>——所以瀏覽器能統一繪製與快取，這是它效能比 inline style 好的原因。

(g) Inline style 的三個缺點：權重極高（1000）很難被覆蓋、無法寫 :hover :focus 與 @media 與偽元素、每個標籤都要重複寫一次沒有重用性。

(h) 對照表：

特性 Inline Style (style="...") <style scoped>
運作原理 直接寫在 DOM 屬性上 獨立 CSS 規則 ＋ 屬性選擇器 [data-v-xxx]
CSS 權重 極高（1000） 一般類別權重（10 + 10 = 20）
支援 :hover / 媒體查詢 不支援 完全支援
渲染效能 差（每個 DOM 都帶重複字串） 佳（瀏覽器統一繪製與快取）

三、lang、src、scoped 三個屬性各管什麼（i–k）

(i) lang（Language）＝告訴編譯器用哪種預處理器解析這個區塊。不寫預設就是 css。<script lang="ts"> 也是同一個機制，只是換成 TypeScript。

(j) src（Source）＝從外部引入獨立檔案，就像 <img src> 或 <script src>。實務上極少用，因為它會破壞 SFC 高度內聚的優勢。

(k) 三者對照：

語法寫法 屬性名稱 作用說明
<style lang="scss"> lang 指定程式語言／預處理器（CSS、SCSS、Less）
<style src="./btn.css"> src 指定外部檔案路徑，把外部 CSS 載進來
<style scoped> scoped 指定作用域隔離，樣式只作用於當前元件

四、CSS 預處理器是什麼（l–n）

(l) CSS 預處理器（CSS Preprocessor）是一種擴充工具，讓你用變數、巢狀、函式、邏輯運算來寫樣式，最後編譯成瀏覽器看得懂的標準 CSS。瀏覽器只認識原生 CSS，預處理器就是翻譯官。

(m) 它解決三個痛點：顏色與尺寸重複複製貼上、選擇器結構冗長（要一直重寫父層 class）、樣式難以拆成小檔再組裝。

// 1. 巢狀結構（Nesting）
.nav {
  background: #333;
  a {
    color: white;
    &:hover { color: yellow; }
  }
}
// 編譯後：.nav{} .nav a{} .nav a:hover{}

// 2. 變數（Variables）
$primary-color: #42b983;
.button { background-color: $primary-color; }

// 3. Mixin（可重用的樣式組）
@mixin flex-center {
  display: flex;
  justify-content: center;
  align-items: center;
}
.card-header { @include flex-center; }

(n) 現況趨勢：原生 CSS 已支援 CSS Variables（--primary-color）與 Nesting（巢狀），所以許多專案改用 PostCSS 這類「後處理器」（Tailwind CSS 背後的技術）取代傳統預處理器的部分功能。主流仍是 Sass / SCSS，Less 已較少見，Stylus 更少。

五、Vue 也可以用 JSX（o–q）

(o) Vue 完全支援 JSX，最常見於 Vue 3 搭配 Vite，靠官方外掛 @vitejs/plugin-vue-jsx 實現。

npm install @vitejs/plugin-vue-jsx -D

// vite.config.js
import { defineConfig } from 'vite'
import vue from '@vitejs/plugin-vue'
import vueJsx from '@vitejs/plugin-vue-jsx'

export default defineConfig({
  plugins: [vue(), vueJsx()],
})

// 副檔名改成 .jsx 或 .tsx，用 setup 函式撰寫
import { defineComponent, ref } from 'vue'

export default defineComponent({
  name: 'Counter',
  setup() {
    const count = ref(0)
    const inc = () => count.value++

    return () => (
      <div class="counter">
        <p>Count: {count.value}</p>
        <button onClick={inc}>+1</button>
      </div>
    )
  },
})

(p) 跟 React JSX 最容易踩到的差異：Vue 的響應式值要寫 {count.value}（React 直接 {count}）；Vue JSX 支援 v-model={text.value}（React 要自己接 value 與 onChange）；大部分 v- 指令（v-if、v-for）在 JSX 裡不能用，要改寫成原生 JS 的三元運算與 map。

(q) 取捨：JSX 的優點是靈活度極高、重構與抽象化方便、TypeScript 型別推導有時比 Template 更直覺，很適合寫 Table / Tree / Dialog 這種高度動態的元件庫；缺點是會失去 Vue Template 編譯器的靜態優化（Block Tree、靜態提升），一般業務頁面沒必要換。

⚠️ 存疑／更正

  • Gemini 的 Vue JSX 對照表把插槽寫成 <MyComponent default: v-slots="{{"> ...，這串語法是壞的、無法執行。正確寫法是把插槽當成物件傳給 v-slots：<MyComponent v-slots={{ default: () => <p>Content</p> }} />，或直接把函式當 children 傳。
  • Gemini 說 scoped 的權重是「10 + 10 = 20」。CSS 權重不是相加的十進位數字，正確的表示是三元組 (id, class, type)：.btn[data-v-xxx] 是 (0, 2, 0)，inline style 則不在這個三元組裡、優先權更高（只有 !important 蓋得過）。用「20 對 1000」來比大小是教學簡化，不是規格。
  • Gemini 說「Sass/SCSS 目前最主流」是對的，但沒提到 Sass 官方已宣布 @import 逐步淘汰、要改用 @use / @forward——所以上面範例刻意寫 @use 而不是舊教學常見的 @import。

使用者： 預處理器是什麼？

Gemini： CSS 預處理器是一種擴充工具，讓你用變數、巢狀、函式、邏輯運算撰寫樣式，最後編譯成標準 CSS。瀏覽器只認識原生 CSS，預處理器就像翻譯官。它解決三個痛點：程式碼重複性高、選擇器結構冗長、模組化困難。常用功能是巢狀結構、變數與主題管理、Mixin。主流是 Sass / SCSS，Less 較少見，Stylus 更少。現今原生 CSS 已支援 CSS Variables 與 Nesting，因此許多人改搭配 PostCSS（Tailwind 背後的技術）取代部分功能。
