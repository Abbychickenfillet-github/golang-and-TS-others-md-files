c[0] c[1] c[2] 到底代表什麼

a先看資料長什麼樣

關鍵在這裡：checks 是一個陣列的陣列，外層每一個元素自己也是一個陣列，裡面固定裝三樣東西。

var checks = [
  ['Object.getPrototypeOf(Object.prototype)', 'null', '這是原型鏈的終點，規格明文寫死'],
  ['Object.keys(Object.prototype)',           '[]',   '12 個成員全部 enumerable 為 false'],
  ['typeof Object.prototype',                 'object', '它自己就是一個 plain object'],
];
//   └──────── 位置 0 ────────┘  └─ 1 ─┘  └──────── 位置 2 ────────┘
c[0] c[1] c[2]

點上面的標籤，看它對應到表格的哪一欄。

三欄都開著。點掉其中一個試試看。
c[0]　指令 c[1]　結果 c[2]　說明

b那七行在做什麼

checks.forEach(function (c) {                 // c 是「其中一筆」，也就是一個長度 3 的陣列
  var tr = document.createElement('tr');      // 造一個空的 <tr>
  tr.innerHTML =                              // 用字串拼出三個 <td> 塞進去
    '<td class="m">' + c[0] + '</td>' +      // 第 1 欄 = 位置 0
    '<td class="k">' + c[1] + '</td>' +      // 第 2 欄 = 位置 1
    '<td class="f">' + c[2] + '</td>';       // 第 3 欄 = 位置 2
  cb.appendChild(tr);                         // 把這一列掛進 <tbody>
});

你的理解是對的：「把 checks 的內容塞進表格裡的每一列」。 forEach 跑三次，每次拿到一筆 c，就生出一個 <tr>。 c[0]、c[1]、c[2] 只是照位置把那三樣東西挖出來， 因為它們住在陣列裡，陣列沒有欄位名字，只能用索引。

c你貼的版本有個括號位置要修

你重打的時候把 } 提前了，變成這樣：

checks.forEach(function(c){ var tr = document.createElement('tr'); } tr.innerHTML = ... ; cb.appendChild(tr); });
兩個問題：
1. 語法直接過不了 —— SyntaxError: missing ) after argument list，因為 } 提前關掉 callback 後，後面的東西不再是合法的參數。
2. 就算把語法喬對，var tr 是宣告在 callback 這個函式作用域裡的，一離開大括號就存取不到，會變成 ReferenceError: tr is not defined。
正確的斷句是：從 function(c){ 到 } 之間的三件事全部都在 callback 裡面 —— 造 tr、填內容、掛進去，三步一組，每一筆資料都完整跑一遍。

這一題可以接回 陣列遍歷-forEach與callback 那篇的「逐句拆解」段落，是同一個觀念。

d老實說：我這裡用陣列的陣列，其實不是最好的寫法

你會問 c[0] 代表什麼，正好證明了這個寫法的缺點 —— 要記位置。三種寫法由差到好：

寫法一：陣列的陣列 我原本寫的

checks.forEach(function (c) {
  ... + c[0] + ... + c[1] + ... + c[2] + ...
});

缺點：c[1] 是什麼？要滾回去看資料才知道。這就是你剛剛遇到的問題。

寫法二：解構賦值 destructuring 改一行就好

checks.forEach(function ([指令, 結果, 說明]) {
  ... + 指令 + ... + 結果 + ... + 說明 + ...
});

資料完全不用改，只在參數位置按位置拆名字，後面就能用有意義的名稱。CP 值最高的一招。

寫法三：改成物件陣列 最好讀

var checks = [
  { 指令: 'Object.keys(Object.prototype)', 結果: '[]', 說明: '全部 enumerable:false' },
];
checks.forEach(function (c) {
  ... + c.指令 + ... + c.結果 + ... + c.說明 + ...
});

資料本身就自帶欄位名，之後要加第四欄也不會亂掉。缺點是資料寫起來比較長。

寫法內層怎麼讀什麼時候用
陣列的陣列 [[...]]c[1]　靠位置純位置對應的資料，例如座標、CSV 的一列、Object.entries 的結果
解構 [a, b, c]結果　有名字資料是陣列的陣列但你想要好讀，改動最小
物件陣列 [{...}]c.結果　有欄位名有語意欄位的資料，例如人、商品、API 清單

這張表跟 物件陣列-陣列層vs物件層存取 那篇的結論是同一件事，只是那篇講概念，這篇是你自己抓到的實例。

e順帶一提：forEach 的 c 其實有三個參數

checks.forEach(function (c, i, arr) {
  // c   = 目前這一筆（這裡是長度 3 的陣列）
  // i   = 目前的索引 0, 1, 2
  // arr = 整個 checks 陣列本身
});

我只寫了 c，因為後兩個用不到。不需要的參數可以直接不寫， JavaScript 不會因為你少收參數就報錯。詳細在 陣列遍歷-forEach與callback 的「callback 會自動收到 3 個參數」那段。
