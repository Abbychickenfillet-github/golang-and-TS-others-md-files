重點整理

(a) Callback 不需要有名字：Abby 原本的疑問是「這邊的 callback 為什麼可以叫 callback，它又不是一個具名函式？」判準只有一個——只要「被當成引數傳進另一個函式、並由那個外層函式在稍後呼叫」，它就是 callback；具名、匿名（Anonymous Function）、箭頭函式（Arrow Function）都算。

(b) 常見誤解：以為「callback 一定要先 function foo(){} 宣告好再傳進去」。其實 arr.reduce((acc, cur) => acc + cur, 0) 裡那個箭頭函式，就是一個標準的 callback，只是它沒有名字而已。

(c) reduce() 的 callback 最多接四個參數：

arr.reduce(function (accumulator, currentValue, currentIndex, array) {
  // ...
  return accumulator;      // 這次的回傳值 = 下一輪的 accumulator
}, initialValue);
參數 意義
accumulator 累加器，儲存並傳遞每一輪的中間結果
currentValue 這一輪正在處理的元素
currentIndex 這一輪元素的索引
array 呼叫 reduce 的原陣列本身

(d) 累加器的「接力棒」性質：每次呼叫 callback 時，accumulator 都會把「上一輪 return 的值」帶進來，因此一定要 return，否則下一輪的 accumulator 會變成 undefined。

(e) 累加器不一定是數字，也不一定是陣列：它的型別完全由 initialValue 決定——給 0 就是數字、給 [] 就是陣列、給 {} 就是物件。這是 Abby 當時最容易搞混的一點。

[1, 2, 3].reduce((a, c) => a + c, 0);        // 6         → number
[1, 2, 3].reduce((a, c) => [...a, c * 2], []); // [2,4,6] → array
['a','b'].reduce((a, c) => ({ ...a, [c]: 1 }), {}); // {a:1,b:1} → object

(f) split() 回傳的一定是陣列：split() 把字串依分隔符切開成陣列，所以 const digits = String(n).split('') 的 digits 會是「每個字元一格」的字串陣列。注意元素仍然是字串，不是數字，要算數值得再 Number() 或 parseInt()。

const digits = String(1234).split('');   // ['1','2','3','4'] ← 字串陣列
const product = digits.reduce((acc, d) => acc * Number(d), 1); // 24

(g) split → map / filter → reduce 是常見組合技：先用 split 拆、用 filter 篩掉不要的、用 map 轉型，最後用 reduce 彙整成單一結果。這條「管線（Pipeline）」的思路比一路寫 for 迴圈更好讀。

(h) 次要備註：reduce 若省略 initialValue，會拿陣列第一個元素當初始累加器、從第二個元素開始跑；空陣列又沒給初始值會直接 throw TypeError，所以建議一律明確寫出 initialValue。
