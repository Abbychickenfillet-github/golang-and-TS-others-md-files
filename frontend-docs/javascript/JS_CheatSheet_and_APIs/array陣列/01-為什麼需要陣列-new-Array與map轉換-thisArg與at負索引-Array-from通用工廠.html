🧠 自我測驗

是非題

  1. new Array(5) 建立出來的是 5 個 undefined，可以直接用 map 產生 5 個元件。

    它是 5 個 empty slot（孔洞），map 會直接跳過。必須先 .fill(0) 才有真正的元素。

  2. 箭頭函式用了大括號 {} 卻沒寫 return，回傳值會是 undefined。

    這就是 map 出來一整排 undefined、React 畫面全白的原因。

  3. arr[-1] 可以拿到陣列的最後一個元素。

    方括號會把 -1 當成字串 key，找不到就回 undefined。要用 arr.at(-1)。

  4. map 的第二個參數 thisArg 對箭頭函式也有效。

    箭頭函式的 this 在定義時就由詞法作用域綁死了，thisArg 對它完全沒作用。

  5. 全域 Symbol（Symbol.for("foo")）不能拿來當 WeakMap 的 key。

    它被全域註冊表永久引用，不是 garbage-collectable value。

  6. 用 Symbol 當 Object 的 key 時，Object.keys() 抓得到它。

    抓不到，必須用 Object.getOwnPropertySymbols()。Map 才會一視同仁。

填空題

  1. 要取陣列最後一個元素，現代寫法是 arr.(-1)。

    at() 支援負索引，slice(-2) 早就是同樣的慣例。

  2. map() 是一個「1 對 的陣列轉換器」，原陣列有幾個元素，新陣列就有幾個。

    等長轉換是 map 的第一大特性。

  3. Array.from 是一個通用方法，建立結果時會呼叫當下的 this 建構函式。

    Generic Factory Method，所以 Array.from.call(NotArray, ...) 會產出 NotArray 實體。

  4. WeakMap 規定 key 必須是 garbage- value。

    能被引擎追蹤引用、沒人用時會被自動清掉的值。

申論題

  1. 面試官問「map 和 forEach 差在哪」，你會怎麼答才不會被追打？

    參考方向：(1) 先講回傳值——forEach 回傳 undefined、map 回傳一個長度相同的新陣列，這是規格層的硬差別。(2) 再講意圖——forEach 表達「我只是要做副作用」（送 API、印 log），map 表達「我要一份加工過的新資料」，讀 code 的人看到 map 就會預期有回傳值被接住。(3) 補三個特性：等長、不改原陣列、跳過 sparse array 的孔洞。(4) 加分點：如果 map 的回傳值沒有被使用，那就是誤用，應該改成 forEach——很多 lint 規則會直接報這個錯。

  2. 為什麼 primitive（Number、String）不能當 WeakMap 的 key，但物件和非全域 Symbol 可以？

    參考方向：(1) WeakMap 的核心是「弱引用」——當 key 沒有其他人持有時，整筆資料要能被 GC 回收。這要求 key 必須有「身分（identity）」，引擎才能追蹤「還有沒有人指著它」。(2) 物件天生有身分（同樣內容的兩個 {} 是不同的東西）。非全域 Symbol 也有身分且獨一無二，所以 ES2023 起被允許。(3) primitive 沒有身分——42 就是 42，無所謂「這個 42 還有沒有人用」，追蹤不了引用狀態，也就無法決定何時回收，所以規格直接禁止。(4) 全域 Symbol 雖然是 Symbol，但被全域註冊表永久持有，永遠不會被回收，放進 WeakMap 等於製造記憶體洩漏，所以也被禁止。

為什麼需要陣列 — new Array 建立、map 轉換、thisArg 與 at 負索引、Array.from 通用工廠

[!info]- 🔗 與既有筆記的關聯
本篇把兩串 Gemini 對話合併：一串是「陣列存在的理由」（很基礎但是面試會被問到「為什麼不用一堆變數」），一串是「new Array 到 map 到 Array.from 的一整條轉換鏈」。
關聯理由如下：
(1) map-轉換陣列重點與練習 已有 map 的練習題，本篇補的是 map 規格層的兩個細節——第二參數 thisArg 與稀疏陣列跳過，兩篇互為表裡。
(2) 陣列遍歷-forEach與callback 講 forEach，本篇第三節正好是「map 與 forEach 的目的差異」，讀完兩篇才不會混用。
(3) Object-keys與Array-keys-稀疏陣列孔洞的差異 講孔洞，本篇 (l) 點的「map 跳過 empty slot」是同一個底層現象的另一個切面。
(4) 最後一節的 Symbol 與 WeakMap 屬於 Symbol-符號型別與物件key 的延伸，因為對話是從「陣列與 Map 的 key 可以放什麼」延伸出去的，故收在本篇並雙向連結。

重點整理

一、陣列存在的理由（a–d）

(a) 陣列的核心價值是「一個變數名稱，裝一整串相關的值」。不用陣列的笨方法是替每個項目各宣告一個變數。

// 笨方法：不使用陣列
let item1 = "蘋果";
let item2 = "牛奶";
let item3 = "麵包";
// 如果有 50 個東西，你就得寫 50 行宣告...

// 好方法：使用陣列
let shoppingList = ["蘋果", "牛奶", "麵包"];

(b) 只要一個變數：不需要為每一個項目分別取名字，也不必事先「盲猜」到底會有幾筆資料。

(c) 長度彈性：要加第四個項目直接 shoppingList.push("雞蛋")，不必回頭去多宣告一個 item4。

(d) 方便處理：要對全部資料做同一件事時，只要一個迴圈跑這一個變數即可，不必寫幾十個 if 或重複的程式碼。

[!tip] 面試一句話
陣列解決的不是「存得下」，而是「數量未知」與「批次處理」這兩件事。

二、new Array(5).fill(0).map() 的星星陷阱（e–h）

(e) 下面這段程式碼會讓畫面一片空白，因為箭頭函式一旦用了大括號 {}，就必須自己寫 return；沒寫 return 的函式預設回傳 undefined，.map() 就產出一個全是 undefined 的陣列。

// ❌ 有 Bug：大括號卻沒有 return
{new Array(5).fill(0).map((_, index) => {
  <Star key={index} />
})}

(f) 兩種正確寫法：

// 寫法 A：補上 return
{new Array(5).fill(0).map((_, index) => {
  return <Star key={index} />;
})}

// 寫法 B：改用小括號直接回傳（最推薦）
{new Array(5).fill(0).map((_, index) => (
  <Star key={index} />
))}

(g) new Array(5) 只是「長度 5 的空洞陣列」，必須 .fill(0) 才會變成真正有 5 個元素的 [0,0,0,0,0]。沒有 fill 的話裡面全是 empty slot，.map() 會直接跳過、什麼都不產生。

(h) 它不是「把 Star 填進原陣列」，而是根據原陣列產生一個全新的 JSX 陣列：[<Star key="0"/>, <Star key="1"/>, ...]，React 收到這個陣列後就渲染出 5 顆星星。

三、怎麼精準解釋 map（i–l）

(i) 一句話定義：map() 是一個「1 對 1 的陣列轉換器」。它巡訪原陣列每個元素、對每個元素做處理，回傳一個長度相同的新陣列，且完全不破壞原陣列。

(j) 只說「對每個元素做事情」不夠精準，會跟 forEach() 搞混。差別在「目的與回傳值」：

方法 目的 回傳值 典型用途
forEach() 純粹做事情 undefined 印 log、送 API、改外部變數
map() 做事情並加工成新資料 長度相同的新陣列 資料轉換、渲染列表

(k) 口語比喻：傳一籃蘋果進削皮機（callback），出來一定是數量一模一樣的一籃削皮蘋果。

(l) 三大特性：等長轉換、不改變原陣列（Immutable）、跳過空位（sparse array 的 empty slot 不執行 callback）。

const numbers = [1, 2, 3];

const doubled = numbers.map((num) => num * 2);
console.log(doubled);  // [2, 4, 6]  新陣列
console.log(numbers);  // [1, 2, 3]  原陣列不受影響

四、map 的第二個參數 thisArg（m–n）

(m) array.map(callback, thisArg) 的 thisArg 用來指定 callback 內部的 this 指向誰。

const multiplier = {
  factor: 3,
  multiply(num) {
    return num * this.factor;   // 這裡的 this 會指向 multiplier
  }
};

const numbers = [1, 2, 3];
const tripled = numbers.map(function (num) {
  return this.multiply(num);    // this 就是 multiplier
}, multiplier);

console.log(tripled);  // [3, 6, 9]

(n) 只有傳統 function() 會受 thisArg 影響，箭頭函式完全不吃這一套，因為箭頭函式的 this 在定義時就由詞法作用域綁死了。現代寫法幾乎不再用 thisArg，屬於「看得懂就好」的規格知識。

五、最後一個元素與負索引 at(-1)（o–q）

(o) arr[-1] 不會拿到最後一個元素。方括號會把 -1 當成字串 key，去找名為 "-1" 的屬性，結果是 undefined。

(p) arr.at(-1) 才可以，at() 支援負數索引，-1 就是最後一個。舊寫法只能 arr[arr.length - 1]。

const colors = ['red', 'green', 'blue'];
console.log(colors[colors.length - 1]);  // 'blue'
console.log(colors.at(-1));              // 'blue'
console.log(colors[-1]);                 // undefined ← 陷阱

(q) 為什麼需要負索引？不必計算長度、不必重複寫變數名稱。舊寫法 getListOfItems()[getListOfItems().length - 1] 會把函式執行兩次，getListOfItems().at(-1) 只執行一次。slice(-2) 早就支援負數，at() 只是把這個慣例補齊。

六、Array.from 是「通用工廠」（r–s）

(r) 這一串組合拳的白話翻譯：

console.log(Array.from.call(NotArray, new Set(["foo", "bar", "baz"])));

「呼叫 Array.from 這個靜態方法，但強制把它的 this 指向 NotArray，並把 Set 的內容交給 NotArray 去實體化出一個新物件。」

(s) Array.from 是通用工廠方法（Generic Factory Method）：它建立結果時會去呼叫「當下的 this 建構函式」，預設 this 就是 Array；用 .call(NotArray) 換掉 this 之後，產出的就不是原生陣列而是 NotArray 的實體。

function NotArray(len) {}

console.log(Array.from.call(NotArray, new Set(["foo", "bar", "baz"])));
// NotArray { '0': 'foo', '1': 'bar', '2': 'baz', length: 3 }

[!note] 這是 MDN 的極端示範
它想證明的是「Array.from 不綁死在 Array 上」，實務上幾乎不會這樣寫，但它是理解 .call() 改變 this 的最好教材。

七、延伸：Symbol 當 Map / WeakMap 的 key（t–v）

(t) Symbol 可以當 Object 的 key，也可以當 Map 的 key 與 value。差別是：Object 用 Symbol 當 key 時，Object.keys() 與 JSON.stringify() 抓不到，必須用 Object.getOwnPropertySymbols()；Map 則一視同仁，myMap.keys() 或 forEach 都能正常遍歷到 Symbol key。

// 貼到 F12 Console 練習
const symKey1 = Symbol("id");
const symKey2 = Symbol("id");   // 描述一樣但完全是不同的 Symbol

const myMap = new Map();
myMap.set(symKey1, "User_001");
myMap.set(symKey2, "User_002");

console.log(myMap.get(symKey1));  // "User_001"
console.log(myMap.size);          // 2

(u) garbage-collectable values（可被垃圾回收的值）指的是「能被引擎追蹤引用狀態、沒人使用時會自動從記憶體清掉」的值。WeakMap / WeakSet 規定 key 必須是這種值。

型別 是不是 garbage-collectable 能不能當 WeakMap 的 key
物件 Object 是 可以
非全域 Symbol（Symbol("foo")） 是（ES2023 起） 可以
全域 Symbol（Symbol.for("foo")） 否，被全域註冊表永久引用 不可以
基礎型別 Number / String / Boolean 否 不可以，丟 TypeError 
const wm = new WeakMap();
const objKey = { name: "test" };
const symKey = Symbol("weakKey");

wm.set(objKey, "value1");     // ✅
wm.set(symKey, "value2");     // ✅ 非全域 Symbol 可以
console.log(wm.get(symKey));  // "value2"

try {
  wm.set(123, "value3");      // ❌
} catch (e) {
  console.error("報錯：", e.message);
  // TypeError: Invalid value used as weak map key
}

(v) 怎麼分辨 Symbol 是不是全域？看你怎麼建立它。Symbol("foo") 是非全域、獨一無二（Symbol("foo") === Symbol("foo") 為 false）；Symbol.for("foo") 會註冊進全域 Symbol Registry，同名就是同一個實體。判斷語法用 Symbol.keyFor(sym)：非全域回傳 undefined，全域回傳描述字串。

⚠️ 存疑／更正

  • Gemini 說「基礎型別通常直接存放在記憶體棧（Stack）」。這是常見的教學簡化，不是 ECMAScript 規格保證。規格只定義語意，值放 stack 還是 heap 是 V8 等引擎的實作選擇（V8 的 Smi 小整數確實內嵌，但字串是放在 heap 的）。真正的規格理由是：primitive 沒有「身分（identity）」，無法被追蹤引用，所以不能當 WeakMap 的 key。
  • Gemini 說 Map 是「Object 的一種子類型（Subtype）」，這在概念上可以接受（new Map() instanceof Object 為 true），但嚴格講 Map 不是 Object 的 subclass，它是獨立的內建型別，只是同屬「引用資料型別」且原型鏈最終指向 Object.prototype。
