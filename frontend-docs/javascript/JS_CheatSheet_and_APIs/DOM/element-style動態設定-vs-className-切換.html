本篇重點 a–j，共 10 個。 背景：Abby 寫了一個「JavaScript 作用域與閉包記憶體綁定動畫」，用 JS 動態設定方塊的 style.left 來畫連線與位移，然後問 Gemini：「這樣寫算 inline 樣式嗎？這樣會不好嗎？」

問題一：用 JS 設 style 算不算 inline style

(a) 算。el.style.left = '120px' 跟直接在 HTML 寫 <div style="left:120px"> 結果完全一樣——它操作的就是元素的 inline style 屬性，會出現在 DOM 的 style attribute 上。

(b) CSS 優先序（specificity）上，inline style 高於任何選擇器（只輸給 !important）。這正是它「好用」與「危險」的同一個原因：它一定蓋得過去，所以也一定不受樣式表管轄。

問題二：這樣會不好嗎——分兩種情況

(c) 會不好的情況：把「靜態的、事先就知道的」樣式寫進 JS。

// ✗ 不好：這些值從頭到尾都不會變，卻散在 JS 裡
box.style.backgroundColor = '#c0392b';
box.style.borderRadius = '8px';
box.style.padding = '12px';

壞處：改配色要翻 JS、無法被 CSS 變數或主題切換影響、沒辦法用媒體查詢做 RWD、樣式散落兩處難維護。

(d) 正解：抽成 class，用 className 或 classList 切換。

// ✓ 好：狀態用 class 表達，長相交給 CSS 決定
box.classList.add('is-active');
box.classList.toggle('is-highlighted', shouldHighlight);

(e) 不會不好的情況：值是「執行期才算得出來的」——動畫座標、拖曳位置、依資料算出的長度或角度、跟著滑鼠跑的元素。

// ✓ 好：這個數字 CSS 事先不可能知道
line.style.left = `${btn.offsetLeft + btn.offsetWidth / 2}px`;
bar.style.width = `${value / max * 100}%`;

(f) 判準一句話：CSS 事先寫得出來的值就交給 CSS，只有執行期才算得出來的數字才寫進 style。Abby 在對話中自己補的那句「那個應該算動態」，用的就是這個判準，方向是對的。

(g) 現代折衷做法：把動態的數字寫進 CSS 自訂屬性，長相仍然留在樣式表裡。這樣既保留了動態性，又讓所有視覺規則集中在 CSS。

el.style.setProperty('--x', `${x}px`);

.node { transform: translateX(var(--x)); transition: transform .3s; }

順帶複習：那支動畫在演什麼

(h) 截圖裡那支動畫演的是迴圈中 var 的經典陷阱：

for (var i = 0; i < 3; i++) {
  btn[i].onclick = function () { console.log(i); };
}
// 三顆按鈕全部印出 3

(i) 原因：var 是函式作用域，被 hoist 到迴圈外，從頭到尾只有「一格」記憶體。三個 onclick 函式的作用域鏈（scope chain）全部指向同一格，迴圈結束時那一格已經被累加到 3，所以誰讀都是 3。

(j) 改成 let 就好了：let 是區塊作用域，每一輪迭代都會建立一個新的綁定（規格上叫 per-iteration binding），三個函式各自捕捉到不同的那一格，所以會分別印出 0、1、2。

關聯筆記與關聯原因

  • 13-閉包-Closure-私有變數與傳址陷阱：(h)–(j) 就是那篇「傳址陷阱」在迴圈場景的具體案例。閉包捕捉的是「綁定」不是「值」，這支動畫把那句抽象的話畫成了畫面。
  • 05-作用域-scope-global-function-block：函式作用域 vs 區塊作用域的差別，決定了 (i) 與 (j) 的不同結果。那篇是理論，這裡是它造成的實際 bug。
  • 事件流與事件代理：同樣是「一個迴圈綁一堆事件」的場景。事件代理提供的是另一條解法——根本不要綁三次，綁在父層用一次。
