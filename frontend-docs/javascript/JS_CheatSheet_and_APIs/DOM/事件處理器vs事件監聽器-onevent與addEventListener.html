🧠 自我測驗

是非題

  1. el.onblur = checkUsername() 這樣寫，事件觸發時會執行 checkUsername。

    加了小括號代表「現在就跑」。這一行執行時函式就跑完了，onblur 拿到的是回傳值 undefined，事件觸發時沒東西可執行。

  2. 對同一個元素的同一個事件用 addEventListener 綁兩個函式，後面的會覆蓋前面的。

    addEventListener 是往佇列排隊，兩個都會留著並依加入順序執行。會覆蓋的是 on-event 插槽寫法。

  3. addEventListener 的第一個參數要寫 'click' 而不是 'onclick'。

    on-event 寫法才要加 on（el.onclick），addEventListener 一律不加。

  4. { once: true } 的意思是「這個按鈕之後被禁止點擊」。

    once 是「listener 執行完一次後自動移除」，按鈕本身還是可以點，只是沒人接了。要真的鎖住得自己控制 btn.disabled。

  5. addEventListener 的 options 只有 capture 與 once 兩個欄位。

    ⚠️ 本篇更正處。常用的有四個：capture、once、passive、signal。面試問第三個參數時 passive 幾乎一定會被追問，因為它跟捲動效能直接相關。

申論題

  1. 請完整說明 el.onclick 與 addEventListener 的差異，至少涵蓋五個面向。

    本質差異一句話：el.onclick 是一個「插槽」，只有一格；addEventListener 是往一條「佇列」排隊。這句話能解釋底下所有差異。 （1）同一事件綁多個函式：on-event 不行，後面的蓋掉前面的；addEventListener 可以，依加入順序執行。 （2）語法：el.onclick = handleClick vs el.addEventListener('click', handleClick)。 （3）事件名稱：on-event 要加 on（onclick、onblur）；addEventListener 不加（'click'、'blur'）。 （4）進階選項：on-event 沒有；addEventListener 第三個參數可傳 capture、once、passive、signal。 （5）移除方式：on-event 寫 el.onclick = null；addEventListener 用 removeEventListener('click', handleClick)，或搭 AbortController 的 signal。 （6）相容性：on-event 極高，很舊的瀏覽器也支援；addEventListener 從 IE9 起全面支援，現代開發沒有問題。 結論：現代開發一律優先用 addEventListener。

  2. 為什麼綁事件時不能加小括號？如果我真的需要傳參數給處理函式，該怎麼寫？

    因為小括號 () 的意思是「現在就呼叫」。 寫 el.onblur = checkUsername 時，你是把函式「本身」當成一個值，賦給 el 的 onblur 插槽，瀏覽器會在使用者讓輸入框失焦時才去呼叫它。 寫 el.onblur = checkUsername() 時，引擎讀到這一行就立刻執行 checkUsername，再把它的回傳值（通常是 undefined）賦給 onblur。結果是函式在不該跑的時候跑了一次，而事件真正觸發時插槽裡是 undefined，完全沒有函式可以執行。 需要傳參數時，包一層函式把呼叫延後就好： el.onblur = () => checkUsername('abby'); el.addEventListener('blur', () => checkUsername('abby')); 注意包成箭頭函式之後，這個匿名函式沒有名字可以參考，所以之後想 removeEventListener 就得先把它存成變數，或改用 AbortController 的 signal。

（b）正確寫法是 el.onblur = checkUsername;，不是 el.onblur = checkUsername();。

（d）記法：小括號 () 的意思是「現在就跑」。你要的是「等一下再跑」，所以不能加。

（e）例外情況是你「真的需要傳參數」，那就包一層函式，把呼叫延後：

el.addEventListener('blur', () => checkUsername('abby')); // listener 寫法

三、on-event 處理器與 addEventListener 的本質差異

（f）el.onclick 是一個「插槽」，addEventListener 是往一條「佇列」裡排隊。這一句解釋得了底下所有差異。

（g）插槽只有一格，所以會互相覆蓋：

const btn = document.querySelector('button');

btn.onclick = functionA;
btn.onclick = functionB;   // functionA 被蓋掉，點擊時只會執行 functionB

（h）佇列可以排很多個，依照加入順序執行：

btn.addEventListener('click', functionA);
btn.addEventListener('click', functionB);  // 點擊時 functionA 與 functionB 都會執行

（i）完整對照：

事件名稱寫法 要加 on，例如 onclick、onblur 不加 on，直接寫 'click'、'blur'

（j）現代開發一律優先用 addEventListener，維護性與擴充性好很多。on-event 寫法只在極簡單的示範或非常舊的程式碼裡出現。

四、once：只觸發一次就自我銷毀

（k）addEventListener 的第三個參數傳 { once: true } 時，這個 listener 執行完一次之後會自動把自己移除，之後再怎麼點都不會再跑。

const btn = document.querySelector('button');

btn.addEventListener('click', function () {
  console.log('這個按鈕只能點一次！');
}, { once: true });

常見情境：領取優惠券或折扣碼的按鈕（防止重複領取）、表單送出按鈕（避免網路慢時使用者連點造成重複送出）、初次導覽教學的一次性彈窗。

（l）補充：once 是「執行完就移除」而不是「禁止再點」。如果你要的是「處理中先鎖住、失敗還能重試」，那要自己控制 btn.disabled，或改用 AbortController 搭配 { signal } 手動決定什麼時候解除監聽。

const ac = new AbortController();
btn.addEventListener('click', handleSubmit, { signal: ac.signal });
ac.abort();   // 想拔掉的時候自己喊停，比記住函式參考再 removeEventListener 乾淨

五、⚠️ 存疑／更正

⚠️ Gemini 把第三個參數只講了 capture 與 once，漏掉常考的另外兩個。完整的 options 物件有四個常用欄位：capture（在捕獲階段觸發）、once（觸發一次後自動移除）、passive（承諾不呼叫 preventDefault，讓瀏覽器可以放心優化捲動效能）、signal（搭配 AbortController 移除）。面試問到 addEventListener 第三個參數時，passive 幾乎一定會被追問，因為它跟捲動效能直接相關。

使用者：所以會寫成 element.onevent = checkUsername() 嗎？

Gemini：不行的，不能加小括號。正確寫法是 el.onblur = checkUsername;。原因：不加小括號（checkUsername）是將函式「本身」當作一個值傳給事件處理器，這樣瀏覽器才會在使用者觸發事件（例如失去焦點 onblur）時，才去呼叫這個函式。加了小括號（checkUsername()）代表「立刻執行」這個函式，程式碼執行到這一行時函式就會馬上跑完，並把函式回傳的結果（通常是 undefined）賦值給 el.onblur，這會導致事件觸發時完全沒有函式可以執行。書中的範例圖示與說明中也有特別標註「不需要小括號」。

使用者：事件處理器跟事件監聽器差在哪？

Gemini：兩者最大的差別在於能不能同時綁定多個函式，以及語法與彈性。（1）事件處理器（Event Handlers）就是傳統寫法，例如 element.onclick = functionName，只能綁定一個函式，如果對同一個事件重複指定，後面的會覆蓋掉前面的。優點是語法簡單直覺、相容性極高；缺點是無法讓同一個事件同時執行多個獨立的任務，移除時只能設為 null。（2）事件監聽器（Event Listeners）是現代 JavaScript 最推薦的標準寫法，使用 addEventListener()，對同一個事件綁定多個函式時它們會依序執行，不會互相覆蓋；事件名稱第一個參數寫 'click'、'blur'、'mouseover'，前面不用加 on；可以傳入第三個參數控制捕獲／冒泡階段（capture）或讓事件只觸發一次（once: true）；隨時可以用 removeEventListener() 移除特定的監聽函式。在現代開發中，基本上都建議優先使用 addEventListener。

使用者：Once！

Gemini：對，once: true 是 addEventListener 非常好用的一個進階設定。當你傳入 { once: true } 時，這個事件監聽器在被觸發執行完一次之後，就會自動自我銷毀（自動移除），後面再怎麼點擊或觸發都不會再執行了。常見的使用情境：領取優惠券／折扣碼按鈕（防止使用者重複點擊領取）、表單提交或送出按鈕（避免使用者因為網路慢連續點擊導致重複送出表單）、初次導覽教學的一次性彈出。
