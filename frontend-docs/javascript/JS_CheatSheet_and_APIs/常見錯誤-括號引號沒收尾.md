# 常見錯誤：括號 / 引號沒收尾 → unexpected end of input

> 來源練習：`JavaScript-practicing/while-loop.html`（map 練習時誤打）
> 相關：[[new-Date-日期物件重點]]（報錯位置≠報錯原因）、[[02-陣列遍歷-forEach與callback]]
> 同家族（2026-10-26 補充）：`Unexpected token '}'`，`for` 後面沒有主體，見文末

## 症狀

```
Uncaught SyntaxError: unexpected end of input  （錯誤行號常指向檔案最後一行）
```

## 真正原因：少了一個收尾符號

有個 `` ` ``、`)`、`}`、`]` 沒有關起來，解析器讀到**檔案結尾**還在等它收尾。

實際踩過的例子（多打一個反引號）：
```js
let labels = people.map(p => `${p.name} is ${p.age} years old``)
//                                                          ↑↑ 兩個反引號！
```
- 第 1 個反引號正常收尾字串。
- 第 2 個反引號**又開了一個新樣板字串**，直到檔尾都沒關 → unexpected end of input。
- 修正：刪掉多餘的那個反引號。

## 關鍵心法（和日期筆記同一條原則）

> **報錯位置 ≠ 報錯原因。** 少收尾符號時，錯誤幾乎都報在「最後一行」（如 `</script>`），
> 真兇在上面某一行沒關起來的符號 → **往上找沒成對的 `` ` `` / `)` / `}` / `]`**。

## 怎麼快速抓

1. 看編輯器的**括號配對highlight**（遊標移到 `)` 會highlight對應的 `(`）。
2. 把可疑那行的 `` ` ``、`(`、`{` 一個一個數，確認**成雙成對**。
3. 善用編輯器自動縮排：縮排突然怪掉的地方，通常就是沒收尾的位置。

## 同家族：`Unexpected token '}'`（`for (...)` 後面沒有主體）

> 日期：2026-10-26　情境：在 Chrome Console 貼上練習 `var` 作用域的程式碼

### 症狀與原始碼

```js
console.log(i);                      // 第 1 行
function start(){                    // 第 2 行
    for (var i = 0; i<5; i++)        // 第 3 行
        
    //console.log(i);                // 第 6 行：被註解掉了
}                                    // 第 7 行
start();
```

```
Uncaught SyntaxError: Unexpected token '}' (at VM298:7:1)
```

`VM298:7:1` 是「第 7 行第 1 個字元」，剛好是函式結尾的 `}`。

### 真正原因：`for (...)` 的主體不能是空的

a. `for (初始化; 條件; 每圈結束後) statement`，三個表頭欄位都可以省略，但**最後的 `statement`（迴圈主體）不能省**。
b. **註解不是語句**：把 `console.log(i)` 註解掉，解析器直接略過它，等於 `for (...)` 後面什麼都沒有。
c. 解析器預期一個語句，卻讀到函式結尾的 `}` → `Unexpected token '}'`。
d. 這是**解析期**錯誤：整份程式碼還沒開始執行就失敗，所以第 1 行的 `console.log(i)` 連機會都沒有。

和上面「unexpected end of input」的差別：

| | 少了收尾符號 | 少了該有的語句 |
|---|---|---|
| 錯誤訊息 | `unexpected end of input` | `Unexpected token '}'` |
| 解析器的狀態 | 讀到檔尾，還在等收尾 | 在**這個位置**需要語句，卻看到了別的符號 |
| 報錯位置 | 常在最後一行，真兇在上面 | **通常就是真兇旁邊**（這個例子報在 `}`，真兇是它前面的 `for`） |

### 三種修法

```js
for (var i = 0; i < 5; i++) {}          // 1. 空區塊
for (var i = 0; i < 5; i++);            // 2. 空語句（分號就是主體，容易看漏，不建議）
for (var i = 0; i < 5; i++) {           // 3. 取消註解，讓它有主體
  console.log(i);
}
```

### 危險的變體：沒報錯，但意思整個變了

MDN 的「Using for without a body」提醒：如果 `for (...)` 後面**剛好有別的語句**，那個語句會**默默變成迴圈主體**，不會報錯：

```js
for (var i = 0; i < 5; i++)
console.log("完成");        // 被當成主體，印 5 次，不是你想的 1 次
```

所以**永遠加大括號 `{}`**，即使主體只有一行。這也是這次註解掉那行才爆炸、反而比較好抓的原因：爆炸比默默做錯事好。

### 修好語法之後，會遇到第二個錯（兩種錯誤的差別）

第 1 行 `console.log(i)` 在函式**外面**，而 `var i` 宣告在 `start` 裡面：

```
ReferenceError: i is not defined
```

| | `SyntaxError` | `ReferenceError` |
|---|---|---|
| 階段 | 解析期，程式還沒跑 | 執行期，跑到那一行才發現 |
| 意思 | 寫法不合法 | 寫法合法，但找不到這個變數 |
| 前一行的程式有沒有執行 | 沒有，整份都不跑 | 有，錯誤之前的程式已經跑完了 |

### 順便驗證 `var` 的兩個特性

```js
function start() {
  console.log(i);            // undefined：宣告被提升，但賦值 = 0 沒有
  for (var i = 0; i < 5; i++) {
    console.log(i);          // 0 1 2 3 4
  }
  console.log(i);            // 5：var 沒有區塊範圍，迴圈結束後 i 還在
}
start();
```

a. **函式範圍**：`var` 只認函式，不認 `{}`。函式外讀它是 `ReferenceError`。
b. **提升（hoisting）**：宣告被移到函式最上面，但只有宣告，賦值不會跟著上去，所以迴圈前讀到 `undefined`，不是錯誤。
c. 改用 `let` 會變成**區塊範圍**，迴圈外讀 `i` 就會是 `ReferenceError`。
