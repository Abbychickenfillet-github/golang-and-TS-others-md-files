一、組合拳到底在做什麼

JSON.parse(JSON.stringify(obj)) 不是把 stringify 當參數傳進去，而是先讓 JSON.stringify（序列化器）把 JS 物件 serialize 成一條 JSON 字串，再把這條字串交給 JSON.parse（JSON parser），由 parser 依 JSON 文法重新長出一個全新的 JS 物件。

const original = { a: 1, b: { c: 2 } };
const text  = JSON.stringify(original);   // '{"a":1,"b":{"c":2}}'
const clone = JSON.parse(text);           // 全新物件
clone.b.c = 999;
console.log(original.b.c);                // 2 ← 第二層也斷開了
  1. a組合拳＝JS 早年最常見的深拷貝寫法。
  2. b需要它是因為 JS 物件是傳址（by reference），const b = a 只是讓兩個名字指向同一塊記憶體。
  3. c淺拷貝（Object.assign、展開運算子）只複製第一層，第二層以上仍共用位址。

二、組合拳的四個限制

情況經過組合拳會變成為什麼
function / Symbol / undefined物件屬性直接消失，陣列元素變 nullJSON 格式裡沒有這三種型別
NaN / Infinity變成 nullJSON 的 number 文法不接受這些字面值
Date變成 ISO 字串，不會自動還原Date.prototype.toJSON 回傳字串，parse 不知道要變回來
循環引用丟 TypeErrorserialize 時會無限遞迴

d 四個限制：型別遺失、特殊數值變 null、Date 降級、循環引用直接爆。

三、現代做法 structuredClone

現代環境直接用原生 structuredClone(obj) 取代組合拳。

const src  = { when: new Date(), tags: new Set(['a']), nested: { n: NaN } };
const deep = structuredClone(src);
deep.when instanceof Date;   // true
deep.tags instanceof Set;    // true
Number.isNaN(deep.nested.n); // true
⚠️ 存疑／補充（Gemini 沒講的部分）
Gemini 只說「建議優先採用 structuredClone」，沒講限制。依 MDN 的 structured clone algorithm：function、Symbol、DOM 節點，以及物件的 prototype 與 getter/setter 都複製不了，碰到 function 會丟 DataCloneError。所以要複製「含方法的 class 實例」仍需自己寫 clone 或用 lodash cloneDeep。

四、parse 之前一定要檢查

function safeJsonParse(str) {
  if (typeof str !== 'string' || str.trim() === '') return null;
  try { return JSON.parse(str); }
  catch (error) { console.error('JSON 解析失敗：', error.message); return null; }
}

function parseJsonObject(str) {
  if (typeof str !== 'string') return null;
  try {
    const result = JSON.parse(str);
    if (typeof result === 'object' && result !== null) return result;
  } catch (e) {}
  return null;
}

g 基本安全版先擋非字串，再用 try…catch 擋語法錯誤。
h 嚴格版多一道 typeof result === 'object' && result !== null，因為 "123"、"true"、"null" 也都是合法 JSON。

五、為什麼「屬性是字串、值好像不是」

整條 jsonString 在記憶體中 100% 是一串文字。看起來值不是字串，是因為 JSON 用「有沒有雙引號」這個文法標記來區分型別。

JSON.stringify({ age: 18, isStudent: true, name: 'Alice' });
// '{"age":18,"isStudent":true,"name":"Alice"}'
//     ↑key 必有引號  ↑18 沒引號＝number  ↑有引號＝string

i 產物是純文字，沒有任何 JS 值留在裡面。
j 引號就是型別標記。
k JSON.parse 也吃 number、boolean、array、null，不限物件。
l JSON 是 JS 的原生內建物件（跟 Math 同一類），不是只有 .json 檔能用。

六、TypeScript 的 <T> 泛型

function safeJsonParse<T>(str: string): T | null {
  try { return JSON.parse(str) as T; } catch { return null; }
}
interface User { name: string; age: number }
const user = safeJsonParse<User>('{"name":"Alice","age":18}');

function deepClone<T>(obj: T): T {
  return JSON.parse(JSON.stringify(obj)) as T;
}

m <T> 是泛型的型別參數佔位符，代表「呼叫時才決定的型別」，讓函式回傳跟傳入相同的型別。
n as T 只是斷言不是驗證，執行期不會真的檢查資料長相，要真驗證請用 Zod 這類 schema 工具。

七、自己考自己

是非題

1. 用組合拳深拷貝 { n: NaN }，拷貝後 n 仍然是 NaN。
2. structuredClone 可以複製物件上的方法（function）。
3. JSON.parse('123.45') 會回傳型別為 number 的 123.45。

填空（點一下藍色色塊看答案）

1. JSON 是 JS 的原生內建物件，跟 Math 同一類。
2. JSON.parse 吃到無效字串會丟 SyntaxError，所以要用 try…catch 包。
3. 組合拳碰到循環引用會丟 TypeError。

申論題

Q：請用「誰 用什麼 做什麼、產物是什麼、再拋給誰」的句式，描述 JSON.parse(JSON.stringify(obj)) 的完整資料流，並說明為什麼這樣做可以斷開第二層的記憶體引用。


JSON.stringify（序列化器）把 heap 上位址 A 的 JS 物件 serialize 成一條 JSON 純文字 → 這條純文字交給 JSON.parse（JSON parser）→ parser 依 JSON 文法（number/string/boolean/null/array/object 六種）逐字元重建，在 heap 上另外配置位址 B 長出全新的物件樹 → 回傳給呼叫端。
斷得開的關鍵是：中繼產物是純文字，文字裡不存在任何記憶體位址，parser 只能「照著文字重新蓋一次」，所以每一層子物件都是新配置的，不會有任何一層還指回原本的位址 A。

Q2：什麼情況下你會選組合拳而不是 structuredClone？


兩種情況：
(1) 執行環境太舊（Node 16 以下或很舊的瀏覽器）沒有 structuredClone；
(2) 你刻意想把 function、undefined、Symbol 這些「不可序列化」的東西清乾淨，只留下純資料——例如要把物件塞進 localStorage 或送進 API 之前先過濾一次。這時組合拳的「限制」反而變成優點。
