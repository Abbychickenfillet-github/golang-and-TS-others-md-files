重點整理

一、名字的由來（因果順序常被弄反）

a. 常見誤解：以為叫 JSON（JavaScript Object Notation）是因為「轉換出來的東西是 JS 物件」。正確順序剛好相反：是因為這套資料格式的「寫法」長得跟 JavaScript 的物件實字（Object Literal）一模一樣，所以才用這個名字。

b. Notation 的意思是「記號法／表示法」，它指的是一種純文字的記錄格式，而不是指轉換之後產生的那個程式物件。

c. JSON 的發明人 Douglas Crockford 想找一種比 XML 更輕量好讀的純文字格式來傳資料，他發現 JavaScript 寫物件的方式（{ "key": "value" }）非常簡潔，就直接拿 JS 的物件語法當成資料格式標準。

d. JSON 被創造出來的本質，就是一種「專為解析（Parsing）與傳送而生的資料交換標準格式」。核心痛點是：JavaScript 的記憶體物件、Python 的 dict、Java 的 Object 結構都不一樣，沒辦法直接經由網路互傳，資料必須先變成純文字（String）才能傳輸。

e. Crockford 的巧思在於：既然這套純文字規範剛好等於 JavaScript 的物件實字語法，那在 JS 裡解析它就完全不必寫複雜的剖析器（Parser），直接 parse 就搞定。

f. 因為語法極度簡化（只有 Object、Array、String、Number、Boolean、Null 六種結構），幾乎所有語言（Python、Java、C#、Go）都能用很少的程式碼把它轉成自己語言內部的資料結構。

二、Whitespace（空白字元）在 JSON 規範裡的地位

g. Whitespace 在語法圖（Syntax Diagram）與 JSON／JavaScript 規範中指的是「空白字元」，用來分隔資料元素、提升可讀性。JSON 中認可的 whitespace 有四種：空格（Space）、製表符（Horizontal Tab，\t）、換行符（Line Feed，\n）、回車符（Carriage Return，\r）。

h. 不影響解析：解析器讀取 JSON 的 value 時會自動忽略這些空白字元。

i. 位置彈性：可以自由在 {}、[]、: 或逗號周圍加上空格或換行（例如美化縮排），資料的結構與內容完全不會改變。這就是為什麼 JSON.stringify(obj, null, 2) 加了縮排之後，JSON.parse 回來的結果一模一樣。

三、JSON.parse 的第二個參數 reviver

j. JSON.parse(text, reviver) 的 reviver 同時具備「過濾」與「修改」雙重功能。解析器會從最內層的屬性開始，逐一把每個屬性的鍵（key）與值（value）丟進 reviver 處理。

k. 三種回傳行為：
- 過濾（刪除）：回傳 undefined（或沒寫回傳值），該屬性就會從最終結果中被刪掉。
- 修改（轉換）：回傳其他值，該屬性就被新值覆蓋（例如把數字乘以 2，或把 ISO 字串轉成 Date 物件）。
- 保留：不想動它就必須原封不動 return v。

l. 最容易搞混的一點：reviver 的參數是 (k, v)，k 是「鍵名稱」、v 是「值」，不是「檢查 key 是不是等於 k」。

JSON.parse('{"p": 5}', function (k, v) {
  if (typeof v === "number") {
    return v * 2;   // 值是數字就乘以 2
  }
  return v;         // 其他狀況原封不動回傳
});

m. 執行順序（由內而外）：
- 第一步（處理內部屬性）：k 傳入 "p"，v 傳入 5，typeof 5 === "number" 成立，回傳 5 * 2 = 10，此時屬性 p 的值變成 10。
- 第二步（處理最外層物件本身）：k 傳入 ""（空字串代表頂層物件），v 傳入已被修改過的物件 { p: 10 }，typeof 是 "object" 不是 "number"，走 return v 原封不動回傳。
- 最終結果是 { p: 10 }。

四、順帶釐清：Gecko、Blink、WebKit 是什麼

n. 排版引擎（Layout Engine／Rendering Engine）負責把 HTML、CSS、JavaScript 的程式碼「畫」成螢幕上看到的畫面並處理互動。三大引擎：
- Gecko：Mozilla 基金會開發，用於 Firefox，搭配的 JS 引擎是 SpiderMonkey。
- Blink：Google 主導（源自 WebKit 的分支），用於 Chrome、Edge、Brave、Opera 等 Chromium 系瀏覽器。
- WebKit：Apple 主導，用於 Safari；iOS 上所有瀏覽器底層也被限制使用它。
在 MDN 文件上看到「Gecko 相關」的註記，代表那是 Firefox 核心團隊針對該功能所做的特殊實作或行為差異（例如更詳細的錯誤提示行數），不是所有瀏覽器都一樣。
