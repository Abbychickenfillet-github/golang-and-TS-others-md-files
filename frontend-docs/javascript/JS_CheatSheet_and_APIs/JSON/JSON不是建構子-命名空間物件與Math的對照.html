🧠 自我測驗

是非題

  1. JSON 不能被 new，是因為它是物件而不是函式。

    方向對但不精確。真正的判準是「有沒有 [[Construct]] 內部方法」。反例是箭頭函式：typeof 是 function，但一樣不能被 new。

  2. JSON() 這樣直接當函式呼叫是可以的，只是不能加 new。

    兩種都不行。JSON() 會丟 TypeError: JSON is not a function。

  3. Math、JSON、Reflect、Intl、Atomics 都是命名空間物件，都不能被 new。

    再加上 WebAssembly，這整個家族都只是靜態方法的容器。

  4. JSON 身上有 prototype 屬性，只是被設成 null。

    'prototype' in JSON 直接回傳 false，它根本沒有這個屬性。

填空題

  1. JSON 這種「只當靜態方法容器、沒有狀態也沒有實例」的全域物件，正式名稱叫 物件（英文 namespace object）。

    MDN 的用語就是 namespace object。

  2. new JSON() 會丟出的完整錯誤訊息是 TypeError: JSON is not a 。

    而 JSON() 丟的是 is not a function，兩者訊息不同。

  3. new 運算子真正在找的內部方法叫做 [[]]，找不到就當場丟 TypeError。

    規範層面的答案。typeof 只是快篩。

  4. Object.prototype.toString.call(JSON) 會回傳 "[object ]"。

    因為 JSON 身上有 Symbol.toStringTag 且值為 'JSON'。

申論題

  1. 為什麼 JSON 不需要被實例化？請從 new 的工作內容反推。

    new 的工作是：建立一個新物件、把 this 綁上去、掛上 prototype、讓這個實例可以保存自己的狀態。 但 JSON 不需要保存任何狀態或實例資料。JSON.parse 與 JSON.stringify 都是純函式：給輸入、出輸出，做完就結束，兩次呼叫之間不需要記住任何東西。 沒有狀態要存，實例就沒有存在的意義，所以設計者直接把它做成命名空間物件——一個裝靜態方法的容器，跟 Math 一模一樣。你不會寫 new Math()，只會直接呼叫 Math.random()。

  2. 同事說「typeof X === 'object' 就代表不能 new」，這句話對嗎？請說明更準確的判準。

    結論上通常會得到正確答案，但推理過程不對。 更準確的判準是「這個值有沒有 [[Construct]] 內部方法」。 反例是箭頭函式：typeof (() => {}) 回傳 'function'，符合「是函式」的條件，但 new (() => {}) 一樣丟 TypeError: ... is not a constructor，因為箭頭函式沒有 [[Construct]]。同樣的還有 class 的方法簡寫、以及大部分內建的工具方法。 所以 typeof X === 'function' 只能當快篩（不是 function 就一定不能 new），規範層面的答案在 [[Construct]]。

使用者：不能寫 new JSON 的意思？

Gemini：在 JavaScript 中，不能寫 new JSON() 的原因在於 JSON 不是一個建構子函數（Constructor Function）。如果你嘗試執行 new JSON()，瀏覽器會直接拋出錯誤：TypeError: JSON is not a constructor。

背後原因與設計邏輯：

  1. JSON 是一個「命名空間物件（Namespace Object）」。JavaScript 中的全局 JSON 物件，設計初衷是用來提供一整組靜態工具方法（Static Methods），例如 JSON.parse()（將 JSON 字串解析成 JavaScript 值／物件）與 JSON.stringify()（將 JavaScript 值轉成 JSON 字串）。它就像 Math 物件一樣——你不會寫 new Math()，而是直接呼叫 Math.random() 或 Math.floor()。JSON 單純只是一個用來存放這些工具函數的容器（命名空間），並不需要實例化（Instantiate）。

  2. 沒有狀態或實例屬性。new 關鍵字的作用是根據類別或建構子創建出一個新的物件實例（Instance），並綁定 this 與內部屬性。然而 JSON 物件本身不需要儲存任何狀態或實例數據，所有的轉換作業都是「給輸入、出輸出」的純函數操作，因此完全沒有實例化的必要。

補充：除了不能用 new 之外，你也不能直接調用它：JSON() 會拋出 TypeError: JSON is not a function。MDN 文件對此有明確定義：與大多數全局物件不同，JSON 不是建構子，你不能將它與 new 運算子一起使用，也不能將 JSON 物件作為函數調用。

總結來說：JSON 只是個工具箱，直接使用裡面的靜態方法 JSON.parse() 與 JSON.stringify() 即可。
