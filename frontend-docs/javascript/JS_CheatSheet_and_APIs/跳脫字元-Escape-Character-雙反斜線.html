重點整理

本篇重點 (a)–(c)，共 3 個。

(a) 單一反斜線在多數語言裡是「特殊字元的信號」

在 JavaScript、JSON 等語言裡，單一反斜線 \ 是用來定義「特殊控制字元」的符號，例如：

  • \n 代表換行
  • \t 代表 Tab 鍵
  • \" 代表字串內的雙引號

如果 Windows 路徑直接寫成 C:\coding\notes...，解析器遇到 \n 會把它當成「換行指令」，導致路徑解析出錯。

(b) 為什麼要寫兩個反斜線 \\——跳脫反斜線本身

為了讓程式知道「這裡只是要表達一個普通的反斜線符號，不是特殊指令」，就必須用另一個反斜線把它跳脫（escape），因此寫成 \\。

(c) 畫面上看到雙斜線，實際執行時會還原成單斜線

畫面顯示的是 JSON／字串格式的原始資料，所以會看到 \\；但當系統背後真正拿去給 Windows 作業系統執行檔案操作（例如搬移檔案）時，它會被正確還原為單一斜線的實際路徑 C:\coding\...。

記憶心法：資料表示層（JSON/字串原始碼）要雙斜線防止誤判；作業系統實際拿到手的是還原後的單斜線真實路徑。
