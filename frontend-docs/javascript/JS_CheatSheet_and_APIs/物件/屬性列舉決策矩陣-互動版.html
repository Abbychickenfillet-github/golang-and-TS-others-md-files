圖主軸圖：四格加一圈

屬性被兩個維度切成四格：key 是字串還是 Symbol，enumerable 是 true 還是 false。再加上「繼承」這一圈。看到任何列舉方法，只要問「它看得到哪幾格」。

a名詞先講清楚

術語全名與意思
enumerable可列舉。屬性描述器上的布林旗標，決定會不會被 Object.keys() 與 for...in 掃到
own property自有屬性。直接寫在物件自己身上的，相對於從原型鏈繼承來的
property descriptor屬性描述器。描述一個屬性「怎麼被定義」的設定物件，不是它的值
data descriptor資料描述器。有 value 與 writable 的那種
accessor descriptor存取器描述器。有 get 與 set 的那種，跟資料描述器互斥
Reflect反射。ES6 新增的內建物件，把「操作物件的底層行為」整理成一組函式

e申論題

先自己講一遍再點開。

e-1. Object.keys 與 Object.getOwnPropertyNames 差在哪？舉一個真實例子。
  • 兩者都只看自有屬性、都只回字串鍵，差別只有一個：keys 只回 enumerable: true 的，getOwnPropertyNames 不管這個旗標，全部都回。
  • 集合關係是 Object.keys(obj) ⊂ Object.getOwnPropertyNames(obj)。
  • 最有感的例子是 Object.prototype：Object.keys 回空陣列，getOwnPropertyNames 回 12 個成員。因為所有內建方法都被設成不可列舉，才不會污染你的 for...in 迴圈。
e-2. 屬性描述器的四個旗標分別控制什麼？設成 false 各會發生什麼事？
  • value 就是值本身，沒有 true false 的問題。
  • writable: false → 賦值會失敗。非嚴格模式靜默失敗，嚴格模式丟 TypeError 並中斷程式。
  • enumerable: false → 從主軸圖第 1 格掉到第 3 格，Object.keys 與 for...in 都看不到它，但 getOwnPropertyNames 還是找得到。
  • configurable: false → delete 會失敗，也不能再用 defineProperty 把它改回來，等於封死。
  • 補充：有 get／set 的存取器描述器就不會有 value 與 writable，兩種描述器互斥不能混寫。
e-3. 為什麼 Object.assign 不能拿來完整複製一個有 getter 的物件？
  • Object.assign 做的是「讀來源的值再寫進目標」，所以遇到 getter 時它會**先執行 getter**，把回傳的結果當成一個普通的死值抄過去。
  • 結果就是複製品的那個屬性從 getter 變成固定值，之後你改了相依的欄位，它也不會跟著變。
  • 正確做法是連描述器一起複製：Object.create(Object.getPrototypeOf(o), Object.getOwnPropertyDescriptors(o))，這樣 getter 還是 getter，原型也一起保留。
  • 順帶一提 Object.assign 也不會複製不可列舉的屬性與 Symbol 以外的隱藏東西，它只搬主軸圖的第 1 格與第 2 格。
e-4. 物件的 key 排序規則是什麼？什麼情況下會被它坑？
  • 三段式：整數字串鍵照數字由小到大 → 其他字串鍵照寫入順序 → Symbol 鍵照寫入順序。
  • { b:1, 2:1, a:1, 1:1, [Symbol("s")]:1, 10:1 } 的 Reflect.ownKeys 是 ["1","2","10","b","a",Symbol(s)]。注意是 1, 2, 10 而不是字串排序的 1, 10, 2。
  • 會被坑的情況是拿使用者 ID、商品編號這種數字當 key，又期待輸出照插入順序。要保證順序請改用 Map，它的 key 順序永遠是插入順序，而且 key 可以是任意型別。
e-5. Reflect 跟 Object 靜態方法有什麼不同？日常需要用嗎？
  • 設計目的不同。Object.xxx 是給人日常寫程式用的，失敗時常常丟 TypeError，回傳值也常常是物件本身不好接。
  • Reflect.xxx 是把「操作物件的底層行為」整理成函式，失敗時回傳 false 讓你自己判斷，回傳值都有意義，主要是配合 Proxy 寫攔截器時使用。
  • 日常寫程式幾乎用不到，唯一的例外就是 Reflect.ownKeys：「我要一個物件所有的 key，一個都不能漏」這個需求只有它做得到，等價於 getOwnPropertyNames 加上 getOwnPropertySymbols。
