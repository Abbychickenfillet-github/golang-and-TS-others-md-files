🧠 自我測驗

是非題

  1. 物件的 key 順序完全等於你新增的順序。

    整數索引 key 會被強制排到最前面並依數值大小排序，只有非數字字串 key 才照新增順序。

  2. Map 的 key 嚴格按照插入順序保存，不管 key 是數字還是字串。

    這是 Map 相對於 Object 最實用的保證。

  3. 普通物件可以直接呼叫 obj.forEach()。

    forEach 掛在 Array.prototype 上，物件沒有，會丟 TypeError: obj.forEach is not a function。

  4. Object 的 key 只能是字串或 Symbol，obj[2] 其實存的是 "2"。

    這正是整數 key 會被特別排序的原因。

填空題

  1. ES6 起物件 key 的排序是三段式：整數索引 → 其他字串 → 鍵。

    Symbol key 排最後，且依建立順序。

  2. 要走訪物件又想用 forEach，最常見的寫法是 Object.(obj).forEach(...)。

    先把 key 轉成陣列。

  3. for...in 會連鏈上的可列舉屬性一起走訪，所以常要搭配 hasOwnProperty 過濾。

    prototype chain。

申論題

  1. 有一份資料的 key 是使用者 ID（純數字），前端顯示時卻發現順序跑掉了。請說明原因與三種可行的修法。

    參考方向：(1) 原因：純數字的 ID 被當成 array index，規格要求依數值由小到大排序，所以無論你怎麼組資料，Object.keys() 出來都會是排序過的。(2) 修法一：改用 Map，key 保持插入順序且可以是數字型別。(3) 修法二：把資料改成陣列 [{id, ...}]，順序由陣列本身保證，這也是最貼近後端 JSON 慣例的做法。(4) 修法三：仍用物件，但另外維護一個 orderedIds 陣列，渲染時依它走訪。(5) 修法四（治標）：把 key 加前綴變成非整數字串（如 "u_1001"），就會照新增順序排——但這只是繞過規格，不建議當主力方案。

重點整理

一、規格層的三段式排序（a–d）

(a) 物件 key 的順序「有規範且固定」，但不完全等於你寫入或新增的順序。自 ES6（ES2015）起這件事被寫進規格，Object.keys()、for...in、Reflect.ownKeys() 都遵守。

(b) 排序三段式：

順位 Key 類型 排序方式
1 整數索引鍵（可轉為正整數的 key，如 "0"、"42"） 依數值大小由小到大
2 其他字串鍵 依建立／新增的先後順序
3 Symbol 鍵 依建立／新增的先後順序

(c) 「新增的一定排在最下面」這個直覺是錯的。整數 key 會被強制插隊到最前面。

const obj = {};
obj["70"] = true;       // 第 1 個新增
obj["0"] = true;        // 第 2 個新增
obj["jessica"] = true;  // 第 3 個新增
obj["8"] = true;        // 第 4 個新增
obj["40"] = true;       // 第 5 個新增
obj["1"] = true;        // 第 6 個新增

console.log(Object.keys(obj));
// 期待（新增順序）：["70", "0", "jessica", "8", "40", "1"]
// 實際：           ["0", "1", "8", "40", "70", "jessica"]

(d) 讀法："0" 和 "1" 明明後來才加，卻被硬塞到最前面；"70" 明明第一個加，卻被排到數字區的最後面；只有非數字的 "jessica" 乖乖留在最後保持新增順序。

二、真的要保序怎麼辦（e–g）

(e) 最推薦：改用 Map。Map 的 key 嚴格按插入順序（Insertion Order）保存，不管 key 是數字、字串還是其他型別。

const myMap = new Map();
myMap.set("b", "字串b");
myMap.set(2, "整數2");
myMap.set("a", "字串a");
myMap.set(1, "整數1");

for (const [key, value] of myMap) {
  console.log(key, value);   // b → 2 → a → 1，完全保留插入順序
}

(f) 次要解法：另外開一個陣列紀錄 key 的順序，走訪時依陣列跑，物件只負責存值。

const order = ["b", 2, "a", 1];
const obj = { b: "字串b", 2: "整數2", a: "字串a", 1: "整數1" };

order.forEach(key => {
  console.log(key, obj[key]);
});

(g) Map 還有一個關鍵差異：Map 的 key 可以是任何型別（物件、函式、Symbol、數字），Object 的 key 只能是字串或 Symbol——obj[2] 其實存的是 "2"，這正是整數 key 會被特別排序的原因。

(g-2) 把 (a)–(g) 壓成一張四維度對照表，決策時看這張就夠（2026-09-17 由 Gemini 對話補入）：

維度 Object Map
排序機制 混合排序：整數索引優先升序 → 字串鍵依新增順序 → Symbol 鍵依新增順序 嚴格依新增順序（FIFO），完全保留寫入順序
Key 的型態限制 僅限字串（String）或 Symbol，數字會被自動轉成字串 任何型態，包含物件、函式、數字、布林值
迭代方式 需要先透過 Object.keys() / Object.entries() 攤成陣列，或用 for...in 內建 Iterable，可直接用 for...of 或 .forEach()
適用場景 結構化資料、靜態屬性定義、要 JSON 序列化 需要頻繁增刪、嚴格保留順序、或 key 是非字串型態

一句話決策：要嚴格維持寫入順序，或要拿數字／物件當 key，就選 Map；只是描述一包固定欄位、而且要 JSON.stringify 送出去，就選 Object（Map 不能直接被 JSON.stringify 序列化，會變成 {}）。

三、order.forEach(key => ...) 裡的 key 是哪來的（h–i）

(h) key 是你自己命名的參數（Parameter），用來接收 forEach 每一輪傳進來的元素，不需要另外 const 或 let 宣告，因為參數本身就是一個綁定。

// forEach 寫法
order.forEach(key => {
  console.log(key, obj[key]);
});

// 等價的 for 迴圈寫法
for (let i = 0; i < order.length; i++) {
  const key = order[i];       // 這裡才需要自己宣告
  console.log(key, obj[key]);
}

(i) 名字可以隨便取，item、k 都一樣：order.forEach(item => console.log(item, obj[item])) 效果完全相同。

四、forEach 不能直接吃物件（j–k）

(j) Array.prototype.forEach 只掛在陣列的原型上，普通物件沒有這個方法。

const obj = { b: "字串b", 2: "整數2" };
obj.forEach(key => { });
// ❌ Uncaught TypeError: obj.forEach is not a function

(k) 要走訪物件的兩條正路：

// 1. 先把 key 轉成陣列（最常用）
Object.keys(obj).forEach(key => {
  console.log(key, obj[key]);
});

// 2. 直接用 for...in（原生專門走訪物件 key，但會往上找到原型鏈上的可列舉屬性）
for (const key in obj) {
  console.log(key, obj[key]);
}

[!warning] for...in 的補充陷阱
for...in 會連原型鏈上的可列舉屬性一起走訪，所以正式程式碼常要搭配 Object.prototype.hasOwnProperty.call(obj, key) 過濾，或直接改用 Object.keys() / Object.entries()。詳見 for-in-迴圈迭代順序與特性。

⚠️ 存疑／更正

  • Gemini 說「整數索引鍵（如 "0", "1", "42"）」，規格用的詞是 array index，範圍是 0 到 2^32 − 2 的正整數字串。超過這個範圍的數字字串（例如 "4294967296"）不算 array index，會被當成一般字串 key、依新增順序排。這個邊界 Gemini 沒有提到。
  • 「負數與小數不算整數索引」也沒提到：obj[-1]、obj[1.5] 都會被當普通字串 key。

使用者： 物件的 key 在印出來的時候到底有沒有按照順序？沒有的話要怎麼達成？

Gemini： 順序是有規範且固定的，但不完全等於寫入或新增的順序。自 ES6 起規範要求：整數索引鍵按數值由小到大 → 非整數字串鍵按新增順序 → Symbol 鍵按新增順序。要完全按插入順序，最推薦用 Map（key 嚴格按 Insertion Order 保存，且 key 可以是任何型別）；或用一個陣列另外紀錄 key 的順序再依序走訪。

使用者： 可是新增的是不是一定會在物件的最下排？那你是在說什麼哪裡有不等於？{70, 0, jessica, 8, 40, 1} 所以 Object.keys(obj) 會變成 ["0","1","8","40","70","jessica"]？

Gemini： 是的，完全正確。「新增的一定在最下排」在 JavaScript 物件中並不成立。若照 70 → 0 → jessica → 8 → 40 → 1 的順序新增，按新增順序應該印出 ["70","0","jessica","8","40","1"]，但整數 key 會被自動強制按數值排序，所以變成 ["0","1","8","40","70","jessica"]。"0"、"1" 後加卻被塞到最前面，"70" 先加卻排到數字區最後，只有 "jessica" 保持新增順序。

使用者： 為什麼這邊有 key 可以直接使用變數？（指 order.forEach(key => { console.log(key, obj[key]) })）

Gemini： 因為在箭頭函式 key => {...} 裡，key 是你自己定義的參數名稱，用來接收 order 每次傳進來的元素。第一輪 key = "b"、第二輪 key = 2、第三輪 key = "a"、第四輪 key = 1。改寫成一般 for 迴圈就是 const key = order[i]。在 forEach 裡它寫在括號內作為參數，不需要再用 const 或 let 宣告，名字可以取成 k 或 item。

使用者： forEach 可以處理物件就對了？

Gemini： 不行，Array.prototype.forEach 不能直接用在物件上。上一段能用是因為 order 是陣列。對普通物件用會直接報錯 Uncaught TypeError: obj.forEach is not a function。要走訪物件請用 Object.keys(obj).forEach(...)（最常用），或用原生的 for...in 迴圈。
