URIError 與 Exception vs Error

本篇重點 a–f，共 6 個

重點整理

(a) URIError 是 JS 內建的 Error 子類型，當 decodeURI()、decodeURIComponent()、encodeURI()、encodeURIComponent() 收到不合法的 URI 就會拋出。
(b) 常見成因：非法的百分比編碼，例如 % 後面不是兩位十六進位數字（%3Z），或字串結尾只有 % 或 %1。
(c) 範例：

try {
  decodeURIComponent('%3Z');          // 'Z' 不是合法十六進位
} catch (error) {
  console.log(error instanceof URIError); // true
  console.log(error.message);             // "URI malformed"（各引擎訊息文字略有不同）
}

逐行：try 圈出可能拋錯的區塊 → decodeURIComponent('%3Z') 解碼失敗，引擎建立 URIError 並丟出 → catch (error) 接住 → instanceof URIError 檢查它的原型鏈是否含 URIError。

(d) 解法：處理使用者輸入或外部來源的 URL 字串時一律包在 try...catch，避免未捕捉的 URIError 讓程式崩潰。
(e) Exception vs Error：Gemini 的說法是 Exception 為「可預期且可處理的狀況」，Error 為「嚴重且通常無法恢復的問題（如記憶體不足）」。
⚠️ 存疑／更正：這個二分法是 Java 的分類（Exception 與 Error 都是 Throwable 的子類）。在 JavaScript 沒有獨立的 Exception 類別，throw 可以丟任何值，慣例是丟 Error 物件，URIError、TypeError、RangeError 都是 Error 的子類，而且都可以被 catch。
(f) 結論：講「Exception handling」時指的是 例外處理機制（try/catch/throw），Error 是被丟出的物件類型之一，兩者在 JS 不是同層級的對立概念。
