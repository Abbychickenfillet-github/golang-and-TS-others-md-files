重點整理

一、核心結論

c. Object.prototype.valueOf() 的預設行為，就是「把 this 原封不動回傳」。它不做任何轉換，所以對一般物件來說呼叫它等於什麼都沒發生：

const obj = {};
obj.valueOf() === obj;   // true ← 回傳的就是自己，連新物件都不是

d. 陣列也一樣，因為 Array.prototype 沒有覆寫 valueOf，繼承下來的還是 Object.prototype 那個：

const arr = [1, 2];
arr.valueOf() === arr;              // true
Array.isArray(arr.valueOf());       // true ← 回傳的還是那個陣列，當然還是陣列
arr.valueOf() === undefined;        // false ← 不會回傳 undefined

e. 最常見的誤解：以為 valueOf() 一定會「把物件變成原始值」。預設實作根本不會。物件之所以能被拿去做數學運算，是因為 valueOf() 失敗（回傳的還是物件、不是原始值）之後，引擎退而求其次改呼叫 toString()——這才是 [] + {} 那類怪現象的真正來源。

二、包裝物件才是 valueOf 真正有用的地方

f. Number、String、Boolean 這三個包裝物件（wrapper object）各自覆寫了 valueOf，會回傳裡面裝的那個原始值：

const n = new Number(42);
typeof n;              // "object" ← 用 new 造出來的是物件
n.valueOf();           // 42
typeof n.valueOf();    // "number" ← 這裡才真的拿到原始值
n === 42;              // false ← 物件跟原始值嚴格比較不相等
n == 42;               // true  ← 寬鬆比較會觸發 ToPrimitive，才變成 42

g. 一句話總結：valueOf 是一個「留給你覆寫的鉤子」。Object.prototype 上的預設版本刻意什麼都不做（回傳自己），需要參與型別轉換的型別才自己覆寫它。

h. 自訂覆寫的實際用法——這是它在真實專案裡唯一常見的場景：

const money = {
  amount: 100,
  valueOf() { return this.amount; }   // 覆寫掉預設行為
};
money + 50;      // 150 ← 引擎做加法時走 ToPrimitive，呼叫到你寫的 valueOf
`${money}`;      // "[object Object]" ← 字串樣板走的是 toString，沒被覆寫
