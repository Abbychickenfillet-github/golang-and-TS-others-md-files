getPrototypeOf 只跳一階，不是跳到頂

這是 Object建構子-plain-object的建立與存取 主軸圖右側「原型鏈」那一格的展開版 ｜實測環境 Node.js v22 與瀏覽器 V8｜2026-08-19

a一句話先講

你的疑問是「為什麼 [] 的答案不是 Object.prototype」。答案不是「陣列跟物件無關」，而是——

Object.getPrototypeOf(x)  問的是「x 的上一階是誰」
                          不是「x 的鏈最上面是誰」

{} 的上一階剛好就是 Object.prototype，所以看起來像是「跳到頂」。 [] 中間多插了一層 Array.prototype，所以第一次呼叫只走到那裡就停了。 再呼叫一次，才會走到 Object.prototype。

b逐階走一次給你看

按「往上一階」，三條鏈會同時往上走一格。注意 {} 那條走兩步就到底，另外兩條要走三步。

c三個容易誤會的地方

誤會實際情況
陣列不是物件 typeof [] 是 "object"，[] instanceof Object 是 true。它就是物件
陣列繼承不到 Object.prototype 繼承得到。Object.prototype.isPrototypeOf([]) 是 true，[].hasOwnProperty 也存在。只是它不在第 1 階
[].toString 就是 Object.prototype.toString 不是。[].toString === Object.prototype.toString 是 false，因為 Array.prototype 自己覆寫了一份。但 ({}).toString === Object.prototype.toString 是 true
所以「是不是 plain object」的判準是「第 1 階是不是 Object.prototype」， 不是「鏈上有沒有 Object.prototype」。後者的話全部都算，那就沒有分類意義了。

f是非題

g申論題

g-1. 為什麼 JS 要在陣列跟 Object.prototype 之間多插一層 Array.prototype？
  • 因為陣列需要一整套 plain object 用不到的方法：push、pop、map、filter、reduce、length 共 40 個。
  • 如果把這些直接塞進 Object.prototype，那每一個物件都會平白多出 40 個方法，連 {name:"Abby"} 都有 push，那是災難。
  • 所以做法是：共用的東西（toString、valueOf、hasOwnProperty）放最上層的 Object.prototype，各自專屬的方法放各自的那一層。這就是原型鏈分層的意義。
  • 同理 Map.prototype 放 get／set／has／size，Date.prototype 放日期方法，各管各的。
g-2. 既然陣列最終也繼承到 Object.prototype，為什麼還要說它「不是 plain object」？
  • 因為如果判準是「鏈上有沒有 Object.prototype」，那除了 Object.create(null) 以外全部都算，這個分類就沒有任何鑑別力了。
  • 有用的判準是「第 1 階是不是 Object.prototype」，它精確對應到「這個東西有沒有額外的專屬 API」。
  • 實務上的意義很直接：你能不能對它用 Object.keys、能不能 JSON.stringify 得到預期結果、能不能用展開運算子複製。plain object 這三件事都行，Map 三件事都不行。
g-3. [].toString 跟 ({}).toString 為什麼不是同一個函式？
  • Array.prototype 自己定義了一份 toString，覆寫 override 掉繼承來的那份。
  • 原型鏈查找是「由下往上找到第一個就停」，所以 [].toString 在第 1 階就找到 Array.prototype.toString，根本走不到 Object.prototype 那份。
  • 效果差很多：[1,2].toString() 得到 "1,2"，而 Object.prototype.toString.call([1,2]) 得到 "[object Array]"。後者就是型別偵測那招之所以要寫 .call() 的原因 —— 必須繞過覆寫，直接指定用原版那份。
