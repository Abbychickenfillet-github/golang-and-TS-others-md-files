重點整理

一、Symbol 本身是什麼（a–g）

a. 在 JavaScript 的物件裡，屬性的 key 只允許兩種型別：String 與 Symbol。其他型別（數字、布林、物件）拿來當 key 都會被自動轉成字串。這也是為什麼 Reflect.ownKeys(obj) 會把字串跟 Symbol 混在同一個陣列裡回傳。

b. Symbol 是「基本型態（Primitive Type）」，不是建構子。JavaScript 一共 8 種資料型態：String、Number、Boolean、Null、Undefined、BigInt、Symbol、Object，Symbol 是其中之一。因為它是基本型態，所以 寫 new Symbol() 會直接丟 TypeError。

c. 每呼叫一次 Symbol() 都會生出一個全世界獨一無二的值。就算傳入一模一樣的描述字串也一樣不相等：

Symbol("foo") === Symbol("foo");   // false ← 描述字串只是給人看的標籤，不參與比較

d. 因為 Symbol 值「印不出來也重建不了」，你必須用一個變數把它記下來，否則之後再也存取不到用它當 key 的那個屬性。所以 const sym1 = Symbol() 這行的重點不是「示範怎麼存變數」，而是「這把鑰匙只有一把，弄丟就沒了」。

Abby 自己的截圖（2026-06-15）：左邊 F12 Console 印出 Symbol 的 typeof，右邊編輯器對照寫法，正好對應 b、c 兩節。

e. 把 Symbol 設成 key 的語法是在 key 外面加中括號，這在 MDN 屬於 Computed property names（計算屬性名稱）。不加中括號的話 { a: 1 } 裡的 a 會被當成字串 "a"，而不是變數 a 的值。

const obj = {};
obj[Symbol("a")] = "a";              // 方式一：中括號賦值
const b = Symbol.for("b");
const object1 = { [b]: "b" };        // 方式二：物件字面值裡直接用中括號

f. Symbol.for("key") 是向「全域 Symbol 註冊表（Global Registry）」索取或建立一個 Symbol。跟 Symbol() 的差別是：Symbol.for 拿得回同一個值，可以跨檔案共用；Symbol() 每次都是新的。

g. 大寫的 Symbol 與小寫的 sym 是兩件事。大寫 Symbol 是「工具箱與製造機」，小寫 sym 才是真正拿來當 key 的基本型態零件。大寫的 Symbol 扮演三個角色：（一）創建 Symbol 值的唯一進入點；（二）全域註冊表（Symbol.for 與 Symbol.keyFor）；（三）掛載 Well-known Symbols（例如 Symbol.iterator，for...of 底層就是去找物件上的這個 key）。

二、弱封裝：藏得住，但藏不死（h–l）

Abby 自己的截圖（2026-08-21）：這就是本節在討論的 MDN 原文段落，也是這場 Gemini 對話的起點。

Abby 自己的截圖（2026-08-21）：右側 Glasp／Web Highlights 劃線側欄。對話中問到「能不能把 AI 的補充寫回劃線上」，答案是不行——側欄是擴充功能獨立渲染的介面，只能手動在該劃線下方的 Note 欄位貼上。

h. MDN 原文說 Symbol 帶來 a form of weak encapsulation, or a weak form of information hiding。所謂「藏起來」，是指下面這些「日常機制」通通看不到 Symbol key：

日常存取機制 看得到 String key 看得到 Symbol key
for...in 迴圈 是 否
Object.keys(obj) 是 否
JSON.stringify(obj) 是 否
Object.getOwnPropertyNames(obj) 是 否
Object.getOwnPropertySymbols(obj) 否 是
Reflect.ownKeys(obj) 是 是 
const secretKey = Symbol("id");
const user = { name: "Alice", [secretKey]: 9527 };

for (let key in user) console.log(key);   // 只印出 "name"
console.log(Object.keys(user));           // ["name"]
console.log(JSON.stringify(user));        // '{"name":"Alice"}'

// 但專用 API 還是挖得到 → 所以叫「弱」封裝
const symbols = Object.getOwnPropertySymbols(user);
console.log(user[symbols[0]]);            // 9527

i. 之所以叫「弱」，是因為 JS 留了後門：Object.getOwnPropertySymbols(obj) 與 Reflect.ownKeys(obj) 只要有人想硬挖就挖得到。它不像 #privateField 那樣是語法層級的真私有。一句話記法：Symbol 是防君子不防小人。

j. Reflect.ownKeys 的底層就是把兩種 key 合起來：

Reflect.ownKeys(obj) === Object.getOwnPropertyNames(obj) + Object.getOwnPropertySymbols(obj)

k. Object.getOwnPropertySymbols() 的三個實務情境：

  1. 讀取私有或內部屬性：在 ES2022 的 # 私有欄位出現之前，大家用 Symbol 藏內部狀態。做單元測試、除錯或狀態備份時要靠這支 API 撈出來。
  2. 實作深拷貝與物件合併：只用 Object.keys() 會漏掉 Symbol 屬性。Lodash 的 cloneDeep 就是靠這支 API 把 Symbol 屬性一併複製。
  3. 檢查框架掛的元資料（Metadata / Hooks）：Redux、React、RxJS 這類函式庫會用 Well-known Symbol（Symbol.iterator、Symbol.dispose）或自訂 Symbol 掛元資料，避免跟使用者的字串 key 撞名。寫 DevTools 或外掛時會用這支 API 檢查物件上掛了什麼。

l. 要「真的」不給存取，有兩條路，強度不同：

// 路線一：Symbol（弱私有）——鑰匙不 export 就進不來，但 getOwnPropertySymbols 挖得到
const _status = Symbol("status");
export class Task {
  constructor(title) { this.title = title; this[_status] = "In Progress"; }
  getStatus() { return this[_status]; }
}
const t1 = new Task("Fix Bug");
console.log(t1.status);        // undefined
console.log(t1["_status"]);    // undefined ← 因為 key 是 Symbol，不是字串 "_status"

// 路線二：ES2022 原生私有欄位（語法層真私有）
class Task2 {
  #status = "In Progress";
  getStatus() { return this.#status; }
}
const t2 = new Task2();
// console.log(t2.#status);    // SyntaxError（這是早期錯誤，連跑都跑不起來）
⚠️ 陷阱

只在變數名前面加底線的 _status 完全不是私有，那只是「拜託你不要碰」的命名慣例，技術上一點防護都沒有。

三、順手釐清的 JSON 三題（m–o）

m. JSON.stringify() 是把 JS 值序列化（Serialization）成 JSON 字串，三個最常見用途：（一）Fetch/AJAX 送 request body（HTTP body 只吃字串）；（二）寫進 localStorage 或 sessionStorage（只支援字串）；（三）除錯排版，第三個參數傳縮排數，例如 JSON.stringify(data, null, 2)。

n. JSON.stringify() 的三個坑：

  • 屬性值是 undefined、Function 或 Symbol 時會被直接丟棄。
  • 物件有循環引用（Circular Reference）時直接丟 TypeError。
  • 所以 JSON.parse(JSON.stringify(obj)) 這種偷懶深拷貝會默默吃掉 Date、Map、Set、Function、Symbol，不是萬用解。

o. JSON.parse(JSON.stringify(obj)) 裡誰在複製？兩個一起才完成複製，但真正「建立新物件」的是 JSON.parse。stringify 負責把物件壓成純文字，順手斬斷跟原本記憶體位址的引用關係（鋪路）；parse 才在記憶體裡重新蓋出一份全新的物件（執行）。

四、靜態方法 vs 原型方法（p–r）

p. 兩者的差別在「掛在哪裡」：

類型 定義位置 呼叫方式 例子
靜態方法 Static 直接掛在 Object 這個函式本身 Object.方法(myObj) Object.assign()、Object.keys()、Object.freeze()、Object.create()、Object.hasOwn()
原型方法 Instance/Prototype 掛在 Object.prototype 原型物件上 myObj.方法() hasOwnProperty()、toString()、valueOf()

靜態方法無法被實例繼承，所以只能寫 Object.keys(myFirstObject)，不能寫 myFirstObject.keys()（會噴 TypeError: myFirstObject.keys is not a function）。

✅ Gemini 給的比喻很好記

把 Object 想成一個工具箱，myFirstObject 是你「用工具箱做出來的一把椅子」。椅子自己有屬性（顏色、材質）跟行為（toString()）；但工具箱上的量測工具（Object.keys()）與複製工具（Object.assign()），你不能叫椅子自己去執行，你得拿著工具箱對著這把椅子用。

q. 為什麼要特地分開？兩個理由：

  1. 命名污染與衝突：如果所有工具都掛在 Object.prototype 上，使用者自訂物件只要剛好也有一個叫 assign 的屬性，myObj.assign() 就會被覆蓋，程式默默壞掉。
  2. 無原型物件的問題：Object.create(null) 造出來的物件沒有原型，方法若都在 Object.prototype 上，這種物件就一個功能都用不到。而這種空原型物件在實務上常被拿來當 Map 的替代品，正因為它不會繼承 Object.prototype 的雜訊。

五、Symbol.species 這個語言設計上的後悔（s–t）

s. Symbol.species 是 ES6（ES2015）引進的 Well-known Symbol。它的原始用意是：當子類別（Subclass）的方法要回傳「新實例」時，用它來決定要用哪個建構子。例如 Array.prototype.map() 回傳新陣列時，規格上會先去讀 [Symbol.species]。ECMA-262 為了規格一致性，替所有內建集合類別（Array、Set、Map、Promise、RegExp、TypedArray）統一加上這個靜態存取器（Getter）。

t. 但 Map[Symbol.species] 目前是一個沒人呼叫的「死屬性」：Map 的內建方法（set()、get()、forEach()）通通不會建立並回傳新的 Map 實例，所以完全沒有東西會去讀它。它保留在規格裡純粹是為了向下相容。

實測範例（這就是「species 沒被讀到」最直白的證據）：

let setCalled = 0;
class MySet extends Set {
  static get [Symbol.species]() { setCalled++; return Set }
}
new MySet([1,2,3]).union(new Set([4])) instanceof MySet;   // false
console.log(setCalled);                                     // 0

整段翻成中文：我做一個叫 MySet 的類別，它 extends（繼承）Set，所以自動擁有 Set 的所有能力。在這個類別本身（不是它產出的實例）上，我用 static get 掛一個名字叫 Symbol.species 的存取器屬性——只要有人讀它，計數器就加一，然後回傳 Set。接著我用 [1,2,3] 建一個 MySet，對它呼叫 union 並傳入一個普通 Set。最後檢查 union 吐回來的東西是不是 MySet 的實例——答案是 false，而且計數器停在 0，代表 union 從頭到尾根本沒讀過 species。

逐字拆解每個關鍵字：

關鍵字 全名／意思 在這行做什麼
class 類別宣告 ES6 語法糖，底層仍是建構函式加原型鏈，不是真正的 class-based OOP
extends 繼承 把 MySet.prototype.[[Prototype]] 指向 Set.prototype，同時把 MySet.[[Prototype]] 指向 Set（所以靜態方法也會繼承）
static 靜態成員 掛在建構函式本身上，不掛在 prototype 上，呼應本篇 p 節
get 存取器 getter 讀取這個屬性時才執行函式，這就是「存取器屬性」，呼應 [[存取器屬性三種定義方式-getter-setter與資料驗證]]
[Symbol.species] 計算屬性名稱 + Well-known Symbol 中括號代表「用變數的值當 key」，呼應本篇 e 節
instanceof 原型鏈檢查 沿著左邊物件的原型鏈找，看有沒有等於右邊建構函式的 .prototype
⚠️ 存疑與更正（對照 TC39 一手資料）

Gemini 說「TC39 傾向未來可能逐漸廢棄（Deprecate）」——這個方向大致正確，但講法要更精確。實際狀況是： 1. Symbol.species 並沒有被正式標記為 deprecated，舊有的 Array、RegExp、Promise、TypedArray 仍然照舊會讀它。 2. TC39 的官方文件用詞是「committee has largely come to regret Symbol.species」（委員會大致上已經後悔了）。ES2025 新加的 Set 方法（union、intersection、difference 等）刻意不使用 species，永遠直接建立基底 Set 型別的實例——這正是上面那段程式碼跑出 false 與 0 的規格依據。 3. 委員會給的理由是：內建方法透過 @@species 建立子類別實例，被許多實作者視為「TC39 對這個語言犯下最大的錯誤之一」，因為它讓引擎最佳化變得極度複雜，並且直接導致過許多資安漏洞。 4. 另有一份提案 proposal-rm-builtin-subclassing（移除內建型別的 subclassing）正在推動更徹底的清理。

申論題 1：為什麼 JavaScript 要把 keys、assign、freeze 設計成 Object 的靜態方法，而不是放進 Object.prototype 讓每個物件直接呼叫？請至少講兩個理由。
參考答案：
一、避免命名污染與覆蓋。若掛在 Object.prototype，使用者自訂物件只要剛好有同名屬性，就會遮蔽掉原型上的方法，導致行為不如預期。
二、支援無原型物件。Object.create(null) 造出的物件沒有原型鏈，若方法都掛在 Object.prototype，這類物件（常被拿來當乾淨的字典使用）就完全無法使用這些功能。
三、語意上這些是「對物件動手的工具函式」而非「物件自身的行為」，放在工具箱比較符合職責分離。（本篇 q 節）
申論題 2：說明為什麼用 Symbol 做的封裝叫「弱封裝」，並舉出至少兩個可以突破它的 API。若要真正的私有應該怎麼寫？
參考答案：
Symbol key 對日常存取機制（for...in、Object.keys、JSON.stringify、Object.getOwnPropertyNames）是隱形的，所以有「藏起來」的效果；但語言留了後門，Object.getOwnPropertySymbols(obj) 與 Reflect.ownKeys(obj) 都能把 Symbol key 撈出來，因此只能算「防君子不防小人」的弱封裝。要真正私有，應使用 ES2022 的 #privateField，從語法層級禁止外部存取（外部存取是 SyntaxError 早期錯誤）。（本篇 h、i、l 節）
申論題 3：解釋 class MySet extends Set { static get [Symbol.species]() { return Set } } 這段程式碼中，class、extends、static、get、中括號各自的作用，並說明為什麼對 MySet 呼叫 union() 之後的結果不是 MySet 的實例。
參考答案：class 宣告類別（底層仍是建構函式加原型鏈）；extends 讓 MySet.prototype 繼承 Set.prototype，同時讓 MySet 本身繼承 Set 的靜態成員；static 表示這個成員掛在建構函式本身而非 prototype 上；get 定義存取器屬性，被讀取時才執行；中括號是計算屬性名稱，讓 Symbol.species 這個 Symbol 值當作 key。
結果不是 MySet 的實例，是因為 ES2025 的 Set 方法（union、intersection、difference 等）在規格上刻意不讀 Symbol.species，一律直接建立基底 Set 型別的實例，所以計數器會停在 0。（本篇 t 節）

3. Map 的 Symbol.species 探討（2026-08）— https://gemini.google.com/app/7b6a8c3812ce011f

使用者： 為何 Map 的 static properties 有 [Symbol.species]？

Gemini： 在 ES6 中引進了衍生物件的概念。Symbol.species 的核心目的在於讓子類別的方法在複製或返回新實例時，能指定要回傳「子類別的實例」還是「父類別（原生）的實例」……ECMA-262 為了保持所有內建集合與類別在 ES6 屬性設計上的一致性，統一為它們加上了 [Symbol.species] 靜態讀取器……在目前的 JavaScript 標準中，Map 的所有內建方法都不會建立並回傳新的 Map 實例，因此 Map[Symbol.species] 實際上是完全沒有被任何內建方法呼叫到的。
