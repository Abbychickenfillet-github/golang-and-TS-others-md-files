申論題

  1. 比較建構子函式與工廠函式的優缺點，並說明各自適合什麼情境。

    參考方向：建構子＋prototype 的優點是方法共用、記憶體效率好、有 instanceof 可判型、符合多數團隊的 OOP 慣例；缺點是必須記得 new、this 容易在拆解方法或當 callback 時丟失指向。工廠函式優點是沒有 this 的坑、呼叫簡單、可用閉包做真正的私有變數；缺點是每個實例各有一份方法（實例量大時記憶體成本高）、無法用 instanceof 判型。情境：需要大量實例或明確繼承關係時選 class；需要私有狀態、要把方法當 callback 到處傳、或想避免 this 心智負擔時選工廠函式。

  2. 把一個「物件模板」改寫成 React Custom Hook 時，有哪些概念是一對一對應的？哪些是 React 特有、原本的 JS 模板沒有的？

    參考方向：一對一的部分——建立實例對應呼叫 hook、物件屬性對應 useState 的 state、物件方法對應 hook 回傳的函式。React 特有的部分：(1) 狀態更新必須產生新物件（不可就地修改），因為 React 靠參考位址比較決定重繪；(2) 更新是非同步且會觸發重新渲染，所以要用函式型更新拿最新值；(3) 每次 render 都會重新執行 hook，函式參考會變，必要時要 useCallback / useMemo 穩定；(4) 有 Hooks 規則限制（只能在頂層呼叫、不能放在條件式裡），這是純 JS 模板沒有的約束。

重點整理

一、兩種「物件模板」的本質

a. 模板（Template）在這裡指的是一種設計概念與架構，不是某種特定語法。建構子函式與工廠函式都是模板，兩者的作用都是「批量生產具有相同屬性與方法的物件」的藍圖，差別只在底層機制與語法風格。

b. 建構子函式（Constructor Function）：用 this 指向新建立的物件，而且必須搭配 new 呼叫；方法通常掛在 prototype 上，透過原型鏈（Prototype Chain）共享，因此相對省記憶體。

c. 工廠函式（Factory Function）：就是一個普通函式，內部直接 return 一個新物件；不需要 this、也不需要 new；靠閉包（Closure）鎖住外層傳進來的變數。

function createHotel(name, rooms, booked) {
  return {
    name,
    rooms,
    booked,
    checkAvailability() {
      return rooms - booked;
    }
  };
}

// 使用方式：不需要 new
const quayHotel = createHotel('Quay', 40, 25);
console.log(quayHotel.checkAvailability()); // 15

d. 工廠函式的三個優點：
- 完全不需要 this，不會有 this 指向改變或作用域丟失的問題（例如把方法當 callback 傳出去就壞掉）。
- 呼叫更簡單，忘記寫 new 也不會出事。
- 利用閉包，函式內部可以直接存取傳入的 rooms 與 booked。

e. ⚠️ 補充更正（Gemini 沒講到的陷阱）：上面那個 checkAvailability 讀的是閉包裡的參數 rooms、booked，不是物件上的屬性。所以之後寫 quayHotel.booked = 30 再呼叫 checkAvailability()，答案仍然是 15 而不是 10。若希望方法跟著物件屬性走，要改寫成先把物件存進變數再參照，例如：

function createHotel(name, rooms, booked) {
  const hotel = {
    name,
    rooms,
    booked,
    checkAvailability() {
      return hotel.rooms - hotel.booked;   // 讀物件屬性，不是讀參數
    }
  };
  return hotel;
}

f. 記憶體取捨：工廠函式每次呼叫都會替每個實例各建一份方法（除非把方法抽到外層共用），建構子＋prototype 則是所有實例共用同一份函式物件。實例數量很大時，這個差異才會有感。

二、同一個模板改寫成 React

g. React 的對應寫法是把「狀態＋操作狀態的方法」封裝成 Custom Hook（自訂鉤子），等於用 useState 取代物件屬性、用回傳的函式取代物件方法。

import { useState } from 'react';

interface HotelInfo {
  name: string;
  rooms: number;
  booked: number;
}

export function useHotel(initialHotel: HotelInfo) {
  const [hotel, setHotel] = useState<HotelInfo>(initialHotel);

  // 相當於原本的 checkAvailability 方法
  const checkAvailability = () => hotel.rooms - hotel.booked;

  const bookRoom = (count: number = 1) => {
    setHotel((prev) => ({
      ...prev,
      booked: prev.booked + count,
    }));
  };

  return { hotel, checkAvailability, bookRoom };
}

h. setHotel((prev) => ({ ...prev, booked: prev.booked + count })) 這行有兩個重點：用函式型更新（functional update）拿到最新的 prev，避免連續呼叫時讀到舊值；用展開運算子產生「新物件」而不是就地修改，因為 React 是靠參考位址比較來決定要不要重繪。

i. 在元件中使用：

import { useHotel } from './useHotel';

export default function HotelCard() {
  const { hotel, checkAvailability, bookRoom } = useHotel({
    name: 'Quay', rooms: 40, booked: 25,
  });

  return (
    <div className="p-4 border rounded-lg max-w-sm">
      <h2 className="text-xl font-bold">{hotel.name} Hotel</h2>
      <p>總房間數：{hotel.rooms}</p>
      <p>已預訂數：{hotel.booked}</p>
      <p className="text-green-600 font-semibold">剩餘空房：{checkAvailability()} 間</p>
      <button onClick={() => bookRoom(1)} className="mt-3 px-4 py-2 bg-blue-500 text-white rounded">
        預約 1 間房
      </button>
    </div>
  );
}
