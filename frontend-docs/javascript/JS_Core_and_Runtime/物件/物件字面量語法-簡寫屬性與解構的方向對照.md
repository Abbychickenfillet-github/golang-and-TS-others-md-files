# 物件字面量語法｜簡寫屬性與解構的方向對照

> [!info] 這篇的由來
> 在 `symbol_data_type.html` 打錯字噴出 `SyntaxError: Invalid shorthand property initializer`，
> 疑問是「我根本沒寫簡寫屬性，為什麼訊息要跟我講簡寫？」
> 追下去發現：**物件字面量與解構賦值長得幾乎一樣，但方向相反**，引擎報錯的當下正在猜你想寫哪一種。
>
> 承接 [[Object建構子-plain-object的建立與存取]]：那篇講「怎麼把物件建出來」，這篇補上「字面量的完整語法規則」。

---

## a. 主軸：同一組大括號，兩個相反的方向

```js
// 建立 —— 把變數「放進去」　（出現在 = 右邊）
const o = { name, age };

// 取出 —— 把值「拿出來」　　（出現在 = 左邊）
const { name, age } = o;
```

**出現在 `=` 右邊是「組」，出現在 `=` 左邊是「拆」。**

---

## b. 語法對照表（本篇的核心）

| 寫法 | 建立物件（`=` 右邊） | 解構賦值（`=` 左邊） |
| --- | --- | --- |
| `{ name }` | 簡寫屬性，等於 `{ name: name }` | 取出 `name` 存成同名變數 |
| `{ name: x }` | key 是 `name`，**值**是變數 `x` | 取出 `name`，**改名**存成變數 `x` |
| `{ name = "預設" }` | **✘ 語法錯誤** | **✔ 合法**，代表預設值 |
| `{ [key]: 值 }` | 計算屬性名，key 由運算決定 | 用變數當 key 來取 |
| `{ ...rest }` | 展開：把別的物件的屬性攤進來 | 其餘：把沒點名的收成一包 |

> [!important] 第二列最容易卡
> **`{ name: x }` 在兩邊的意思完全不同。**
> 建立的時候冒號右邊是「值」，解構的時候冒號右邊是「新變數名」。

---

## c. 那個錯誤訊息在講什麼

```js
const user2 = {
    name = "Christine",     // ✘
    [id] = 9453;            // ✘
};
// SyntaxError: Invalid shorthand property initializer
```

引擎的推理過程：

- a. 看到 `{ name` → 猜「他要用**簡寫屬性**」
- b. 看到後面接了 `=` → 「等等，簡寫屬性不能有初始值」
- c. 報錯：Invalid shorthand property initializer

**引擎沒猜錯方向，它只是先猜了簡寫，才發現接不上。**

而它之所以會覺得「可能有初始值」，是因為在解構那一邊，`{ name = "預設" }` 是完全合法的：

```js
const 來源 = { a: 1 };
const { a, b = "我是預設值" } = 來源;
b;   // "我是預設值"  ← 合法
```

> [!tip] 讀錯誤訊息的通用心法
> 錯誤訊息常常不是在講「你錯在哪」，而是在講「**引擎當下猜到哪一步**」。
> 看懂它猜的方向，往往比看懂錯誤本身更有用。

正確寫法：

```js
const user2 = {
    name: "Christine",
    [id]: 9453,
};
```

物件字面量的規則只有一條：**冒號配對、逗號分隔**。

---

## d. 第二個常見錯誤：宣告時不能帶中括號

```js
const object_id[id] = id;
// SyntaxError: Missing initializer in const declaration
```

`const 名字 = 值` 的「名字」只能是一個**乾淨的識別字**。
`object_id[id]` 是「存取某個既有物件的屬性」，那是**運算**不是**宣告**，而且那個物件在那一行的當下根本還不存在。

```js
// ✔ 分兩步
const object_id = {};
object_id[id] = id;

// ✔ 用計算屬性名一次寫完
const object_id = { [id]: id };
```

---

## e. 計算屬性名 computed property name

中括號裡放的是**運算式**，運算結果拿來當 key：

```js
const key = 'name';
const id = Symbol('id');
const n = 2;

const o = {
  [key]: 'Abby',            // key 是字串 "name"
  [id]: 9453,               // key 是那個 Symbol
  ['item' + n]: 'x',        // key 是字串 "item2"
  [1 + 1]: 'y',             // key 是字串 "2"（數字會被轉字串）
};
```

> [!warning] 一個已經踩過的坑
> `{ ["__proto__"]: X }` 用計算屬性名時**不會設定原型**，只會建立一個叫 `__proto__` 的普通屬性。
> 但 `{ __proto__: X }` 直接寫就會設定原型。詳見 [[Object建構子-plain-object的建立與存取]] 的 k 節。

## f. 其他容易忘的字面量語法

```js
const o = {
  // 方法簡寫（ES2015）
  greet() { return 'hi'; },

  // 存取器
  get full() { return this.a + this.b; },
  set full(v) { [this.a, this.b] = v.split(' '); },

  // 展開
  ...另一個物件,

  // 尾隨逗號（合法，改動時 diff 比較乾淨）
  last: 1,
};
```

## g. 面試可以怎麼答

**Q：`{ name }` 是什麼意思？**

看它在哪邊。在 `=` 右邊是**簡寫屬性**，等於 `{ name: name }`，把變數 `name` 的值放進新物件。在 `=` 左邊是**解構**，把來源物件的 `name` 屬性取出來存成同名變數。同一組語法，方向相反。

**Q：為什麼 `const o = { a = 1 }` 會錯，但 `const { a = 1 } = src` 不會？**

因為 `=` 在解構那邊代表「預設值」—— 來源沒有這個屬性時才用。建立物件的時候沒有「來源」這個概念，所以不存在預設值的語意。錯誤訊息 `Invalid shorthand property initializer` 就是在說「我以為你要寫簡寫屬性，但簡寫屬性不能有初始值」。

**Q：`{ name: x }` 在解構裡是什麼意思？**

是**改名**，不是取值。把來源的 `name` 屬性取出來，存進叫 `x` 的變數。這跟建立物件時「key 是 name、值是變數 x」剛好相反。
