申論題

  1. 請解釋為什麼在 Proxy 的 trap 裡要寫 return Reflect.set(target, key, value, receiver) 而不是 target[key] = value。

    參考方向：兩個理由。(1) 回傳值：set trap 必須回傳布林值告知賦值成不成功，Reflect.set 剛好回傳布林；直接寫 target[key] = value 在非嚴格模式下失敗會靜默通過，嚴格模式下 trap 沒回傳 true 還會丟 TypeError。(2) receiver：Reflect.set 可以把 receiver 傳下去，讓原始物件上 setter 內部的 this 指向代理物件而不是原始物件。少了這個，若 target 上有 getter／setter 或有繼承關係，框架的依賴追蹤就會漏記，導致該更新的畫面沒更新。更一般的設計意圖是：Reflect 的方法名與 13 個 trap 一一對應，就是為了讓你在攔截之後能乾淨地「把原本該做的事照做一遍」。

  2. 用 Proxy 說明「不改動原始物件就能加入自訂邏輯」這句話的價值，並延伸到 Vue 3 的響應式。

    參考方向：代理模式的核心是在存取路徑上插入一層攔截器，原始物件 raw 完全不用改寫、不用繼承、不用加裝飾器。範例裡插入的是 console.log 側錄；把它換成框架的邏輯，get 時記下「目前正在執行的那個 effect 依賴了這個屬性」（track），set 時查表找出所有依賴這個屬性的 effect 並重新執行（trigger），就得到了資料驅動畫面。相較 Vue 2 用 Object.defineProperty 逐個屬性改寫，Proxy 是攔截整個物件的存取行為，因此新增屬性、刪除屬性、陣列索引賦值都能被偵測到，這是 Vue 3 最實質的升級。代價是無法 polyfill，且代理物件與原始物件是兩個參考，混用容易出錯。

Proxy 與 Reflect — 13 個攔截器（trap）與框架響應式原理

本篇重點 a–v，共 22 個。

重點整理

一、Proxy 是誰的東西

(a) Proxy 是原生 JavaScript（ES6／ES2015）的標準語法，不是任何框架的專利。所以 React、Vue、Angular 的專案裡都可以直接使用，不用裝任何套件。

(b) Vue 3 的響應式系統（Reactivity System）底層就是用 Proxy 實作的。Vue 2 用的是 Object.defineProperty，那條路無法偵測新增屬性與陣列索引賦值，換成 Proxy 才一次解決。

(c) React 沒有內建響應式系統，它走的是「重跑函式 + 比對」的路線，所以 React 本身不用 Proxy；但 MobX、Valtio 這類 React 狀態管理庫就是用 Proxy 做的，可見這是語言層能力而非框架能力。

二、handler 的 13 個攔截行為

(d) new Proxy(target, handler) 的 handler 是一個物件，裡面可以定義最多 13 種攔截行為（trap，攔截器）。完整清單：

trap 攔截什麼
get 讀屬性 obj.x
set 寫屬性 obj.x = 1
has in 運算子
deleteProperty delete obj.x
ownKeys Object.keys / for...in / Object.getOwnPropertyNames
getOwnPropertyDescriptor Object.getOwnPropertyDescriptor
defineProperty Object.defineProperty
preventExtensions Object.preventExtensions
isExtensible Object.isExtensible
getPrototypeOf Object.getPrototypeOf
setPrototypeOf Object.setPrototypeOf
apply 呼叫函式 fn()
construct new fn()

日常最常用的就是前三個：get、set、has。

三、get 與 set 的參數逐一拆解

(e) get(target, key, receiver) — 讀取屬性時觸發：

  • target：被代理的原始物件（範例中的 raw）。
  • key：被讀取的屬性名稱，例如 'count'。型別可能是 string 或 symbol。
  • receiver：實際發起這次讀取的那個物件，通常就是代理物件本身（state），若有繼承關係則是繼承鏈上的那一個。

(f) set(target, key, value, receiver) — 寫入屬性時觸發：

  • target、key、receiver 同上。
  • value：準備要寫進去的新數值。
  • set 必須回傳布林值。回傳 false 在嚴格模式（strict mode）下會丟 TypeError。這就是為什麼要寫 return Reflect.set(...) 而不是只呼叫不回傳。

(g) 逐行範例：

const raw = { count: 0 }

const state = new Proxy(raw, {
  get(target, key, receiver) {
    console.log(`讀取 ${String(key)}`)
    return Reflect.get(target, key, receiver)   // 把讀取轉交給原始物件，回傳該屬性的值
  },
  set(target, key, value, receiver) {
    console.log(`寫入 ${String(key)} = ${value}`)
    return Reflect.set(target, key, value, receiver)  // 執行實際賦值，回傳 true 表示成功
  },
})

state.count        // 印出「讀取 count」，得到 0
state.count = 1    // 印出「寫入 count = 1」

四、Reflect 是什麼

(h) Reflect 是一個內建物件（built-in object），不是函式，也不是建構子。不能 new Reflect()，也不能當函式呼叫。它只提供一堆靜態方法（static method），就像 Math 一樣。

(i) Reflect 的方法名稱與 Proxy 的 13 個 trap 一一對應（Reflect.get、Reflect.set、Reflect.has、Reflect.ownKeys…）。這個設計是刻意的：你在 trap 裡想「照原本該做的做一遍」，就呼叫同名的 Reflect 方法，不用自己手刻。

(j) 為什麼不直接寫 target[key] = value 而要用 Reflect.set？兩個理由：

  1. Reflect.set 會回傳布林值告訴你成不成功，target[key] = value 失敗時在非嚴格模式下會靜默失敗。
  2. Reflect.set 可以傳 receiver，讓 getter／setter 裡的 this 正確指向代理物件。少了這個，繼承場景與 getter 內部的依賴追蹤就會漏掉。

五、new Proxy 的身分釐清

(k) Proxy 是標準建構子（Constructor），不是「靜態方法」。new Proxy(target, handler) 是在呼叫建構子實例化出一個新的代理物件。這跟 Object.keys() 那種「掛在 Object 上的靜態方法」是兩回事。

(l) 判準口訣：要 new 的是建構子，直接 X.method() 呼叫的是靜態方法。Proxy 要 new，Reflect 不能 new。

六、這個範例到底在表達什麼

(m) 核心觀念是代理模式（Proxy Pattern）：用 new Proxy 把原始物件 raw 包成 state，之後所有對 state 的讀寫都會先經過 handler 攔截器。

(n) 價值在於「不改動原始物件」就能插入自訂邏輯——範例裡是 console.log 側錄，換成框架就是「記下誰依賴了這個屬性」與「這個屬性變了就通知誰重繪」。

(o) 把 (n) 展開就是 Vue 3 響應式的兩個動作：get 時做 track（依賴收集），set 時做 trigger（觸發更新）。這就是「資料驅動畫面」的底層真相。

(p) Proxy 的兩個限制要記住：一是 Proxy 無法被 polyfill（ES5 做不出來），所以只能在支援 ES6 的環境跑，這也是 Vue 3 放棄 IE11 的原因；二是代理物件與原始物件是兩個不同的參考，state !== raw，混用容易出現「改了 raw 但畫面沒更新」的 bug。

(q) 次要備註：receiver 這個參數名容易讓人以為是「接收者」很抽象，其實把它讀成「這次操作真正發起的那個物件」就好。多數簡單場景下 receiver === proxy。

順帶記下的 Bash 小知識（同一段對話）

  • 命令替換（Command Substitution）：RESULT=$(gh run list) 的 $( ) 會先執行裡面的指令，再把它的標準輸出當成字串塞進變數。
  • STATUS=$(echo "$RESULT" | grep -o '"status":"[^"]*"') 逐段讀法：echo "$RESULT" 把變數內容吐到標準輸出 → | 管線交給 grep → grep -o 的 -o 是 only-matching，只印出「符合的那一小段」而不是整行 → 結果再存進 STATUS。
  • [^"]* 是「連續零個以上、不是雙引號的字元」，用來抓到下一個引號為止。
  • 這是 Bash 語法不是 Python，sleep 20 才是暫停 20 秒的寫法。

追加 2026-09-05：為什麼 dog = new Proxy(dog, {...}) 還叫 dog

(r) let 允許變數被重新賦值，所以 dog = new Proxy(dog, {...}) 是把識別字 dog 改指向新建立的 Proxy 實體，原本那個 { name: '來福', age: 6 } 物件變成 Proxy 的 target，被包在裡面。

let dog = { name: '來福', age: 6 };

dog = new Proxy(dog, {
  get(target, prop, receiver) { /* ... */ },
  set(target, prop, value, receiver) { /* ... */ },
});

(s) 這是很常見的寫法：當你想攔截「之後所有對 dog 的存取」時，直接覆寫同一個識別字，就不必再多一個 proxyDog 變數名稱，也避免有人不小心繞過代理直接動原始物件。

(t) 但要注意：原始物件並沒有消失。如果別的地方還持有原本那個物件的引用（例如先 const raw = dog 再覆寫），透過 raw 的存取仍然完全繞過 Proxy。所以「覆寫同名變數」只是遮住這一個入口，不是真正的封裝。

(u) handler 裡看到 get 和 set 兩個函式，並不代表 handler 只能有兩個。這是這段範例只定義了兩個 trap 而已，完整可用的 trap 有 13 個（見上面第二節）。

(v) 沒有定義的 trap 會直接「穿透」到 target 上，行為完全不變。例如只寫了 get 沒寫 set，那麼 dog.age = 7 就會原封不動地作用在原始物件上，不會報錯也不會被攔截——這是 Proxy 設計上「預設無害」的性質。
