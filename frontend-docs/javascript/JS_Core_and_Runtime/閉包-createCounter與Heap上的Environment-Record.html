重點整理

  • (a) closure（閉包）指內層函式（increment / decrement）把它引用的外層變數（count）一起帶走：外層函式 createCounter() 執行完後其 Stack Frame 會 Pop 清除，但被內層函式引用的變數不會消失。
  • (b) 引擎（V8（Chrome 的 JS 引擎））每呼叫一次 createCounter()，就在 Heap 配置一份新的 Environment Record（環境記錄，存放被捕捉變數的物件），count 住在那裡，而不是住在 Stack。
  • (c) 呼叫一次 createCounter()：increment 與 decrement 指向同一份 Environment Record，所以共用同一個 count。
  • (d) 呼叫兩次 createCounter()：counterA 與 counterB 各有獨立的 Environment Record，counterA.increment() 不會影響 counterB。
  • (e) 只要還有外部變數（例如 counter）引用著內層函式，這份 Environment Record 就不會被 GC（Garbage Collection，垃圾回收）清掉。
  • (f) 在 React Effect 的脈絡下被問到「context 主要記住的是函式，還是內部函式引用的變數」：答案是 記住的是內部函式所引用的外部變數（閉包捕捉的環境資料），不是函式本身。
  • (g) 不需要 HTML 也能驗證：用 Node.js 直接執行 node 檔名.js，加 console.log 即可；要「觸發」必須加小括號呼叫，counter.increment 只是取得函式物件，不會執行。
function createCounter() {
  let count = 0;                       // 住在 Heap 的 Environment Record
  return {
    increment() { return ++count; },
    decrement() { return --count; },
  };
}
const counterA = createCounter();
const counterB = createCounter();
console.log(counterA.increment()); // 1
console.log(counterA.increment()); // 2
console.log(counterB.increment()); // 1（與 counterA 隔離）
情境 Environment Record 數量 count 是否共用
呼叫一次 createCounter() 1 共用
呼叫兩次 createCounter() 2 各自獨立
