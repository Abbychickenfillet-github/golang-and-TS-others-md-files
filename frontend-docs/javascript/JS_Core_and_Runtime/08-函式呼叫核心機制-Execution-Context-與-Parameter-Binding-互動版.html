2. 只要是小括弧都是引數表達式嗎？——看對照表

() 出現的地方例子屬於哪個文法產生式裡面是引數表達式嗎？
呼叫式foo(a, b)CallExpression → MemberExpression Arguments✅ 是
函式定義的參數列表function foo(x, y) {}FormalParameters（見上方第 1 節文法樹）❌ 不是，是參數宣告
純分組（提升優先權）(1 + 2) * 3Grouping Operator❌ 不是，只是分組
控制流程關鍵字語法if (x)、while (x)、for (...)各自語句自己的產生式❌ 不是
IIFE 雙層括號(function(){})()外層 Grouping／內層 Arguments外層 ❌／內層 ✅
箭頭函式的參數列(a, b) => a + bArrowParameters（先被掩護文法收下，看到 => 才重讀）❌ 不是，是參數宣告
💡 一句話

只有緊跟在「被呼叫的東西」後面、屬於 CallExpression／Arguments 這個文法節點的括號，裡面才是引數表達式——判斷方式是看括號屬於哪個文法產生式，不是看有沒有括號。

3. 宣告的文法產生式：Initializer 為什麼有時可選、有時必要（2026-09-29 新增）

3-1 三條產生式擺在一起看

// var 走這條
VariableDeclaration :
    BindingIdentifier Initializer(opt)       ← 可選
    BindingPattern Initializer                ← 沒有 opt，必要

// let 與 const 共用這條
LexicalBinding :
    BindingIdentifier Initializer(opt)       ← 可選（但 const 另有早期錯誤規則）
    BindingPattern Initializer                ← 沒有 opt，必要

先把三個名詞的位置對上：

BindingIdentifier單一名稱綁定 foo、array1、使用者名稱
就是一個普通的變數名。
BindingPattern解構模式 { a, b }、[ x, y ]
從一個物件或陣列裡拆出值來的寫法。
Initializer初始值 = 右邊那一整段
(opt) 是 optional 的縮寫，代表文法允許整段不寫。

3-2 為什麼 BindingPattern 後面的 Initializer 沒有 (opt)

一句話

解構的語意就是「從某個東西裡面拆出值」，沒有那個「某個東西」，就沒有東西可以拆。
let { a } 這句話在語意上根本不成立——你要從哪裡把 a 拆出來？所以文法直接不給你這個選項。

實測（Node v22.22.2，2026-09-29）——注意三個關鍵字全部被擋：

寫法結果
var { a }SyntaxError: Missing initializer in destructuring declaration
let { a }同上
let [ a ]同上
const { a }同上
let { a } = { a: 1 }✅ 合法，a 是 1
⚠️ 這裡有兩種不同層級的「擋」，錯誤訊息也不一樣
const foolet { a }
被哪一層擋下早期錯誤 Early Error 規則文法產生式本身沒有 (opt)
擋哪些關鍵字只擋 const，var foo／let foo 都合法三個全擋，連 var 都不行
錯誤訊息Missing initializer in const declarationMissing initializer in destructuring declaration

看錯誤訊息的後半段就知道自己撞到哪一層：const declaration ＝ 撞到早期錯誤規則，destructuring declaration ＝ 撞到文法產生式。

3-3 為什麼對 var／let 而言，沒有 Initializer 是完全合法的

關鍵在於：「沒有 Initializer」不等於「沒有值」，而是「值用預設的 undefined」。

寫法引擎實際做了什麼結果
var fooCreation Phase 執行 InitializeBinding(foo, undefined)✅ 合法，值是 undefined
let foo執行到那一行時執行 InitializeBinding(foo, undefined)，TDZ 在那一刻結束✅ 合法，值是 undefined
const foo—❌ SyntaxError: Missing initializer in const declaration

三個必須支援「不寫 Initializer」的場景：

// a. 先宣告、後依條件賦值
let 結果                       ← 沒有 Initializer，完全合法
if (條件) 結果 = 'A'
else      結果 = 'B'

// b. for...in ／ for...of 的位置根本沒有 =
for (const 鍵 of Object.keys(物件)) { }

// c. 函式參數、catch (e) 的參數也是 BindingIdentifier，同樣不帶 Initializer
那 const 為什麼不行

如果允許 const foo，會造出一個永遠是 undefined、而且永遠不能改的綁定——它完全沒有任何用途，寫出來一定是打錯字。

所以規範用一條早期錯誤規則直接禁止：如果 Initializer 不存在，而且這個 LexicalDeclaration 是常數宣告，就是 Syntax Error。
文法允許省略，是 const 自己額外加了一條規則把它擋掉的。

3-4 回頭看 2026-09-18 那個 const array 1

同一個打字錯誤（識別碼中間多一個空白），三個關鍵字給你兩種完全不同的訊息：

寫法錯誤訊息
const array 1 = [1]SyntaxError: Missing initializer in const declaration
var array 1 = [1]SyntaxError: Expected a semicolon
let array 1 = [1]SyntaxError: Expected a semicolon

原因：parser 把 const array 讀成一個完整的 LexicalBinding——BindingIdentifier 是 array，沒有 Initializer。

  • 對 const：那條早期錯誤規則立刻觸發，所以抱怨「少了初始值」。
  • 對 var／let：沒有 Initializer 是完全合法的，所以 parser 認為宣告到此結束，接著開始抱怨後面那個 1 前面應該要有分號。
💡 一句話

錯誤訊息長什麼樣，取決於 parser 在哪一條產生式上卡住，不是取決於你以為自己犯了什麼錯。

4. lexical 這個字在 JS 裡有三個意思（2026-09-29 新增）

⚠️ 先破除一個誤解

LexicalBinding 跟箭頭函式完全無關。
它就是 let／const 宣告裡「一個名字 ＋ 它的初始值」那一格而已。

const foo = () => {}
      └─────────┘  ← 這一整格是 LexicalBinding
                     箭頭函式只是它 Initializer 的「值」

const foo = 1
      └───────┘   ← 這也一樣是 LexicalBinding，跟上面同一條產生式

問題出在 lexical 這個字在 JavaScript 裡被用在三個互不相干的地方：

① Lexical Scope 詞法作用域 作用域規則 一個名字指的是誰，由它寫在原始碼的哪一層決定，跟被誰呼叫無關。
同義詞：靜態作用域 Static Scope。
② LexicalDeclaration／LexicalBinding 文法產生式名稱 就是 let 與 const 宣告。
跟箭頭函式毫無關係，const x = 1 也走這條。
③ [[ThisMode]] = lexical 函式物件的內部欄位 這個才是箭頭函式。代表它沒有自己的 this 與 arguments，沿用外層。

為什麼 let／const 的產生式叫「Lexical」

因為它們是區塊作用域的——作用域邊界由程式碼寫在哪一對 {} 裡面決定，這是一種「看位置」的性質，也就是詞法的（lexical）。

反過來 var 不受 {} 限制（只認函式邊界），所以它的產生式就叫 VariableDeclaration，名字裡沒有 Lexical 這個字——這個命名差異本身就是線索。

產生式名稱對應關鍵字作用域邊界名字裡有 Lexical 嗎
VariableStatement / VariableDeclarationvar函式作用域❌ 沒有
LexicalDeclaration / LexicalBindinglet、const區塊作用域✅ 有
💡 一句話

看到 lexical 先問「這句話在講作用域、講宣告關鍵字、還是講 this」——三個答案完全不同，別把它們串在一起。
