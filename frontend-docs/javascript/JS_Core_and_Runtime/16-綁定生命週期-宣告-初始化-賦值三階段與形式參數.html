綁定生命週期——宣告、初始化、賦值三階段，與形式參數落在哪一階段

本篇重點 a–n，共 14 個。 這篇補的是 08-函式呼叫核心機制-Execution-Context-與-Parameter-Binding 沒有明講的一個細節：「配置記憶體」到底算不算「初始化」。答案是不算，而這一個字的差別，正是 TDZ 存在的原因。

起手式：Execution Context 包含哪些階段

(a) 一個完整的 Execution Context（執行上下文）包含兩個階段：先是 Creation Phase（建立階段）做環境設置，接著才是 Execution Phase（執行階段）逐行跑程式碼。

(b) 常見誤解：以為「Execution Context = Creation Phase」，或以為 Execution Phase 是另一個獨立的東西。兩者合起來才是一個完整的執行環境。

(c) 形式參數（Formal Parameter，函式定義時寫在括號裡的那些名字）是在 Creation Phase 被處理的，也就是在函式內部的程式碼真正開始跑之前。

(d) 引數（Argument）綁定到哪裡？綁定到執行上下文的環境紀錄（Environment Record），函式執行時就是從這裡查值。

核心：三階段，不是兩階段

(e) 很多教材只講「宣告」跟「賦值」兩件事，這會解釋不了 TDZ。實際上規格層面可以拆成三個動作：

階段 引擎做什麼 這時候能讀嗎
1. 宣告／建立（Declaration） 在 Environment Record 中建立名稱（Binding），配置記憶體空間 不能，記憶體位置預留了但還沒有值
2. 初始化（Initialization） 第一次把具體的值綁上去（undefined 或傳入的引數值） 可以，完成後才能合法讀取
3. 賦值（Assignment） 執行到賦值陳述式時，把值改寫成新的 可以

(f) 關鍵觀念：配置記憶體 ≠ 初始化。配置記憶體屬於第 1 階段，只是「預留了一個位置」；初始化是第 2 階段，是「第一次把值放進去」。這是 Abby 在對話中直接追問到的點，也是最容易被含糊帶過的地方。

那為什麼 var 好像沒有這個問題？

(g) 因為對 var 和形式參數來說，引擎把「初始化」的時間點提前到 Creation Phase 一起做掉了：

  • var：Creation Phase 配置記憶體，並順便初始化為 undefined。
  • 形式參數：Creation Phase 配置記憶體，並順便初始化為傳入的引數值（沒傳就是 undefined）。

(h) 所以不是「配置記憶體這個動作叫做初始化」，而是「這兩種綁定的初始化時機剛好被提前了」。這兩句話聽起來像同一件事，但只有後者能解釋 let 為什麼不一樣。

(i) let 與 const：Creation Phase 只做第 1 階段（建立 Binding），不做初始化。所以從函式／區塊開始，到執行到那一行為止，這個名字處於 TDZ（Temporal Dead Zone，暫時性死區），這段期間存取會丟 ReferenceError。

(j) let x = 1 執行到那一行時，才同時完成第 2 階段（初始化）與第 3 階段（賦值）。

規格上的名字：FunctionDeclarationInstantiation

(k) 依照 ECMAScript 規格，參數綁定與變數提升（Hoisting）是在同一個內部作業裡完成的，這個作業叫做 FunctionDeclarationInstantiation。它在 Creation Phase 執行，工作內容包含：

  1. 建立環境紀錄（Environment Record）
  2. 綁定形式參數並初始化為引數值
  3. 處理函式內部的 var 宣告（初始化為 undefined）
  4. 建立 let / const 的綁定但不初始化

(l) 記憶法：同一個作業裡，var 與參數走「建立＋初始化」兩步到位；let / const 只走「建立」一步，剩下那一步留給 Execution Phase。TDZ 就是那一步之間的空隙。

一分鐘總結表

綁定種類 Creation Phase Execution Phase 提前存取的結果
形式參數 建立 + 初始化為引數值 可再賦值 拿得到值
var 建立 + 初始化為 undefined 執行到那行才賦值 undefined
let / const 只建立，不初始化 執行到那行才初始化＋賦值 ReferenceError（TDZ）
函式宣告 建立 + 初始化為完整函式物件 — 拿得到完整函式

(m) 面試講法：「Hoisting 不是把程式碼搬到上面，而是 Creation Phase 在環境紀錄裡先建立綁定。差別在初始化時機——var 與參數在建立當下就初始化了，let / const 沒有，所以有 TDZ。看到 undefined 代表初始化過了只是還沒賦值；看到 ReferenceError 代表連初始化都還沒發生。」

(n) 這也解釋了 15-ReferenceError-vs-undefined-值與錯誤的分界 那一篇的分界線：undefined 是一個「值」，ReferenceError 是一個「狀態不合法」的錯誤，兩者的差別就落在第 2 階段做了沒有。

使用者： Formal parameter 它會跟 host 的什麼階段在一起？還是它其實是 initialize 階段呢？

Gemini： Formal parameters are typically processed when the function's execution context is created right before the code inside runs. That's when memory is allocated for them and their values are initialized.

使用者： Execution context 是 creation phase 而已，還是 creation phase 包含 execution phase 合起來叫做一個 execution context？

Gemini： 一個完整的 Execution Context 其實包含了這兩個階段。首先是進行環境設置的 Creation Phase，接著才是逐行執行程式碼的 Execution Phase，兩者合起來才算是一個完整的執行環境。

使用者： 那 bindings parameters 到底是引數繫結到哪裡？繫結到環境嗎？

Gemini： 沒錯，引數確實是綁定在執行上下文的環境紀錄中，讓函式在執行時能夠存取對應的值。

使用者： 那依照 ECMAScript，他是跟變數提升的那一個階段一起？

Gemini： 依照 ECMAScript 規格，參數繫結（Parameter Binding）確實是跟變數提升（Variable Hoisting）在同一個階段處理的。在 JavaScript 引擎建立執行上下文的 Creation Phase 中，會執行一個叫做 FunctionDeclarationInstantiation 的內部作業：建立環境紀錄（Environment Record）⋯⋯ - var 變數與函式參數：在 Creation Phase 就會被分配記憶體，並自動初始化為 undefined（如果是有傳入值的參數，則直接初始化為傳入的值）。 - let 與 const 變數：在 Creation Phase 雖然會被宣告（Hoisting），但不會進行初始化，因此會進入所謂的暫時性死區（TDZ, Temporal Dead Zone）。

使用者： 請問有分配記憶體的話，就算 initialized phase？

Gemini： 不算。配置記憶體（Memory Allocation）屬於建立階段（Creation Phase / Declaration），並不等於初始化（Initialization）。在 JavaScript 規格中，變數與綁定的生命週期可以明確分為三個階段： 1. 宣告／建立階段：引擎在 Environment Record 中創建變數名稱（Binding），並配置記憶體空間。此時記憶體位置已經被預留，但變數本身尚未被初始化。 2. 初始化階段：引擎第一次將具體的值（例如 undefined 或實際傳入的引數）綁定到該記憶體位置上。完成初始化後，該變數才可以在程式碼中被合法讀取。 3. 賦值階段⋯⋯

JavaScript 引擎在 Creation Phase 時，順便幫你連同初始化一起做掉了：var 在 Creation Phase 時分配記憶體並順便初始化為 undefined；Formal Parameter 在 Creation Phase 時分配記憶體並順便初始化為傳入的引數值。這只是因為它們的初始化時間點被提前到了 Creation Phase，並不是因為配置記憶體這個動作本身叫做初始化。
