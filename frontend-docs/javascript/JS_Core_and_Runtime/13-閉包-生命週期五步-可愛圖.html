🔄 一個閉包的生命週期五步

以 createCounter 的 count 為例：從 V8 決定它放哪裡，到最後被 GC 回收

①決策

Parse
Scope Analysis 看出 count 會被內層函式捕獲，決定放 Heap 的 Context
只做一次
➡️

②誕生

create
執行到函式定義：生出函式物件，並在 Heap 建好 Context，函式的 context 欄位指向它，＝ 閉包誕生
執行幾次生幾份
➡️

③外層退場

caller pop
外層函式 return，它的 Stack Frame 被 pop 掉
Context 不受影響
➡️

④被持有

retained
被監聽器、計時器或變數抓著，閉包一直活著
跟有沒有在跑無關
➡️

⑤斷線 ➜ 回收

unreachable
移除監聽器、元件卸載或設成 null 之後，沒有人指著它，GC 才回收
可達性說了算
★ 第 ④ 格就是本篇「執行時間 ≠ 存活時間」在講的事：使用者晾在那十分鐘不動，debounce 裡的 timer 依然活著，因為事件監聽器還抓著它。
