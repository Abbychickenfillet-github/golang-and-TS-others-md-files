TDZ、var-let-const 提升與初始化 vs 實例化

geminijavascripthoistingTDZscope更新 2026-11-03

JS 引擎執行腳本前，會先做「作用域實例化」（為每個宣告建立 binding），再決定要不要「初始化」（賦予初值）。TDZ、提升與 foo is not a function 這類錯誤都能用這兩步驟一次講完。相關：[[函式呼叫核心機制-Execution-Context-與-Parameter-Binding]]（同樣談 Execution Context 與 binding）。

重點整理

本篇重點 a–i，共 9 個　 （點一下重點可隱藏／顯示，自己考自己）

(a)實例化（Instantiation）：引擎在記憶體中為每個宣告建立 binding（決定屬於哪個作用域並配置位置）。初始化（Initialization）：替這個 binding 賦予初始值。實例化先發生，初始化後發生。比喻：實例化是蓋好毛胚屋，初始化是裝潢入住。
(b)ECMAScript 規格中全域腳本的這一步叫 GlobalDeclarationInstantiation，函式內則是 FunctionDeclarationInstantiation，兩者都在「執行第一行程式碼之前」完成。
(c)三種宣告的差別（核心表）：
var：binding 建立在函式作用域或全域作用域，並立刻初始化為 undefined，所以宣告前讀取得到 undefined。
let／const：binding 同樣被建立（所以也算有提升），但不初始化，直到執行到宣告那一行才初始化。
函式宣告：binding 建立並直接初始化為函式物件本身，所以宣告前就能呼叫。
(d)TDZ（Temporal Dead Zone，暫時性死區）就是「let／const 已實例化但尚未初始化」的那段時間，期間讀寫該變數會丟 ReferenceError。
(e)函式表達式的錯誤類型：var foo = function(){} 在宣告前呼叫，foo 是 undefined，所以報 TypeError: foo is not a function。const／let foo = ... 在宣告前呼叫，因為處於 TDZ，報 ReferenceError。
(f)var 的「提升到頂端」是一種直覺說法，實際上是函式（或全域）作用域在實例化階段（Creation Phase）就把 binding 放進 Environment Record 並設為 undefined，程式碼位置並沒有被搬動。
(g)一般函式宣告會被完整提升，但 this 不是變數，它的值由「函式如何被呼叫」決定，不會被提升。
(h)<script> 放 <body> 最底部的原因與 TDZ、實例化無關：是為了避免 JS 下載與執行阻塞 HTML 渲染，並確保執行時 DOM 已經載入。（現代做法也可在 <head> 用 defer。）
(i)物件導向語境的同一組詞：new User() 是實例化（配置出物件），constructor 裡的 this.name = name 是初始化（賦予初始狀態）。
⚠️ 存疑/更正：Gemini 在第一則回答用「跟 global instantiation 有關係」帶過 script 位置的問題，後續自己更正為「無關」，以後者為準。

自我測驗

console.log(a); var a = 1; 會印出什麼？為什麼？
印出 undefined。var 在實例化階段就被初始化為 undefined。
console.log(b); let b = 1; 會發生什麼？
ReferenceError，因為 b 在 TDZ，已實例化但未初始化。
是非題：let 不會被提升。
錯。let 有被提升（binding 已建立），只是沒有初始化，才會有 TDZ。
申論：說明實例化與初始化的差異並各舉一個 JS 例子。
實例化＝建立 binding 或物件實體（new User()、作用域建立變數 binding）。初始化＝給初值（var 設 undefined、constructor 賦值）。let 就是只實例化、尚未初始化的例子。
