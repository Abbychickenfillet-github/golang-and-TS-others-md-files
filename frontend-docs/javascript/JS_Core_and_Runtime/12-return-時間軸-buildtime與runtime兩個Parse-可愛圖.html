⑤呼叫與 return

① 呼叫：V8 push 一個 Stack Frame
② 若有變數被捕獲：同時在 Heap 建 Context 物件
③ 執行函式本體
④ return：V8 pop 整片 Frame，Heap 不動
⑤ Context 沒人指了 ➜ GC 不定時回收
🔁 再呼叫一次，整包重來
🔵 buildtime 的 Parse
Babel、bundler 的 parser 做的。目的是改寫或打包程式碼，跟「變數住哪」無關
⭐ 決策與執行隔很遠
「該不該逃到 Heap」在第 ③ 格決定，「真的配置與清除」在第 ⑤ 格。兩者常被壓縮成同一件事來想，這就是誤會的來源
🟢 次數怎麼算
③④ 每個函式只做一次。⑤ 呼叫幾次就重來幾次：V8 push 與 pop 的次數相同，順序相反（LIFO）
