執行緒 vs 非同步 vs 延遲（含執行緒／線程術語釐清與四象限）

🔖 本篇重點索引：a–q，共 17 個。

重點整理

三者都跟「時間、等待」有關，但本質完全不同。用飲料店比喻最好懂。

一、執行緒 Thread —「做事的人」

(a) 執行緒（Thread，執行緒／線程）定義：作業系統能進行運算排程的最小單位，就是「實際動手做事的員工」。

(b) 單執行緒：只有一個員工，做完一杯才能接下一單；遇到要現榨很久的果汁，整條人龍就卡住。這是 JavaScript 的本質。

(c) 多執行緒：請了四五個員工分工，某人卡住其他人仍能服務別的客人。

二、非同步 Asynchronous —「做事的方法（切換任務）」

(d) 非同步定義：一種程式設計架構模式，任務執行順序不必死板地等前一件完全做完。

(e) 同步（Synchronous）：員工點完餐死站在廚房等茶煮好，不收錢不接單，整店「卡死（Blocking，阻塞）」。生活案例——去櫃檯排隊點餐，點完站在櫃檯等餐點做好才離開。

(f) 非同步（Asynchronous）：把茶葉丟進熱水（發出請求）後不等它好，立刻轉身服務下一位；計時器逼逼叫（完成通知）才回來把茶倒出。生活案例——去美食街點餐，拿了震動取餐牌就回座位滑手機，震動了再去拿餐。

📝 核心

JavaScript 雖然只有「一個員工（單執行緒）」，但它是時間管理大師，靠「非同步」在等待空檔塞別的事做，所以網頁才不會動不動卡死。

三、延遲 Latency / Delay —「等待的時間」

(g) 延遲定義：不是人也不是方法，而是一個物理指標——從發出指令到看到結果中間消耗的時間差。飲料店：點完餐到拿到飲料隔了 10 分鐘，這 10 分鐘就是延遲。

(h) 程式中的兩種延遲：

  • 網路延遲（Network Latency）：fetch 請求到 API 伺服器、資料傳回花了 200ms。
  • 人為延遲（Delay）：你刻意寫 setTimeout(() => {}, 3000) 製造的等待。

(i) 一句話總結：執行緒是「誰做」、非同步是「怎麼做」、延遲是「等多久」。

四、「執行緒」跟「線程」是不同東西嗎

(j) 答案：完全同一個東西，差別只在翻譯地區。英文原文都是 Thread；台灣慣用「執行緒」，中國大陸慣用「線程」。不是兩種技術，也沒有細微差別。

(k) 常見術語兩岸對照表（看技術文件與影片時很常兩套並用）：

英文原文 台灣（繁體） 大陸（簡體）
Process 程序／行程 进程
Thread 執行緒 线程
Multi-threading 多執行緒 多线程
Context Switch 內文切換／上下文切換 上下文切换
Coroutine 協程／協同程序 协程

(l) ⚠️ 台灣用語的地雷：Process 在台灣同時被翻成「程序」與「行程」，但「程序」這個詞在中文裡也常指 program／procedure（程式、程序步驟），非常容易誤讀。建議一律寫「行程（Process）」或直接寫英文，把「程序」留給別的意思。

(m) 工廠比喻—行程與執行緒的關係：

  • 行程（Process）＝一間工廠：擁有獨立的資源（空間、電力、原料），也就是獨立的記憶體位址空間。
  • 執行緒（Thread）＝工廠裡的工人：一間工廠可以有多個工人（多執行緒），所有工人共享工廠內的資源（記憶體空間）。
  • 工人之間可以協同工作，但也可能同時搶同一個工具而衝突——這就是死鎖（Deadlock）與競爭條件（Race Condition）的由來。

(n) 執行緒的兩個關鍵特性：資源共享（同一行程內的執行緒共享記憶體）與輕量化（建立與切換執行緒的成本比行程低很多，因為不必重建整套位址空間）。

(o) 搜尋小技巧：在台灣開發環境建議習慣寫「執行緒」，但用 Google 查技術問題時，搜「線程」往往能撈到更多簡體中文的技術討論資源。

五、同步／非同步 與 執行緒 是不同維度

(p) 兩者分屬完全不同的維度，不要混談：

概念 屬於哪一層 回答什麼問題
執行緒（Thread） 硬體／作業系統層面 「有幾個 CPU 通道在運算？」——是誰在做
同步／非同步（Sync／Async） 程式流程控制層面 「任務發出後，呼叫者要不要阻塞等待？」——怎麼等

(q) 四象限—破除「非同步就是開多執行緒」的誤解：

組合 實際狀況
同步 ＋ 單執行緒 最基礎模式，程式碼一行一行執行，卡住就全卡住（例如 JS 沒處理好耗時工作時）
同步 ＋ 多執行緒 開另一個工人去做，但主執行緒依然停下來等那個工人做完
非同步 ＋ 單執行緒 最容易搞混的一格。例如 JavaScript——只有一個執行緒，卻透過事件循環（Event Loop）達成非同步：先去做別的小任務，等 I/O 好了再回來
非同步 ＋ 多執行緒 最強大的組合，開另一個工人去做，主執行緒繼續忙自己的，互不干擾
⚠️ 一句話記住

非同步不代表一定要開新執行緒。廚房比喻——你把水燒開後去旁邊切菜，等水壺鳴笛再回來；你只有一個人（單執行緒），照樣可以非同步。

⚠️ 存疑／補充

  • Gemini 在第一回合把 Process 譯為「程序」，但同一份對話的對照表又並列「程序／行程」。台灣技術圈實務上「行程」較不易誤讀，本篇重點 (l) 已補上這個提醒。
  • Gemini 說「多執行緒可以同時處理多件事（平行處理）」——嚴格來說要在多核心 CPU 上才是真正的平行（Parallelism）；單核心上的多執行緒只是快速切換造成的並行（Concurrency）錯覺。這個區分在面試時常被追問，值得記住。
