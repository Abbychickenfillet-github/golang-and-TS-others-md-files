Promise 是物件、NaN 屬於 Number、以及 JS 編譯階段做了哪三件事

本篇重點 a–n，共 14 個。三個看似無關的小問題，其實都指向同一件事：「你以為的型別」跟「引擎眼中的型別」常常不一樣。

重點整理

一、Promise 本身永遠是一個物件

(a) Promise 是一個建構函式（Constructor），而建構函式在 JavaScript 裡本身就是函式物件。用 new Promise(...) 會實例化並回傳一個 Promise 物件實例。

const p = new Promise((resolve, reject) => {
  resolve('完成')
})

console.log(typeof p)            // "object"
console.log(p instanceof Promise) // true

(b) 逐行解釋 (a) 這段：
- new Promise(...) — new 這個運算子做四件事：建立一個空物件、把它的原型指向 Promise.prototype、把 this 綁到這個新物件上執行建構函式、最後回傳這個物件。
- (resolve, reject) => {...} — 這個叫 executor（執行器），它會被同步、立刻執行（不是等到 .then 才跑），resolve 與 reject 是 JS 引擎傳給你的兩個內建函式。
- typeof p — typeof 對所有非函式的物件都回傳 "object"，所以這裡是 "object"。
- p instanceof Promise — instanceof 是沿著 p 的原型鏈（Prototype Chain）往上找，看有沒有一個環節等於 Promise.prototype，有就是 true。

(c) 要分清楚兩件事：Promise「這個容器」永遠是物件，Promise「解開之後的結果」是什麼型別完全取決於你在 resolve() 裡傳了什麼。

const a = Promise.resolve({ id: 1 })
const b = Promise.resolve('hello')

await a   // { id: 1 }  → 物件
await b   // 'hello'    → 原始值（string）

(d) 次要備註：這也是為什麼 async function 一定回傳 Promise ——即使你 return 1，引擎也會幫你包成 Promise.resolve(1)；await 做的事就是把這層容器拆掉，把裡面的值交給你。

二、NaN 屬於 Number，不是 undefined

(e) NaN（Not a Number）在 JavaScript 的型別系統中屬於 Number，名字非常會誤導人。

console.log(typeof NaN)   // "number"

(f) 為什麼叫「不是數字」卻是數字型別？因為 NaN 是 IEEE 754 浮點數標準裡定義的一個特殊數值（Special Value）。當數學運算算不出有意義的結果（例如 0 / 0、'abc' * 2、Math.sqrt(-1)），JavaScript 不會拋錯，而是回傳 NaN 表示「這是一個無效的數值結果」。它佔的是 Number 型別裡的一組特殊位元樣式，所以型別當然還是 Number。

(g) 跟 undefined 的分界：

值 意思 typeof
undefined 變數尚未被賦值，或屬性不存在 "undefined"
NaN 變數有值、且是數值型別，但這個數值內容無效 "number"

(h) NaN 是 JavaScript 中唯一不等於自己的值：NaN === NaN 是 false。所以不能用 === 去判斷。

(i) 正確的檢查方式是 Number.isNaN()：

Number.isNaN(NaN)       // true
Number.isNaN('hello')   // false ← 正確：'hello' 本來就不是 number
isNaN('hello')          // true  ← 陷阱：全域舊版 isNaN 會先做型別轉換

全域的 isNaN()（沒有 Number. 前綴的那個舊 API）會先把參數 ToNumber 轉型再判斷，所以 isNaN('hello') 會是 true，這幾乎一定不是你要的。ES2015 之後請一律用 Number.isNaN()，它不做任何轉型。

三、JS 在編譯階段做了哪三件事

(j) JavaScript 雖然常被叫「腳本語言」，但執行前一樣會經過編譯階段（Compilation Phase）。V8 這類引擎在這個階段做三件事：語法解析、作用域建立與記憶體配置、生成位元組碼。

(k) ① 語法解析（Parsing）

  • 詞法分析（Lexical Analysis／Tokenization）：把原始碼字串拆成最小單位的 Token。let x = 10; 會被拆成 let、x、=、10、;。
  • 語法分析（Syntactic Analysis）：把 Token 組成 AST（Abstract Syntax Tree，抽象語法樹）。
  • 語法有誤在這一步就會拋 SyntaxError，而且整份程式碼一行都不會執行——這就是為什麼少打一個括號會讓整個檔案完全不動，而不是「跑到那一行才壞掉」。

(l) ② 作用域建立與提升（Scope & Hoisting）——這是編譯階段最核心的操作。引擎掃描所有變數與函式宣告，建立 作用域鏈（Scope Chain）：

宣告方式 編譯階段做的事 結果
function foo() {} 在記憶體中建立函式物件，並把名稱直接綁到該物件 可以在宣告前呼叫
var a 註冊變數名，預設賦值 undefined 宣告前存取得到 undefined
let / const 註冊變數名，但不初始化，劃入 TDZ（Temporal Dead Zone，暫時性死區） 宣告前存取拋 ReferenceError

關鍵補充：編譯階段完全不執行任何賦值。var x = 10 裡的 = 10 是留到執行階段才做的，所謂「提升」提升的只有「宣告」這件事。

(m) ③ 生成位元組碼（Bytecode Generation）

  • V8 的解譯器 Ignition 把 AST 轉成中介語言 Bytecode（位元組碼）。
  • 同時為 JIT（Just-In-Time Compilation，即時編譯）做準備：執行階段若某段程式碼變成熱點（Hot Code，被反覆執行），最佳化編譯器 TurboFan 會把它進一步編成高效能的機器碼（Machine Code）。

(n) 編譯階段與執行階段的分工：

階段 主要任務 處理的東西
編譯階段 語法檢查、建立作用域、配置記憶體位置（提升）、生成位元組碼 var a;／function foo() {}／攔截語法錯誤
執行階段 依序執行、變數賦值、函式呼叫、JIT 最佳化 a = 1;／foo()／計算與邏輯運算
