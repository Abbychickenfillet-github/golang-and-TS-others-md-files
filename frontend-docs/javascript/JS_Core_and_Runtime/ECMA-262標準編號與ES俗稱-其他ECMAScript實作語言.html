ECMA-262 標準編號與 ES 俗稱 — 為何規格書不寫「我是 ES 幾」

本篇重點 a–i，共 9 個

重點整理

a. ECMA-262 是一組「標準編號」而不是版本名稱。ECMA（European Computer Manufacturers Association，歐洲電腦製造商協會）用流水編號來區分它管轄的各種技術標準，例如 ECMA-402 是國際化 API（Internationalization API）標準，而 ECMA-262 專門用來記載 ECMAScript 這個語言的規格。

b. ECMAScript 是 ECMA-262 規格書裡面所定義的那個「標準語言」本身，它只規範語法、型別、內建物件與抽象操作。

c. JavaScript 則是「基於 ECMAScript 標準所做出來的實作與延伸」。瀏覽器裡的 JavaScript 除了實作 ECMAScript 核心語法之外，還多了 DOM（Document Object Model，文件物件模型）與 BOM（Browser Object Model，瀏覽器物件模型）這些規格書裡根本沒有的 API。

d. 三者的正確關係鏈：ECMA-262（規格書編號）→ 內容定義了 ECMAScript（標準語言）→ JavaScript（實作 ECMAScript 並加上宿主環境 API 的語言）。Abby 原本說「ECMA-262 就是 JavaScript 語言」大體正確但不夠精準，差在中間漏掉了 ECMAScript 這一層。

e. 規格書裡找不到「ES6」這種字眼是正常的，不要以為自己讀錯版本。官方在封面與內文用的量詞是 Edition（第幾版），例如俗稱的 ES5，正式名稱是 ECMA-262 5th Edition。

f. 2015 年起 TC39（Technical Committee 39，ECMA 底下負責 ECMAScript 的第 39 號技術委員會）把發布模式改成「每年定期發布」，官方名稱也改成按年份命名，例如 ECMAScript 2015、ECMAScript 2026。因此「ES＋數字」從此退化成開發者之間口語溝通用的俗稱，而不是標準文件上的正式標題。

g. ES6 就是 ECMAScript 2015，這是同一份文件的兩種叫法，前者是社群俗稱、後者是官方年份名稱。

h. 除了 JavaScript 之外，歷史上還有其他語言是照 ECMAScript 規格實作出來的：
- ActionScript：Adobe（前身 Macromedia）開發，Flash 的核心語言，ActionScript 3.0 大量參考了當時還在草擬中的 ES4。
- JScript / JScript .NET：微軟在 1990 年代為了對抗 Netscape 的 JavaScript 而推出的實作，用在早期 Internet Explorer 與 Windows 腳本環境。
- TypeScript：嚴格說是 JavaScript 的超集（Superset），完整遵循 ECMAScript 語法規格，在編譯階段額外加上型別系統，最後仍轉譯回標準 ECMAScript。
- Qt Script：嵌入式 C++ 框架 Qt 曾提供的腳本語言，直接實作 ECMA-262（ES3 / ES5），讓 C++ 應用具備腳本擴充能力。

i. 現況備註：ActionScript 與 JScript 已隨 Flash 和舊版 IE 淘汰而退場，目前實務上幾乎只剩 JavaScript 與 TypeScript 在實作這份規格。
