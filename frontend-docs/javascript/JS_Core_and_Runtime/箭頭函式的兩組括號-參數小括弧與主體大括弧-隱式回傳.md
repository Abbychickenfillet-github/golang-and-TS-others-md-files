# 箭頭函式的兩組括號

> 本篇重點 a–l，共 12 個。
> 起因：`array1.find((e, i) => e < 2)` —— **參數用小括弧包著，執行區卻沒有大括弧**，為什麼？

一句話：**這是兩組完全獨立的括號，各有各的規則，不要混在一起想。**

```
(e, i)  =>  e < 2
└─ ①  ─┘    └─ ② ─┘
 參數的小括弧    主體：沒有大括弧
```

---

## 1. 第一組：參數的小括弧 `()`

| 參數個數 | 小括弧 | 範例 |
|---|---|---|
| **0 個** | **必須寫** | `() => 42` |
| **1 個** | **可以省略** | `e => e * 2`　或　`(e) => e * 2` |
| **2 個以上** | **必須寫** | `(e, i) => e < 2` |

- (a) 所以你那行寫 `(e, i)` 是**因為有兩個參數，不得不寫**，不是什麼特殊語法。如果只收 element，可以寫成 `e => e < 2`。
- (b) ⚠️ **單一參數但下列情況仍必須加小括弧**：
  1. 有預設值：`(e = 0) => e`
  2. 用 rest：`(...args) => args`
  3. 解構：`({ id }) => id`、`([a, b]) => a`
  4. 有 TypeScript 型別註記：`(e: number) => e`
- (c) `async` 可以直接放前面，不影響省略規則：`async e => await f(e)` 合法。

---

## 2. 第二組：主體的大括弧 `{}` —— 這才是你問題的核心

**箭頭函式的主體有兩種形態，差別在「要不要自己寫 return」。**

| 形態 | 寫法 | 正式名稱 | 回傳行為 |
|---|---|---|---|
| **沒有大括弧** | `e => e < 2` | **concise body（簡潔主體）**／expression body | **自動回傳**該表達式的值 ← implicit return（隱式回傳） |
| **有大括弧** | `e => { return e < 2; }` | **block body（區塊主體）** | **必須自己寫 `return`**，沒寫就回 `undefined` |

- (d) ★ 所以 `(e, i) => e < 2` **完全等同於** `(e, i) => { return e < 2; }`。
  `e < 2` 是一個**比較表達式**，它求值後是 `true` 或 `false`，簡潔主體把這個值直接當回傳值。
- (e) 這就是為什麼 `find` 的 callback 可以寫這麼短 —— 它只需要一個 truthy/falsy 的答案，一個表達式就夠了。

```js
// 以下四行行為完全相同
array1.find((e, i) => e < 2);
array1.find((e, i) => { return e < 2; });
array1.find(function (e, i) { return e < 2; });
array1.find(e => e < 2);              // 用不到 index 就別收
```

- (f) ⚠️ **忘記 return 是最常見的 bug**：

```js
const double = n => { n * 2; };    // ❌ 回 undefined，大括弧裡沒有 return
const double = n => n * 2;         // ✅
const double = n => { return n * 2; };  // ✅
```

---

## 3. 為什麼簡潔主體「只能放一個表達式」

- (g) 因為**簡潔主體的位置在語法上只接受 expression（表達式），不接受 statement（陳述式）**。

| | 表達式 Expression | 陳述式 Statement |
|---|---|---|
| 定義 | **會求值出一個值** | **執行一個動作**，本身沒有值 |
| 例子 | `e < 2`、`a + b`、`f()`、`x ? y : z` | `if (...) {}`、`for (...) {}`、`return`、`const a = 1` |
| 能放進簡潔主體嗎 | ✅ 可以 | ❌ 不行，語法錯誤 |

```js
e => if (e > 0) return e;      // ❌ SyntaxError：if 是陳述式
e => e > 0 ? e : 0;            // ✅ 三元運算子是表達式
e => { if (e > 0) return e; return 0; }   // ✅ 要用 if 就得開大括弧
```

- (h) 詳見 [[03-陳述式-Statement-vs-表達式-Expression]] —— 那篇是本節的地基。

---

## 4. 最經典的陷阱：回傳物件字面量

- (i) ★★★ **想回傳一個物件時，簡潔主體會把 `{` 當成 block body 的開頭。**

```js
const make = id => { id: id };       // ❌ 回 undefined
const make = id => ({ id: id });     // ✅ 用小括弧包起來，強迫它被當成表達式
const make = id => { return { id }; }; // ✅ 老實開 block 寫 return
```

為什麼第一行不報錯卻回 `undefined`？因為 `{ id: id }` 被解析成：

```js
{              // ← block 的開頭
  id: id;      // ← id: 被當成「標籤 label」，id 是一個沒用到的表達式陳述式
}              // ← 沒有 return，所以回 undefined
```

**這跟 `{}` 在 JS 裡身分不明是同一個問題** —— 它既可以是 block 也可以是物件字面量，靠**所在位置**決定。

---

## 5. 什麼時候「該」用大括弧（可讀性建議）

- (j) 規則不是「越短越好」，而是**用括號表達意圖**：

| 情境 | 建議 | 理由 |
|---|---|---|
| 只是求一個值 | 簡潔主體 | `e => e < 2` 一眼看完 |
| 超過一行 | 大括弧 | 硬擠成一行反而難讀 |
| **有副作用、不需要回傳值** | **大括弧** | 見下面 (k) |

- (k) ⚠️ **副作用陷阱**：

```js
arr.forEach(e => list.push(e));
//              ↑ 簡潔主體「回傳了」push 的結果（新長度），只是 forEach 不在乎

arr.map(e => list.push(e));
//      ↑ 同樣的寫法換成 map，你會拿到一堆數字 [1,2,3,...] 而不是你以為的東西

arr.forEach(e => { list.push(e); });   // ✅ 加大括弧，明示「我不回傳東西」
```

## 6. 順帶：分號屬於誰

- (l) `const f = e => e * 2;` 最後那個分號**不屬於箭頭函式**，它屬於外層的 `const` **變數宣告陳述式**。
  箭頭函式本身是一個**表達式**，表達式不需要分號。所以當它當作引數傳進去時，裡面不會有分號：

```js
array1.find((e, i) => e < 2);
//                          ↑ 這個分號是 find(...) 這整個「表達式陳述式」的結尾
//                            不是箭頭函式的
```

這也解釋了你手稿上寫的疑問「跟了分號 / 括弧」—— **分號跟著陳述式走，括弧跟著函式語法走，兩者無關。**

---

## 7. 順帶提醒：箭頭函式不只是「短的 function」

它與一般函式還有五個**行為上**的差異（不只是寫法），跟本篇的括號規則無關但常一起考：

1. **沒有自己的 `this`** —— 沿用外層詞法作用域的 `this`（所以 `find` 的 `thisArg` 對箭頭函式無效）
2. **沒有 `arguments`** 物件
3. **不能用 `new`** 呼叫（不是建構函式）
4. **沒有 `prototype`** 屬性
5. **不能當 generator**（不能寫 `function*` 的箭頭版）

詳見 [[JavaScript-函式類型總整理]] 與 `JS_CheatSheet_and_APIs/原生function/JavaScript-call-apply-bind-改變this指向.md`。
