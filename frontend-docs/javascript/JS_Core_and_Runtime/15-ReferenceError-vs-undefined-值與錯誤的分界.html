ReferenceError 與 undefined—「值」與「錯誤」的分界

🔖 本篇重點索引：a–j，共 10 個。

重點整理

(a) 一句話分界：undefined 是一個「值（Value）」，ReferenceError 是一個「錯誤（Error）」。兩者都跟「找不到東西」有關，但層級完全不同——前者程式照跑，後者程式當場中斷。

(b) 白話比喻：

  • undefined＝位子佔了，但位子上沒人。變數已經宣告，只是還沒被賦值。
  • ReferenceError＝你試圖叫一個根本不存在的人。引擎在目前的範疇（Scope，作用域）裡完全找不到這個識別碼的宣告。

(c) undefined 的產生時機：宣告變數卻沒給初始值時，JavaScript 會自動塞一個 undefined 當預設值。

let a;
console.log(a);        // undefined
console.log(typeof a); // "undefined"

(d) 可以主動賦值 undefined，但實務上不建議：語法上 x = undefined 合法，不過表達「這裡刻意是空的」時，慣例會用 null——null 是「開發者主動放的空」，undefined 是「引擎自動給的空」，語意上要分開。

(e) ReferenceError 的產生時機：存取一個完全沒有用 var／let／const 宣告過的識別碼（Identifier，標識符）。

console.log(b); // Uncaught ReferenceError: b is not defined

(f) 核心對比表：

特性 undefined ReferenceError
性質 原始型別（Primitive Type）的一個值 執行期錯誤（Runtime Error）
變數狀態 已宣告，但未初始化 未宣告，或處於暫時性死區（TDZ）
白話 「我知道這東西，但還不知道它是什麼」 「我根本沒聽過這東西」
對程式的影響 程式繼續執行 當場中斷，後面的程式碼不會跑

(g) 陷阱—typeof 會吃掉未宣告變數的錯誤：對一個從未宣告的變數用 typeof，不但不會報錯，還會乖乖回傳字串 "undefined"。這是 JavaScript 為了向後相容保留的特例，除錯時很容易被它蓋掉真正的 ReferenceError。

console.log(typeof notDeclaredVar); // "undefined"（不報錯！）
console.log(notDeclaredVar);        // ReferenceError（這才會炸）

(h) 陷阱的陷阱—TDZ 不吃這一套：typeof 的保護只對「完全未宣告」有效。若變數是用 let／const 宣告、但還在暫時性死區（TDZ，Temporal Dead Zone）裡，typeof 照樣拋 ReferenceError。這點 Gemini 原始回答的對比表寫錯了，見下方「⚠️ 存疑／更正」。

console.log(typeof c); // ❌ ReferenceError: Cannot access 'c' before initialization
let c = 10;

console.log(typeof d); // ✅ "undefined"（d 從頭到尾沒宣告過）

(i) 三種最常見的觸發情境：

  • 拼字錯誤：宣告了 myVariable，呼叫時打成 myVarible。
  • 作用域問題：在函式外部去存取函式內部宣告的變數。
  • 暫時性死區（TDZ）：在 let／const 宣告之前就先使用該變數。

(j) 為什麼 var 不會有 TDZ 問題：var 在提升（Hoisting）階段就會被初始化為 undefined，所以提前存取只是拿到 undefined；let／const 雖然也會被提升，但不會初始化，在賦值那行之前存取一律是 ReferenceError。這正是 TDZ 的設計目的——把「用了還沒準備好的變數」從沉默的 bug 變成大聲的錯誤。

console.log(v); // undefined（var 提升後已初始化）
var v = 1;

console.log(l); // ReferenceError（let 提升但未初始化 → TDZ）
let l = 1;
