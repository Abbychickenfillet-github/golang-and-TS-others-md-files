重點整理

本篇重點 (a)–(d)，共 4 個。

(a) ECMA-262 是誰寫的？

這份文件正式名稱是 ECMAScript Language Specification（ECMA-262），是 JavaScript 的官方標準規格書。制定組織是 Ecma International 旗下的 TC39（Technical Committee 39）技術委員會。JavaScript 最初由 Brendan Eich 創立，規範則由 TC39 委員會成員共同編寫審查，歷代主要專案編輯包括 Allen Wirfs-Brock、Brian Terlson、Jordan Harband、Kevin Gibbons、Shu-yu Guo、Michael Ficarra、Richard Gibson、Ron Buckton、Nicolò Ribaudo、Linus Groh 等人，並結合廣大開源社群的貢獻。

(b) 這些語法規則屬於哪個 Level？

屬於高階語言規格層級，並不直接等於 RAM 或 CPU 的操作層級：

層級 內容
規範層級 ECMA-262 定義 JS 語法（Lexical & Syntactic Grammar）與執行語意，只是文字規則
引擎層級 V8/SpiderMonkey/JavaScriptCore 讀規格、實作 Parser 轉 AST，再經 JIT 編譯成 Bytecode 或機器碼
硬體層級 引擎編譯出的機器碼，執行時才真正操作 CPU 暫存器與 RAM

NonOctalDigit、LegacyOctalLikeDecimalIntegerLiteral 這類文法符號定義在規範 Annex B.1.1（Web 瀏覽器附加相容性規格）：NonOctalDigit 指數字 8 或 9（八進位只有 0-7）；LegacyOctalLikeDecimalIntegerLiteral 是為了相容舊網頁「開頭補 0」寫法保留的「類八進位十進位整數」——例如 012 是純八進位（=10），但 018／089 因含 8/9，會退回以十進位解析（=18／89）。現代 JS 在嚴格模式或 ES Modules/Classes 下已禁止這種模糊寫法，會直接拋 SyntaxError，請改用標準前綴 0o（例：0o12）。

(c) ECMA-262 跟 MDN，誰更新得快？

ECMA-262 較快：是滾動更新的官方規格草案，TC39 一旦通過新語法進入 Stage 4，該語法立即併入主分支與 Draft 規格，是所有新特性的源頭。
MDN 稍慢：屬於「二次整理與撰寫」的文件，通常要等提案接近完成、或瀏覽器開始實驗性實作，社群與 Mozilla 編輯團隊才會寫成白話文教學，時間點上略落後 ECMA-262 草案。

(d) 誰更專業？該看哪一份？

兩者定位不同、互補，不是誰取代誰：

ECMA-262（語言的「法律條文」） MDN（開發者的「實用手冊」）
性質 權威性 100%，官方標準規範 Web 開發領域最專業的應用教學與 API 參考
目標受眾 JS 引擎開發者、編譯器作者（Babel/TypeScript）、語言設計者 應用層開發者（前端／Node.js／Web 工程師）
特點 極度嚴謹形式化語言（文法規則、抽象操作、演算法步驟），不含教學或範例 白話文＋大量範例、最佳實踐、瀏覽器相容性表格；還涵蓋 HTML/CSS/Web API（ECMA-262 不涵蓋）
適合查閱時機 想了解最底層執行邏輯、型別轉換演算法、語法解析邊界條件、研究最新 Stage 4 前沿提案 日常寫程式、查 API 用法、看語法範例、確認瀏覽器支援度
