1. 區塊語句與作用域（a–c）

(a) 區塊語句（Block statement）是最基本的語句，用一對大括號把多條語句組合在一起，通常跟 if、for、while 這些控制流語句搭配使用。

while (x < 10) {
  x++;      // { x++; } 就是一個區塊語句
}

(b) var 宣告的變數不具備區塊作用域，它的作用域屬於包含它的函式或整份腳本，所以在區塊裡設定的效果會持續到區塊之外。

var x = 1;
{
  var x = 2;
}
console.log(x); // 2 ← 在 C 或 Java 裡同樣的程式碼會印出 1

(c) 改用 let 或 const 就能把作用域收回區塊內，完整的三兄弟比較寫在 04-變數宣告-let-const-var，區塊作用域本身寫在 05-作用域-scope-global-function-block。

2. 條件語句與 falsy（d–g）

(d) if...else 的規則是：condition 求值為 true 就執行 statement1，否則執行 statement2，兩者都可以是任何語句，包括再嵌一層的 if。串聯多個條件時用 else if，只有第一個求值為 true 的條件會被執行。

(e) 最佳實踐：永遠寫大括號，尤其在巢狀 if 的情況下，可讀性與後續維護都靠它。

(f) 避免在 if 的條件位置寫賦值，if (x = y) 看起來像比較，實際是把 y 指派給 x 再拿結果去判斷真假。
同一個坑在陣列方法裡也會踩到（arr.find(e => e = 2)），實例寫在 05-find方法-短路與falsy陷阱-如何取得所有符合的索引。

(g) falsy 值清單：false、undefined、null、0、NaN、空字串 ""。
其他所有數值（包含所有物件）在條件語句中都求值為 true。

const b = new Boolean(false);
if (b) {
  // 這裡會進來，因為 b 是「物件」，物件永遠 truthy
}
if (b == true) {
  // 這裡不會進來
}

切勿混淆原始布林值 `true`／`false` 與 `Boolean` 物件包起來的 `true`／`false`。

⚠️ 存疑／更正：Gemini 原文只列了六個 falsy 值。MDN 的 Falsy 詞條另外還收錄 0n（BigInt 零）與 document.all（歷史相容用的特例），完整是八個。日常寫 code 記六個就夠，但面試被問「全部」時要補上 0n。

3. switch 與貫穿（h–i）

(h) switch 的運作是：求值一個表達式，拿它的值去跟每個 case 標籤比對，找到匹配就執行關聯的語句。

(i) break 是可選的，少寫就會「貫穿（fall-through）」，程式會繼續執行下一個 case 內部的語句，直到遇到 break 或 switch 結束。

switch (fruitType) {
  case "Oranges":
    console.log("Oranges are $0.59 a pound.");
    break;
  case "Apples":
    console.log("Apples are $0.32 a pound.");
    break;
  default:
    console.log(`Sorry, we are out of ${fruitType}.`);
}

4. 例外處理：throw 與 try/catch/finally（j–n）

(j) JavaScript 幾乎可以拋出任何東西，字串、數字、布林、物件都行。

throw "Error2";                                   // String
throw 42;                                         // Number
throw true;                                       // Boolean
throw { toString() { return "I'm an object!"; } }; // Object

<mark style="background: #BBFABBA6;">但實務上請拋專門為此建立的例外類型</mark>，例如 ECMAScript 的 `Error`（及其子類 `TypeError`、`RangeError`）或 DOM 的 `DOMException`，因為它們帶 `name`、`message` 與 stack trace，錯誤處理函式才有東西可用。

(k) try...catch 的三個區塊，動詞—受詞—拋接關係寫清楚是這樣：

區塊 誰在做什麼 什麼時候跑
try 引擎執行這一組語句，一旦任何一行 throw，就立刻中斷並把拋出的值交給 catch 一定會進入
catch (e) 接住 try 拋來的值，綁到識別碼 e 上，執行補救語句 只有 try 真的拋出時才跑
finally 不管前面有沒有拋出，都執行收尾語句 一定會跑

(l) catch 的識別碼只在 catch 區塊執行期間存在，離開區塊就消失，這一點跟 let 的區塊作用域一致。

function getMonthName(mo) {
  mo--; // 調整成陣列索引（0 = Jan，11 = Dec）
  const months = [
    "Jan", "Feb", "Mar", "Apr", "May", "Jun",
    "Jul", "Aug", "Sep", "Oct", "Nov", "Dec"
  ];
  if (!months[mo]) {
    throw new Error("Invalid month code");
  }
  return months[mo];
}

try {
  monthName = getMonthName(myMonth);
} catch (e) {
  monthName = "unknown";
  logMyErrors(e); // 把例外物件傳給錯誤處理函式
}

(m) finally 的典型用途是釋放資源，例如關閉檔案、關閉連線、清掉 loading 狀態。

openMyFile();
try {
  writeMyFile(theData);
} catch (e) {
  handleError(e);
} finally {
  closeMyFile(); // 確保檔案總是會被關閉
}

(n) 一句話總結：try 負責「試著做」、catch 負責「接住壞掉的東西」、finally 負責「不管好壞都要善後」，三者的責任互不重疊。
