一、先講結論

  1. 第二次載入少很多檔案，是因為瀏覽器把第一次下載的 JS 與 CSS 存進快取了。下次要用同一個網址的檔案時，先看快取，不用再問伺服器。
  2. 「檔名一樣就不重讀」成立的前提，是伺服器在回應標頭寫了 Cache-Control: public, max-age=31536000, immutable。意思是「這個網址的內容一年內都不會變，不用再來問」。
  3. 檔名會變的原因是打包工具把內容算出一段 hash 放進檔名（例如 main-8bc660a98b463b2d.js）。內容沒改，hash 就不變，檔名不變，快取繼續有效。內容改了，檔名就變，等於是一個全新網址，瀏覽器自然去下載。
  4. 換檔名是打包工具做的事，不是 React、Vue、Angular 這些框架本身做的。三大框架現在的預設打包流程都會換 hash，下面第五節有線上實測。
  5. HTML 本身不能換檔名（使用者輸入的網址是固定的），所以 HTML 要設成「每次都問一下，沒變就回 304」。HTML 裡面寫著最新的 JS 檔名，這就是整個機制的槓桿點。

用 F12 自己驗證

  1. 開 F12 → Network，勾選 Disable cache 先取消勾選（不然看不到快取效果）。
  2. 第一次進站：Size 欄位顯示實際傳輸大小（例如 85 kB）。
  3. 再按網址列進入（不是 F5）：Size 欄位變成 (disk cache) 或 (memory cache)，Time 接近 0 ms。
  4. Network 上方的 transferred 數字會從十幾 MB 掉到幾 KB。

五、換檔名是誰做的：框架對照與實測

換檔名不是框架本身的功能，而是打包工具（bundler）在輸出檔案時做的事：打包工具用雜湊演算法對每個 chunk 的內容算出 hash，寫進檔名，再把新檔名寫回 HTML 的 <script src>。

生態系實際負責換檔名的工具設定名稱線上實測檔名（2026-10-02）
React（Next.js）Next.js 內建的 webpack／Turbopack[contenthash]main-8bc660a98b463b2d.js（react.dev）
React（CRA／Webpack）webpackoutput.filename: '[name].[contenthash].js'同上規則
Vue（Vite）Vite 以 Rollup 輸出Rollup 的 [hash]app.B91ytTIH.js（vuejs.org）
AngularAngular CLI 的 builderoutputHashingmain-53YHTYUY.js（angular.dev）
結論：React、Vue、Angular 都會換 hash，因為它們各自預設的打包流程都開著 content hash。React 是一個函式庫，自己沒有檔名機制，所以「React 會換檔名」更精確的說法是「React 專案用的打包工具會換檔名」。

content hash 的連鎖失效

  1. chunk A 裡面寫了「我要 import chunk B（檔名 b-1111.js）」。
  2. B 的內容一改，B 的檔名變成 b-2222.js。
  3. A 的內容裡那段檔名字串也跟著變，所以 A 的 hash 也變。這叫連鎖失效。
  4. 解法：webpack 用 runtimeChunk: 'single' 把「檔名對照表」抽成獨立小檔，用 splitChunks 把很少變動的 node_modules 抽成 vendor chunk，用 moduleIds: 'deterministic' 讓模組編號不因為新增檔案而亂跳。這樣改一行業務程式碼，只會有 1 到 2 個檔名變。

六、「等 10 分鐘」與「強制」分別對應流程圖哪裡

你想要的行為怎麼做對應主軸圖
等 10 分鐘之內不要重讀，過了才去問回應標頭寫 Cache-Control: max-age=600調整 B 的新鮮期為 600 秒。過期後走到 C，用 ETag 問一次，沒變回 304
檔名一樣就一直不重讀檔名帶 hash，再加 max-age=31536000, immutableB 永遠是「是」
使用者按 F5（一般重新整理）瀏覽器送 Cache-Control: max-age=0 加條件標頭強制 B 視為過期，走到 C，沒變就 304。有 immutable 的檔案瀏覽器會略過這個檢查
Ctrl+Shift+R（強制重新整理）瀏覽器送 Cache-Control: no-cache 與 Pragma: no-cache整個跳過 A 與 B 與 C，直接 GET 拿完整 200
開發時整個站不要快取F12 → Network → 勾選 Disable cache（F12 開著才有效）同強制重新整理
hash 檔名的搭配規則：HTML 不能設長快取。如果 HTML 也被快取一年，使用者拿到的永遠是舊 HTML，裡面寫的永遠是舊 JS 檔名，新版就永遠上不去。所以 HTML 設 max-age=0, must-revalidate 或 no-cache，JS 才設一年。

七、自我測驗

填空（點黃底框顯示答案）

  1. 檔名帶 hash 的 JS 檔，回應標頭通常寫 點我，表示一年內不用再問伺服器。
  2. 一般重新整理（F5）時，瀏覽器會送 點我，伺服器沒變就回 點我。
  3. webpack 讓檔名只在內容改變時才變的替換字串叫 點我。
  4. 強制重新整理（Ctrl+Shift+R）時，瀏覽器送出的快取標頭是 點我。

是非題

a. 只有 React 專案才會自動把 chunk 檔名加上 hash。

b. 為了效能，HTML 也應該設 max-age=31536000。

c. 網站改版時只改了一個元件，沒有被牽連的 chunk 會繼續使用瀏覽器快取。

申論題

用主軸圖的 A、B、C 三個菱形，說明「第二次載入 26 個 JS 檔只花 1 個請求」與「改版後使用者怎麼拿到新檔案」。

第二次載入時，HTML 因為 max-age=0 在 B 判為過期，走到 C 帶 ETag 問伺服器，沒變就 304，這是唯一的請求。26 個 JS 檔的網址含 hash，在 A 命中快取，在 B 因為一年期限判為新鮮，直接使用，0 個請求。改版後 HTML 變了，伺服器回 200 與新 HTML，新 HTML 引用的新 JS 檔名在 A 找不到，走到最左邊的方框 GET 下載。沒被改到的 chunk 檔名不變，繼續命中快取。
