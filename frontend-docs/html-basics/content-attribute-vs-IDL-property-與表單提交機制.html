✅ 重點 h–k：最常踩的四個坑
h. 打包用的 key 是 name 不是 id。id 給 CSS／JS／<label for> 用，沒有 name 的欄位根本不會被送出。
i. <input type="submit"> 的按鈕文字由 value 決定，跟文字框用 value 存內容是兩回事。
j. form 內的 <button> 不寫 type 預設是 submit，會意外整頁刷新；只想做一般按鈕要明寫 type="button"。

l. SPA 裡通常 e.preventDefault() 攔下預設提交，改用 fetch 自己送，避免整頁刷新。
m. 即使攔下來，仍建議保留 <form> 與 name：能用 new FormData(formEl) 一行收齊，鍵盤 Enter 送出與螢幕閱讀器的表單語意也靠它。

申論題

1. 有人回報「我用 setAttribute('value', '新值') 更新欄位，第一次進頁面有效，但使用者打過字之後就完全沒反應」。請用 content attribute 與 IDL property 的關係解釋原因，並給出正確寫法。
畫面上顯示的是 IDL property el.value。頁面剛載入時 property 還是「乾淨」的，會跟著 content attribute 走，所以改 attribute 看得到效果。 使用者一輸入，瀏覽器就把該 input 的 dirty value flag 設起來，從此 property 不再跟隨 attribute，setAttribute 只改到了「預設值」（等同 defaultValue），畫面當然不動。 正確寫法是直接寫 property：el.value = '新值'。若同時想改掉 reset 後會回到的預設值，才另外寫 el.defaultValue = '新值'。
2. 用「動詞—受詞—拋接關係」的完整句子，描述使用者按下 submit 到伺服器收到資料之間的每一步，並指出哪一步決定了「有些欄位沒被送出」。
使用者按下按鈕 → 瀏覽器對該 <form> 觸發 submit 事件 → 瀏覽器走訪 form 內所有可提交控制項，只收集有 name 的那些，把它們的 name 與當前 IDL property 值組成 form data set → 瀏覽器依 method 把 data set 編碼（GET 接成 query string 貼在 URL 後，POST 放進 request body）→ 瀏覽器向 action 的 URL 送出 HTTP request → 伺服器解析後回應 → 瀏覽器用回應內容整頁換掉。
決定「沒被送出」的是第三步：沒有 name 的控制項在收集階段就被跳過，不論它有沒有 id、有沒有值。
3. 為什麼 HTML 規格要同時維持 content attribute 與 IDL property 兩套，而不是只留一套就好？請各舉一個「只有那一套做得到」的情境。
因為兩套回答的是不同問題：attribute 回答「這份文件被作者寫成什麼樣」，property 回答「這個元素此刻處於什麼狀態」。
只有 attribute 做得到：序列化（el.outerHTML、SSR 輸出 HTML 字串）、CSS 屬性選擇器 input[value="x"]、以及表單 reset 要回到的那個基準值。
只有 property 做得到：表達非字串型別（el.checked 是真 Boolean、el.classList 是 DOMTokenList）、表達使用者互動後才存在的狀態（打了什麼字、選了哪一項），這些在原始碼裡從來沒被寫過，attribute 無從記起。
