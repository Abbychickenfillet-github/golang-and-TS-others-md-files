瀏覽器 Geolocation API 與 App 原生 GPS 定位差異

本篇重點 a–h，共 8 個。

重點整理

(a) 網頁版定位比 App 版差，核心原因是「取得定位權限」與「底層技術」本質不同——即使同一支手機，網頁版 Google Maps 拿到的定位精準度與更新頻率通常還是輸給原生 App。

(b) 手機 App 屬於高權限：可直接存取手機內建 GPS 晶片、陀螺儀、電子羅盤，甚至用周圍 Wi-Fi 基地台與電信基地台做多重三角定位（A-GPS）。

(c) 瀏覽器網頁屬於低權限：出於隱私與資安限制，透過 HTML5 Geolocation API 取得定位時通常無法直接呼叫底層高頻率的原生 GPS 晶片，拿到的是系統包裝過、頻率較低的估算位置。

(d) 網頁常退而求其次用 IP 位址定位，IP 的位置通常是電信商機房或出入口，會造成定位偏移數公里到數十公里；網頁版也缺少硬體羅盤輔助，難以即時捕捉移動方向。

(e) 抓取頻率不同：App 可在背景持續追蹤並用感測器動態平滑演算（測算移動速度與方向）；網頁通常只在開啟頁面或點擊定位按鈕時發送一次性請求，資訊常是延遲或過時的。

(f) 「預估店家距離」誤差的連鎖反應：起點（你的位置）先被抓錯 → 有些簡易網頁版只算兩點間「直線距離（Haversine 公式）」而非實際道路路線 → 若拿到的起點不精準，規劃出的距離就會嚴重歪斜。

(g) 改善網頁版定位準確度的做法：在手機/電腦「設定 → 隱私權」開啟瀏覽器的「精確定位」權限；地圖右下角有「瞄準圖示（顯示我的位置）」，重新點擊可強制瀏覽器重新撈取最新座標。

(h) 延伸：這個機制解釋也適用於理解 HTML5 Geolocation API 在網頁開發中的定位，屬於瀏覽器提供的裝置能力 API 之一，與 [[HTML5演進-Quirks-Mode與HTML5-API]] 中的 HTML5 API 概念相關聯——都是「瀏覽器把裝置硬體能力包裝成 JS 可呼叫介面」的例子，只是 Geolocation 精度受限於瀏覽器安全沙盒。
