🥫 useEffect 的 setup 與 cleanup：Call Stack 罐頭時間軸

以 <ChatRoom /> 為例：一個 useEffect（deps 是 [roomId]），兩條路線。左邊是 Call Stack（罐頭疊），下面是 Heap 上的 Effect 物件
❌ 常見的想像setup 罐頭先進 stack，cleanup 罐頭疊在它上面，所以 cleanup 先彈出
✅ 實際情況cleanup 從來沒有跟 setup 同時在 stack 上，它是被 React 在「之後另一次」呼叫的，先後由 React 的 commit 排程決定
🔴 路線一：deps 變了（第一次掛載 → roomId 改變）
🟢 路線二：deps 沒變（例如只是在輸入框打字，roomId 沒變）
🥫 Call Stack 是後進先出（LIFO）只決定「同一時間疊在一起」的函式誰先彈出，例如 setup() 一定比呼叫它的 commitHookEffectListMount 先彈出
🔄 同一次 commit 的順序React 先跑完所有要清理的 cleanup（commitPassiveUnmountEffects），再跑所有 setup（commitPassiveMountEffects）
🏠 兩個函式都住在 Heapsetup（create）與 cleanup（inst.destroy）都是 Heap 上的函式物件，各被一個欄位記著位址。閒置時 stack 是空的，位址只存在 Heap 的 Effect 物件裡
📌 stack 上的位址只是暫時的只有「被呼叫期間」，呼叫它的函式才有局部變數持有位址，例如 const destroy = inst.destroy。函式彈出，這個局部變數就消失，Heap 的函式物件不受影響
