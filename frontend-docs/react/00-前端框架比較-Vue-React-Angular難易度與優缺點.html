一、先把三塊地基講清楚

class BaseModule {
  constructor(name) { this.name = name; }              // 實例屬性
  render() { return `Rendering ${this.name}`; }        // 實例方法（掛 prototype）
  static create(name) { return new BaseModule(name); } // 靜態方法（掛 class 本體）
}

// 存取器屬性：用 Property Descriptor 攔截讀寫
Object.defineProperty(BaseModule.prototype, 'status', {
  get() { return this._status; },
  set(value) { this._status = value; /* ← 可在此插入 side effect */ },
  enumerable: true, configurable: true
});
機制掛在哪裡特性適合表達什麼
實例方法prototype 或實例本身依賴 this，與實例狀態耦合「這個東西會做什麼」
靜態方法建構函式／class 本體不用 new 就能叫，無狀態工具函式、工廠
存取器屬性Property Descriptor 的 get／set攔截屬性的讀寫，可插入副作用隱式響應式、依賴追蹤

二、三個框架各挑了哪一塊

框架挑中的 JS 底層機制狀態變更機制心智模型
Vue.js存取器屬性（Vue 2 defineProperty → Vue 3 Proxy）隱式攔截與自動依賴追蹤響應式資料驅動
AngularES6 Class 的實例方法 ＋ TS 裝飾器顯式更新；舊版 Zone.js、新版 Signals傳統 OOP 物件導向
React純函式、閉包與頂層靜態工具函式顯式呼叫 setter，靠不可變性與 Object.is 比對函式式 UI 快照

Vue：reactive(obj) 用 Proxy 包住物件，get trap 做依賴收集（track）、set trap 做派發更新（trigger），所以你只要寫 count.value++ 視圖就自己更新。Vue 2 到 3 的升級，本質上就是「把逐屬性的 defineProperty 換成整個物件層級的 Proxy」，才解決動態新增／刪除屬性攔不到的老問題。

Angular：元件與 Service 都是被 new 出來的 class 實例，生命週期鉤子 ngOnInit 就是實例方法，DI 把服務塞進 constructor；靜態方法主要用在模組工廠（NgModule.forRoot()）。

React：現代 function component 把 this 整個丟掉，核心 API 全是頂層靜態工具函式。React 刻意不用 Object.defineProperty 或 Proxy 做隱式攔截，要求你顯式呼叫 setter，用不可變性換可預測性。

三、這對 Abby 的意義

框架的 API 長什麼樣，不是設計者的個人喜好，而是「他選了哪一個 JS 機制當地基」的必然結果。

  1. 1看到 Vue 的 .value 很囉嗦 → 因為 getter／setter 一定要有個東西可以掛。
  2. 2看到 Angular 到處是 class 與裝飾器 → 因為它的地基是實例方法與 this。
  3. 3看到 React 一堆 useXxx 頂層函式 → 因為它的地基是閉包與靜態工具，沒有 this 可以用。
這也是投鐵人賽 Web Platform 組很好的切角：把「靜態方法／實例方法／存取器屬性」當主線，三個框架當三個案例。

四、自己考自己

1. React 也是用 Proxy 攔截狀態讀寫來觸發更新的。
2. Vue 2 到 Vue 3 的響應式升級，本質是 defineProperty 換成 Proxy。

填空：Vue 的 get trap 負責 依賴收集（track），set trap 負責 派發更新（trigger）。

申論：為什麼 Vue 2 的 Object.defineProperty 攔不到「動態新增的屬性」，而 Vue 3 的 Proxy 可以？


Object.defineProperty 是逐個屬性去改寫描述子的：Vue 2 在元件初始化時遍歷 data 的每一個 key，一個一個裝上 getter／setter。既然是初始化當下才裝，之後才 obj.newKey = 1 新增的屬性就沒有人幫它裝，自然攔不到（所以 Vue 2 要用 Vue.set）。
Proxy 則是把整個物件包起來，攔截的是「對這個物件的任何操作」這個層級的 trap（get、set、deleteProperty、has…），不管 key 是本來就有的還是後來加的，都會經過同一組 trap，所以動態新增與刪除都攔得到。
