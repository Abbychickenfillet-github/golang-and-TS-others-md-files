🧬 Effect 的三個層次：概念 ➜ API ➜ 內部資料

同一個「Effect」，在三個不同的地方有三種長相。以 <ChatRoom /> 連聊天室為例，顏色對應：setup cleanup deps

🌱 ① 概念層

Effect（大寫，React 的專有詞）
🧩元件
🔄保持同步
💬外部系統
讓元件和外部系統保持同步由「元件出現在畫面上」這件事本身引起，不是由某個點擊引起
只有兩個動作：開始同步、停止同步跟元件的 mount／unmount 生命週期不是一回事
跟 side effect（小寫）的關係side effect 泛指改動函式以外世界的行為，Effect 是安放它們的地方
➡️你把概念
寫成程式

✍️ ② API 層

useEffect(setup, deps)（你寫的 Hook）
useEffect(() => {
  const c = createConnection(roomId)
  c.connect()            // 開始同步
  return () => {
    c.disconnect()        // 停止同步
  }
}, [roomId])              // 何時重新同步
這一行在 render 時被呼叫，只負責「登記」登記 setup 與 deps，不會立刻執行 setup
setup 與 cleanup 要等 commit 之後才由 React 呼叫時機：掛載後、deps 變了、卸載後
➡️React 把它
存成資料

🗄️ ③ 資料層

Fiber 上的 Effect 物件（在 Heap）
Hook ② 的 memoizedState ➜ Effect 物件
🔌 create = setup 函式
📋 deps = 依賴陣列
🏠 inst 跨 render 共用
🧹 destroy = cleanup 函式
🔗 next 串成環，掛在 fiber.updateQueue
commit 時標記 Passive 旗標，再由 flushPassiveEffects 走過這個環取出 create 或 inst.destroy 來呼叫

🔗 同一件事，三個層次的叫法對照

要表達的事① 概念層② API 層（你寫的）③ 資料層（React 存的）
開始連上外部系統開始同步setup 函式（c.connect() 那幾行）Effect.create
斷開外部系統停止同步cleanup 函式（return 出去的函式）Effect.inst.destroy
什麼時候要重新同步同步的對象改變了依賴陣列 [roomId]Effect.deps，用 Object.is 逐項比較
什麼時候被執行元件出現在畫面上之後commit 之後（掛載、deps 變、卸載）Passive 旗標，由 flushPassiveEffects 呼叫
❓ 「StrictMode 多跑一輪，是第二次執行 useEffect 嗎？」不是。第 ② 層的 useEffect(...) 登記動作沒有重來，是第 ③ 層同一個 Effect 物件的 create 與 inst.destroy 被再呼叫一輪。
💡 為什麼要分三層讀官方文件講的是第 ① 層，寫程式碰的是第 ② 層，除錯與讀原始碼會碰到第 ③ 層。每次遇到「Effect」先問：它指的是哪一層？
