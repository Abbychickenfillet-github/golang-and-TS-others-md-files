重點整理

一. React 的 useRef

(a) useRef 的兩個用途：儲存「不需要觸發重新渲染的可變值」，或直接存取 DOM 元素。

(b) 澄清一個常見誤解：這裡的「可變值」不限於基本型別（primitive）或字串。物件、陣列、函式、DOM 元素、計時器 ID，幾乎什麼都可以塞。「可變」講的不是型別，是「你可以隨時改它，而 React 不會因此重畫」。

(c) 改 ref.current 不會觸發重新渲染，這就是它跟 useState 的分水嶺：

useState useRef
改值的方式 setCount(1) ref.current = 1
會重新渲染嗎 會 不會
值存在哪 React 內部的 fiber 上 同一個永遠不變的物件的 .current 屬性上
適合放 要顯示在畫面上的東西 計時器 ID、上一次的值、DOM 節點、不想被畫面看見的旗標

(d) 為什麼一定要 .current 這一層？因為 React 每次渲染都會重跑整個組件函式。如果 useRef 直接回傳一個值，那個值一離開這次渲染就沒了。回傳一個身分永遠不變的物件，你改的是物件裡的屬性（傳址），跨渲染就留得住。這跟 Vue 的理由是同一個。

二. 中文輸入法（注音／IME）的實際場景

(e) 對話裡提到「打注音時每打一個字都在變更」。這是 IME composition（組字）的經典題：使用者打注音時，onChange 會一直觸發，但那些中間狀態不是最終文字。

(f) 正解做法：用 useRef 存一個 isComposing 旗標，配合 onCompositionStart / onCompositionEnd 事件。組字進行中就跳過送出邏輯，組字結束才處理。這個旗標不需要出現在畫面上，所以用 ref 而不是 state，可以少掉一整輪重新渲染。

三. Vue 的 ref 與 .value

(g) ref() 建立的是一個包含 .value 屬性的物件。.value 代表 ref 物件內真正儲存的值。

(h) 為什麼要包一層：JavaScript 沒辦法攔截「對一個變數重新賦值」這件事。count = 5 這種事引擎不會通知任何人。但「對一個物件的屬性賦值」可以被攔截，所以 Vue 把值裝進物件，用 getter / setter 包住 .value：讀 .value 時做依賴收集（track），寫 .value 時觸發更新（trigger）。

(i) 在 template 裡不用寫 .value，是因為 Vue 的編譯器看得出 count 是個 ref，編譯階段自動幫你補上。在 <script setup> 的 JS 邏輯裡沒有這個魔法，該寫還是要寫。

(j) 最容易混淆的一句話，記起來：

React 的 useRef 是為了「避開響應式」；Vue 的 ref 是為了「建立響應式」。名字像，.current 與 .value 也像，目的完全相反。

四. 順帶釐清的 getter / setter

對話中途 Gemini 冒出 getter / setter 的定義（因為語音辨識誤判），但這個概念剛好就是 (h) 的核心，順手記下來：

  • Getter：讀取屬性時被呼叫的函式，讓你在「讀」的瞬間插入邏輯。
  • Setter：寫入屬性時被呼叫的函式，讓你在「寫」的瞬間插入驗證或副作用。
  • Vue 2 用 Object.defineProperty 做這件事，Vue 3 改用 Proxy，差別在 Proxy 能攔截新增／刪除屬性與陣列索引，defineProperty 不行。
