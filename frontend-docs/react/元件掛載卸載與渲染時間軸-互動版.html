    規則

    • render 階段是純函式：同樣輸入得到同樣輸出，不寫 DOM、不綁事件
    • 副作用（量高度、綁事件）放 useEffect，在 commit 之後執行
    • ref 在 commit 階段才被填入，render 階段讀到的是 null
    • useCallback 快取的壽命 = 元件實例的壽命，卸載即消失
    • 條件渲染消失、key 改變、換頁，都會卸載後重新掛載，快取從零開始
    • StrictMode 開發模式會刻意：掛載、清理、再掛載，並把元件函式呼叫兩次

    自我測驗

    1. render 階段能讀到 deckRef.current 嗎？
    不能，是 null。ref 在 commit 階段才填入。
    2. 第二次渲染產生的 goTo#2 去哪了？
    依賴 [deckRef] 沒變，useCallback 丟掉 goTo#2，回傳 goTo#1。
    3. 離開頁面後再回來，goTo 還是 goTo#1 嗎？
    不是。卸載時實例與 hook 資料被丟棄，再造訪是新實例，產生新的函式。
    4. 清理函式什麼時候執行？
    依賴變了，在下一次 setup 之前。卸載時，在實例消失之前。
