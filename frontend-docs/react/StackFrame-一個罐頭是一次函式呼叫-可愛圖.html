🥫 Stack Frame（堆疊框）：一個罐頭 = 一次函式呼叫，不是一個 Hook

Stack Frame 是 JS 每「呼叫」一次函式就在 Call Stack 疊上去的一個罐頭，函式回傳就彈出。以 <ChatRoom /> 的一個 useEffect 為例

❌ 你的圖：整個 useEffect 一個框，cleanup 疊在 setup 上

① frame 是「每一次呼叫」一個，不是「每個 useEffect」一個 useEffect 一輩子會產生好幾個不同時間的罐頭 ② setup 與 cleanup 是兩次不同的呼叫，從不同時在 stack 上 setup 回傳彈出之後，過了很久才輪到 cleanup ③ cleanup 不是被 setup 呼叫的，呼叫它的是 React 所以它不會疊在 setup 上面

🔬 解剖一個罐頭：以 setup() 為例

📮 返回位址函式做完要回到誰。這裡是呼叫它的 React commit 函式
這也是 setup() 彈出之後程式接著跑的位置
📥 參數setup 沒有參數
每個罐頭各有自己的一份，不會跟別的呼叫共用
📦 區域變數const connection = createConnection(...)
一般區域變數放在罐頭裡，罐頭彈出就消失
🏠 閉包例外connection 被 cleanup 的函式抓住，所以引擎把它放到 Heap 的 Context
罐頭彈出後它還活著，這就是 cleanup 之後還能 disconnect 的原因

📏 判斷「畫在同一個罐頭堆裡」的規則

疊在一起A 呼叫 B，B 還沒做完，A 也還在等。例如 commit 函式呼叫 setup()
不會疊在一起兩次呼叫發生在不同時間，前一個已經回傳。例如 setup() 與之後的 cleanup()
要畫成時間軸想表達「誰先誰後」時，用左到右的多個罐頭堆，不要塞進同一個
Hook 本身「useEffect」是一個概念，不是罐頭。罐頭只對應「某一次函式呼叫」
