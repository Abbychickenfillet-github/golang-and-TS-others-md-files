申論題

  1. 有人跟你說「路由不就是路由，前後端有什麼差」。請用 Next.js 的 [slug]、Vue Router 的 :id、Express 的 app.get 三個例子，說明它們各自解決什麼問題、輸出的東西有什麼本質差異，以及為什麼 Next.js 非得用中括號不可。

    參考方向：(1) 本質差異在「輸出什麼」。Express 的路由輸入是 HTTP 請求、輸出是資料（JSON、HTML 字串），它決定的是伺服器怎麼回應；Next.js 與 Vue Router 的路由輸入是網址、輸出是要渲染哪個組件，它決定的是使用者看到什麼畫面。全端框架 Next.js 兩件事都做（app/api 是前者，app/page 是後者），所以特別容易混淆。(2) 宣告位置不同。Express 與 Vue Router 把路由表寫在程式碼裡，是執行期資料結構，因此可以動態 addRoute；Next.js 把路由寫在檔案系統裡，是編譯期就決定的靜態結構，換來的是自動 code splitting 與更好的靜態分析。(3) 中括號 vs 冒號：冒號在 Windows 與多數 OS 的檔名中是非法字元，Next.js 既然選擇用檔名承載路由規則，就不可能用冒號，只好改用中括號。這是被檔名規則逼出來的設計，不是任意選的。(4) 延伸：main.tsx 的有無也是同一條線索——Vite/CRA 把進入點交給你寫，Next.js 收回去自己管，換取約定優於配置。

重點整理

一. Next.js 的 [slug]：檔名決定規則，params 決定取值

(a) slug 是「對人類閱讀友善的網址關鍵字」，例如 /posts/react-guide 裡的 react-guide。它不是 Next.js 專有名詞，是網頁界的通用術語。

(b) 關鍵觀念：[slug] 與 ({ params }) 不是二選一，是一組搭配。

  • [slug] 是檔案系統層的宣告。資料夾或檔名寫成中括號，就是在告訴 Next.js：「這一段網址是變數，不是固定字串。」
  • ({ params }) 是程式碼層的接收。Next.js 把網址上的實際字串打包成物件，透過 props 傳給組件。

(c) 對照範例：

層級 寫法
Pages Router 檔案 pages/posts/[slug].js
App Router 檔案 app/posts/[slug]/page.js
使用者造訪 /posts/react-guide
組件內取值 params.slug === "react-guide" 
export default function Post({ params }) {
  // 此時 params.slug 的值就是 "react-guide"
  return <h1>目前文章 slug 是：{params.slug}</h1>;
}

(d) 逐段拆解這一行：export default 讓 Next.js 知道這是這個路由要渲染的組件；function Post({ params }) 用解構賦值（destructuring）直接從 props 物件裡把 params 挖出來，等同於寫 function Post(props) { const params = props.params; ... }；{params.slug} 是 JSX 的插值表達式，大括號裡放的是 JavaScript 運算式，結果會被轉成文字節點。

(e) 版本陷阱：Next.js 15 之後 App Router 的 params 變成 Promise，必須 await。上面那段是 Next.js 14 以前的舊寫法。Gemini 沒有提到這件事，寫的時候務必對照你專案的 Next.js 版本。

// Next.js 15 以後的正確寫法
interface PageProps {
  params: Promise<{ slug: string }>;
}

export default async function Page({ params }: PageProps) {
  const { slug } = await params;
  return <h1>slug 是：{slug}</h1>;
}

改成 Promise 的理由是效能：Next.js 可以先把頁面能靜態渲染的部分渲染完，再去解析動態值，不必為了等一個 slug 卡住整頁。沒 await 時的典型錯誤訊息是 Route "/blog/[slug]" used params.slug. params should be awaited before using its properties. 或 TypeScript 的 Type '{ params: { slug: string; }; }' does not satisfy the constraint 'PageProps'。

二. Vue Router 的冒號寫法

(f) Vue 不用檔案系統宣告，而是在路由表裡用冒號標記動態參數：/user/:id。

(g) 組件內用 $route.params.id（Options API）或 useRoute().params.id（Composition API）取值。

(h) Vue Router 還支援執行期動態加入路由（router.addRoute()），所以可以依照使用者權限動態生成導覽清單，這是權限型後台常見做法。

三. Express 的 app.get：名字裡也有 app，但是完全不同層

(i) 最容易搞混的地方：Node/Express 的 app.get 跟 Next.js 的 App Router，兩個名字裡都有 app，但根本不是同一件事。

Express 的 app Next.js 的 App Router
所在層 後端伺服器 前端 / 全端框架
負責 接收 HTTP 請求，回傳資料（JSON 等） 決定畫面上顯示哪個組件
寫法 app.get('/users/:id', handler) 資料夾 app/users/[id]/page.tsx
動態參數 req.params.id params.id

(j) 最底層的 Node http 模組其實沒有路由這回事，你得自己判斷 req.url 與 req.method。Express 的價值就是把那一堆 if-else 包成 app.get / app.post 這種語意化 API。

(k) 記憶點：Express 用冒號 :id，跟 Vue Router 一樣；Next.js 用中括號 [id]，因為它靠的是檔案系統，而冒號在多數作業系統的檔名裡是非法字元。這不是巧合，是被檔名規則逼出來的設計。

四. main.tsx 進入點：Vite/CRA 有，Next.js 沒有

(l) 傳統 React 專案（Vite、CRA）的 main.tsx 做三件事：

import { createRoot } from 'react-dom/client';
import App from './App';

createRoot(document.getElementById('root')).render(<App />);
  • createRoot(...) 指定掛載點（mount point），通常是 index.html 裡那個 <div id="root">。
  • <App /> 是最外層組件。
  • 如果用 React Router，<BrowserRouter> 這類 Provider 也會包在這一層。

(m) Next.js 裡看不到這段是正常的，你沒記錯。Next.js 採用基於檔案系統的路由，初始化與掛載由框架自動完成，開發者只寫 layout.tsx 與 page.tsx。要塞 Provider 的話就寫在 app/layout.tsx 裡。

使用者： 左邊這段範例程式碼是想教我什麼？就 slug？

Gemini： 左邊的範例主要是在介紹 Next.js 的動態路由（Dynamic Routes）機制，特別是 slug 參數（Route Parameters）的用法。抓取 URL 中的動態變數：在 Next.js（App Router）中，如果你把資料夾命名為 [slug]，網址上對應位置的字串就會被當作變數抓進來。處理傳入的 params：組件可以透過 props.params 取得這個動態值。實作動態頁面：當使用者存取 /posts/hello-world，params.slug 就會是 "hello-world"。

使用者： 所以是依照 ({slug}) 取網址名稱還是 [slug].js？

Gemini： 答案是兩者配合：[slug] 是檔案／資料夾名稱，({ params }) 是程式碼內部拿取該名稱的方式。檔案系統命名用中括號宣告動態路由；程式碼元件用 ({ params }) 從 props 中把變數取出來使用。

使用者： 那個 Node.js 的路由會怎麼規劃？我記得 Node.js 好像也可以規劃路由。

Gemini： 如果使用最基本的 http 模組，你需要手動檢查 req.url 和 req.method。不過通常我們會使用像 Express.js 這類的框架，它提供了更直覺的方法，像是 app.get 或 app.post。

使用者： app 點什麼？它就是跟 app router，前端 react 的這個鼎鼎有名的 app router，它這個字是一樣的嘛？

Gemini： 雖然它們的名字裡都有「app」，但它們在架構上的角色可是大不相同。Node.js 裡的 app.get 或 app.post 是用來處理後端伺服器的路由，負責接收特定的 HTTP 請求然後送回資料。而 React 這裡的 App Router 則是前端或全端框架 Next.js 用來管理頁面和組件導航的機制。簡而言之，一個是處理後端 API，另一個是決定畫面上要顯示什麼內容。

使用者： 前端的 main.tsx 好像都會放一些什麼樣的東西？

Gemini： 在前端的 React 應用中，像 main.tsx 這樣的主要進入點，主要負責把整個 React 應用渲染到實際的網頁 DOM 裡面。在這個檔案中，通常會透過 createRoot 來指定應用的掛載點，像是 document.getElementById('root')。接著你會導入最外層的組件，通常是 <App />。如果你的應用使用了路由系統，比如 React Router，相關的設定也會在這個階段被引入並包裝在組件的最外層。

使用者： 可是我記得我用 next 的時候，好像沒有看過這個寫法。還是我記錯了？

Gemini： 你並沒有記錯。在 Next.js 裡面，你確實不會手動去寫 main.tsx 和 createRoot 這一類的程式碼。在 Next.js 的架構下，它採用基於檔案系統的路由機制，會自動幫你處理應用的初始化與掛載。

使用者： vue 是怎麼做動態路由的？

Gemini： 在 Vue 裡面，動態路由是透過 Vue Router 實現的。核心做法是在定義路由規則時，使用冒號來標記動態參數。例如設定一個路徑為 /user/:id，這樣當使用者造訪不同的 ID 時，同一個組件就能夠動態載入。在組件內部，你可以透過 $route.params.id 來取得網址上的實際數值。Vue Router 還支援在執行期間動態添加路由。
