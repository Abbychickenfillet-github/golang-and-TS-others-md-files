🔄 真正的「環」有兩個，都不是 Hook 鏈

環：最後一個元素的 next 又指回第一個。外面的指標只記住「最後一個」，要找第一個就走一步 last.next。新增元素時接在最後一個後面，再把指標改指向新的最後一個
① Effect 清單（掛在 fiber 上）：本例有兩個 Effect：第 2 個 Hook（useEffect）與第 4 個 Hook（useImperativeHandle）。useState、useRef 不產生 Effect，不在環裡。同一個 Effect 物件也被它那一節 Hook 的 memoizedState 指著，所以在 Hook 鏈與這個環上都找得到
② 待處理更新（掛在 useState 的 queue 上）：每呼叫一次 setCount 就多一封更新
第一次 setCount 時只有一封，它的 next 指向自己

📖 這四個 Hook 各是什麼意思？（它們都在上方的 Effect 環裡）

共同點：都是「React 做完某件事之後，請幫我跑一段我寫的程式」。差別只在「跑的時間點」不同，所以 Effect 物件上用 tag 旗標區分。React 每次 commit 依序處理：Insertion ➜ Layout ➜ Passive（畫面畫完才輪到）

⚡ useEffect

Passive：畫面畫完之後
白話：「畫面更新完了，再去跟外面的世界對一下」。外面的世界指計時器、網路連線、瀏覽器事件監聽、第三方套件。
例：useEffect(() => { const id = setInterval(tick, 1000); return () => clearInterval(id) }, [])。掛載後開始計時，卸載時停掉
為什麼在環裡：它就是最典型的 Effect，create ＝ 你寫的 setup，inst.destroy ＝ 你 return 的 cleanup

📐 useLayoutEffect

Layout：DOM 改好、畫面還沒畫出來
白話：「我要在使用者看到畫面之前，先量尺寸或調位置」。因為它會擋住畫面繪製，所以只在不得不時用。
例：提示框要先量按鈕的位置與自己的高度，才知道該放上面還是下面。用 useEffect 會先閃一下錯的位置，用 useLayoutEffect 則使用者只看到對的位置
為什麼在環裡：跟 useEffect 同一種 Effect 物件，只是 tag 是 Layout，所以跑得比較早

🎨 useInsertionEffect

Insertion：最早，早於所有 Layout
白話：「在別人讀版面之前，先把 CSS 規則塞進頁面」。設計給 CSS-in-JS 套件的作者用，一般應用程式幾乎用不到。
例：樣式函式庫在這裡把 <style> 規則插入 document.head，後面的 useLayoutEffect 去量尺寸時，樣式已經生效。此時還讀不到 ref
為什麼在環裡：同一種 Effect 物件，tag 是 Insertion。原始碼中它在 commit 的 mutation 階段執行

🔌 useImperativeHandle

Layout：跟 useLayoutEffect 同時間
白話：「爸爸拿到我的 ref 時，只讓他看到我挑好的幾個方法」。原本 ref 會直接給出 DOM 節點，這個 Hook 讓子元件改成只露出 focus()、reset() 這類自己挑的功能。
例：useImperativeHandle(ref, () => ({ focus() { inputRef.current.focus() } }), [])。爸爸只能呼叫 ref.current.focus()，碰不到內部的 input
為什麼在環裡：原始碼把它做成一個 Layout Effect：create 時做 ref.current = 你的物件，cleanup 時把 ref.current 設回 null
