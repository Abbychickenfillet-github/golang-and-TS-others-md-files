前端框架比較：Vue、React、Angular 難易度與優缺點

與 [[React-純函數與嚴格模式-StrictMode]] 相關：那篇談 React 內部的純函數規則，這篇往外拉一層，比較 React 跟另外兩個主流框架（Vue、Angular）在學習門檻與整體優缺點上的差異，適合決定「該學哪一個」時對照著看。

重點整理

本篇重點 (a)–(d)，共 4 個。

(a) 學習難易度排序：Vue ⟶ React ⟶ Angular

  • Vue.js（最平易近人）：難度低。採用傳統 HTML／CSS／JavaScript 分離語法（Single File Component），傳統網頁開發者可無縫轉銜，官方文件完善，新手能快速建立全貌概念。
  • React（中等，需掌握 JS 底子）：難度中等。強調「Everything is JavaScript」，全寫在 JSX 中。核心 API 精簡，但需熟練 ES6+ 語法、函數式程式設計（Functional Programming）概念與狀態管理機制。
  • Angular（最陡峭）：難度高。強制要求使用 TypeScript，並引進大量設計模式與架構概念，如依賴注入（Dependency Injection）、RxJS 響應式程式設計、Decorators 等，需一次性吸收完整開發規範。

(b) Vue.js 優缺點

優點：

優點 說明
極低門檻 學習曲線最平緩，能以最快速度產出專案
雙向資料綁定 處理表單與簡單互動時非常直覺
漸進式採納 可直接透過 <script> 標籤引入小專案，也能擴充成大型 SPA（單頁應用程式）
官方生態系整合佳 路由（Vue Router）與狀態管理（Pinia/Vuex）均由官方維護，不必花時間挑選套件

缺點：大型專案架構彈性過大，若沒有良好規範，不同開發者程式碼風格容易混亂；北美／全球職缺相對較少，在亞洲（台灣、中國）需求極高，但歐美市場規模略次於 React。

(c) React 優缺點

優點：

優點 說明
生態系極度龐大 社群最豐富的 UI 套件庫、第三方工具與社群支援
跨平台延伸能力強 掌握 React 後可無縫學習 React Native，開發 iOS／Android App
高度靈活 核心僅為 UI View 層，能自由搭配所需的各類套件庫

缺點：選擇疲勞——官方沒有提供統一的路由或狀態管理方案，需自己從生態系做技術選型（如 Redux、Zustand、React Query）；語法更新頻繁，從 Class Component 轉到 Hooks，再到 Server Components，技術迭代快，需持續學習。

(d) Angular 優缺點

優點：

優點 說明
開箱即用（All-in-One） 包含 HTTP 客戶端、路由、表單驗證、狀態管理等完整工具鏈，不必額外安裝第三方套件
高度標準化 大型團隊合作時，不同工程師寫出來的架構高度一致，利於企業級維護
原生 TypeScript 支持 型別檢查嚴謹，大幅減少大型專案中的 Runtime 錯誤

缺點：打包體積較大，初期載入時間與效能相較 Vue／React 較不易最佳化；程式碼較為冗長，開發小型專案時容易顯得笨重；社群與職缺成長放緩，相較 React 與 Vue，新手社群聲量與新創專案採用率較低。

(e) Angular 模板語法範例（Standalone Component + Signals）

現代 Angular（Angular 17 以後）的標準寫法已改為 Standalone Component（獨立組件，不必再宣告 NgModule）搭配 Signals（訊號，Angular 的細粒度響應式狀態原語）：

// user-list.component.ts
import { Component, signal } from '@angular/core';

interface User { id: number; name: string; role: string; }

@Component({
  selector: 'app-user-list',
  standalone: true,
  templateUrl: './user-list.component.html',
  styleUrl: './user-list.component.css'
})
export class UserListComponent {
  title = '使用者管理系統';
  isLoading = signal<boolean>(false);

  users = signal<User[]>([
    { id: 1, name: 'Alice', role: 'Admin' },
    { id: 2, name: 'Bob', role: 'Developer' }
  ]);

  selectedUser = signal<User | null>(null);

  selectUser(user: User): void { this.selectedUser.set(user); }

  addUser(): void {
    const newUser: User = { id: Date.now(), name: 'User_new', role: 'Member' };
    this.users.update(list => [...list, newUser]);   // update 收一個函式，回傳新陣列
  }
}

<!-- user-list.component.html -->
<div class="container">
  <h1>{{ title }}</h1>                                <!-- 插值綁定 -->

  <button [disabled]="isLoading()" (click)="addUser()">新增使用者</button>
  <!-- [prop] 是屬性綁定，(event) 是事件綁定，注意 signal 要加 () 才會取值 -->

  @if (isLoading()) {
    <p class="loading">資料載入中...</p>
  } @else {
    <ul class="user-list">
      @for (user of users(); track user.id) {
        <li [class.active]="selectedUser()?.id === user.id" (click)="selectUser(user)">
          <span class="name">{{ user.name }}</span>
          <span class="role">({{ user.role }})</span>
        </li>
      } @empty {
        <li class="empty">目前尚無使用者資料</li>
      }
    </ul>
  }

  @if (selectedUser(); as user) {                     <!-- as 可把值鎖進區域變數 -->
    <div class="detail-card">
      <h3>使用者詳細資訊</h3>
      <p>ID: {{ user.id }}</p>
      <p>姓名: {{ user.name }}</p>
    </div>
  }
</div>

核心模板語法對照：

語法類型 寫法範例 用途說明
資料渲染 {{ value }} 把 Component 的狀態輸出至 DOM
屬性綁定 [disabled]="isPending" 把 DOM 屬性綁定至 Component 變數
事件綁定 (click)="handleClick()" 監聽 DOM 事件並執行 Component 方法
條件渲染 @if (cond) { ... } @else { ... } 取代舊版 *ngIf，內建控制流
列表渲染 @for (item of list; track item.id) 取代舊版 *ngFor，強制要求指定 track 效能鍵
類別動態切換 [class.active]="isSelected" 條件成立時自動附加 CSS class
💡 跟 React 對照著記

Angular 的 @if / @for 對應 React 的 {cond && ...} 與 list.map()；track user.id 對應 React 的 key={user.id}，兩者都是為了讓框架用最小代價 diff 出真正變動的節點。差別是 Angular 從 v17 起把 track 設為強制，React 的 key 只會警告。

(g) React Native 也是用 JSX，差在 UI 組件與樣式

React Native 完全使用 JSX，State／Props 傳遞機制與 Web 端 React 幾乎一模一樣。主要差異在基本 UI 組件與樣式寫法：

比較項目 React (Web) React Native (Mobile)
容器／區塊 <div> <View>
文字 <p> <span> <h1> <Text>（所有文字必須包在 <Text> 內）
圖片 <img src="..." /> <Image source={...} />
可點擊元素 <button> <a> <TouchableOpacity> <Pressable>
滾動列表 <div> + CSS overflow <ScrollView> <FlatList>
樣式處理 CSS／SCSS／Tailwind JS 物件（StyleSheet.create），預設 Flexbox
點擊事件 onClick onPress 
import React, { useState } from 'react';
import { View, Text, TouchableOpacity, StyleSheet } from 'react-native';

export default function App() {
  const [count, setCount] = useState(0);
  return (
    <View style={styles.container}>
      <Text style={styles.title}>當前計數：{count}</Text>
      <TouchableOpacity style={styles.button} onPress={() => setCount(count + 1)}>
        <Text style={styles.buttonText}>加 1</Text>
      </TouchableOpacity>
    </View>
  );
}

const styles = StyleSheet.create({
  container: { flex: 1, justifyContent: 'center', alignItems: 'center' },
  title: { fontSize: 18, marginBottom: 10 },
  button: { backgroundColor: '#007AFF', padding: 10, borderRadius: 5 },
  buttonText: { color: '#FFF' }
});

核心心智模型（Component、Hooks、Data Flow）完全共通，所以 React 開發者通常只需補學原生 UI 組件與裝置 API。

(h) Vue 是「漸進式框架」，可當函式庫也可當框架

Vue 官方定位是 Progressive JavaScript Framework（漸進式 JavaScript 框架），意思是它可大可小：

  • 當輕量函式庫用：像引入 jQuery 那樣直接用 <script> 標籤掛進現有 HTML 頁面，只負責特定區塊的 UI 與資料綁定，不控制整個專案架構。
  • 當完整框架用：搭配官方生態系 Vue Router（路由）、Pinia（狀態管理）、Vite（建構打包）、SFC 單檔案組件規範，此時它掌握整個應用程式架構。

三者定位對比：

工具 定位類型 運作哲學
React UI 函式庫 核心僅專注 View 渲染，路由與狀態管理自由搭配社群套件（React Router、Zustand）
Vue 漸進式框架 核心可輕量載入，需要時導入官方維護的路由與狀態管理，兼顧靈活與一致
Angular 全功能框架 開箱即用，內建 HTTP 客戶端、表單驗證、路由，架構規範嚴格
ℹ️ 為什麼這一格要跟 [[程序編程-Procedural-Programming-與控制反轉IoC對比]] 一起看

「Vue 是框架還是函式庫」這題之所以難答，正是因為判準是控制權讓渡了多少，而不是體積或功能數量。用 <script> 引入時你的程式仍主導流程（程序式），用 SFC + Router 時進入點變成 Vue 的 runtime（控制反轉）。同一個工具在光譜上滑動，這就是「漸進式」三個字的真正含意。
