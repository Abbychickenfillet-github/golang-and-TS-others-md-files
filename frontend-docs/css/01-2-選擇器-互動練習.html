零‧先分清楚：Compound selector跟Combinator不是同一件事

官方分類（來源：CSS selector structure - MDN，最後更新於2025-12-16）：compound selector是好幾個simple selector黏在一起、中間沒有分隔符，同時作用在同一個元素上，例如.image.active；complex selector才是用combinator（空白、>、+、~）分隔、代表兩個不同元素之間關係的選擇器，例如.image .active（中間有空白，變成後代組合器）。下面四種是complex selector裡會用到的combinator，先弄清楚這個前提再往下看。

一‧四種組合選擇器對照

名稱語法範圍
後代選擇器A B任意深度的子孫都算
子選擇器A > B只算直接子層，隔一層就不算
相鄰兄弟選擇器（相鄰選擇器）A + B只選緊接在A後面的那一個B
一般手足選擇器（手足選擇器）A ~ B選A後面同層所有的B，不用緊接

四‧是非題

1. div > span可以選到<div><p><span>裡面那個span。
是
非
答案：非。子選擇器>只選直接子層，中間隔了一層p，這個span是div的孫層而不是子層，選不到。如果要選到它，要用後代選擇器div span。
2. ~跟+都只能選「後面」的手足，CSS沒有辦法選「前一個」手足。
是
非
答案：是。純CSS選擇器沒有「往前選手足」的組合器，這是規格上的限制，要做到這件事只能靠JavaScript或調整HTML結構順序。
3. ::before不需要寫content屬性也會顯示出來。
是
非
答案：非。::before／::after必須搭配content屬性（哪怕是空字串content:""）才會真正被渲染出來，沒寫content的話即使有其他樣式規則也不會顯示。

五‧申論題

Q：為什麼OOCSS反對用.sidebar h3這種後代選擇器寫法？這跟這篇筆記的組合選擇器概念有什麼關係？
👉 展開參考答案
因為後代選擇器.sidebar h3把樣式綁在「h3被放在哪個容器裡」，而不是綁在h3自己身上的class，這正是OOCSS反對的「位置依賴（location-dependent）樣式」；同一個h3只要被搬到別的容器，樣式就會直接跑掉。而且後代選擇器通常會讓選擇器鏈變長，容易疊高specificity，變成之後要覆蓋時得寫更長的選擇器或動用!important，這也是為什麼BEM、OOCSS都鼓勵直接把樣式寫在元素自己身上的單一class，而不是靠後代選擇器去間接命中。
