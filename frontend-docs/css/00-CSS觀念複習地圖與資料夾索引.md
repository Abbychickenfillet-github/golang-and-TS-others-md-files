# CSS觀念複習地圖與資料夾索引

> 用途：這份是「觀念複習順序」的地圖，回答的問題是「這個資料夾裡的東西該按什麼順序看、看之前要先懂什麼」。跟同資料夾的[[CSS練習位置索引]]用途不同，那篇是「某個練習用的html實體檔案放在硬碟的哪個角落」，是純粹的檔案定位工具，兩篇不合併，但互相加了反向連結，避免以後搞混這兩份「索引」各自是做什麼用的。

---

## 一‧核心複習順序（依前備知識由淺到深排列）

a. **選擇器（Selectors）**：官方定義的五種選擇器結構——Simple／Compound／Complex／Selector List／Relative Selector，以及四種combinator。前備知識：無，這是整個CSS最底層的基礎。
   - 已有筆記[[01-1-選擇器-組合後代手足相鄰偽選擇器]]跟互動練習[[01-2-選擇器-互動練習]]，這一版已經改成完全照[CSS selector structure - MDN](https://developer.mozilla.org/en-US/docs/Web/CSS/Guides/Selectors/Selector_structure)（最後更新於2025-12-16）官方分類重寫，因為Abby看完官方文件後覺得自己原本整理的分類方式比較亂，官方的準確度優先。
   - Abby自己的[Google文件筆記](https://docs.google.com/document/d/1HWVhoPRm26mj7GBmXHXZo62gQxC61bTkNjbJlmRzz24/edit?usp=sharing)（含自寫範例、jQuery程式碼、F12截圖跟YouTube參考影片）保留當作補充範例來源，之後有空可以把裡面的`.row2`/`.col2`這類自己的範例跟F12截圖穿插進正式筆記裡，但主幹架構以官方文件為準。

b. **盒模型（Box Model）**：搭配精美圖片重點講`border-box`，這階段先不用鋪開講其他屬性。前備知識：a（至少要能用選擇器選到元素，才有東西可以套盒模型）。已有筆記[[02-1-盒模型-BoxModel與border-box]]跟互動練習[[02-2-盒模型與border-box-互動練習]]，內含盒模型圖解SVG跟content-box／border-box即時互動demo；也可以順便跟第三節的「其他CSS雜項筆記」互相對照，因為之前`grid-alignment-issue.md`裡討論的表頭/內容列對齊偏移，本質上就是盒模型沒抓對造成的。

c. **其他屬性的縮寫方法**：用你的Google Slides講義代替（[連結](https://docs.google.com/presentation/d/1qByGnhhy9N3VTiv0G6XlqUZkSpqJVwOV/edit?usp=sharing&ouid=102773491422871022603&rtpof=true&sd=true)），不用另外重複做本地筆記。前備知識：a、b（要先知道選擇器選到誰、盒模型有哪些屬性，才看得懂哪些屬性可以縮寫、縮寫時的順序規則）。

d. **CSS自訂屬性 / SCSS變數（補一項你原本沒列出、但我建議插進來的前備知識）**：原生CSS的`--variable`跟SCSS的`$variable`差在哪、`:root`全域宣告的意義。已有筆記：[[03-1-樣式階層表變數定義帶編譯解釋]]。前備知識：a、b。建議放在四大方法論之前讀，理由見下方「二」的說明。

e. **Specificity權重 + inherit繼承概念**：目前這兩塊內容都埋在[[04-1-CSS方法論與權重-OOCSS-BEM-SMACSS-ITCSS]]這篇筆記的後半段（「CSS權重速查」與「補充筆記」兩節），不是獨立檔案。前備知識：a（權重計算要看選擇器種類：ID、class、元素各佔多少）。建議調整順序見下方「二」。

f. **CSS四大方法論（OOCSS／BEM／SMACSS／ITCSS）**：已有完整筆記[[04-1-CSS方法論與權重-OOCSS-BEM-SMACSS-ITCSS]]，外加兩份互動練習[[04-2-OOCSS-vs-BEM-CSS命名方法論]]、[[04-3-CSS方法論時間軸與OOCSS結構觀念-互動練習]]。前備知識：a、b、d、e——OOCSS的「結構外觀分離」要看得懂盒模型屬性有哪些才分得出「哪些是結構、哪些是外觀」；ITCSS的Settings層放的就是d的變數；ITCSS整層排序的邏輯依據就是e的specificity由低到高；BEM為什麼要避免巢狀選擇器，也是因為e的specificity概念。這是目前資料夾裡份量最重、也複習得最完整的一塊。

## 一點五‧檔名編號規則（主題號-子項號，方便同主題底下多檔案時計數）

資料夾裡實際檔名前面改用「主題號-子項號」兩段式數字，跟上面「一」的字母a~f是兩套不同的編號系統，對照關係如下：

- `01-1` = a的筆記本體、`01-2` = a的互動練習（選擇器）
- `02-1` = b的筆記本體、`02-2` = b的互動練習（盒模型）
- c（屬性縮寫）沒有對應的本地檔案，直接用你的Google Slides講義，所以數字序列跳過c
- `03-1` = d的筆記本體（CSS自訂屬性／SCSS變數），目前只有一份，之後如果多做一份互動練習就會是`03-2`
- `04-1` = e＋f的筆記本體（specificity權重＋inherit繼承＋四大方法論，e目前是嵌在這篇筆記裡面，還沒拆成獨立檔案）、`04-2` = OOCSS vs BEM互動練習、`04-3` = 方法論時間軸互動練習、`04-4` = ITCSS實戰盤點（把`04-1`的七層理論套到 official_website 專案上，實測全域檔現況）
- 之後同一個主題如果又新增檔案（例如01再多一份延伸筆記），依序往下編號成`01-3`、`01-4`……不要另外開新的主題號，這樣同一主題底下有幾份檔案，一看子項號就數得出來。

## 二‧跟你原本順序不同的地方（e跟f的順序建議對調，並補了d）

你原本列的順序是「4方法論 → 5權重 → 6繼承（你也發現混在4裡面了）」。我的建議是把e（權重＋繼承）搬到f（方法論）**之前**，原因是：

- 方法論本質上是「解決cascade／specificity問題的架構套路」，如果還沒搞懂specificity是什麼、怎麼算，就沒辦法真正理解「BEM為什麼堅持只用單一class、不疊加ID或巢狀選擇器」「ITCSS為什麼要按照特異性由低到高排檔案順序」這些設計背後的道理，只能死背規則。
- 相反地，specificity跟inherit這兩個是CSS cascade本身的底層機制，跟你用不用OOCSS、BEM完全無關，先獨立搞懂它們，之後看四大方法論才會覺得「喔原來是在解決這個問題」，而不是「這是另一套要背的新規則」。
- d（變數）建議也搬到f之前，因為ITCSS七層裡的Settings層，裝的就是這些`--variable`／`$variable`，如果d沒先懂，f那篇筆記裡`@use 'settings'`那段會看得一頭霧水。

至於實際筆記檔案要不要真的物理拆開（把e從那篇方法論筆記獨立出來成一個檔案），這個我先不動，因為那篇筆記已經累積了不少跨連結內容，值不值得拆是你的判斷——如果你之後想「只複習權重，不想從頭滑到底找」，跟我說一聲，我可以幫你拆成三個獨立檔案並保留反向連結。

## 三‧同資料夾其他資料整理（第7點回覆）

除了上面a~f這條複習主線之外，資料夾裡還有幾篇性質不同的筆記，分四組，附上分類理由跟建議：

**視覺效果／裁切遮罩技巧（應用類，建議a~f都熟了之後再看，因為要靈活運用背景與盒模型）**
- [[background-clip-text-文字鏤空]]：`background-clip:text`做文字鏤空透底圖。
- [[圖形中間挖空-hollow-的CSS做法]]：`mask-image`、`clip-path`、`box-shadow`做圖形挖空。
- 這兩篇本質上是同一類問題（怎麼把背景/形狀「裁切」出鏤空效果），建議之後可以加一個共用的tag例如`#裁切效果`，或考慮合併成一篇「CSS裁切鏤空效果總整理」，目前分開存放也不影響閱讀。

**SVG基礎（獨立技術主題，不算CSS cascade本身，但常跟CSS搭配使用）**
- [[svg-basics-and-display]]：SVG是什麼、必要結構、`display`行為。
- 這篇建議保留在原地即可，但如果之後SVG相關筆記變多，可以考慮獨立一個`svg-problem`資料夾。

**框架與除錯實務筆記（實務踩坑紀錄，不是觀念學習，屬於「用到某個框架時遇到的坑」）**
- [[chakra-spacing-and-heading-alignment]]：Chakra UI數字間距換算成rem/px。
- [[grid-alignment-issue]]：Grid表頭跟內容列對齊偏移的除錯過程。
- [[tailwind-arbitrary-value-and-min-height]]：Tailwind任意值語法、`min-h`跟`h`的差異。
- 這三篇風格上比較像「專案踩坑紀錄」而不是「打基礎的觀念筆記」，如果之後這類筆記持續增加，建議獨立出一個`troubleshooting`或`project-notes`子資料夾，目前只有三篇，量還不大，先留在原地、用tag區分即可。

**檔案定位工具（跟學習進度無關）**

## 四‧給你的建議總結

- 這份索引檔名前面加了`00-`，目的是讓它在檔案總管或Obsidian檔案列表裡永遠排在最前面，方便你每次打開資料夾第一眼就找得到。
- 之後每寫一篇新的CSS筆記，建議順手回來這份索引補一行，不然索引會跟實際筆記脫節（[[CSS練習位置索引]]目前就已經有「待整理」的欠帳，是同一個問題）。
- e（specificity＋inherit）要不要從方法論筆記拆成獨立檔案，等你需要「只複習權重」的時候再決定，跟我說一聲就能拆。
- a、b目前都已經有本地筆記（[[01-1-選擇器-組合後代手足相鄰偽選擇器]]、[[02-1-盒模型-BoxModel與border-box]]），a這篇已改版改照MDN官方CSS selector structure的分類重寫過；c維持用你的Google Slides講義即可，不用另建本地筆記；d、e、f已經有紮實的筆記，複習優先度可以往後排。
- 檔名編號從單段（`01-`、`02-`……）改成兩段式（`01-1`、`01-2`……），是因為同一個主題常常不只一份檔案（筆記本體＋互動練習），單段編號沒辦法一眼看出同主題底下有幾份檔案，兩段式讓子項號直接對應「這是這個主題的第幾份檔案」，之後新增同主題檔案只要接著往下編號即可，見上方「一點五」的對照表。
