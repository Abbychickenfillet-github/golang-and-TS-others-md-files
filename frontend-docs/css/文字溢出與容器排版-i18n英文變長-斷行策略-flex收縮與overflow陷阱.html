🧠 自我測驗

是非題

  1. 中文比英文更容易造成文字溢出容器。

    相反。中文每字等寬、可在任意兩字之間換行；英文是空白分隔的單字，瀏覽器預設不會把單字切斷，所以更容易撐破容器。

  2. word-break: break-word 是目前規範建議的寫法。

    它已被標示為 deprecated，現代規範建議用 overflow-wrap: break-word 或 overflow-wrap: anywhere。

  3. overflow: hidden 會連 box-shadow 一起裁掉。

    它切掉所有超出邊界的繪製內容，陰影與溢出文字都會被吃掉，是排版除錯的常見兇手。

  4. 父層是 display: flex 時，子層寫 width: 100% 一定會生效。

    flex 子項預設 flex-shrink: 1，空間不夠時會被壓縮；交叉軸方向若父層設 align-items: center，子層還會縮成內容的最小尺寸。

  5. max-width 搭配 width: 100% 一起寫，才能兼顧上限與可收縮。

    max-width 管上限、width: 100% 管空間不足時能縮，缺一都會在某個斷點出事。

  6. 用 <label> 包住整張卡片可以讓整張卡片都變成可點擊區。

    label 與內部 input 產生關聯，點 label 任一處都會觸發該 input，對螢幕閱讀器也更友善。

填空題

  1. 排查文字溢出時，第一個要去 Computed 面板檢查的屬性是 white-space 是不是 。

    它會讓文字完全不換行，一路往右衝，是頭號嫌疑犯。

  2. 只有在整行放不下時才把單字切開，應該用 : break-word。

    斷得最自然，是一般文案的首選。

  3. 網址或雜湊值這種無空白的長字串，可用 word-break: 強制切斷。

    不管單字邊界，滿了就切。

  4. 多語系容器建議用 max-width 搭配 單位，例如 34ch。

    ch 代表字元寬度，中英文都能自動適應，不必寫死 px。

  5. i18n 的 i 與 n 中間有 個字母。

    Internationalization 的縮寫由來。

  6. 讓 flex 子項不被壓縮，要設 flex-: 0。

    預設值是 1，代表空間不足時允許收縮。

申論題

  1. Future Sign 官網切到英文版時 footer 標語溢出容器。請說出你的完整排查順序與三種修法的取捨。

    排查順序：一、F12 選到溢出元素，看 Computed 的 white-space 是不是被設成 nowrap；二、往上找有沒有寫死的 width 或 max-width（本例是 .footer-tagline-container 的 max-width: 260px）；三、檢查父層是不是 display: flex、子層有沒有被 flex-shrink 壓縮；四、檢查有沒有 overflow: hidden 把內容切掉；五、最後才調字級與行高。三種修法：方案一放寬容器上限（max-width 從 260px 改 320px 並加 width: 100%），最推薦，因為它處理的是根因——容器對英文而言太窄，且 width: 100% 保住小螢幕的可收縮性；方案二讓文字自動斷行（white-space: normal 加 overflow-wrap: break-word），適合寬度不能動的情況，缺點是長單字被切開閱讀體驗較差；方案三調 font-size 與 line-height，只適合超出一點點的微調，缺點是動到字級會影響視覺層級的一致性。實務上最好的長期解是改用 max-width 搭配 ch 單位，讓中英文都自動適應。

  2. 同事說「我 flex 子層明明寫了 width: 100%，為什麼還是縮成一小塊？」請完整解釋原因並給出修法。

    因為 flex 子項的預設 flex-shrink 是 1，代表主軸空間不足時允許被壓縮，width: 100% 只是「期望值」而非「保證值」，flex 演算法會依照 flex-basis、flex-grow、flex-shrink 重新分配。另外若父層 flex-direction: row 且設了 align-items: center，交叉軸（此時是垂直方向）不再 stretch，子層會縮成內容的最小尺寸——要注意這影響的是交叉軸方向，不是寬度，很多人在這裡搞混。修法有三：一、對不該被壓縮的子項設 flex-shrink: 0；二、把 align-items 改回預設的 stretch，讓子項在交叉軸撐滿；三、若真正需要的是最小寬度保護，設 min-width（注意 flex 子項的 min-width 預設是 auto，有時要顯式設成 0 才能讓內容正常收縮）。排查時建議在 DevTools 把可疑的 overflow: hidden 暫時關掉，確認不是它造成的視覺誤判。

文字溢出與容器排版：i18n 英文變長、斷行策略、flex 收縮與 overflow 陷阱

本篇重點 a–n，共 14 個。兩段 Gemini 對話合併：Future Sign 官網切換英文版時 footer 標語溢出容器的修法，以及票券／掃描頁面卡片排版被 +container 那一層影響的除錯方向。

重點整理

一、為什麼切英文就爆版

  • i18n ＝ Internationalization，國際化（i 與 n 中間有 18 個字母），指讓同一套介面支援多語系。
  • CJK ＝ Chinese、Japanese、Korean，中日韓文字。

(a) 同一句話翻成英文通常會變長 30% 到 50%，而中文每個字都是等寬方塊、可以在任意兩字之間換行；英文是由空白分隔的單字串，瀏覽器預設不會把一個單字從中間切斷，所以固定寬度的容器一旦裝不下最長的那個單字就會撐破或溢出。

(b) 本例的元凶是 .footer-tagline-container 寫死了 max-width: 260px，中文標語剛好塞得下，英文版 "A story about home, time, and the beauty of imperfection." 就滿出來。

二、三種修法（由推薦到微調）

(c) 方案一：放寬容器上限（最推薦）

.footer-tagline-container {
  max-width: 320px; /* 由 260px 放寬以容納英文 */
  width: 100%;      /* 小螢幕時仍能收縮，不會硬撐 */
}

重點是 max-width 搭配 width: 100% 一起寫：max-width 管上限、width: 100% 管「空間不夠時可以縮」，兩者缺一都會在某個斷點出事。

(d) 方案二：讓文字自動斷行

.footer-tagline {
  white-space: normal;      /* 確保沒有被別的規則設成 nowrap */
  word-break: break-word;   /* 遇到超長單字強制斷開 */
  overflow-wrap: break-word;/* 標準寫法，優先讓字在單字邊界換行 */
}

(e) 三個屬性的差別要分清楚：

屬性 行為 什麼時候用
white-space: nowrap 完全不換行，一路往右衝 溢出時的頭號嫌疑犯，先檢查有沒有被誰設成這個
overflow-wrap: break-word 只有在整行放不下時才把單字切開 一般文案的首選，斷得最自然
word-break: break-all 不管三七二十一，滿了就切 網址、雜湊值、無空白的長字串

(f) word-break: break-word 其實是已被規範標示為 deprecated 的舊寫法，現代規範建議用 overflow-wrap: break-word 或 overflow-wrap: anywhere。兩個一起寫是為了相容舊瀏覽器，不是必須。

(g) 方案三：微調字級與行高（只差一點點時）

.footer-tagline {
  font-size: 14px;  /* 或 0.9rem */
  line-height: 1.6;
}

(h) 實務建議：多語系網站不要對文字容器寫死 px 寬度，改用 max-width ＋ ch 單位（例如 max-width: 34ch，代表約 34 個字元寬），這樣中英文都能自動適應。

三、卡片與掃描區的排版優化（票券頁）

(i) 卡片間距：卡片之間留 margin-bottom: 16px 左右的垂直間距，增加呼吸感，比擠在一起好掃讀。

(j) 點選回饋範圍：右側是 radio 或 checkbox 時，要讓整張卡片都是可點擊區（clickable area），而不是只有那個小圓圈。做法是用 <label> 包住整張卡片內容，這樣點卡片任一處都會觸發對應的 input，同時對螢幕閱讀器也更友善。

(k) 狀態區分：已被選中的卡片除了原本的黃色邊框，可再加上淡底色或輕微的 box-shadow，讓選取狀態有一致的視覺語彙。

(l) 相機掃描區（Scanner UI）：預覽框的 border-radius 要與上方卡片一致，維持圓角語彙統一；「相機準備中」時放一段簡單的掃描線動畫當佔位符（placeholder），提示使用者這裡即將出現畫面。

四、+container 那一層為什麼會影響排版

(m) Flexbox 衝突：如果父層是 display: flex，子層寫 width: 100% 常常會失效。原因是 flex 子項的預設值是 flex-shrink: 1，空間不夠時會被壓縮；再加上父層若有 align-items: center（交叉軸置中），子層在交叉軸方向會縮成內容的最小寬度而不是撐滿。修法是視情況加 flex-shrink: 0，或把 align-items 改成 stretch（預設值）。

(n) Overflow 限制：檢查該層是否有 overflow: hidden。它會切掉超出邊界的內容，連 box-shadow 和溢出的文字都會被硬生生裁掉，看起來就像陰影消失或文字被吃掉。除錯時先在 DevTools 把這條暫時關掉，就能確認是不是它造成的。

除錯順序（遇到文字溢出時照這個順序查）

  1. 開 F12 選到溢出的元素，看 Computed 面板的 white-space 是不是 nowrap。
  2. 往上找有沒有寫死的 width 或 max-width（px 值）。
  3. 檢查父層是不是 display: flex，子層有沒有被 flex-shrink 壓縮。
  4. 檢查有沒有 overflow: hidden 把東西切掉。
  5. 最後才調 font-size 或 line-height。

⚠️ 存疑／更正

  • Gemini 建議 word-break: break-word，但這個值在 CSS 規範中已被標示為 deprecated（僅為相容舊內容而保留），正解應以 overflow-wrap: break-word 為主，必要時用 overflow-wrap: anywhere。詳見 MDN 的 word-break 條目說明。
