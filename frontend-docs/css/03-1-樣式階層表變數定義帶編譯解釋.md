# CSS
定義變數=自訂屬性Custom Properties
它的核心規則是名稱前面一定要加上兩條減號--，而且通常會定義在:root（代表全域，整個網頁都抓得到）裡面。

```css
/* 步驟1：在:root全域宣告變數 */
:root{
	--primary-color: #007bff;
	--card-padding: 20px;
}

/* 步驟2：使用var() 函數把變數呼叫出來*/
.card{
	padding: var(--card-padding);
	border: 1px solid #ccc;
}
```
原生CSS的變數則是必須寫在選擇器內

原生CSS變數是「執行時（Runtime）」動態讀取：
變數會原封不動地送進瀏覽器，瀏覽器在渲染網頁時才去動態讀取--primary-color是什麼顏色。

# SCSS
```css
$primary-color: #3b5998;
$font-stack: Helvetica, sans-serif;

body{
	font-family: $font-stack;
	color: $primary-color;
}
```

SASS/SCSS變數是**「編譯時（Build time）處理」**：
肇因：瀏覽器根本看不懂$primary-color。
但專案打包、編譯時，Sass編譯器（目前主流是用Dart語言寫的Dart Sass，屬於Source-to-source compiler／原始碼對原始碼轉譯器）預先把所有的$primary-color替換成真實的顏色（例如#3b5998），最後產出一份純粹的原生CSS給瀏覽器

> [!warning] ⚠️ 存疑／更正（2026-07-19）
> 這裡原本寫「用BABEL從SASS到CSS」是錯的。Babel只管JavaScript（把ES6+語法轉成舊版相容語法），完全不處理CSS或Sass。真正把.scss編譯成.css的是Sass自己的編譯器（現在最常用Dart Sass），跟Babel是兩條平行、互不相干的轉譯流程，在Webpack或Vite這類打包工具裡分開處理：.scss交給Sass編譯器、.js/.jsx交給Babel。來源：Gemini對話澄清（查證日2026-07-19）。

# 用 JS 動態修改原生 CSS 變數
```CSS
document.documentElement.style.setProperty('--primary-color','#fff')
```

他們：
- 運作時間點不同
- 能不能被JavaScript動態修改
	- SASS/SCSS變數：不行。因為編譯成CSS後，$的痕跡已經完全消失了，JS找不到它。
	- 原生CSS變數：可以，可以用以上語法去改:root的變數做到全站一秒換主題

# UI Library 的變數機制：不是二選一，是混合式

本篇重點 a–d，共 4 個。

原生 CSS 變數是純執行時，SASS/SCSS 是純編譯時——但主流 UI library 大多是**兩者混用**，差別在「誰負責把 token 算成最終值」。

| | 主要機制 | 編譯時 or 執行時 | 能不能不重新建置就換主題 |
|---|---|---|---|
| Bootstrap ≤4 | Sass 變數（`$primary`），編譯時被字面值取代 | 純編譯時 | ❌ 要重新跑 Sass |
| **(a) Bootstrap 5** | Sass 變數控制預設值，但**輸出的 CSS 用的是 `--bs-*` 原生變數** | 兩層：Sass 決定預設值，輸出結果是可執行時覆寫的 CSS 變數 | ✅ 部分可以——`--bs-primary` 能在執行時被 JS/CSS 覆寫 |
| **(b) Ant Design v4 及以前** | Less 變數（`@primary-color`），`less-loader` 的 `modifyVars` 編譯時取代 | 純編譯時 | ❌ 不行（早期 `@ant-design/dark-theme` 曾把整個 Less 編譯器搬進瀏覽器在執行時重編譯，效能很差，後來被 v5 取代） |
| **(c) Ant Design v5** | Design Token（JS 物件）＋ `@ant-design/cssinjs` 動態插入 `<style>` | 純執行時，但走的是 **CSS-in-JS**，不是原生 CSS 變數 | ✅ `ConfigProvider` 換 theme 不用重新建置 |
| **(d) Tailwind v3** | JIT 在建置／dev server 階段掃 class 名稱，產生對應靜態 CSS | 主要編譯時 | ❌ 改 `tailwind.config.js` 要重新建置；但透明度、漸層這類 class 內部用 `--tw-bg-opacity`、`--tw-gradient-from` 這種執行時 CSS 變數做組合，是編譯時規則裡藏的執行時接縫 |
| Tailwind v4 | `@theme` 區塊直接把設計 token 生成原生 CSS 變數 | 編譯時決定「有哪些 class」，但 token 值本身是執行時 CSS 變數 | ✅ 比 v3 多，因為 `--color-red-500` 這類 token 可以直接在執行時被覆寫 |

**判準**：問「換主題要不要重新跑建置工具」。Sass/Less 變數要；原生 CSS 變數不用。Bootstrap 5、Tailwind v4、Ant Design v5 能做到「執行時換主題」的共同解法，都是**把最終產物落在原生 CSS 變數或執行時注入的 style 上**，差別只在「誰負責算出這個值」——Bootstrap／Tailwind 是建置工具把 Sass/token 轉成 CSS 變數，Ant Design v5 是直接用 JS 在瀏覽器裡即時算。
