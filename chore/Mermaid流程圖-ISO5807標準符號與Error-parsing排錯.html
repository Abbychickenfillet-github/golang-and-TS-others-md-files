一、flowchart TD 本身沒有錯

flowchart TD 是 Mermaid 完全合法且標準的開頭。出現 Error parsing mermaid diagram 時，問題幾乎不在這一行，而在後面某個字元。

a TD ＝ Top-Down，同義寫法 TB；其他方向有 LR、RL、BT。
b 舊寫法 graph TD 還能用，但官方已改推 flowchart。

三、ISO 5807 標準符號

形狀名稱用途Mermaid 語法
圓角矩形Terminator 起止流程的開始與結束A([開始])
平行四邊形Input／Output資料進出B[/"輸入：Source Code"/]
矩形Process 處理系統做的運算或動作C[詞法分析 Lexer]
菱形Decision 決策條件判斷D{有語法錯誤嗎}
圓柱形Database資料庫／持久化E[(資料庫)]
圓形Connector跨頁接點F((接點))

f 原本的疑問「起頭該不該用圓邊起止符號寫 ESLint」——不該。起止符號寫的是動作的起訖（「開始：執行 ESLint」），工具名稱本身放在 Process 矩形裡。
g 輸入的原始碼用平行四邊形是對的，這個直覺完全正確。

範例：ESLint 從 Source Code 到 AST

flowchart TD
    A([開始：執行 ESLint]) --> B[/"輸入：Source Code 原始碼"/]
    B --> C[詞法分析 Lexer：把程式碼拆成 Tokens]
    C --> D[語法分析 Parser：把 Tokens 組成 AST]
    D --> E[/"輸出：AST 抽象語法樹"/]
    E --> F[走訪 AST 節點並比對規則]
    F --> G{有 error 等級的違規嗎}
    G -- Yes --> H[回報 Error 或執行 --fix]
    G -- No  --> I[通過檢查]
    H --> J([結束])
    I --> J

錯在 subgraph 標題的中括號裡同時出現 (、) 與 ->。Mermaid 的 lexer 看到裸露的 ( 會以為你要開一個「體育場形節點」，看到 -> 會以為是邊線語法，於是整段 parse 失敗。
