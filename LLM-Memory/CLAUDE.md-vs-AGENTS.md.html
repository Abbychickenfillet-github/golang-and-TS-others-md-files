一、Claude Memory vs CLAUDE.md

比較項目Claude Memory（記憶功能）CLAUDE.md（專案設定檔）
主要定位使用者個人化的長期記憶單一專案的開發規範指引
運作層級帳號層級，跨專案、跨對話專案層級，綁在某個 repository
運作平台Claude 的 Web／App 介面Claude Code（CLI）與相關工具
誰在維護AI 自動擷取，使用者也可手動增刪開發者手寫，進 Git 版控

團隊共享不會（是你個人的）會（commit 進 repo，全隊共用）

一句話分辨：Claude Memory 是「AI 記住『你』是誰」，CLAUDE.md 是「AI 了解『這個專案』該怎麼開發」。

實務後果
Abby 自己的 vault CLAUDE.md 就註明：「Claude Desktop 設定裡的記憶是全域、app 層級的偏好，跟這個 vault 的 CLAUDE.md 不會自動同步；以下是手動鏡射。」
這正是上表「運作層級」那一列的後果：兩邊不會互相寫入，改了一邊另一邊不會知道，所以需要手動鏡射一份。

二、自己考自己

1. Claude Memory 跟 CLAUDE.md 是同一個東西的兩種寫法。
2. CLAUDE.md 可以 commit 進 Git 讓團隊共用同一套 AI 行為規範。

填空：Claude Memory 的運作層級是 帳號層級，CLAUDE.md 是 專案層級。

申論：如果你希望「所有專案都用繁體中文回答」，這條規則該寫在哪裡？為什麼？


寫在 Claude Memory（或 app 層級的個人偏好設定）。因為「用繁體中文回答」是關於你這個人的偏好，跟任何一個 codebase 都無關，寫進 Memory 之後每開一個新對話、每換一個專案都會生效。
反過來，「本專案 commit 前要先跑 npm run lint 與 docker compose up --build」這種就該寫在 CLAUDE.md，因為它只對這個 repo 成立，而且要讓團隊每個人都拿到同一份。
