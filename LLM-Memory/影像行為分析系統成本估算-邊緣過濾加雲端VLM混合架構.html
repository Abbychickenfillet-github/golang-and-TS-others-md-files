費用要拆成兩塊看

(a) 一次性的硬體成本（電機端）與持續性的 API 成本（模型端）。會把人燒死的是後者，不是前者——硬體是幾千塊一次付清，API 是每天都在扣。

一、硬體端（一次性）

(b) 影像採集端三種選法：

方案 用途 對話中的估價（NTD）
ESP32-CAM 極低成本、定時拍照上傳 $250 – $400
Raspberry Pi 5 + 鏡頭模組 主流選擇，支援即時串流與初步過濾 $3,000 – $4,500
USB 網路攝影機 / IP Cam 串接現成監視器 $1,000 – $3,000

(c) 周邊：3D 列印外殼、壁掛支架、Type-C 供電與變壓器，約 $300 – $800。

(d) 選配但關鍵：邊緣運算推論卡（Hailo-8、Google Coral 之類），約 $3,000 – $6,000。它的投資報酬不在效能，在於幫你擋掉 90% 以上不需要送雲端的畫面。

(e) 硬體小計：樹莓派＋一般鏡頭一台端點約 NT$4,000 – NT$6,000。

二、模型端（持續性）——為什麼會爆

(f) 影像消耗的 token 遠比文字多。一張圖通常折算 1,000 – 3,000 tokens，相當於一整頁文字。最致命的錯誤是把未過濾的影片串流直接往 LLM API 塞，那樣一天可以燒掉四位數。

(g) 兩種觸發策略的試算對比（假設一張關鍵影格 2,000 input tokens，輸出行為紀錄約 100 tokens，以輕量多模態模型費率估）：

方案 觸發方式 每日圖片數 每日 API 費用 每月估算
A 定時觸發 每 5 分鐘截一張 288 張 約 US$0.20 – 0.40 約 NT$200 – 400
B 動態偵測 邊緣端偵測到人動才送 50 次 約 US$0.05 約 NT$50

(h) 兩者差了 4 到 8 倍，而差別只在「有沒有在邊緣端先過濾」這一個設計決策。這就是本篇真正該記住的東西。

三、省錢的三個關鍵做法

(i) 絕對不要把未過濾的 video stream 無腦往 LLM API 塞。

(j) 善用 Prompt Caching（提示詞快取）。「行為定義」那一大段 System Prompt 每次都一樣，快取起來後讀取成本可以降到原價的一小部分（各家折扣不同，Anthropic 的快取讀取約為輸入價的 10%）。這對本案特別有效，因為 system prompt 固定不變、只有圖片在換。

(k) 地端／雲端混合架構（推薦）：

鏡頭 ──► 樹莓派本地跑 YOLO（免費、離線）
              │
              ├─ 沒偵測到人 ──► 丟棄，不花任何錢
              │
              └─ 偵測到人在動 ──► 截當下影格（或前後 3 秒短片）
                                      │
                                      ▼
                            多模態 VLM API 辨識詳細行為
                                      │
                                      ▼
                              寫入資料庫（時間＋行為描述）

分工原則：便宜的模型做「有沒有」，貴的模型做「是什麼」。YOLO 只回答「畫面裡有沒有人、有沒有在動」，這種二元判斷不需要語言模型；只有需要生成「14:30 陳小姐坐在書桌前開始翻閱書籍」這種語意描述時，才值得叫 VLM。

(l) 用這種架構，單個鏡頭的模型運作成本可以壓在每月 NT$100 以內。
