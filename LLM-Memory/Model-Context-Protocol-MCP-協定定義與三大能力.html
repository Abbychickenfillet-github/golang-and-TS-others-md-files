一句話定義

(a)MCP（Model Context Protocol，模型上下文協定）是一個開放標準，用來讓 LLM 應用程式（Host）以統一的方式，安全地連接到外部的資料來源與工具。

(b)Abby 原本的講法「讓應用軟體接到外面的服務」方向是對的，需要修正的只有一個詞：重點不在「裝置」，而在「資料與工具的串接」。裝置只是其中一種可能的後端。

(c)常見的比喻：MCP 之於 AI 應用，就像 USB-C 之於周邊裝置——在它出現之前，每一個 AI 應用要接每一個資料源都要寫一套自己的整合，是 M × N 的工作量；有了共同協定之後變成 M + N。

三個角色

(d)Host：使用者實際在用的 AI 應用（例如 Claude Desktop、Cowork、IDE 外掛）。它負責決定要載入哪些伺服器、以及要不要讓模型呼叫某個工具。

(e)Client：Host 內部針對「每一個」Server 開的連線代理，一對一。

(f)Server：提供能力的那一端，例如檔案系統、資料庫、Gmail、Figma。Server 不需要知道自己被哪個模型使用，這是這個協定能通用的關鍵。

使用者  ──►  Host（AI 應用）
                 ├── Client 1 ──► Server A（檔案系統）
                 ├── Client 2 ──► Server B（資料庫）
                 └── Client 3 ──► Server C（Gmail）

Server 對外暴露的三大能力

(g)Tools（工具）：可被模型呼叫的函式，附帶自然語言描述與 JSON Schema 參數定義。這是唯一會「產生副作用」的類型，所以規格上是「model-controlled，但需要 Host 取得使用者同意」。實際會用 Tools 做的事：發送 Email、查詢資料庫、執行 Git 命令、操作 GitHub API、呼叫 Google Search API。

(h)Resources（資源）：用 URI 識別的唯讀上下文，例如一份檔案、一筆資料列。它是「被讀進脈絡」而不是「被執行」。常見的 Resources 內容：本地專案文件、日誌檔案（Logs）、資料庫 Schema、特定 API 回傳的 JSON 資料。

(i)Prompts（提示範本）：可重複使用的提示樣板，通常由使用者主動選用（例如斜線指令）。常見範例：程式碼審查範本（Code Review Template）、Bug 除錯引導流程。

(o)現成 MCP Server 的常見應用情境：GitHub / GitLab MCP（讀 Issue、PR、Commit 紀錄或建立 Branch）、PostgreSQL / MySQL MCP（唯讀查詢資料庫結構與執行 SQL）、Fetch / Web Browsing MCP（抓取網頁內容或爬蟲）、Filesystem MCP（限定存取電腦中特定資料夾的檔案）。這些對照到上面的表格，資料庫查詢與檔案系統多半落在 Resources，會寫入或執行動作的（建 Branch、發 Email）落在 Tools。

(p)使用者視角 vs 開發者視角容易搞混的地方：claude.ai/directory/manage（Submissions）是開發者提交、管理「自己寫的」MCP Server 審核狀態的地方，不是使用者安裝入口，所以還沒發佈過就會看到空白，這是正常現象。一般使用者要安裝別人寫好的 MCP Server，要嘛在本機設定檔（例如 claude_desktop_config.json）裡設定，要嘛去官方或社群的 Claude Connectors Directory 找現成服務。

傳輸方式（Transport）

(j)stdio：Server 以本機子行程執行，透過標準輸入輸出交換訊息。本機工具最簡單的選擇，也是大多數桌面應用的預設。

(k)Streamable HTTP：2025-03-26 版引入，單一 MCP 端點同時支援 POST 與 GET，並可選用 SSE（Server-Sent Events）串流。取代了更早的 HTTP+SSE 雙端點設計。

2026-07-28 規格的重大變動

(l)協定核心改為無狀態（stateless）：移除傳輸層的 session 管理與 Mcp-Session-Id 標頭。實務意義：MCP Server 可以直接放在一般的 HTTP 負載平衡後面水平擴充，不必再做黏性連線（sticky session）。

(m)其他新增項目：Multi Round-Trip Requests（多輪往返請求）、header-based routing（以標頭做路由）、cacheable list results（清單結果可快取）、授權強化、正式的 Extensions 擴充框架、Tasks，以及 MCP Apps——讓 Server 可以附帶互動式 HTML 介面，由 Host 放在沙箱 iframe 中呈現。

(n)面試講法：「MCP 把『AI 應用 ↔ 外部系統』的整合從 M×N 降到 M+N。它定義三種能力：Tools 是可呼叫且有副作用的函式，Resources 是唯讀上下文，Prompts 是提示範本。傳輸支援本機 stdio 與遠端 Streamable HTTP。2026-07-28 版把協定核心改成無狀態，拿掉 session 標頭，讓 Server 能用一般 HTTP 基礎設施水平擴充。」

關聯筆記與關聯原因

  • [[網頁轉API供Agent使用-vs傳統爬蟲]]：兩者解的是同一個問題的兩種路線——都是「怎麼把外部世界變成 Agent 能吃的結構化輸入」。爬蟲是單向硬解，MCP 是雙方約定好的協定。
  • [[rag-vs-memory-comparison]]：MCP 是「取得上下文的管道」，RAG 是「挑選上下文的策略」。管道與策略是正交的兩件事，實務上常一起用（MCP Server 提供檢索工具，內部跑 RAG）。
