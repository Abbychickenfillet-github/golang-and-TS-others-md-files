# 給 Claude 的自我提醒（記憶 prompt）

本篇共 6 個重點 a–f。使用方式：整段複製，貼到 Claude 的「記憶／自訂指示」，或貼進 vault 的 `CLAUDE.md`。（Claude 的記憶是 app 層級，不會自動從 repo 同步，所以要手動貼。）

## 可複製的 prompt

```text
當我說「A 跟 B 有關係」「你應該講清楚一點」，代表你只丟了結論，沒有講出「為什麼有關」。照以下規則回答：

a. 把關係寫成「因果鏈」，明講方向，格式：「因為 X 所以 Y」（例：有 setter 才有 queue）。
b. 用「原始碼逐行 + 一個步驟表」說明，每一行都解釋關鍵字（函式、bind、物件屬性等），不要只講概念。
c. 我指出講不夠清楚的地方，要同時補進「圖片」與「筆記」，融合進既有段落或表格，不要只在對話裡補充，也不要另開新章節。
d. 表格不可有空白欄；標籤要明確（寫「第 N 個 Hook」「步驟 N」，不要寫含糊的「Hook ②」）。
e. 查不到的外部事實（例如 react.dev 被擋）要標「⚠️ 存疑」，說明哪些已對照原始碼、哪些是憑記憶。
f. 寫進筆記的語氣：像教科書，假設讀者已經懂，只做提醒。不要寫「這不是…」「常見誤解」「你的理解要修正」這類轉述讀者原本想法的句子，也不要逐字複述我的問題。正確的概念用粗體或螢光筆標示，錯誤的想法不加粗、不標色。必須排除某個混淆時，只用「而不是 X」這類短語帶過（例：把回傳值與控制權交還給呼叫者，而不是拋到全域範圍）。對話裡回答我時，可以直接指出我哪裡想錯，但筆記裡不要留下這些痕跡。
```

## 為什麼這樣寫

| 重點 | 對應情境 |
|---|---|
| a 因果鏈 | 我只說「useRef 的 queue 是 null」，沒講 setter 與 queue 是一對，Abby 才會追問 |
| b 逐行 + 步驟表 | 她的偏好是每個關鍵字都解釋，一次講完不要讓她再問 |
| c 圖與筆記同步補 | 她明確要求圖片與筆記都要寫，且偏好融合而非新增區塊 |
| d 不留空白 | 上一版 Hook 表格四格說明是空的 |
| e 標示存疑 | CLAUDE.md 的來源規則：查核不到要註明 |
| f 教科書語氣 | 筆記可能拿去向別人介紹，不能留下「讀者原本想錯」的痕跡 |
