一句話原理：PowerShell 管線裡跑的是物件不是文字。Get-Command git 給你一個物件，外層 ( ) 先把它算出來，再用 .屬性 去讀身上掛的那一欄。所以同一個指令，換個 .屬性 就拿到不同東西。

一、.Source 為什麼不一定是路徑？（冷知識重點）

.Source 的內容，完全取決於這個指令的 CommandType：

CommandType.Source 是什麼例子
Application（外部 exe）✅ 執行檔完整路徑git / node / python
ExternalScript（.ps1）✅ 腳本完整路徑claude.ps1
Cmdlet❌ 是「模組名稱」不是路徑Get-ChildItem → Microsoft.PowerShell.Management
Alias❌ 空的！要用 .ResolvedCommand 追dir → Get-ChildItem
(Get-Command dir).CommandType        # Alias
(Get-Command dir).ResolvedCommand    # Get-ChildItem   ← 追到真身

這也是筆記 CLAUDE.md 裡那則「claude 殼有了但跑不起來」會看到 ExternalScript claude.ps1 的原因：npm 全域安裝在 Windows 上會放 claude、claude.cmd、claude.ps1 三個殼。

二、為什麼 dir /s /b 找不到檔案？

C:\Users\User> dir /s /b "Claude對於push到遠端是會出錯的啊.md"
找不到檔案

但檔案明明在 C:\coding\futuresign\Abby-notes\claude CLI\...，同一顆 C 槽啊？

🔑 病根：/s 是「從目前目錄往下遞迴」，不是「掃整顆磁碟」

C:\                          ← 根
├── Users\User\              ← 你人在這裡（cwd），/s 只掃這棵子樹
└── coding\...\claude CLI\
        └── Claude對於push到遠端是會出錯的啊.md   ← 掃不到！

C:\Users\User 和 C:\coding 只是兄弟，共同掛在 C:\ 底下。同一顆磁碟 ≠ 同一棵子樹。

解法是把搜尋起點拉到根：dir /s /b "C:\*push到遠端*"（會很慢，因為要掃整顆 C）。

三、PowerShell 裡正確的找檔案方式

❌ 不要在 PowerShell 打 dir /s /b：這裡的 dir 是 Get-ChildItem 的別名，不吃 /s /b 這種 CMD 斜線參數，會把 /s 當路徑解析然後報錯。

Get-ChildItem -Path C:\coding -Recurse -Filter "*push到遠端*" -ErrorAction SilentlyContinue |
    Select-Object -ExpandProperty FullName
參數為什麼要
-Recurse才會往子資料夾鑽（等同 CMD 的 /s）
-Filter "*關鍵字*"由檔案系統底層過濾，比 -Include 快很多，找檔名優先用它
-ErrorAction SilentlyContinue掃到沒權限的資料夾會噴紅字，用這個吞掉

縮寫版（互動時打字用）

gci C:\coding -r -fi "*push到遠端*" -ea 0 | % FullName

gci=Get-ChildItem、-r=-Recurse、-fi=-Filter、-ea 0=-ErrorAction SilentlyContinue、%=ForEach-Object。
