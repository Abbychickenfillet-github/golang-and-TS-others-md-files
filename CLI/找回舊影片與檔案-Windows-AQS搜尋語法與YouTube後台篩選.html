是非題

  1. 設為「不公開（Unlisted）」的 YouTube 影片，用前台搜尋框還是找得到。

    前台絕對搜不到，必須進 YouTube Studio 後台的「你的影片」才看得見。

  2. AQS 支援正規表示式，可以用 .* 做模式比對。

    AQS 只有欄位加比較運算子，要做真正的模式比對得走 PowerShell。

  3. Everything 之所以快，是因為它直接讀 NTFS 的主檔案表（MFT），不必等索引建好。

    代價是它預設只搜檔名、不搜內容。

  4. 找不到自己錄的影片時，用「內容關鍵字」比用「檔案大小」更可靠。

    當年隨手取的檔名通常跟內容對不上，客觀屬性（大小、日期、型別）才可靠。

  1. AQS 的全名是 Advanced Syntax，是 Windows 檔案總管與 Windows Search 共用的查詢語言。

    進階查詢語法。

  2. 只列出系統判定為影片的檔案，AQS 要寫成 kind:video（含精確比對符號）。

    = 是精確比對，kind:=video 比 kind:movie 明確。

  3. 要篩出大於 100MB 的檔案，跨語系最保險的寫法是 :>100MB。

    中文版 Windows 雖然接受部分中文欄位名，但英文欄位名才通用。

  4. 螢幕錄影檔常常不在「影片」資料夾，而是躺在錄影軟體的 儲存路徑底下。

    OBS、Zoom、QuickTime 各有各的預設資料夾。

找回舊影片與檔案：Windows AQS 搜尋語法、Everything 與 YouTube 後台篩選

本篇重點 a–j，共 10 個

情境：要找一支自己錄的 XSS 學習影片，但用標題關鍵字怎麼查都查不到。核心觀念是 — 當年隨手取的檔名跟你現在記得的內容通常對不上，所以要放棄「用內容關鍵字找」，改成「用檔案的客觀屬性篩」：型別、副檔名、大小、日期。

1. 先講清楚縮寫：AQS 是什麼

a. AQS 是 Advanced Query Syntax（進階查詢語法），Windows 檔案總管與 Windows Search 共用的一套查詢語言。你在搜尋框輸入的 kind: 、ext: 、size: 、datemodified: 這些都是 AQS 的欄位，冒號後面接條件，多個條件用空白隔開就是 AND。

b. AQS 不是正規表示式（Regex），它沒有 .* 這類萬用比對，只有欄位加比較運算子。想做真正的模式比對要走 PowerShell，見 PowerShell-找檔案與遞迴搜尋陷阱。

2. Windows：用屬性篩，不要用檔名篩

c. 常用 AQS 欄位對照（查證 2026-09-09）：

欄位 意思 範例
kind:=video 只列出系統判定為影片的檔案 kind:=video
ext: 指定副檔名 ext:mp4
size: 依檔案大小篩選 size:>100MB
datemodified: 依修改日期篩選，可用區間 datemodified:>01/01/2026
datecreated: 依建立日期篩選 datecreated:>01/01/2026
contents: 搜尋檔案內容（需已建索引） contents:XSS

d. 組合起來就是一句查詢：kind:=video size:>100MB datemodified:>01/01/2026。
這句話翻成人話是「請列出所有系統認得是影片、檔案大於 100 MB、而且 2026 年 1 月 1 日之後被改過的檔案」。螢幕錄影檔通常很大，所以「大小」比「檔名」可靠得多。

e. Everything 是更快的替代方案。它是 Windows 上的免費檔名搜尋工具，直接讀 NTFS 的主檔案表（MFT），所以是即時列出全機檔名，不必等索引建好。缺點是它預設只搜檔名、不搜內容。

f. 最常被忽略的一步：去看錄影軟體的預設儲存路徑。OBS、Zoom、QuickTime、Windows 內建的螢幕錄影，各自有自己的預設資料夾，檔案很可能根本不在你以為的「影片」資料夾，而是躺在 C:\Users\<使用者>\Videos 或 Documents 底下。

3. YouTube：前台搜不到不代表影片不存在

g. 關鍵觀念：設為「不公開（Unlisted）」或「私人（Private）」的影片，在 YouTube 前台搜尋是絕對搜不到的。要找就必須進 YouTube Studio 後台的「你的影片（Your Videos）」。

h. 後台的三個篩法：
1. 篩選器選「瀏覽權限」，把「不公開」與「私人」都勾起來。
2. 篩選器選「日期」，縮到你大概學那個主題的月份或年份。
3. 把每頁顯示筆數拉到最大，直接用縮圖肉眼掃 — 學習錄影的縮圖多半是編輯器畫面，即使標題是「未命名」或一串日期，看縮圖也認得出來。

i. 別忘了播放清單：當初可能順手歸到「課程」「程式學習」「未分類」之類的清單裡，從清單反查比從搜尋框查快。

4. 最後一條線索：回頭查自己的筆記庫

j. 在 Obsidian 裡搜 XSS、Web Security、Cross-Site Scripting、錄影，看當時的筆記有沒有順手貼上不公開連結，或寫了「今天錄了 XSS 的影片，檔名是⋯」這種雜記。
這也反過來說明為什麼筆記要跟產出物互相連結 — 筆記本身就是最後一道索引。

行動 checklist

  • [ ] 用 kind:=video 或 ext:mp4 撈出所有影片，按「修改日期」排序。
  • [ ] 檢查 OBS／QuickTime／螢幕錄影軟體的預設儲存路徑。
  • [ ] 用 size:>100MB 依大小排序，長影片一定排在前面。
  • [ ] 進 YouTube Studio 後台（不是前台首頁）。
  • [ ] 篩選器勾「不公開」與「私人」。
  • [ ] 用縮圖掃有沒有程式碼畫面的影片，即使標題是預設日期或「未命名」。
  • [ ] 回 Obsidian 搜主題關鍵字，看筆記裡有沒有留連結或檔名。

5. ⚠️ 存疑與更正

  • Gemini 寫的 kind:movie 大小:>100MB 混用了中英文欄位名。中文版 Windows 的搜尋框確實接受部分中文欄位名，但跨語系一律用英文欄位名 size: 才保險，本篇表格已統一改成英文。
  • Gemini 把 kind:movie 與 kind:=video 混著寫。= 是精確比對，kind:=video 比 kind:movie 明確，建議固定用前者。
  • macOS 的部分本篇不展開，因為 Abby 目前是 Windows 環境；Finder 的搜尋框跟 Spotlight 原生查詢語法（mdfind）規則不同，Gemini 給的 ext:mp4 OR ext:mov 不保證在 Finder 搜尋框直接生效，真要用建議走 mdfind 指令。

6. 關聯筆記與理由

  • PowerShell-找檔案與遞迴搜尋陷阱 — 當 AQS 的欄位篩選不夠用（例如要用萬用字元或遞迴比對內容），下一步就是走 PowerShell 的 Get-ChildItem -Recurse，那篇講了遞迴會踩到的坑。
  • 檔案命名禁用字元與空格規則 — 這次找不到檔案的根本原因是「命名」，那篇講的是命名規則，兩篇合起來就是「怎麼命名才不會有下次」。
  • grep-options — 在 Linux／WSL 環境下，contents: 的對應工具就是 grep，概念一樣是「不靠檔名靠內容」。
  • 副檔名意義總表 — 用 ext: 篩之前得先知道錄影軟體會吐哪些副檔名（.mp4、.mov、.mkv、.webm），那份圖鑑就是查這個用的。
