重點整理

(a) Windows／macOS 等現代作業系統禁止用在檔名中的特殊字元：\ / : * ? " < > | 這幾個符號，其中最容易被忽略的是結尾處的冒號 :——實測案例中使用者一直找不到問題字元，最後才發現是檔名結尾藏了一個冒號，導致系統拒絕重新命名。

(b) 空格是允許的：只要不使用上述那組禁用符號，檔名中間留空格在 Windows 和 macOS 都能正常命名，不會被系統拒絕。

(c) 作業系統允許的字元，放進網址不一定安全：網址只允許一小組字元直接出現，其他字元都要經過百分比編碼（percent-encoding），轉成 % 加兩位十六進位的形式。

  1. 可以直接出現的是 RFC 3986 的 unreserved 字元：A-Z a-z 0-9 - . _ ~。
  2. 其他字元都要編碼，例如空格變成 %20，^ 變成 %5E，中文先轉成 UTF-8 的 bytes，每個 byte 寫成一組 %XX（「與」變成 %E8%88%87）。
  3. 實際案例（2026-11-15）：筆記檔名 13-SemVer語意化版本-版本號的^與~怎麼看.html 在 Obsidian 打得開，用 VS Code Live Server 開卻出現 Cannot GET。錯誤訊息裡的網址解碼後是「版本號的與~怎麼看」，^ 在組網址的過程中被丟掉了，沒有被正確編碼成 %5E，伺服器因此去找一個不存在的檔名。~ 屬於 unreserved 字元，所以留了下來。
    Obsidian 打得開，是因為它直接讀硬碟上的檔案，不經過網址這一層。
  4. 處理方式：把檔名改成 13-SemVer語意化版本-版本號的caret與tilde怎麼看.html（caret 是 ^ 的英文名稱，tilde 是 ~）。
  5. 之後要用 Live Server 或 GitHub Pages 開的檔名，只用英數字、-、_ 和中文，避開 ^ # % & + ? 和空格這類在網址裡有特殊意義、或需要編碼的字元。
