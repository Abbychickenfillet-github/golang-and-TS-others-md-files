重點整理

(a) Get-Content settings.json（不加 -Raw）會把檔案內容逐行讀成字串，並以陣列形式回傳——用 $content.GetType() 檢查會看到是集合型態，每一行是陣列中的一個元素。

(b) Get-Content settings.json -Raw（加上 -Raw）會把整個檔案當成一個完整的長字串讀取，這樣才能正確解析出完整的 JSON 結構（無論原始資料是陣列還是物件）。-Raw 並不是把 JSON 的方括號移除，而是讓解析器能一次看到完整的 JSON 定義，避免逐行讀取把結構切碎。

(c) 為什麼不加 -Raw 會讓 ConvertFrom-Json 解析出錯：因為 JSON 格式通常是一個整體結構，若被逐行拆成字串陣列，ConvertFrom-Json 可能無法正確還原原本的資料結構。

(d) 管線（pipe |）的意義：把左邊指令的輸出當作右邊指令的輸入。Get-Content settings.json -Raw | ConvertFrom-Json 整句意思是：把檔案完整讀成一個字串，交給 JSON 解析器（parser）處理。

(e) JSON 解析器 vs HTML 解析器的差異：JSON 解析器把輕量資料交換格式轉換成程式語言的資料結構（物件/陣列）；HTML 解析器把網頁原始碼轉換成 DOM 樹用來呈現網頁結構——一個處理資料、一個處理文件結構呈現。

(f) JSON 解析不需要像 Webpack/Vite 那樣的大型打包工具，因為它只是一種資料格式，多數程式語言都有內建解析工具：JS/TS 用內建 JSON.parse()，Java、Python 也都有對應內建函式庫或模組，不需額外安裝。
