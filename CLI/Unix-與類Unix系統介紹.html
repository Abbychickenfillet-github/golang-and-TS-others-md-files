Unix 與類 Unix 系統介紹

重點整理

Unix 家族可分成兩大類：經官方認證的「正統 Unix」，以及行為高度相似但法理上不能叫 Unix 的「類 Unix（Unix-like）」。個人電腦最常見的是 Windows，但伺服器、工程工作站與蘋果生態系都是 Unix 家族的天下。

1. 蘋果 Apple（macOS / iOS）該看鳥哥網站

鮮為人知：Mac 是目前世上發行量最大的官方認證 Unix 系統。

  • 核心叫 Darwin，以 BSD（著名 Unix 分支）＋ Mach 微核心為基礎。
  • 通過 The Open Group 的 UNIX 認證（UNIX 03 合規），所以 MacBook、iMac、Mac mini／Studio 本質上都是 Unix 電腦。

2. 傳統企業級 Unix 工作站／伺服器

由科技巨頭為高效能運算或企業伺服器開發，多採非 x86 的專屬處理器：

  • IBM AIX：跑在 IBM Power 系統上，廣用於銀行、金融、大型企業核心系統。
  • Oracle Solaris（原 Sun Microsystems）：學術界與大型網路伺服器名系統，跑在 SPARC 或 x86。
  • HP-UX：HP 為其專有伺服器開發的 Unix。

3. 類 Unix：Linux 家族

Linux 因商標與授權原因不能直接叫 Unix，但完全模仿 Unix 的架構與哲學，現今絕大多數伺服器都跑 Linux。

  • 常見發行版：Ubuntu、Debian、CentOS、RHEL（Red Hat）、Alpine Linux 等。
  • 載體：雲端與企業伺服器、容器（Docker 映像常用 Alpine／Debian）、嵌入式裝置等。

[!info] 一句話
macOS＝有認證的正統 Unix；Linux＝沒掛 Unix 商標但骨子裡是 Unix 的類 Unix；兩者都遵循 Unix 哲學，所以指令與操作手感相通。

追加 2026-09-09：/usr 到底是什麼——它不是「使用者資料夾」

[!danger]+ 最大的誤會先破除
/usr 不是 Windows 的「使用者」資料夾。名字長得像，內容卻剛好相反。Unix 上真正對應 Windows C:\Users\你的帳號 的是 /home/你的帳號（macOS 上是 /Users/你的帳號）。

/usr 的名字由來與定位

  • FHS＝Filesystem Hierarchy Standard（檔案系統階層標準），由 Linux Foundation 維護，規定 Linux／類 Unix 系統上每個頂層目錄該放什麼。現行版本是 FHS 3.0。
  • /usr 這個名字在歷史上有兩種解釋：UNIX Source Repository（Unix 原始碼倉庫）與 UNIX System Resources（Unix 系統資源）。早期它確實曾是放使用者家目錄的地方，後來家目錄被搬到 /home，/usr 就轉型成「系統資源」。
  • FHS 對 /usr 的定義是 shareable, read-only data（可共享、唯讀的資料）——放的是系統上所有使用者共用的程式、函式庫與文件，例如 curl、git 這些工具。
  • 為什麼是唯讀？因為 FHS 刻意把靜態檔案與會變動的檔案分開：會變動的全部搬去 /var，剩下的 /usr 就可以掛成唯讀、甚至放在唯讀媒體上，也不必跟著變動資料一起備份。開機不需要的東西才放這裡（開機必需的在 /bin、/sbin、/lib）。

對照表：/usr vs Windows 使用者目錄

Unix /usr Windows C:\Users\<帳號>
屬於誰 全系統所有使用者共用 特定單一使用者專屬
放什麼 共用程式、函式庫、標頭檔、說明文件 個人文件、下載檔案、應用程式的個人設定
可寫性 FHS 規定為唯讀（安裝套件時才由套件管理員寫入） 該使用者可自由讀寫
真正的對應者 對應 Windows 的 C:\Program Files 與 C:\Windows\System32 對應 Unix 的 /home/<帳號>（macOS 為 /Users/<帳號>）

/usr 底下的常見子目錄

路徑 放什麼
/usr/bin 一般使用者可執行的指令（git、curl、python3）
/usr/sbin 系統管理用的指令
/usr/lib 程式用到的函式庫
/usr/share 與架構無關的共用資料（說明文件、圖示、語系檔）
/usr/include C／C++ 的標頭檔
/usr/local 你自己手動編譯安裝的軟體，跟套件管理員裝的分開放，避免升級時被覆蓋

[!tip]+ 在 WSL 與 macOS 上的實際體感
在 WSL（Windows Subsystem for Linux）裡 ls /usr/bin 看到的是 Linux 那套工具，跟 Windows 的 C:\Windows\System32 是兩套完全獨立的東西——WSL 有自己的完整 Linux 檔案系統。要從 Linux 側去呼叫 Windows 程式，走的是 interop 機制，見 WSL-interop-從Linux叫Windows程式。macOS 因為是正統 Unix，/usr 的結構與 Linux 幾乎一致，但蘋果自己的東西放在 /System 與 /Library。
