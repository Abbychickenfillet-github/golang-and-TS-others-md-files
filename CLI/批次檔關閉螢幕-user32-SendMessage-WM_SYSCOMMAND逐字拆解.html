🧠 自我測驗

是非題

  1. @echo off 前面那個 @ 的作用，是連 echo off 這一行自己都不要印出來。

    因為 echo off 這行是在 echo 還開著的時候執行的，不加 @ 會先印出 echo off 五個字才生效。

  2. taskkill /f /im cmd.exe 只會關掉當前這個 CMD 視窗。

    /im 是依映像名稱比對，會殺掉所有叫 cmd.exe 的行程。你另外開的視窗會一起陪葬。想只關自己用 exit。

  3. Add-Type 可以在執行期間即時編譯一段 C# 並把型別載入當前 PowerShell session。

    所以這一行做的事是「現場寫 C#、現場編譯、現場用」。

  4. Add-Type 不加 -PassThru 也一樣可以接著用 :: 呼叫靜態方法。

    不行。-PassThru 才會把編譯出來的型別物件回傳出去，沒有它就接不到東西。

  5. SendMessage 是非同步的，丟出去就馬上返回。

    SendMessage 會等對方的視窗程序處理完才返回（同步阻塞）。丟了就走的是 PostMessage。

  6. SendMessage 的第一個參數傳 -1，代表廣播給系統中所有最上層視窗。

    -1 就是 HWND_BROADCAST。

  7. lParam 傳 1 是關閉螢幕、傳 2 是進入低耗電。

    反了。1 是低耗電，2 才是關閉，-1 是開啟。這組最常記錯。

  8. 把這支腳本包成 Windows 服務，開機就能自動關螢幕。

    因為 Session 0 Isolation，服務沒有存取顯示器的權限，這招在服務裡會失效。

填空題

  1. 負責視窗、訊息佇列、選單、滑鼠鍵盤輸入的 Windows 核心元件是 .dll。

    另外兩支常見的是 kernel32.dll（記憶體與行程）與 gdi32.dll（繪圖）。

  2. 讓 .NET 受管理程式碼去呼叫原生 DLL 函式的機制，縮寫 P/Invoke，全名 Platform Services。

    靠 [DllImport] 屬性標註來宣告。

  3. C# 裡宣告「這個方法沒有 body、實作在外部」的關鍵字是 。

    配合 [DllImport] 一起用。

  4. 0x0112 這個訊息代碼的常數名稱是 WM_。

    代表這是一則系統指令訊息。

  5. 0xF170 這個子指令的常數名稱是 SC_。

    WM_SYSCOMMAND 的子類別：顯示器電源管理。

  6. 微軟文件要求處理 WM_SYSCOMMAND 時，wParam 要先跟 0x 做 AND 遮罩才拿去比對常數。

    因為低 4 位元被系統保留給內部使用。

  7. PowerShell 裡呼叫靜態成員的運算子是兩個冒號 ，等同 C# 的點。

    例如 [Math]::Pow(2,10)。

申論題

  1. 有人在論壇丟給你一支三行的 .bat 檔說「按一下就能關螢幕」。請完整說明：這三行分別在做什麼（逐個參數解釋 SendMessage 的四個魔術數字）、你會在執行前檢查哪些資安紅旗、原版有哪兩個實作缺陷、以及為什麼它在 Windows 服務裡不會生效。

    參考方向：(1) 第一行 @echo off——echo off 關掉指令回顯，前綴 @ 讓這行自己也不顯示。(2) 第二行 powershell -windowstyle hidden -command "..."——啟動 PowerShell、隱藏視窗、執行單行指令；裡面的 \" 是跳脫字元，因為整串已經被一對雙引號包住。核心是 Add-Type 即時編譯一段帶 [DllImport("user32.dll")] 的 C#（這是 P/Invoke，Platform Invocation Services），-Name a 命名、-PassThru 把型別回傳出來，再用 :: 呼叫靜態方法 SendMessage。(3) 四個參數——hWnd = -1 是 HWND_BROADCAST，廣播給所有最上層視窗；hMsg = 0x0112 是 WM_SYSCOMMAND，系統指令訊息；wParam = 0xF170 是 SC_MONITORPOWER，顯示器電源管理；lParam = 2 是關閉（-1 開啟、1 低耗電）。順帶一提官方要求處理時 wParam 要先 & 0xFFF0，因為低 4 位元系統保留。(4) 第三行 taskkill /f /im cmd.exe——/f 強制、/im 依映像名稱。(5) 資安紅旗——-windowstyle hidden 隱藏視窗、一長串看不懂的內嵌程式碼、直接呼叫底層 API 這三點是惡意腳本的典型長相；ClickFix 那類社交工程攻擊就是誘騙使用者貼上執行看不懂的 PowerShell。執行任何來路不明的 .bat 前要先用記事本讀完。(6) 兩個缺陷——/im cmd.exe 會誤殺所有 CMD 視窗（該用 exit）；沒有先 sleep，你按 Enter 的殘留輸入會立刻把螢幕喚醒。另外 hWnd 宣告成 int 在 64 位元下不嚴謹，正式寫法應該用 IntPtr。(7) 服務失效的原因——Session 0 Isolation，Windows 服務跑在工作階段 0，沒有存取互動式桌面顯示器的權限。

原始碼

@echo off
powershell -windowstyle hidden -command "(Add-Type '[DllImport(\"user32.dll\")]public static extern int SendMessage(int hWnd, int hMsg, int wParam, int lParam);' -Name a -Passthru)::SendMessage(-1, 0x0112, 0xF170, 2)"
taskkill /f /im cmd.exe

f. 目的：關閉顯示器（讓螢幕進入省電狀態），然後把自己開出來的 CMD 視窗殺掉，做到「按一下就黑屏、不留視窗」。

重點整理

一、Batch 外層（g–i）

g. @echo off

片段 意思
echo on / echo off Batch 的內建開關。on（預設）會把每一行指令本身也印在畫面上；off 只印執行結果
開頭的 @ 「連這一行自己都不要印」。因為 echo off 這行本身是在 echo 還開著的時候執行的，不加 @ 就會先印出 echo off 這五個字才生效

h. taskkill /f /im cmd.exe

片段 意思
taskkill Windows 內建的行程終止工具（等同 PowerShell 的 Stop-Process、Linux 的 kill）
/f force，強制終止。不給行程收尾的機會，等同 Linux 的 kill -9（SIGKILL）
/im cmd.exe Image Name，用「執行檔名稱」指定目標，而不是用 PID

i. 陷阱：/im cmd.exe 是「殺掉所有叫做 cmd.exe 的行程」，不是「殺掉我自己」。如果你同時開了三個命令提示字元視窗，這一行會把三個都關掉。要只關自己，比較安全的寫法是 exit，或用 PID 精準指定。

二、PowerShell 的外層參數（j–k）

j. powershell -windowstyle hidden -command "..."

片段 意思
powershell 呼叫 Windows PowerShell 5.1（powershell.exe）。若是 PowerShell 7 則是 pwsh
-windowstyle hidden 執行時不要顯示那個藍色視窗。使用者完全看不到有東西閃過
-command "..." 把引號裡的字串當成 PowerShell 指令執行完就退出

k. -windowstyle hidden 是資安上的紅旗。合法的自動化腳本會用它避免畫面閃爍，但惡意程式也用它藏住自己的動作。看到來路不明的腳本帶這個參數，先停下來讀完內容再說。

裡面那些 \" 是 跳脫字元：整個 PowerShell 指令已經被一對雙引號包住了，所以字串內部的雙引號必須寫成 \"，CMD 才不會提早把引號閉合掉。

三、Add-Type 與 P/Invoke（l–o）

l. Add-Type 是 PowerShell 的 cmdlet，作用是在執行期間即時編譯一段 C# 程式碼，並把產生的 .NET 型別載入當前 session。換句話說，這一行做的事是「現場寫一個 C# class、現場編譯、現場用」。

參數 意思
第一個位置參數（那段 C# 字串） 要編譯的成員定義
-Name a 給這個臨時型別取名叫 a
-PassThru 把編譯出來的型別物件「回傳出去」，這樣才能接著用 :: 呼叫它的靜態方法。沒有這個參數的話 Add-Type 不回傳東西

m. [DllImport("user32.dll")] public static extern int SendMessage(...)

這是 .NET 的 P/Invoke（Platform Invocation Services，平台叫用服務） 寫法，讓受管理的 .NET 程式碼去呼叫非受管理的原生 DLL 函式。

片段 意思
[DllImport("user32.dll")] 屬性標註（Attribute），宣告「下面這個方法的實作在 user32.dll 裡面，不是我寫的」
user32.dll Windows 的核心元件之一，負責使用者介面：視窗、訊息佇列、選單、滑鼠鍵盤輸入
public static extern extern 是關鍵字，意思是「這個方法沒有 body，實作在外部」。static 讓它可以不建立實例直接用 :: 呼叫
int SendMessage(int hWnd, int hMsg, int wParam, int lParam) 對應原生 API 的簽章。四個參數的意義見下一節

n. SendMessage 是 Windows 訊息機制的核心函式，把一則訊息送進指定視窗的視窗程序（Window Procedure），而且會等到對方處理完才回來（同步阻塞）。相對的 PostMessage 是丟進佇列就走人（非同步）。

o. ::SendMessage(...) 裡的 :: 是 PowerShell 的靜態成員存取運算子，等同 C# 的 .。(Add-Type ... -PassThru)::SendMessage(...) 就是「把剛編出來的型別接住，直接呼叫它的靜態方法」。

四、四個魔術數字（p–r）

p. SendMessage(-1, 0x0112, 0xF170, 2) 逐個參數解讀：

參數位置 值 常數名稱 意義
hWnd（目標視窗控制代碼） -1 HWND_BROADCAST 廣播給系統中所有的最上層視窗，而不是指定某一個
hMsg（訊息代碼） 0x0112 WM_SYSCOMMAND 這是一則「系統指令」訊息
wParam（第一個參數） 0xF170 SC_MONITORPOWER 系統指令的子類別：顯示器電源管理
lParam（第二個參數） 2 — 電源狀態值

q. lParam 的三種值（這是最常記錯的一組）：

值 效果
-1 顯示器開啟（powering on）
1 顯示器進入低耗電狀態（low power）
2 顯示器關閉（shut off）

r. 為什麼 0xF170 這麼奇怪：WM_SYSCOMMAND 的所有子指令都落在 0xF000 以上，而且低 4 位元被系統保留給內部使用。微軟文件明確要求：處理 WM_SYSCOMMAND 時要先把 wParam 跟 0xFFF0 做 AND 遮罩，才拿去比對常數。

五、⚠️ 安全與限制（s）

s. 三件要知道的事：

項目 說明
惡意用途 這種「看不懂的一行 PowerShell」正是惡作劇程式與惡意軟體的典型長相。執行來源不明的 .bat 前，一定要先用記事本打開讀完
只能在互動式桌面 session 跑 因為 Session 0 Isolation（工作階段 0 隔離），Windows 服務無法用這招關螢幕。它必須從有存取顯示器權限的使用者 session 發出
螢幕可能立刻自己亮回來 只要有任何滑鼠移動或鍵盤輸入，Windows 就會重新喚醒顯示器。所以有些腳本會在發送訊息前先 Start-Sleep -Seconds 1，避開你按下 Enter 那一瞬間的殘留輸入

Gemini 說法 查證後 說明
