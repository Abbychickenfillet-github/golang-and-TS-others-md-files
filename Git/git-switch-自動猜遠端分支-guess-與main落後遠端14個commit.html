git switch --guess 與 main 落後遠端

本篇重點 a–g，共 7 個

重點整理

  • (a) git switch new-topic：本地沒有該分支、而遠端（如 origin）剛好有同名分支時，Git 會自動建立本地分支並設定追蹤，輸出 Branch 'new-topic' set up to track remote branch 'new-topic' from 'origin'。這就是 --guess（預設開啟的 DWIM，Do What I Mean）。
  • (b) 並非強制：單次用 git switch --no-guess <branch>，本地沒有就直接報錯；永久關閉用 git config --global checkout.guess false。
  • (c) ⚠️ 存疑／更正：Gemini 說「git checkout 完全沒有 --guess 功能」不精確。依官方手冊，git checkout 也有 --guess／--no-guess 與同名遠端分支自動建立追蹤的行為（git checkout 這個 DWIM 早於 2.23 就存在），git switch 只是把它獨立成專職指令。請以 git help checkout 核對。
  • (d) 兩個以上遠端都有同名分支（origin／upstream）時，自動猜測會因含糊而報錯，需手動指定 git switch -c <name> --track origin/<name>。
  • (e) SYNOPSIS git switch [<options>] [--no-guess] <branch>：<branch> 是這個指令的核心必填對象，所以獨立寫出；[<options>] 只放微調行為的選填開關。若併入 options 就變成「分支可有可無」，與語意不符。
  • (f) 終端機顯示 main「落後遠端 14 commits」：代表遠端 main 比本地多 14 個 commit，常見原因是在 GitHub 以 Pull Request 合併，本地沒有 git pull／git fetch 同步。先 git fetch 看差異，再 git pull（或 --ff-only）更新本地 main。
  • (g) 「Git 分支狀態」該篇的 Gemini 回答被截斷，後半解釋未取得，上述 (f) 為前半句推得，待 Abby 重開對話補充。
