CRLF 與 LF 的差異

本篇重點 a–e，共 5 個。關聯：git-line-endings-notes（Git 的 autocrlf 設定細節請看該篇）

重點整理

(a) 換行（Line Feed，LF，\n，ASCII 10）：文字中「結束當前一行、游標往下一行」的控制字元。

(b) 回車（Carriage Return，CR，\r，ASCII 13）：最初源自打字機與電傳打字機，作用是把游標（打字頭）移回「行首」。

(c) CRLF = CR + LF 兩個字元（\r\n）：Windows 與許多網路協定（HTTP、SMTP）使用。LF 只有一個字元（\n）：Linux、macOS 使用。

(d) 並非「不需要回車」：現代系統把「移回行首＋下移一行」整合成單一換行操作（LF），但回車符號在網路協定與舊格式（如 HTTP header 用 CRLF 分隔）中仍有特定作用。

(e) 實務陷阱：跨平台協作時 CRLF 與 LF 混用，會造成 Git diff 整檔變動或 shell script 報 ^M 錯誤，處理方式見 git-line-endings-notes。
