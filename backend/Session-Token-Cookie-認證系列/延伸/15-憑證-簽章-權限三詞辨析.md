# 憑證、簽章、權限三個詞不是同一件事

> 本篇重點 a–e，共 5 個。

## 重點整理

(a) <mark style="background: #FFF3A3A6;">權限 ≠ 憑證 ≠ 簽章</mark>：三者回答的是三個不同的問題，不能劃等號。Abby 一開始想把 credentials、權證、憑證、簽證 都列成同義詞，結果是「中文譯名重疊」造成的混淆，不是英文原詞同義。

| 概念 | 回答的問題 | 英文 | 典型例子 |
|---|---|---|---|
| 憑證 | 你是誰（身分證明） | Credentials | 帳號密碼、Session Cookie、Auth Token |
| 簽章 | 資料有沒被竄改、是不是本人發出 | Digital Signature | JWT 的 signature（HMAC 或 RSA 簽出來） |
| 權限 | 你可以做什麼 | Permissions、Authorization | Roles、Scope、Admin 權限 |

(b) <mark style="background: #ADCCFFA6;">憑證 一詞有兩個英文</mark>：Credentials（登入用的身分資料）與 Certificate（X.509 數位憑證，由 CA 簽發）在中文都叫「憑證」，這是最容易混的地方，讀文件時先確認原文是哪個字。

(c) 三者串成的運作順序：使用者出示憑證 → 伺服器驗證後核發帶簽章的 Token → 之後每次請求，伺服器先驗證簽章（確認 Token 沒被改、確實是自己簽的）→ 再依 Token 內的身分查權限 → 決定放行或 403。

(d) 對應到本系列：憑證與 Cookie 見 [[1-Cookie-與-Session]]，簽章與 Token 見 [[3-Session與JWT-有狀態與無狀態驗證-過期機制與Base64url]] 與 [[4-jwt-signing-algorithms-and-access-refresh-flow]]。關聯原因：JWT 的 signature 就是 (a) 表中的「簽章」，payload 裡的 role 或 scope 則是「權限」。

(e) 英文對照：認證 Authentication 對應「憑證」，授權 Authorization 對應「權限」，完整性 Integrity 對應「簽章」。

### ⚠️ 存疑／更正

(f) Gemini 把 RFC 7519 標成「數位簽章與憑證標準」並不精確：RFC 7519 定義的是 JWT 與 claims，簽章格式在 RFC 7515（JWS），X.509 憑證在 RFC 5280。
