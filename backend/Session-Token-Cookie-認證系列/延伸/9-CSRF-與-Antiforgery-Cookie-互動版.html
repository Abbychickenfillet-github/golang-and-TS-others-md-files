CSRF 與 Antiforgery Cookie

1. CSRF 是什麼（攻擊流程）

CSRF ＝ Cross-Site Request Forgery，跨站請求偽造。核心:利用「瀏覽器會自動帶上該網站的 cookie」這個特性,在你已登入 A 網站的狀態下,誘導你的瀏覽器對 A 發出你沒打算發的請求。

攻擊者從頭到尾「沒看到也沒偷到」你的 cookie，只是借用你已登入的狀態

白話:CSRF 不是偷 cookie（偷 cookie 是 XSS）,是讓你的瀏覽器替攻擊者送請求,反正瀏覽器會自動附上你的登入 cookie。

2. 為什麼 cookie 會害你中招

  • .AspNetCore.Antiforgery 這支 cookie 的用途是防止跨站請求偽造攻擊（CSRF, Cross-Site Request Forgery），用來驗證表單送出時的安全性。
  • 它跟「帳戶被鎖定」沒有關係，刪掉它也不會解鎖帳戶。帳戶鎖定通常是後端的登入失敗次數 / 安全策略造成的。
  • 正解：系統顯示「用戶帳戶被鎖定」時，應直接聯絡該網站客服處理，而不是自己刪 cookie。

3. Origin 與 Referer 到底指到哪裡（你問的）

你問:Origin、Referer 到底是指哪裡?畫出來。

兩個都是瀏覽器自動加的請求標頭,告訴後端「這個請求是從哪個頁面發出來的」。差別在範圍不同:

Origin ＝「哪個網站」；Referer ＝「哪一個網頁」（更細，含路徑）
  • 送出請求後若 DevTool 的 Network 沒有出現 200 成功回應，代表該動作沒有真的串到 API（前端表單可能根本沒打到後端）。這是判斷「重置密碼到底有沒有生效」的好線索。
  • 查 cookie 用途：F12 → Application → Cookies，看 cookie 的 name 與 domain。看到 Antiforgery、XSRF-TOKEN、csrf 這類字眼，多半就是 CSRF 防護 token，不是身分驗證或鎖定相關。

4. 三道防線

① SameSite cookie

現代主力。叫瀏覽器「跨站請求時不要帶這顆 cookie」。

  • Strict:跨站一律不帶(連點外站連結進來都不帶)。
  • Lax:跨站的安全導航(點連結 GET)會帶,但跨站 POST／表單／img 不帶 → 擋掉大多數 CSRF。現代瀏覽器預設 Lax。
  • None:跨站也帶(必須配 Secure),給需要跨站嵌入的場景。

② CSRF token（anti-forgery）

後端產一個隨機 token,放進頁面(表單 hidden 欄位或 meta);送請求時前端把它一起帶上,後端比對。

evil.com 受同源政策擋著,讀不到也猜不到這個 token,補不上就被擋。.AspNetCore.Antiforgery、XSRF-TOKEN 就是這類。

③ 驗 Origin / Referer

後端檢查請求的 Origin／Referer 標頭是不是自家網域,不是就拒絕(搭配第 3 節)。

5. SameSite 在 F12 長怎樣（示意）

查法:F12 → Application → Cookies → 點該網域,看右邊表格的 SameSite 欄。示意(仿 DevTools 畫面):

白話:看到 SameSite 欄是 Lax 或 Strict,就代表這顆 cookie 已經有「跨站不帶」的 CSRF 防護;XSRF-TOKEN 這種名字就是防 CSRF 的 token(不是身分驗證,也跟帳號鎖定無關)。

6. 認 cookie：Antiforgery / XSRF-TOKEN（融合原筆記）

  • .AspNetCore.Antiforgery 這顆 cookie 的用途是 防 CSRF、驗證表單送出安全性。
  • 它跟「帳戶被鎖定」沒關係,刪掉它也不會解鎖。帳戶鎖定通常是後端登入失敗次數／安全策略造成的。
  • 正解:看到「帳戶被鎖定」,直接聯絡該網站客服,而不是自己刪 cookie。
  • 認法:F12 → Application → Cookies,看到 Antiforgery、XSRF-TOKEN、csrf 這類字眼,多半就是 CSRF 防護 token,不是身分驗證或鎖定相關。

7. CSRF vs XSS（最容易搞混）

CSRF（跨站請求偽造）

  • 攻擊者看不到、偷不到你的 cookie。
  • 是「借用」你已登入的狀態,讓你的瀏覽器替他送請求。
  • 防:SameSite、CSRF token、驗 Origin／Referer。

XSS（跨站腳本）

  • 攻擊者真的注入 JS、能讀到頁面資料(可偷非 HttpOnly 的 cookie)。
  • 是「在你的頁面裡跑他的程式」。
  • 防:輸出轉義、CSP、HttpOnly cookie(見 [[8-XSS竊取Cookie原理與Next-cookies-API-HttpOnly防線]])。

一句話分:CSRF 借你的「身分」,XSS 偷你的「資料」。

8. 自我測驗

  1. (是非)CSRF 攻擊中,攻擊者必須先偷到你的 cookie 才能得手。

    不用。CSRF 是「借用」你已登入的狀態,瀏覽器會自動帶 cookie;偷 cookie 那是 XSS。

  2. (填空)Origin 標頭只到 層級(scheme+host+這個),不含路徑;Referer 則含 。

    Origin ＝ scheme://host:port(到 port);Referer ＝ 完整網址,含 path。

  3. (是非)現代瀏覽器 cookie 的 SameSite 預設是 Lax,能擋掉大多數跨站 POST 的 CSRF。

    對。Lax 下跨站 POST／表單／img 不帶 cookie,擋掉多數 CSRF。

  4. (申論)看到名為 .AspNetCore.Antiforgery 的 cookie,它是做什麼的?跟帳號被鎖定有關嗎?

    它是 CSRF 防護的 anti-forgery token,驗證表單送出安全性;跟帳號鎖定無關,刪它也不會解鎖,帳號鎖定要找客服。
