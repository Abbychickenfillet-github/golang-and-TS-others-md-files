主軸圖：一則訊息怎麼被壓縮傳送

重點整理

(a) 它是什麼：WebSocket 的壓縮擴充（Extension），握手協商，雙方都支援才生效，用 DEFLATE（與 gzip 同源）壓縮每則 payload。

(b) 名稱怎麼讀：⚠️ 更正：「每個訊息阻止膨脹」是誤譯。per-message ＝ 逐則訊息，deflate ＝ 壓縮（相反詞 inflate ＝ 解壓縮）。

(c) 誰做什麼：client 在握手標頭 Sec-WebSocket-Extensions 提出 → server 接受 → sender 用 zlib 壓縮 → 拋給對端 → receiver 用 zlib inflate 還原。

(d) ws 預設值：server 預設關閉，client 預設開啟，client 要 server 也啟用才真壓縮。

(e) 取捨：省頻寬（JSON／文字效果大）↔ 吃 CPU 與記憶體。

(f) 風險：高併發＋Linux＋Node.js 可能記憶體碎裂、效能下降。只在頻寬受限時啟用，上線前用正式負載測過。

const { WebSocketServer } = require('ws');
const wss = new WebSocketServer({
  port: 8080,
  perMessageDeflate: { threshold: 1024 }, // 小於 1KB 不壓縮
});
