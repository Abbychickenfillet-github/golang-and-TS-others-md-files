🧠 自我測驗

是非題

  1. HTTP 的 POST 是冪等的。

    POST 每次都新建一筆資料，重送會產生重複；PUT 與 DELETE 才是冪等。

  2. DELETE 是冪等的，因為刪第二次的結果仍然是「這筆資料不存在」。

    結果狀態相同，即使回傳的 status code 可能不同。

  3. 冪等的通用代數式是 a × a = a。

    那只有 a=0 或 a=1 成立；通則是 f(f(x)) = f(x)。

  4. PATCH 一定是冪等的。

    看內容：{"count": 5} 冪等，{"count": "+1"} 不冪等。

填空題

  1. 為了讓付款 API 在重送時不會扣兩次款，前端會產生一個唯一的 Key 隨請求送出，後端用它去重。

    Stripe 的 Idempotency-Key header 就是這個做法。

  2. 冪等的定義是：一個操作重複執行多次，結果與執行 次相同。

    f(f(x)) = f(x)。

  3. 冪運算的逆運算是 （用於計算底數要幾次方才能變成真數）。

    若 aˣ = N，則 x = log_a N。

申論題

  1. 設計一支「建立訂單」的 API，要如何確保使用者連點兩次送出鈕不會產生兩筆訂單？請說明完整機制。

    參考方向：(1) POST 本質不冪等，所以要靠外加的冪等鍵。前端在進入結帳頁時就產生一個 UUID 當 Idempotency-Key，放在 header 隨請求送出；重試時沿用同一個 key（不是每次重新產生）。(2) 後端收到請求先用該 key 查一張 idempotency 表（或 Redis），若已存在且處理完成，直接回傳上次的結果與 status；若存在但處理中，回 409 或讓客戶端稍後重試。(3) 寫入時把 key 設成資料庫的 UNIQUE 約束，靠資料庫層級保證併發下也只成功一筆（唯一索引衝突 = 重複請求）。(4) key 設定合理 TTL（例如 24 小時）避免無限膨脹。(5) 前端仍要做按鈕 disable 與 loading 狀態，但那只是體驗優化，不能當成正確性保證——真正的防線在後端。

關聯原因：冪等性是「重試策略」能安全成立的前提——沒有冪等，指數退避重試就會製造重複訂單；也是 REST 動詞設計（GET／PUT 冪等、POST 不冪等）的判準。

重點整理

一、兩個長得像但完全不同的詞

(a) 「冪等」不能當成「升冪」用，兩者在數學與資訊科學裡是完全不同的概念，中文只是剛好都有「冪」字。

特性 冪等（Idempotent） 升冪／冪運算（Exponentiation）
核心概念 重複操作，結果不變 數值累乘，數值持續變化
典型式子 f(f(x)) = f(x) a × a × a = a³
程式關聯 API 設計、資料庫寫入邏輯、重試機制 演算法複雜度、科學計算
重複執行的後果 穩定，沒有副作用累積 數值爆炸或塌縮

二、冪等（Idempotence）

(b) 定義：一個操作重複執行多次，其結果與執行一次相同。代數寫法是 f(f(x)) = f(x)。

(c) 數學例子：乘以 1（1 × 1 = 1）、乘以 0。這些是「重複做也不會變」的特例。

(d) 程式例子：toUpperCase() 轉兩次還是大寫；HTTP GET 讀一百次結果都一樣。

(e) HTTP 動詞的冪等性是面試常考題：

動詞 安全（Safe） 冪等（Idempotent） 說明
GET 是 是 純讀取，不改變狀態
HEAD 是 是 同 GET 但只回 Header
PUT 否 是 整筆覆蓋，做幾次結果一樣
DELETE 否 是 刪第二次仍是「不存在」這個結果
POST 否 否 每次都新建一筆，會產生重複資料
PATCH 否 不一定 看內容，{"count": 5} 冪等、{"count": "+1"} 不冪等

(f) 實務上最痛的場景：使用者連點兩次「付款」，或網路逾時後前端自動重送。解法是冪等鍵（Idempotency Key）——前端產生一個唯一 key 隨請求送出，後端用它去重，同一個 key 只真正執行一次。Stripe 的 Idempotency-Key header 就是這個做法。

三、升冪／冪運算（Exponentiation）

(g) 定義：把一個數自乘若干次，也就是 aˣ = N。

(h) 對數（Logarithm）是冪運算的逆運算：若 aˣ = N（a > 0 且 a ≠ 1），則 x = log_a N，其中 a 是底數、N 是真數。常見底數是 10（常用對數 log）與 e（自然對數 ln）。

(i) 與冪等剛好相反：除非底數是 1 或 0，否則重複執行會讓數值持續變化，這正是「冪等」所要求的穩定性的反面。

Gemini： 在數學和資訊科學中，「冪等」（Idempotent）與「升冪」（Power／Exponentiation）是兩個完全不同的概念，它們並不能互換使用。
1. 冪等（Idempotence）——定義：指一個操作如果重複執行多次，其結果與執行一次的結果相同。代數公式：f(f(x)) = f(x) 或 a × a = a。常見例子：數學上是數字 1 的乘法（1×1=1）或數字 0 的乘法；程式／資安上，GET 請求通常被視為冪等的（讀取一百次結果都一樣），或是將資料轉換成大寫的函式 toUpperCase()（轉換兩次結果還是大寫）。
2. 升冪／冪運算（Exponentiation）——定義：指將一個數自乘若干次的運算，也就是 aˣ = N。特性：除非底數是 1 或 0，否則重複執行會導致數值持續變化（增加或減少），這與「冪等」的穩定性剛好相反。
總結對比：冪等的核心概念是「重複操作，結果不變」，典型公式 f(x) = f(f(x))，程式關聯是 API 設計與資料庫寫入邏輯；升冪的核心概念是「數值累乘，數值變化」，典型公式 a×a×a = a³，程式關聯是演算法複雜度與科學計算。所以在專業語境下，我們不會把冪等當成升冪。
