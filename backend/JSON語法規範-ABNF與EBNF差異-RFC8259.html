JSON 語法規範——ABNF 與 EBNF 的差異，以及 RFC 8259 裡的符號

本篇重點 a–g，共 7 個。

重點整理

(a) ABNF（Augmented Backus-Naur Form，擴充巴科斯-諾爾範式）是 BNF 的變體，定義在 RFC 5234，專門用來寫網路協定與資料格式的語法。它和 EBNF 一樣是描述上下文無關文法（Context-Free Grammar）的「元語言」。

(b) ABNF 與 EBNF 的差異：

  • 終端字元：ABNF 用十六進位或範圍明確指定編碼，例如 %x5B 是 [、%x7B 是 {、%x30-39 是數字 0 到 9。
  • 重複語法：EBNF 用 { ... } 或 *，ABNF 用 a*b 表示重複 a 到 b 次，1*DIGIT 是至少一個數字。
  • 註解：ABNF 用分號 ; 開頭。

(c) MDN 頁面貼的那段不是單一 data property，而是 RFC 8259 對整個 JSON 格式的文法：物件、陣列、鍵值對、字串、數字、空白處理全都在內。begin-array = ws %x5B ws 就是「前後可有空白的 [」。

(d) 物件成員的定義是 member = string name-separator value，其中 name-separator 是冒號 %x3A。value 可以是基本型別，也可以遞迴包含 object 或 array。

(e) JSON 沒有分號。MDN 上看到的 ; 是 ABNF 的註解符號，後面的 ; [ left square bracket 只是 RFC 作者的說明，不屬於 JSON。

(f) JSON 實際用到的符號只有：冒號 :（分隔鍵與值）、逗號 ,（分隔成員或元素）、{}（物件）、[]（陣列）、雙引號 ""（字串與鍵，只能雙引號）、反斜線 \（跳脫）、小數點 .、-、+、e、E（數字）。

(g) ⚠️ 存疑／更正：Gemini 寫「JSON 最外層 JSON-text = object / array」，這是 舊版 RFC 4627 的定義。RFC 8259 已改為 JSON-text = ws value ws，所以單獨一個 "hello"、123、true、null 也是合法的 JSON 文件。寫 parser 或驗證時別假設最外層一定是物件或陣列。

使用者：知道 EBNF，那 ABNF 是什麼？這邊講的是 JSON 裡面可以有中括弧，還是 JSON 的 data property？

Gemini：ABNF（Augmented Backus-Naur Form）是 BNF 的另一種變體，定義於 RFC 5234。差異為：終端字元用 %x 進位制或範圍、重複用 a*b、註解用分號。MDN 展示的是 RFC 8259 定義的整個 JSON 語法，begin-array 與 begin-object 定義結構開頭，JSON 最外層可以是 object 或 array（JSON-text = object / array，此句有誤，見 (g)）。物件內部成員 member = string name-separator value，name-separator 為冒號。

使用者：可是就我知道的json裡面沒有那麼多符號可以用吧 有colon? semicolon?

Gemini：冒號 JSON 有，分號完全沒有。MDN 上的分號是 ABNF 的註解符號。JSON 使用的符號：冒號、逗號、大括號、中括號、雙引號、反斜線、小數點、負號正號 e E。
