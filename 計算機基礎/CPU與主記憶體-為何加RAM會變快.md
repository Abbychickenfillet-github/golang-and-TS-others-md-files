# CPU 與主記憶體 —— 「加大記憶體就會變快」到底是什麼意思？

相關筆記：[[記憶體最小定址單位 (Byte Addressability)]]、[[ASCII-美國資訊交換標準碼]]、[[傳值vs傳址-賦值與記憶體空間]]

---

## 1. CPU 的內部分工

CPU 的工作主要是**管理**與**運算**，內部分成兩個主要單元：

| 單元 | 英文 | 負責什麼 |
|---|---|---|
| **算術邏輯單元** | ALU (Arithmetic Logic Unit) | **程式運算與邏輯判斷**（加減乘除、比大小、AND/OR） |
| **控制單元** | CU (Control Unit) | **協調各周邊元件與各單元間的工作**（決定下一步做什麼、去哪拿資料） |

打個比方：**ALU 是廚師（實際做菜），CU 是內場總管（叫誰做什麼、什麼時候出菜）。**

---

## 2. 資料的必經之路：所有東西都要過「主記憶體」

這是**馮紐曼架構（von Neumann architecture）**的核心：**程式和資料都存在同一個記憶體裡，CPU 從記憶體取指令、取資料、運算、寫回。**

```
     ┌──────────────────────────────┐
     │            CPU                │
     │   ┌────────┐   ┌────────┐    │
     │   │  ALU   │   │   CU   │    │   ← 運算 + 控制
     │   └────────┘   └────────┘    │
     │        ↕  暫存器 (register)   │   ← 最快，但超小（幾十 bytes）
     └───────────┬──────────────────┘
                 ↕  ★ 所有資料的必經之路 ★
     ┌───────────┴──────────────────┐
     │      主記憶體 (RAM)            │   ← 快，但斷電就消失
     └───────────┬──────────────────┘
                 ↕
     ┌───────────┴──────────────────┐
     │   硬碟 / SSD（外部儲存）        │   ← 慢！但斷電資料還在
     └──────────────────────────────┘
```

> 🔑 **CPU 不能直接運算硬碟上的資料**。硬碟裡的東西**一定要先載入主記憶體**，CPU 才碰得到。
> 這就是「所有資料都要經過主記憶體傳輸」的意思。

### 速度差距有多誇張？

| 層級 | 存取時間（量級） | 換算成「人的時間感」 |
|---|---|---|
| CPU 暫存器 | ~1 ns | 1 秒 |
| L1/L2 快取 | ~1–10 ns | 幾秒 |
| **主記憶體 (RAM)** | **~100 ns** | **~2 分鐘** |
| **SSD** | **~100 µs** | **~1.5 天** |
| 傳統硬碟 (HDD) | ~10 ms | **~4 個月** 😱 |

**記憶體比 SSD 快約 1000 倍，比 HDD 快約 10 萬倍。** 這個量級差距是理解下一節的關鍵。

## 3. ⚠️ 「加大記憶體就會變快」——正確理解（別直接背！）

很多教材（如鳥哥的 Linux 私房菜）會說：

> 「因為所有的資料都要經過主記憶體的傳輸，所以記憶體的容量如果太小，資料快取就不足，影響效能相當大！尤其針對 Linux 作為伺服器的環境下。」

**這句話的結論是對的，但如果你把「原因」理解成「記憶體大 = 傳輸快」，就錯了。**

### ❌ 錯誤理解
> 記憶體越大，資料在裡面跑得越快。

**不對。** 記憶體的**速度**跟容量無關，8GB 和 64GB 的存取速度是一樣的。

### ✅ 真正的機制：**避免 swap（記憶體交換）**

**記憶體不夠時，作業系統會把塞不下的資料丟到硬碟上（Linux 叫 swap，Windows 叫分頁檔 pagefile）。**

```
記憶體夠用：
  程式要資料 → 從 RAM 拿 → 100 ns  ✅ 快

記憶體不夠（發生 swap）：
  程式要資料 → 不在 RAM 裡！→ 去硬碟撈回來 → 100 µs ~ 10 ms  ❌ 慢 1000～100000 倍
              （還要先把別的資料踢出去騰空間，又是一次硬碟寫入）
```

一旦開始**頻繁 swap**（叫 **thrashing / 記憶體顛簸**），系統會卡到像當機——因為它 99% 的時間都在搬資料，根本沒空算東西。

> 🎯 **所以「加記憶體」的真正效果是：讓 swap 不要發生。**

### ✅ 第二個機制：**page cache（檔案快取）**

Linux 會**自動把讀過的檔案內容暫存在閒置的記憶體裡**。下次再讀同一個檔案，直接從 RAM 拿，不用碰硬碟。

**這就是鳥哥說「資料快取不足」的意思**——記憶體越大，能快取的檔案越多。

**為什麼在伺服器環境特別重要？** 因為伺服器會**反覆讀取同樣的檔案**（網頁、資料庫索引、設定檔），命中快取的機率極高。桌機使用者感受沒那麼強烈。

> 💡 這也是為什麼 Linux 的「可用記憶體」看起來總是很少——**它故意把閒置記憶體拿去當快取**。閒著也是閒著，不如拿來加速。這叫 "free memory is wasted memory"。

## 4. 🚨 所以到底該不該加記憶體？

```
記憶體用量已滿、一直在 swap  →  加記憶體  →  效能暴增 ✅
記憶體只用 40%、系統還是慢    →  加記憶體  →  一點屁用都沒有 ❌
                                              （瓶頸在 CPU 或硬碟，不在記憶體）
```

> **口訣：加記憶體能「消除瓶頸」，不能「超越瓶頸」。**
>
> 先看記憶體有沒有滿、有沒有在 swap，再決定要不要加。不要無腦加。

怎麼看：

```powershell
# Windows：看「認可」大小 vs 實體記憶體
Get-CimInstance Win32_OperatingSystem | Select-Object @{n='總記憶體(GB)';e={[math]::Round($_.TotalVisibleMemorySize/1MB,1)}}, @{n='可用(GB)';e={[math]::Round($_.FreePhysicalMemory/1MB,1)}}
```

```bash
# Linux：看 swap 那一行有沒有在動
free -h
vmstat 1        # si/so 欄位持續有數字 = 正在 swap = 該加記憶體了
```

## 5. 🤔 這對學 JavaScript 有什麼幫助？（誠實版）

### ❌ 跟 Event Loop **沒有關係**（別把兩者連在一起！）

很直覺會想：「資料都要經過 CPU 和記憶體，那是不是跟 event loop 有關？」

**接不起來。這是兩個不同層次的東西：**

| | 在講什麼 | 為什麼存在 |
|---|---|---|
| **CPU / 記憶體架構** | **硬體**怎麼搬資料 | 物理限制 |
| **Event Loop** | **JS 怎麼排隊處理任務** | 因為 **JS 是單執行緒**，不能因為等一個 API 回應就整個卡死 |

**Event loop 存在的原因是「等待 I/O」，不是「記憶體不夠」。**

當你 `fetch()` 一個 API，那 200 ms 的等待期間，**CPU 根本是閒著的**——它不是在運算、也不是在搬記憶體，它是在**等網路封包從地球另一端回來**。Event loop 就是為了「等的時候別呆站著，先去做別的事」。

> 🚫 **就算你電腦有 1 TB 記憶體、CPU 快一萬倍，`fetch` 還是要等那 200 ms，event loop 還是得存在。**
> 硬體再猛也救不了「等別人回應」這件事。**強行把兩者連在一起，會讓你對 event loop 建立錯誤的心智模型。**

### ✅ 但這些地方**真的**用得到

| JS 主題 | 為什麼需要記憶體概念 |
|---|---|
| **傳值 vs 傳址** ⭐ 最直接 | `const b = a` 時 `b` 拿到的是**記憶體位址**，不是複製一份。沒有記憶體概念**根本理解不了**。見 [[傳值vs傳址-賦值與記憶體空間]] |
| **Stack vs Heap** | 為什麼遞迴太深會 `Maximum call stack size exceeded`？因為 **stack 是固定大小的小塊空間**，堆滿就爆 |
| **GC / 記憶體洩漏** | 為什麼忘記 `removeEventListener` 會讓網頁越用越卡？因為那塊記憶體**永遠回收不掉** |
| **bit / byte** | `rgb(255,0,0)`、`#FF0000`、`charCodeAt()`——天天在用。見 [[記憶體最小定址單位 (Byte Addressability)]]、[[ASCII-美國資訊交換標準碼]] |

## TL;DR

1. CPU 內部：**ALU**（運算與邏輯判斷）+ **CU**（控制、協調）。
2. **馮紐曼架構**：CPU 摸不到硬碟，**所有資料都必須先載入主記憶體**。
3. 速度差距：RAM 比 SSD 快 **~1000 倍**，比 HDD 快 **~10 萬倍**。
4. **「加記憶體變快」的真正原因不是「傳輸變快」，而是**：
   - **避免 swap**（記憶體塞不下就得去硬碟搬，慢上千倍）
   - **增加 page cache**（讀過的檔案快取在 RAM，下次不用碰硬碟）← 伺服器環境效益最大
5. **加記憶體能「消除瓶頸」，不能「超越瓶頸」。** 沒在 swap 的話，加了也白加。
6. ⚠️ **這些跟 JS 的 Event Loop 無關**——event loop 是為了「等 I/O」而生，不是為了記憶體。但**傳值/傳址、Stack/Heap、GC** 確實需要記憶體概念。
