重點整理

  • (a) I/O（Input/Output，輸入輸出）指資料在 CPU／記憶體與外部設備（網路 Socket、硬碟、資料庫、鍵盤）之間的「傳輸與等待過程」；資料只要離開暫存器與 Cache、要經過匯流排（Bus）到外面，就算 I/O。
  • (b) Input / Output 是相對概念，必須先定第一人稱主體：以 Server 為主體，收 HTTP request 是 Input、回 HTTP response 是 Output；以 Client 為主體則剛好相反。談後端時預設主體是 Server 的 CPU 與記憶體。
  • (c) async/await 不是 I/O 的性質，而是處理 I/O 的方式：async/sync（非同步／同步）、blocking/non-blocking（阻塞／非阻塞）描述程式架構，async/await 是語言提供的語法糖，讓非同步 I/O 看起來像同步寫法。
  • (d) Thread（執行緒）是作業系統調度 CPU 執行程式碼的最小單位，更大的單位是 process（行程），再往上是多處理架構（multi-processing）。
  • (e) Thread 是「執行上下文與排班表」，CPU Core 才是真正的運算資源；比喻：Core 是工廠機器，Thread 是工人的工作手冊。
  • (f) Thread 的兩大開銷：Context Switch（上下文切換，把暫存器與堆疊指標 SP（Stack Pointer，堆疊指標）存回記憶體再載入另一個 Thread 的狀態）與每個 Thread 預先配置的 RAM Stack（約數百 KB 到數 MB）。
  • (g) Thread 太多會吃光記憶體並讓切換變頻繁，所以高併發 I/O 場景常改用 Node.js 的單執行緒事件迴圈（event loop）或 Go 的輕量 goroutine。
  • (h) I/O 等待期間 CPU 通常閒置，這正是 async 能「等待時先去做別的事」的價值。
概念 角色 說明
CPU Core 運算機器 加減乘除與邏輯判斷
Thread 調度單位 開銷為 Context Switch 與 RAM Stack
I/O 搬運與等待 記憶體與網卡、硬碟等之間的傳輸
Input / Output 相對方向 依第一人稱主體而定

⚠️ 存疑/更正：Gemini 把 Go 與 Node.js 並列為「單執行緒事件迴圈」是簡化；Go 的 runtime 實際上會用多個 OS thread 排程 goroutine，不是單執行緒事件迴圈（依我所知，未連網查證）。
