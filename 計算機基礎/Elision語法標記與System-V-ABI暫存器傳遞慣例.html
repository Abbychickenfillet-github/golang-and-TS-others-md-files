Elision語法標記與System-V-ABI暫存器傳遞慣例

本篇重點 a–h，共 8 個

重點整理

a. 什麼是 ECMAScript 規格書裡的 Elision

Elision 指「省略、空缺、逗號之間的空位」。在 JavaScript 陣列字面值（Array Literal）裡，如果寫出兩個連續逗號，中間被留白的位置就是 Elision：

const arr = [1, , 3];
// 中間那個未定義的空位（稀疏陣列 sparse array）在語法解析時就標記為 Elision

b. 什麼是規格書裡的 opt 標記

opt 是 optional 的縮寫。ECMAScript 規格書（Spec）的 BNF 文法標記法裡，某個語法符號右下標了 opt（或寫成 [opt]），代表這個語法元素可以出現、也可以不出現。

c. 合起來讀：Elision opt

規格書裡常見的陣列元素定義：

ElementList :
  Elision opt AssignmentExpression
  ElementList , Elision opt AssignmentExpression

意思是：陣列的第一個元素前面可以有空位（Elision opt），也可以直接接運算式（例如 [, 1] 或 [1] 都合法）；元素與元素之間也可以包含一個或多個空位（例如 [1, , , 2]）。

d. 浮點數在函式呼叫時走哪個暫存器：與整數分開傳

現代 CPU 架構的呼叫慣例（Calling Convention）裡，浮點數（float／double）即使是簡單的基本型別（Primitive），底層也不會放進通用暫存器（如 x86-64 的 rax、rdi、rsi），而是直接放進浮點／SIMD 暫存器（如 x86-64 的 xmm0 ~ xmm7）。

原因：x86-64（System V ABI 或 Windows x64）已淘汰早期的 x87 浮點協同處理器，改由 SSE/AVX（即 SIMD 暫存器）接管浮點運算；xmm 暫存器雖然主要設計給 SIMD（單指令多資料）用，但同時也是執行純量浮點數（Scalar Floating-Point）運算的地方。

e. 整數 vs 浮點數在 System V ABI 下的暫存器分配範例

以 C 函式 void foo(int a, double b, int c, float d); 在 x86-64 Linux（System V ABI）為例，編譯成組合語言後：

參數 型別 分配到的暫存器
a 整數 int 通用暫存器 edi
b 浮點數 double SIMD 暫存器 xmm0
c 整數 int 通用暫存器 esi
d 浮點數 float SIMD 暫存器 xmm1

結論：小數依然是直接傳值（By Value），不需要傳記憶體位址；但因為 CPU 硬體把「整數算術邏輯單元 ALU」與「浮點／向量運算單元 FPU/SIMD」分開設計，浮點數一定走 xmm／ymm 這種浮點/SIMD 暫存器通道傳遞，跟整數的通用暫存器通道是分開的兩條路。

f. System V ABI 是什麼

System V ABI（Application Binary Interface）就是上面 d、e 兩點描述的那套規範：定義 CPU 暫存器如何傳遞函式參數、記憶體如何對齊、執行檔（ELF）格式，是現代 Linux、macOS 等平台的硬體溝通標準。「System V」這個名字的完整歷史脈絡（AT&T 商業版 UNIX、與 BSD 的 UNIX 戰爭、System V IPC、System V Init）記在 Unix-與類Unix系統介紹 的「追加 2026-09-28」段落，因為那屬於 Unix 系統史而非 JS 語法或暫存器機制本身，兩篇互相對照著看。
