## 有没有「唯一性」？

要分两层看：

### 1. 同一个函数的参数列表内 → 必须唯一

```javascript
function foo(a, a) {}  // ❌ SyntaxError（严格模式 / module 下）
```

同一个 `function` 的参数名不能重复。

```javascript
function createCounter(buttonId) { ... }

function other(buttonId) { ... }  // ✅ 完全可以，各自有自己的 scope
```

`buttonId` 只在**那次 `createCounter` 调用**的 lexical environment 里有效，不会和别的函数冲突。

## 和 `let` / `const` 的关系

在 ES6 之后，可以把它想成：**参数就是函数 scope 里的绑定**，和函数体内的 `let` 几乎同一层 scope。

```javascript
function createCounter(buttonId) {
    let count = 0;           // 函数 scope 内的 binding
    const button = ...;    // 同上
    // buttonId 也是这个 scope 里的 binding，只是由「调用时的实参」初始化
}
```

差别主要是**初始化方式**：

| | 参数 | `let` / `const` |
|---|------|----------------|
| 谁赋值 | 调用者传入的 argument | 自己写 `= 值` |
| 何时建立 | 函数被 **call** 时 | 执行到那一行时 |
| scope | 整个函数 body | 整个函数 body（和参数同层） |

旧时代（ES5）参数和 `var` 有奇怪的 hoisting 互动；现在学的话，用「参数 ≈ 由实参初始化的局部绑定」就够了。

- 你只是传了一个字串 `"counter1"`
- `buttonId` 是 **createCounter 内部新建立的局部名字**，接住这个字串

这和 outer scope **没有名字上的关系**。

### 情况 B：closure 记住的是「外层函数的 binding」

```javascript
function createCounter(button) {
    let count = 0;                    // createCounter 的 binding
    return function inner() {
        count++;                      // inner 引用的是外层的 count
        button.textContent = count;   // 引用的是外层的 button
    };
}
```

这里 inner **不是**通过参数「接住」外层变量，而是 **closure 捕获外层 lexical environment 里的 binding**。

---

## 传 id 字串 vs 传 DOM，和参数的关系

```javascript
// 传字串
createCounter("counter1");
function createCounter(buttonId) {
    const button = document.getElementById(buttonId);
}

// 传 DOM
const btn = document.getElementById("counter1");
createCounter(btn);
function createCounter(button) {
    // button 接住的是 btn 那个「引用」的副本
}
```

参数做的事都一样：**建立一个局部名字，接住 call 时传进来的值**。

- 传 `"counter1"` → `buttonId` 绑定到字串
- 传 DOM → `button` 绑定到**同一个 DOM 物件的引用**（不是复制整颗 DOM）

之后你在函数里用 `getElementById`，才从字串变成 DOM；传 DOM 则跳过这一步。

---

## 你最后一句：「参数位置是否符合 Identifier 定义？」

**符合。** 在 ECMAScript 语法里，FormalParameter 用的就是 `BindingIdentifier`。

更准确的说法是：

1. 参数名是 **identifier**
2. 在同一个 parameter list 里 **不能重复**（这是语法规则，不是「全局唯一」）
3. 它是 **函数 scope 的 binding**，不是 outer scope 的 alias
4. 每次 `createCounter(...)` 调用都会 **新建** 一套 binding（所以两个 counter 互不影响）

---

## 一句话总结

参数不是「去外层找同名变量」，而是「函数被调用时，在函数自己的 lexical scope 里宣告一个名字来接住实参」。  
它有 identifier 的规则、在参数列表内要唯一，但和 `let`/`const` 一样都是局部绑定；closure 则是 inner 函数去抓**外层函数 scope** 里的 binding，那是另一回事。

你如果把 `buttonId` 想成「这次调用专用的局部变量，初值由 caller 决定」，就和 JS 的模型很接近了。
